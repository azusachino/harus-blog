When the OCI runtime (`runc` or `youki`) creates a Pod sandbox with `CLONE_NEWNET`, the resulting network namespace contains nothing except a down loopback interface (`lo`). How does that isolated namespace acquire an `eth0` interface, a routable Pod IP address, default gateway routes, and transparent access to Kubernetes `ClusterIP` Services?

Neither `kubelet` nor `containerd` hardcodes virtual switches or IP allocators. Instead, `containerd` invokes external binaries adhering to the CNCF **Container Network Interface (CNI)** specification. Over the past decade, those CNI dataplanes have evolved from virtual Ethernet (`veth`) bridges and linear `iptables` rules into **Cilium eBPF socket-layer load balancers** and **sidecarless Service Meshes (`ztunnel`)**.

This chapter traces a packet from a container `sendmsg()` call through both the classic Linux bridge/`iptables` path and the modern eBPF fast path.

## Before you start

Every Kubernetes pod gets its own IP address and must be able to reach every other pod, on any node. The kernel does not do this by itself, so a network plugin has to build it each time a pod starts: create a virtual cable, plug one end into the pod, plug the other into the host, and add the routing rules. This chapter covers the plugin contract (CNI), the classic way of doing it with a bridge and iptables, and why that gets slow in big clusters.

The scaling problem is easy to picture. iptables checks packets against a list of rules one after another, so with 10,000 services a packet may walk thousands of entries. A hash-table lookup, which is what eBPF-based plugins such as Cilium use, takes about the same time however large the table is.

Know [chapter 1](/tech/series/cncf-containers/01.namespaces-cgroups-and-pid1/) first, especially network namespaces. Chapter 3 explains who calls the plugin.

Terms used in this chapter:

- **CNI**: the Container Network Interface, a small standard where the runtime executes a plugin binary with `ADD` or `DEL` to connect or disconnect a container.
- **veth pair**: two virtual network interfaces joined like a cable; whatever enters one end comes out the other.
- **bridge**: a virtual switch inside the host that connects several interfaces at layer 2.
- **iptables**: the Linux packet-filtering and address-rewriting rules, evaluated as ordered lists.
- **eBPF**: a way to load small verified programs into the kernel and attach them to events such as packet arrival or socket calls.
- **Cilium**: a CNI plugin that implements pod networking and load balancing with eBPF instead of iptables.
- **service mesh**: infrastructure that adds encryption, retries and metrics to service-to-service traffic.
- **sidecar**: a helper container placed in every pod, as opposed to one shared per-node proxy.

## 1. The CNCF CNI Contract (`ADD`, `DEL`, `CHECK`)

Unlike CSI (storage) or CRI (runtime), which communicate with long-running daemons over gRPC, the **CNI specification** is deliberately a **stateless fork/exec CLI protocol**:

When `containerd` handles `RunPodSandbox`, it forks the configured CNI binary (e.g., `/opt/cni/bin/bridge`, `/opt/cni/bin/flannel`, or `/opt/cni/bin/cilium-cni`), passes the network configuration JSON (`10-containerd-net.conflist`) on **`stdin`**, and sets environment variables such as:

```bash
CNI_COMMAND=ADD
CNI_CONTAINERID=9b81f2a4...
CNI_NETNS=/var/run/netns/cni-3d8a1-91f2
CNI_IFNAME=eth0
CNI_PATH=/opt/cni/bin
```

### What `CNI_COMMAND=ADD` Executes Step by Step

1. **IPAM (IP Address Management) Delegation**: The main CNI binary invokes an IPAM plugin (such as `host-local` or `cilium-ipam`) to allocate a free IP from the node's Pod CIDR (e.g., `10.42.0.18/24` with gateway `10.42.0.1`).
2. **Virtual Ethernet (`veth`) Pair Creation**:
   A `veth` pair is a virtual patch cable with two ends (`vethA <---> vethB`): any frame transmitted into one end immediately emerges as an ingress packet on the peer end.
   - Inside `/var/run/netns/cni-3d8a1-91f2`, the CNI plugin creates `eth0` peered with a host-namespace interface `veth8a91b2c`.
3. **Host Plumbing & Routing**:
   - **Bridge / Overlay mode (`flannel` / `bridge`)**: Attaches `veth8a91b2c` as a bridge port on `cni0` (`ip link set veth8a91b2c master cni0`), assigns `10.42.0.18/24` to container `eth0`, and adds `default via 10.42.0.1 dev eth0` inside the Pod netns.
   - **L3 Routed / eBPF mode (`cilium` / `calico`)**: Skips the `cni0` bridge entirely! Assigns a `/32` route (`10.42.0.18/32 dev lxc8a91b2c`) in the host routing table (or eBPF endpoint map) pointing straight to the host end of the `veth` pair.
4. **JSON Result on `stdout`**: The CNI plugin prints the allocated `ips[]`, `interfaces[]`, `routes[]`, and `dns` JSON to `stdout` and exits with code `0`.

## 2. Why Legacy `veth` + `cni0` + `iptables` Degrades at Scale

In a traditional Kubernetes cluster using `cni0` bridges and `kube-proxy` in `iptables` mode, trace what happens when Pod A (`10.42.0.18`) calls `connect()` to a Kubernetes `ClusterIP` Service (`10.96.14.20:443`) backed by Pod B (`10.42.1.55:8443`):

1. **Pod TCP/IP Traversal**: Pod A constructs a TCP `SYN` packet (`src=10.42.0.18`, `dst=10.96.14.20:443`), traverses the Pod's own TCP/IP stack, netfilter hooks, and queuing discipline (`qdisc`), and transmits over `eth0` (`veth`).
2. **Cross-Namespace Softirq Context Switch**: Crossing the `veth` boundary into the host's `cni0` bridge enqueues the `sk_buff` onto the CPU's per-core backlog queue (`enqueue_to_backlog`) and raises a **`NET_RX_SOFTIRQ`** software interrupt.
3. **$O(N)$ `iptables` Linear Rule Scan**:
   In the host `PREROUTING` / `OUTPUT` `nat` table, `kube-proxy` maintains a sequential chain `KUBE-SERVICES` with one rule per Service across the entire cluster!
   - If the cluster has **10,000 Services**, every new TCP connection must linearly scan an average of **5,000 `KUBE-SVC-*` rules** before matching `10.96.14.20:443` and jumping to `KUBE-SEP-*` to perform `DNAT` (`dst -> 10.42.1.55:8443`) and insert a `nf_conntrack` state entry.
   - Worse still: updating a single endpoint in a 10,000-Service cluster requires `iptables-restore` to serialize, lock, and atomically replace a megabyte-sized blob containing **tens of thousands of rules**.

## 3. Cilium & the eBPF Dataplane Revolution

**Cilium** (a CNCF Graduated project) replaces both `kube-proxy` (`iptables`) and the `cni0` software bridge with **eBPF programs** attached directly to the container's **cgroup socket hooks** (`cgroup/connect4`, `cgroup/sendmsg4` for service load balancing; `sock_ops`, `sk_msg` for same-node bypass) and **Traffic Control (`tcx` / `tc` ingress & egress)** hooks:

| Mechanism | eBPF Hook & Map Type | How It Eliminates Legacy Overhead |
| :--- | :--- | :--- |
| **Socket-Layer Load Balancing (`kube-proxy` replacement)** | `BPF_PROG_TYPE_CGROUP_SOCK_ADDR` (`cgroup/connect4`, `cgroup/sendmsg4`) + `BPF_MAP_TYPE_HASH` | Intercepts `connect(fd, 10.96.14.20:443)` **at the syscall boundary before any packet is built**! Looks up `10.96.14.20:443` in an **$O(1)$ eBPF hash map** and rewrites `sockaddr_in.sin_addr` in place to `10.42.1.55:8443`. Zero `DNAT` packet rewriting or `conntrack` overhead! |
| **Same-Node Socket Bypass (`Sockmap`, optional)** | `BPF_PROG_TYPE_SOCK_OPS` + `BPF_PROG_TYPE_SK_MSG` (`BPF_MAP_TYPE_SOCKHASH`) | When two Pods (or an app container and its local proxy) communicate on the same node, `sk_msg` copies payload bytes **directly from the sender socket's send buffer to the receiver socket's receive queue**, bypassing TCP/IP framing, `veth`, and `netns` transitions. This acceleration has been experimental in Cilium, so check your version's docs before relying on it. |
| **L3 Fast Redirect (`bpf_redirect_peer`)** | `BPF_PROG_TYPE_SCHED_CLS` (`tc` ingress on host `veth`) | For packets that do leave the Pod `veth`, `bpf_redirect_peer()` jumps directly into the destination Pod's `netns` `eth0` Rx queue in a single CPU pass without scheduling a backlog `NET_RX_SOFTIRQ` or touching a host bridge. |

## 4. Sidecar vs. Ambient Service Mesh (`ztunnel` & HBONE)

When platform teams adopt a **Service Mesh** (such as **Istio** or **Linkerd**) for mutual TLS (`mTLS` SPIFFE identity `spiffe://cluster.local/ns/prod/sa/payments`), L7 retries, and traffic splitting, two architectural models compete:

```text
  1. Traditional Sidecar Mesh                  2. Istio Ambient Mesh (Sidecarless)
  ===========================                  ===================================
  +------ Pod Network Namespace ------+        +---- Pod Netns ----+   +-- Node Shared --+
  |  App Container <--> Envoy Sidecar |        |   App Container   |   |  ztunnel (Rust) |
  |         ^                 ^       |        +---------+---------+   |  L4 mTLS HBONE  |
  |         +-- iptables -----+       |                  |             +--------+--------+
  |          redirect :15006/:15001   |                  +--- netns socket / ---+
  +-----------------------------------+                       eBPF redirect
```

1. **Sidecar Model (`istio-proxy` / Envoy per Pod)**:
   - An init container (`istio-init`) injects `iptables` rules inside every Pod's network namespace to intercept all inbound (`:15006`) and outbound (`:15001`) TCP connections through a co-located Envoy sidecar container.
   - *Trade-off*: Every single Pod pays the memory footprint (tens of MiB of RSS per Envoy instance, multiplied by $N$ Pods), and upgrading Envoy requires restarting every application Pod in the cluster.
2. **Ambient Mesh (`ztunnel` + Waypoint Proxies)**:
   - Decouples **Layer 4 zero-trust mTLS** from **Layer 7 HTTP/gRPC processing**.
   - A single lightweight node-level DaemonSet written in Rust (**`ztunnel`**) enters each Pod's network namespace via CNI socket redirection (`istio-cni`) to wrap traffic in **HBONE** (HTTP-Based Overlay Network Environment — HTTP/2 `CONNECT` tunnels over mTLS) with zero sidecar containers inside application Pods.
   - Only namespaces or services that explicitly need L7 features (HTTP header routing, gRPC retries, OpenTelemetry span generation) deploy an optional shared **Waypoint Proxy**.

## 5. Verification Lab: CNI `ADD`/`DEL` Protocol & `iptables` $O(N)$ vs. eBPF $O(1)$ Datapath

The following self-contained Python 3 verification script implements:

1. **A Spec-Compliant CNI Plugin (`ADD`, `CHECK`, `DEL`) & `host-local` IPAM**: Allocates deterministic `/24` Pod IPs, wires virtual `veth` peer pairs (`eth0 <-> lxc<id>`), and outputs the CNI v1.0.0 JSON result structure.
2. **`iptables` Linear Chain vs. Cilium eBPF `cgroup/connect4` + `SOCKHASH` Simulator**: Counts lookup operations and simulated stack traversals for clusters of 100 and 5,000 Kubernetes Services (same-node backend case).

```python
#!/usr/bin/env python3
"""
Verification Lab 05: CNI ADD/DEL IPAM Protocol & iptables O(N) vs Cilium eBPF O(1) Datapath
Run directly: python3 lab05_cni_ebpf_datapath.py
"""
import hashlib
from dataclasses import dataclass, field
from typing import Dict, List, Optional, Tuple


# ---------------------------------------------------------------------------
# 1. CNI v1.0.0 Plugin & host-local IPAM Simulator
# ---------------------------------------------------------------------------
@dataclass
class CNIEnv:
    command: str  # ADD, DEL, CHECK
    container_id: str
    netns: str
    ifname: str = "eth0"


class CNIPluginSimulator:
    def __init__(self, subnet_prefix: str = "10.42.0.", gateway: str = "10.42.0.1/24"):
        self.subnet_prefix = subnet_prefix
        self.gateway = gateway
        self.next_host_octet = 10
        self.allocated_by_cid: Dict[str, Dict[str, object]] = {}

    def invoke(self, env: CNIEnv) -> Dict[str, object]:
        if env.command == "ADD":
            ip_cidr = f"{self.subnet_prefix}{self.next_host_octet}/24"
            self.next_host_octet += 1
            host_veth = "lxc" + hashlib.sha256(env.container_id.encode()).hexdigest()[:8]
            result = {
                "cniVersion": "1.0.0",
                "interfaces": [
                    {"name": host_veth, "sandbox": ""},
                    {"name": env.ifname, "sandbox": env.netns},
                ],
                "ips": [{"address": ip_cidr, "gateway": self.gateway.split("/")[0], "interface": 1}],
                "routes": [{"dst": "0.0.0.0/0", "gw": self.gateway.split("/")[0]}],
            }
            self.allocated_by_cid[env.container_id] = result
            return result
        if env.command == "CHECK":
            if env.container_id not in self.allocated_by_cid:
                raise RuntimeError("CNI CHECK failed: container netns not found")
            return self.allocated_by_cid[env.container_id]
        if env.command == "DEL":
            self.allocated_by_cid.pop(env.container_id, None)
            return {"cniVersion": "1.0.0"}
        raise ValueError(f"Unknown CNI_COMMAND: {env.command}")


# ---------------------------------------------------------------------------
# 2. Legacy iptables O(N) vs. Cilium eBPF cgroup/connect4 + SOCKHASH Simulator
# ---------------------------------------------------------------------------
class DatapathBenchmarkSimulator:
    def __init__(self, num_services: int):
        # Populate N Services: 10.96.<hi>.<lo>:80 -> Backend Pod IP + Node ID
        self.iptables_chain: List[Tuple[str, str, str]] = []
        self.bpf_lb_map: Dict[str, Tuple[str, str]] = {}
        for i in range(1, num_services + 1):
            vip = f"10.96.{(i >> 8) & 0xFF}.{i & 0xFF}:80"
            backend_ip = f"10.42.{i % 4}.{(i % 200) + 10}:8080"
            node_id = "node-1" if (i % 2 == 0) else "node-2"
            self.iptables_chain.append((vip, backend_ip, node_id))
            self.bpf_lb_map[vip] = (backend_ip, node_id)

    def simulate_legacy_veth_iptables(self, target_vip: str, sender_node: str = "node-1") -> Dict[str, int]:
        rule_comparisons = 0
        matched_node = ""
        for vip, _backend, node_id in self.iptables_chain:
            rule_comparisons += 1
            if vip == target_vip:
                matched_node = node_id
                break
        # Legacy path traverses Pod TCP stack -> veth -> host cni0 bridge (softirq) -> iptables DNAT -> dst veth/NIC
        netns_crossings = 2 if matched_node == sender_node else 1
        tcp_stack_passes = 2 if matched_node == sender_node else 1
        return {
            "rule_lookups": rule_comparisons,
            "netns_veth_crossings": netns_crossings,
            "tcp_stack_passes": tcp_stack_passes,
        }

    def simulate_cilium_ebpf(self, target_vip: str, sender_node: str = "node-1") -> Dict[str, int]:
        # O(1) BPF hash map lookup inside cgroup/connect4 hook before SYN packet construction!
        _backend, matched_node = self.bpf_lb_map[target_vip]
        if matched_node == sender_node:
            # Same-node Pod communication uses sk_msg + BPF_MAP_TYPE_SOCKHASH socket buffer copy
            return {"rule_lookups": 1, "netns_veth_crossings": 0, "tcp_stack_passes": 0}
        # Cross-node uses bpf_redirect_neigh / XDP direct routing without host bridge
        return {"rule_lookups": 1, "netns_veth_crossings": 1, "tcp_stack_passes": 1}


def main() -> None:
    print("=== 1. CNI v1.0.0 ADD / CHECK / DEL Lifecycle Verification ===")
    cni = CNIPluginSimulator()
    env_add = CNIEnv(command="ADD", container_id="pod-a81f90", netns="/var/run/netns/cni-a81f90")
    res_add = cni.invoke(env_add)
    print(f"  CNI ADD allocated IP={res_add['ips'][0]['address']}, interfaces={res_add['interfaces']}")
    assert res_add["ips"][0]["address"] == "10.42.0.10/24"
    cni.invoke(CNIEnv(command="CHECK", container_id="pod-a81f90", netns="/var/run/netns/cni-a81f90"))
    cni.invoke(CNIEnv(command="DEL", container_id="pod-a81f90", netns="/var/run/netns/cni-a81f90"))
    assert "pod-a81f90" not in cni.allocated_by_cid

    print("\n=== 2. Legacy iptables O(N) vs. Cilium eBPF O(1) Datapath Comparison ===")
    for n_svc in (100, 5_000):
        sim = DatapathBenchmarkSimulator(num_services=n_svc)
        # Target the last Service in the table (same-node backend since n_svc is even)
        target = f"10.96.{(n_svc >> 8) & 0xFF}.{n_svc & 0xFF}:80"
        leg = sim.simulate_legacy_veth_iptables(target, sender_node="node-1")
        bpf = sim.simulate_cilium_ebpf(target, sender_node="node-1")
        print(f"  [Cluster Size = {n_svc:5d} Services | Same-Node Call to {target}]")
        print(f"    Legacy veth+iptables : {leg}")
        print(f"    Cilium eBPF+SOCKHASH : {bpf}")
        assert leg["rule_lookups"] == n_svc
        assert bpf["rule_lookups"] == 1 and bpf["tcp_stack_passes"] == 0

    print("\nAll Lab 05 CNI & eBPF datapath invariants verified.")


if __name__ == "__main__":
    main()
```

## Key Takeaways

1. **CNI is a clean fork/exec contract**: `containerd` passes `CNI_COMMAND=ADD` and `CNI_NETNS` to the CNI binary, which allocates an IP via IPAM, plumbs the Pod's network namespace, and prints a JSON result to `stdout`.
2. **Socket-level eBPF (`cgroup/connect4`) eliminates `ClusterIP` packet DNAT**: Rewriting destination socket addresses at the `connect()` / `sendmsg()` syscall boundary turns an $O(N)$ `iptables` rule scan into an $O(1)$ BPF hash table lookup before a single TCP `SYN` packet is even allocated.
3. **Choose sidecarless `ztunnel` unless per-Pod L7 Envoy is required**: Istio Ambient Mesh (`ztunnel`) delivers zero-trust SPIFFE mTLS at Layer 4 with a single node-level Rust agent, adding L7 Waypoint proxies only for namespaces that need HTTP/gRPC traffic shaping.
