If a process inside a standard rootful container runs as `UID 0` (`root`) without a user namespace (`CLONE_NEWUSER`), **what is its UID on the host kernel?** It is **`UID 0` (`root`) on the host kernel as well**.

What stops that container process from loading a malicious kernel module (`init_module`), mounting the host NVMe disk (`/dev/nvme0n1`), or reading `/etc/shadow`? Not a hypervisor, and not a different user ID—only the intersection of **mount namespaces (`pivot_root`)**, stripped **Linux Capabilities**, **Seccomp-BPF** system-call filters, and **LSMs (AppArmor / SELinux)**. If a kernel vulnerability or misconfigured volume mount (`-v /:/host` or `--privileged`) breaches any of those layers, a rootful container escapes straight into host `root`.

**Rootless containers**—pioneered in daily developer workflows by **Podman** and supported in modern `containerd` / Kubernetes (`userNamespaces` in PodSpec)—eliminate this root daemon blast radius at the root: even `UID 0` inside the container is an unprivileged high-numbered UID (such as `1000` or `100000`) on the host.

## 1. Daemonless Podman (`conmon`) vs. Client-Server `dockerd`

Before examining user namespaces, compare how `docker run` and `podman run` spawn a container:

```text
  Docker (Client-Server Root Daemon)           Podman (Daemonless Fork/Exec Model)
  ==================================           ===================================
  $ docker run ... (unprivileged user)         $ podman run ... (UID 1000)
        |                                            |  (direct fork/exec under user's
        | Unix socket /var/run/docker.sock           |   systemd user.slice cgroup!)
        v                                            v
  dockerd (UID 0 root daemon)                  conmon (UID 1000 tiny C monitor)
        |                                            |
        v                                            v
  containerd -> containerd-shim-v2             crun / youki / runc (OCI runtime)
        |                                            |
        v                                            v
  Container Process                            Container Process (Host UID 1000 / 100000+)
```

- **Why `docker.sock` is equivalent to passwordless `sudo`**: Anyone in the `docker` group who can write to `/var/run/docker.sock` can ask the root-owned `dockerd` daemon to run `docker run -v /:/host --privileged alpine chroot /host sh`.
- **How Podman runs without a daemon**: When you run `podman run`, the `podman` CLI executes directly under your own Linux user login session (`user@1000.service` systemd slice). It forks a lightweight C supervisor called **`conmon`** (Container Monitor, ~1–2 MiB RSS, the exact analogue of `containerd-shim-v2`), invokes the OCI runtime (`crun` or `youki`), and exits. Every container inherits the caller's audit login UID (`/proc/self/loginuid`), so `auditd` logs trace every container action back to the exact human SSH user who launched it.

## 2. How Rootless User Namespaces (`CLONE_NEWUSER`) Work

How can an unprivileged user (`haru`, `UID 1000`) run `apt-get install` or `chown root:root` inside a container when `chown(2)` and `mount(2)` require `CAP_CHOWN` and `CAP_SYS_ADMIN`?

The answer is **`CLONE_NEWUSER`**:

1. **Unprivileged Creation**: Unlike every other namespace flag, `unshare(CLONE_NEWUSER)` can be called by an unprivileged user with zero capabilities in the initial host namespace.
2. **Namespace-Scoped Capabilities**: The moment a process enters a new User Namespace, the kernel grants it a full set of capabilities (`CAP_SYS_ADMIN`, `CAP_NET_ADMIN`, `CAP_CHOWN`, etc.) **scoped strictly to that User Namespace**. Whenever the process performs a privileged operation (like mounting a `tmpfs` inside its own mount namespace or creating a `veth` pair inside its own network namespace), the kernel calls `ns_capable(target_ns->user_ns, CAP_SYS_ADMIN)`—which checks whether the caller holds `CAP_SYS_ADMIN` *in the user namespace that owns that mount or network namespace*, NOT the host's initial user namespace!
3. **Subordinate UID/GID Mappings (`/etc/subuid` & `/proc/<pid>/uid_map`)**:
   A container needs more than just `UID 0` (`root`); packages like `postgres` (UID `70` or `999`) and `nobody` (UID `65534`) require thousands of distinct UIDs. On the host, `/etc/subuid` delegates a block of 65,536 subordinate UIDs to `haru`:

   ```text
   # /etc/subuid
   haru:100000:65536
   ```

   Using the setuid/file-capability helper `newuidmap(1)`, Podman writes two lines into `/proc/<pid>/uid_map` (`<container-uid-start> <host-uid-start> <count>`):

   ```text
   0       1000          1
   1     100000      65536
   ```

| UID Inside Container (`getuid()`) | Mapped Host UID in Kernel (`kuid_t`) | Meaning on the Host Filesystem |
| :--- | :--- | :--- |
| **`0` (`root`)** | **`1000` (`haru`)** | Files created by container `root` in a bind-mounted host folder are owned cleanly by `haru` (`UID 1000`)! |
| **`1`** | **`100000`** | First subordinate UID in `/etc/subuid` |
| **`999` (`postgres`)** | **`100998`** | Isolated from both host `root` (`0`) and host `haru` (`1000`) |
| **Unmapped (e.g. Host `UID 0`)** | **`65534` (`nobody` / `overflowuid`)** | Any host root-owned file appears inside the container as owned by `nobody` (`65534`) and cannot be modified even by container `UID 0`! |

### Rootless Storage & Networking Consequences

Because container `UID 0` has **zero capabilities in the host's initial user namespace**:

- **Storage**: Since Linux 5.11+, the native kernel `overlay` filesystem supports unprivileged mounts inside a user namespace via the `userxattr` mount option (storing `user.overlay.opaque` instead of `trusted.overlay.opaque`, which required host `CAP_SYS_ADMIN`).
- **Networking**: An unprivileged process cannot attach a `veth` interface to a host root bridge (`cni0`). Instead, Podman uses **`pasta`** (Part of `passt` — Plug A Simple Socket Transport) or `slirp4netns`, which opens a TAP device inside the container's network namespace and translates container TCP/UDP traffic into ordinary unprivileged host `socket(AF_INET, SOCK_STREAM)` calls in user space.

## 3. Linux Capabilities & the `execve(2)` Bitmask Equations

Even inside a container, running an application with all 41 Linux capabilities (`CAP_SYS_ADMIN`, `CAP_NET_RAW`, `CAP_SYS_PTRACE`, `CAP_DAC_OVERRIDE`, etc.) violates least privilege. The Linux kernel splits root privileges into five 64-bit capability sets per thread (`/proc/<pid>/status`):

- **`CapInh` ($P_{\text{inh}}$, Inheritable)** — passed across `execve()` when combined with file inheritable bits.
- **`CapPrm` ($P_{\text{prm}}$, Permitted)** — the superset of capabilities the thread may activate in `CapEff`.
- **`CapEff` ($P_{\text{eff}}$, Effective)** — the bitmask actually checked by the kernel on every privileged syscall.
- **`CapBnd` ($P_{\text{bnd}}$, Bounding)** — ceiling mask restricting capabilities acquired from setuid/file-capability binaries during `execve()`. Once a bit is dropped from `CapBnd`, no descendant can ever regain it.
- **`CapAmb` ($P_{\text{amb}}$, Ambient)** — capabilities preserved across `execve()` for **non-root** (`UID != 0`) processes without requiring `setcap` extended attributes on the binary file. (Invariant: $P_{\text{amb}} \subseteq (P_{\text{prm}} \cap P_{\text{inh}})$.)

When a container process calls `execve(binary)`, the kernel computes the new thread's capability masks ($P'$) from the old thread's masks ($P$) and the binary file's xattr masks ($F$) using:

$$P'_{\text{amb}} = \begin{cases} 0 & \text{if binary is setuid/setgid or has file caps } F \\ P_{\text{amb}} & \text{otherwise} \end{cases}$$

$$P'_{\text{inh}} = P_{\text{inh}}$$

$$P'_{\text{prm}} = (P_{\text{inh}} \cap F_{\text{inh}}) \;\cup\; (F_{\text{prm}} \cap P_{\text{bnd}}) \;\cup\; P'_{\text{amb}}$$

$$P'_{\text{eff}} = \begin{cases} P'_{\text{prm}} & \text{if } F_{\text{eff}} \text{ bit is set (or running as root)} \\ P'_{\text{amb}} & \text{otherwise} \end{cases}$$

> **Why `allowPrivilegeEscalation: false` (`PR_SET_NO_NEW_PRIVS`) Matters**:
> In Kubernetes `securityContext`, setting `allowPrivilegeEscalation: false` calls `prctl(PR_SET_NO_NEW_PRIVS, 1)`. With `no_new_privs` enabled, `execve()` **ignores setuid-root bits and file capabilities ($F_{\text{prm}}$)** on binaries inside the container image, ensuring an attacker who gains RCE as UID `1000` can never escalate to UID `0` via a leftover `su`/`sudo` binary in the base image.

## 4. Seccomp-BPF: Filtering the System Call Table

Even with all capabilities dropped (`drop: ["ALL"]`), a container process can still invoke over 300 unprivileged Linux system calls—and historically, kernel privilege-escalation CVEs (such as `io_uring`, `keyctl`, `userfaultfd`, or `perf_event_open` bugs) reside inside obscure system calls that normal web servers never use.

**Seccomp-BPF (`prctl(PR_SET_SECCOMP, SECCOMP_MODE_FILTER, &prog)`)** attaches a classic Berkeley Packet Filter (cBPF) program to the task that runs on every `syscall` instruction before the kernel dispatches `sys_call_table[nr]`, inspecting `struct seccomp_data`:

```c
struct seccomp_data {
    int   nr;                   /* System call number (e.g., __NR_clone3 = 435) */
    __u32 arch;                 /* AUDIT_ARCH_X86_64 or AUDIT_ARCH_AARCH64      */
    __u64 instruction_pointer;  /* CPU RIP/PC at syscall entry                  */
    __u64 args[6];              /* Up to 6 64-bit register arguments            */
};
```

Docker, Podman, and `containerd`'s `RuntimeDefault` Seccomp profile operate on a **default-deny allowlist (`SCMP_ACT_ERRNO(EPERM)`)**:

- Around ~44 dangerous syscalls (`kexec_load`, `init_module`, `finit_module`, `acct`, `swapon`, `mount`, `umount2`, `pivot_root`, `bpf`, `perf_event_open`, `keyctl`, `userfaultfd`) are blocked outright, returning `EPERM` before reaching kernel subsystem code.
- Notice that `clone(2)` and `clone3(2)` are allowed for normal thread creation (`CLONE_VM | CLONE_THREAD`), but blocked by argument inspection if the caller attempts to pass `CLONE_NEWUSER` or `CLONE_NEWNS` inside an unprivileged container!

## 5. Verification Lab: Rootless `uid_map`, Capability `execve` & Seccomp-BPF

The following self-contained Python 3 verification script implements:

1. **Rootless `/proc/<pid>/uid_map` Kernel Translation (`map_id_down` / `map_id_up`)**: Verifies how container `UID 0` maps to host `UID 1000`, container `UID 999` maps to host `UID 100998`, and host `UID 0` (`/etc/shadow`) maps to `65534` (`overflowuid`), blocking modification.
2. **Linux Capability Bitmask Equations across `execve()`**: Verifies how `no_new_privs` (`allowPrivilegeEscalation: false`) blocks setuid/file-capability escalation while `CapAmb` allows a non-root process (`UID 1001`) to retain `CAP_NET_BIND_SERVICE` (`1 << 10`) across `execve()`.
3. **Seccomp-BPF `seccomp_data` Filter Engine**: Evaluates `RuntimeDefault` syscall and bitmask argument rules (`clone` thread creation allowed vs. `clone(CLONE_NEWUSER)` blocked with `EPERM`).

```python
#!/usr/bin/env python3
"""
Verification Lab 04: Rootless uid_map Translation, Capability execve() & Seccomp-BPF Filter
Run directly: python3 lab04_rootless_security.py
"""
from dataclasses import dataclass
from typing import List, Optional, Tuple


# ---------------------------------------------------------------------------
# 1. Linux User Namespace uid_map / gid_map Kernel Translator
# ---------------------------------------------------------------------------
@dataclass
class IdMapExtent:
    ns_first: int
    host_first: int
    count: int


class UserNamespaceMap:
    OVERFLOW_UID = 65534  # /proc/sys/kernel/overflowuid (nobody)

    def __init__(self, extents: List[IdMapExtent]):
        self.extents = extents

    def ns_to_host_kuid(self, ns_uid: int) -> Optional[int]:
        """Kernel map_id_down(): translates container UID to host kuid_t."""
        for ext in self.extents:
            if ext.ns_first <= ns_uid < ext.ns_first + ext.count:
                return ext.host_first + (ns_uid - ext.ns_first)
        return None

    def host_kuid_to_ns(self, host_kuid: int) -> int:
        """Kernel from_kuid_munged(): translates host kuid_t into container UID view."""
        for ext in self.extents:
            if ext.host_first <= host_kuid < ext.host_first + ext.count:
                return ext.ns_first + (host_kuid - ext.host_first)
        return self.OVERFLOW_UID


# ---------------------------------------------------------------------------
# 2. Linux Capability Bitmask Transformation Across execve(2)
# ---------------------------------------------------------------------------
CAP_CHOWN = 1 << 0
CAP_SETUID = 1 << 7
CAP_NET_BIND_SERVICE = 1 << 10
CAP_NET_RAW = 1 << 13
CAP_SYS_ADMIN = 1 << 21


@dataclass
class CredCapSets:
    inh: int
    prm: int
    eff: int
    bnd: int
    amb: int
    no_new_privs: bool = False


@dataclass
class FileCapSets:
    inh: int = 0
    prm: int = 0
    eff_flag: bool = False
    is_setuid_root: bool = False


def compute_execve_caps(old: CredCapSets, fcap: FileCapSets, is_root_uid: bool) -> CredCapSets:
    # Ambient capabilities are cleared if binary is setuid or carries file capabilities
    has_file_privs = fcap.is_setuid_root or (fcap.prm != 0) or (fcap.inh != 0)
    new_amb = 0 if has_file_privs else old.amb

    if old.no_new_privs:
        # PR_SET_NO_NEW_PRIVS: file capabilities and setuid cannot grant privileges beyond old.prm
        effective_fprm = fcap.prm & old.prm
        is_effective_root = is_root_uid
    else:
        effective_fprm = (0xFFFFFFFF if fcap.is_setuid_root else fcap.prm)
        is_effective_root = is_root_uid or fcap.is_setuid_root

    new_inh = old.inh
    new_prm = (old.inh & fcap.inh) | (effective_fprm & old.bnd) | new_amb
    if (fcap.eff_flag and not old.no_new_privs) or is_effective_root:
        new_eff = new_prm
    else:
        new_eff = new_amb

    return CredCapSets(inh=new_inh, prm=new_prm, eff=new_eff, bnd=old.bnd, amb=new_amb, no_new_privs=old.no_new_privs)


# ---------------------------------------------------------------------------
# 3. Seccomp-BPF Syscall & Argument Filter Evaluator
# ---------------------------------------------------------------------------
CLONE_VM = 0x00000100
CLONE_THREAD = 0x00010000
CLONE_NEWNS = 0x00020000
CLONE_NEWUSER = 0x10000000


class RuntimeDefaultSeccompFilter:
    AUDIT_ARCH_X86_64 = 0xC000003E
    BLOCKED_SYSCALLS = {"kexec_load", "init_module", "finit_module", "mount", "pivot_root", "bpf", "keyctl"}

    def evaluate(self, arch: int, syscall_name: str, arg0_flags: int = 0) -> str:
        if arch != self.AUDIT_ARCH_X86_64:
            return "SCMP_ACT_KILL_PROCESS"
        if syscall_name in self.BLOCKED_SYSCALLS:
            return "SCMP_ACT_ERRNO(EPERM)"
        if syscall_name in ("clone", "clone3"):
            if arg0_flags & (CLONE_NEWNS | CLONE_NEWUSER):
                return "SCMP_ACT_ERRNO(EPERM)"
        return "SCMP_ACT_ALLOW"


def main() -> None:
    print("=== 1. Rootless Podman /proc/<pid>/uid_map Verification ===")
    # 0 -> 1000 (count 1), 1 -> 100000 (count 65536)
    umap = UserNamespaceMap([IdMapExtent(0, 1000, 1), IdMapExtent(1, 100000, 65536)])
    kuid_root = umap.ns_to_host_kuid(0)
    kuid_postgres = umap.ns_to_host_kuid(999)
    ns_view_of_host_root = umap.host_kuid_to_ns(0)
    print(f"  Container UID 0 (root)       -> Host kuid_t = {kuid_root}")
    print(f"  Container UID 999 (postgres) -> Host kuid_t = {kuid_postgres}")
    print(f"  Host UID 0 (/etc/shadow)     -> Container sees UID = {ns_view_of_host_root} (overflowuid/nobody)")
    assert kuid_root == 1000 and kuid_postgres == 100998 and ns_view_of_host_root == 65534

    print("\n=== 2. Linux Capabilities & PR_SET_NO_NEW_PRIVS Verification ===")
    # Non-root container (UID 1001) drops ALL except Ambient CAP_NET_BIND_SERVICE, sets no_new_privs=True
    initial_caps = CredCapSets(
        inh=CAP_NET_BIND_SERVICE,
        prm=CAP_NET_BIND_SERVICE,
        eff=CAP_NET_BIND_SERVICE,
        bnd=CAP_NET_BIND_SERVICE | CAP_SETUID,
        amb=CAP_NET_BIND_SERVICE,
        no_new_privs=True,
    )
    # Case A: execve() normal web server binary -> retains CAP_NET_BIND_SERVICE via Ambient set
    after_normal = compute_execve_caps(initial_caps, FileCapSets(), is_root_uid=False)
    # Case B: Attacker runs a setuid-root binary inside the container -> blocked by no_new_privs!
    after_suid = compute_execve_caps(initial_caps, FileCapSets(is_setuid_root=True), is_root_uid=False)
    print(f"  Normal binary execve CapEff  = 0x{after_normal.eff:x} (has CAP_NET_BIND_SERVICE={bool(after_normal.eff & CAP_NET_BIND_SERVICE)})")
    print(f"  Setuid binary execve CapEff  = 0x{after_suid.eff:x} (blocked CAP_SETUID={not bool(after_suid.eff & CAP_SETUID)})")
    assert after_normal.eff == CAP_NET_BIND_SERVICE
    assert after_suid.eff == 0

    print("\n=== 3. Seccomp-BPF Syscall & Argument Filter Verification ===")
    seccomp = RuntimeDefaultSeccompFilter()
    r_pthread = seccomp.evaluate(seccomp.AUDIT_ARCH_X86_64, "clone", CLONE_VM | CLONE_THREAD)
    r_newuser = seccomp.evaluate(seccomp.AUDIT_ARCH_X86_64, "clone", CLONE_NEWUSER)
    r_bpf = seccomp.evaluate(seccomp.AUDIT_ARCH_X86_64, "bpf", 0)
    print(f"  clone(CLONE_VM|CLONE_THREAD) -> {r_pthread}")
    print(f"  clone(CLONE_NEWUSER)         -> {r_newuser}")
    print(f"  bpf() syscall                -> {r_bpf}")
    assert r_pthread == "SCMP_ACT_ALLOW"
    assert r_newuser == "SCMP_ACT_ERRNO(EPERM)"
    assert r_bpf == "SCMP_ACT_ERRNO(EPERM)"
    print("\nAll Lab 04 rootless & syscall security invariants verified.")


if __name__ == "__main__":
    main()
```

## Key Takeaways

1. **Rootless user namespaces eliminate host `UID 0` equivalence**: Mapping container `UID 0` to an unprivileged host user (`1000`) and `1..65536` to `/etc/subuid` ensures that even if a container mounts a host directory or breaks out of its filesystem, the process runs with zero capabilities in the host user namespace.
2. **Drop `ALL` capabilities and enable `no_new_privs`**: Hardened Kubernetes Pods set `allowPrivilegeEscalation: false` (`PR_SET_NO_NEW_PRIVS`), `runAsNonRoot: true`, and `capabilities.drop: ["ALL"]`, using Ambient capabilities (`CAP_NET_BIND_SERVICE`) only when binding privileged ports is genuinely required.
3. **`RuntimeDefault` Seccomp-BPF blocks nested namespace escapes**: Always set `seccompProfile.type: RuntimeDefault` so unprivileged containers cannot invoke `clone(CLONE_NEWUSER)` to fabricate a nested user namespace and reach buggy kernel `CAP_SYS_ADMIN` code paths.
