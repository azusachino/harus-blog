A persistent myth in software engineering is that a container image is a monolithic "lightweight VM disk image." In reality, an **Open Container Initiative (OCI) image** is not a block device or a running container at all—it is a **content-addressable Merkle Directed Acyclic Graph (DAG)** of immutable JSON metadata documents and compressed `tar` archives, indexed strictly by their cryptographic `SHA-256` digests.

When `containerd` or `podman` starts a container from an image, it does not copy gigabytes of files into a new directory. Instead, its **Snapshotter** stacks the unpacked read-only layers together and mounts a Linux **OverlayFS** union filesystem (`mount -t overlay`) with a thin, ephemeral writable `upperdir` on top.

This chapter dissects the OCI Image Specification byte by byte, traces how `containerd` transforms compressed blobs into `ChainID`-indexed snapshots, explains why modifying a single byte in a 500 MiB file triggers an OverlayFS **copy-up latency cliff**, and demonstrates how single-node production clusters import local-first images directly into `containerd` without a remote registry.

## Before you start

When you type `docker pull postgres:17`, you download a few JSON files and several compressed tar archives, each named by the SHA-256 hash of its content. A running container then sees those archives stacked on top of each other as one directory tree, with a thin writable layer on top. The problem this chapter is about is how that stacking works and what it costs: how the hashes tie an image together, why two images can share layers, and why changing one byte of a large file inside a running container is surprisingly slow.

A rough analogy is a stack of transparent sheets. You can read through to the lowest sheet that has ink at a given spot, but if you want to edit something printed on a lower sheet, you first have to copy it onto your top sheet.

Read [chapter 1](/tech/series/cncf-containers/01.namespaces-cgroups-and-pid1/) first if "a container is just a process with a private view of the filesystem" is new to you.

Terms used in this chapter:

- **OCI**: the Open Container Initiative, which publishes the standard formats for container images and runtimes.
- **layer**: a tar archive holding the files added, changed or deleted by one build step.
- **manifest**: a JSON file listing an image's config and its layers by digest.
- **digest**: the SHA-256 hash of some content, used as its name; change the content and the name changes.
- **OverlayFS**: a Linux filesystem that presents several read-only directories plus one writable directory as a single merged tree.
- **copy-up**: OverlayFS copying a whole file from a read-only layer into the writable layer the first time it is modified.
- **whiteout**: a marker file in the writable layer that hides a file deleted from a lower layer.

## 1. The Four Artifacts of the OCI Image Specification

When you pull an image such as `mirror.gcr.io/library/postgres:17.4`, the registry protocol (**OCI Distribution Specification**, `/v2/`) resolves the human-readable tag into a root cryptographic digest and traverses four distinct content-addressed objects:

```text
  1. OCI Image Index (application/vnd.oci.image.index.v1+json)
     "Multi-arch fat manifest" -> maps (os, arch) to platform Manifest digest
        |
        +--> linux/amd64: sha256:4a9c...
        +--> linux/arm64: sha256:9f12...
                |
                v
  2. OCI Image Manifest (application/vnd.oci.image.manifest.v1+json)
     Lists the exact Config digest + ordered compressed Layer descriptors
        |
        +--> config:    sha256:7b31... (application/vnd.oci.image.config.v1+json)
        +--> layers[0]: sha256:1d04... (application/vnd.oci.image.layer.v1.tar+gzip)
        +--> layers[1]: sha256:8e55... (application/vnd.oci.image.layer.v1.tar+zstd)
```

### Compressed Layer Digest vs. Uncompressed `DiffID` vs. `ChainID`

Why does an OCI image store layer hashes in *two* different places—once in the **Image Manifest** (`layers[].digest`) and again inside the **Image Configuration JSON** (`rootfs.diff_ids[]`)?

1. **Compressed Blob Digest (`layers[].digest` in Manifest)**: The `SHA-256` of the *compressed* (`tar+gzip` or `tar+zstd`) stream transferred over the network. This allows the registry client (`containerd` Content Store) to verify network integrity before decompressing a single byte, and to deduplicate compressed downloads across images.
2. **Uncompressed `DiffID` (`rootfs.diff_ids[]` in Config JSON)**: The `SHA-256` of the *uncompressed* raw `.tar` archive. Why is this needed? Because re-compressing the exact same `.tar` layer with `gzip -9` vs. `zstd` changes the compressed digest, while the uncompressed filesystem content (`DiffID`) remains identical! Furthermore, verifying the `DiffID` after decompression detects a tampered or corrupted layer even if the compressed blob was re-encoded along the way.
3. **Snapshot `ChainID`**: Can `containerd` index unpacked filesystem directories solely by a layer's `DiffID`? **No!** Suppose Layer $L_1$ simply runs `rm -rf /etc/nginx/conf.d/default.conf`. Applying $L_1$ on top of an Ubuntu base layer ($L_0^{\text{ubuntu}}$) produces a completely different cumulative directory tree than applying the exact same $L_1$ on top of an Alpine base layer ($L_0^{\text{alpine}}$). Therefore, `containerd` identifies each cumulative unpacked snapshot by its recursive **`ChainID`**:
   $$\text{ChainID}(L_0) = \text{DiffID}(L_0)$$
   $$\text{ChainID}(L_k) = \text{SHA256}\bigl(\text{ChainID}(L_{k-1}) \mathbin{\Vert} \text{" "} \mathbin{\Vert} \text{DiffID}(L_k)\bigr)$$

## 2. Inside Linux OverlayFS (`lowerdir`, `upperdir`, `workdir`, `merged`)

Once `containerd`'s OverlayFS snapshotter unpacks each layer into `/var/lib/containerd/io.containerd.snapshotter.v1.overlayfs/snapshots/<num>/fs`, it mounts the container's root filesystem with a single `mount(2)` syscall:

```bash
mount -t overlay overlay \
  -o lowerdir=/snapshots/3/fs:/snapshots/2/fs:/snapshots/1/fs,upperdir=/snapshots/4/fs,workdir=/snapshots/4/work \
  /run/containerd/io.containerd.runtime.v2.task/k8s.io/<cid>/rootfs
```

### How OverlayFS Resolves Lookups, Reads, Writes, and Deletions

| VFS Operation in `merged/` | Kernel OverlayFS (`fs/overlayfs/`) Behavior | Performance & Inode Implication |
| :--- | :--- | :--- |
| **`open(..., O_RDONLY)` + `read()`** | Resolves topmost matching dentry across `upperdir`, then `lowerdir[0..N]`. If found in `lowerdir`, opens the underlying `lowerdir` file directly. | **Zero copy-up**. All 100 containers sharing a base image read the exact same `lowerdir` inode and share a **single copy of physical RAM pages** in the Linux Page Cache! |
| **`open(..., O_WRONLY \| O_RDWR)` on a `lowerdir` file** | Intercepts `open()` before returning the file descriptor, allocates a new file in `workdir`, **copies the entire file data + xattrs from `lowerdir` to `upperdir`**, and atomically renames it into `upperdir`. | **The Copy-Up Cliff**: Modifying 1 byte inside a 1 GiB database file or log archive stored in an image layer blocks `open(2)` while copying all 1 GiB into `upperdir` and doubles Page Cache consumption. |
| **`unlink(path)` on a `lowerdir` file** | `lowerdir` is strictly immutable. OverlayFS creates a **whiteout character device node with major `0`, minor `0`** (`c--------- 1 root root 0, 0`) at `upperdir/<path>`. | When translating into an OCI tar layer, the builder serializes this `0,0` char device as a `.wh.<filename>` prefix file. |
| **`rmdir(dir)` + `mkdir(dir)` on a `lowerdir` directory** | Sets the extended attribute `trusted.overlay.opaque = "y"` (or `user.overlay.opaque = "y"` in rootless mounts) on `upperdir/<dir>`, hiding all entries from `lowerdir/<dir>`. | Serialized in OCI tar layers as a special marker file `.wh..wh..opq` inside the directory. |

> **Production Rule**: Never bake mutable database files, large SQLite tables, or frequently touched log files into container image layers (`lowerdir`). Always mount persistent or write-heavy directories via **volumes (`emptyDir`, `PersistentVolume`, or bind mounts)**, which bypass OverlayFS completely and write directly to the host filesystem (`ext4` / `xfs`).

## 3. Local-First Image Workflows (`imagePullPolicy: Never`)

In hyperscale multi-node clusters, pushing images to an external OCI registry is mandatory so worker nodes can pull them on demand. However, on a single-node homelab or edge cluster, pushing private self-developed services to Docker Hub or GHCR introduces unnecessary registry latency, rate limits, and privacy exposure.

Because `k3s` embeds `containerd` directly, you can export an OCI archive from `podman build` and stream it straight into `containerd`'s `k8s.io` namespace Content Store:

```bash
# 1. Build with a placeholder registry prefix (never pushed anywhere)
podman build -t registry.example.com/myapp:0.4.2 .

# 2. Import the OCI tar stream directly into k3s's embedded containerd k8s.io namespace
podman save --format oci-archive registry.example.com/myapp:0.4.2 \
  | sudo k3s ctr --namespace k8s.io images import -

# 3. Verify the image digest and unpacked ChainID snapshots exist in containerd
sudo k3s ctr --namespace k8s.io images list | grep registry.example.com/myapp
```

In the Kubernetes Deployment manifest, you then pair `registry.example.com/myapp:0.4.2` with **`imagePullPolicy: Never`** (rather than `IfNotPresent`). Why? Because `registry.example.com` does not host an OCI `/v2/` registry endpoint: if a node cache prune or mismatched tag ever left the image absent from `containerd`, `IfNotPresent` would silently attempt a network pull and fail with a misleading registry timeout (`ErrImagePull`), whereas `Never` fails fast and explicitly with `ErrImageNeverPull`, immediately signaling that the `ctr images import` step was skipped.

## 4. Verification Lab: OCI Merkle DAG Builder & OverlayFS Union Simulator

The following self-contained Python 3 verification script builds a complete, spec-compliant OCI image in memory (computing compressed `Manifest` digests, uncompressed `DiffID`s, and recursive Snapshotter `ChainID`s) and runs a functional **OverlayFS Union Mount simulator** that proves Page Cache inode sharing on `O_RDONLY`, full-file `copy-up` on `O_WRONLY`, `(0,0)` whiteout creation on `unlink()`, and `.wh..wh..opq` opaque directory masking.

```python
#!/usr/bin/env python3
"""
Verification Lab 02: OCI Image Spec Digests (DiffID / ChainID) & OverlayFS Copy-Up / Whiteouts
Run directly: python3 lab02_oci_overlayfs.py
"""
import gzip
import hashlib
import io
import json
import tarfile
from dataclasses import dataclass, field
from typing import Dict, List, Optional, Tuple


# ---------------------------------------------------------------------------
# 1. OCI Layer Builder: Compressed Digest vs. Uncompressed DiffID vs. ChainID
# ---------------------------------------------------------------------------
def build_oci_layer(files: Dict[str, bytes]) -> Tuple[bytes, str, str]:
    """Returns (compressed_tgz_bytes, compressed_digest, uncompressed_diff_id)."""
    raw_tar_buf = io.BytesIO()
    with tarfile.open(fileobj=raw_tar_buf, mode="w", format=tarfile.PAX_FORMAT) as tf:
        for path, content in sorted(files.items()):
            info = tarfile.TarInfo(name=path)
            info.size = len(content)
            info.mtime = 0
            info.uid = info.gid = 0
            tf.addfile(info, io.BytesIO(content))
    raw_tar_bytes = raw_tar_buf.getvalue()
    diff_id = "sha256:" + hashlib.sha256(raw_tar_bytes).hexdigest()

    gz_buf = io.BytesIO()
    with gzip.GzipFile(filename="", mode="wb", fileobj=gz_buf, mtime=0) as gz:
        gz.write(raw_tar_bytes)
    compressed_bytes = gz_buf.getvalue()
    compressed_digest = "sha256:" + hashlib.sha256(compressed_bytes).hexdigest()
    return compressed_bytes, compressed_digest, diff_id


def compute_chain_ids(diff_ids: List[str]) -> List[str]:
    """OCI Image Spec: ChainID(L0)=DiffID(L0); ChainID(Lk)=sha256(ChainID(Lk-1) + ' ' + DiffID(Lk))."""
    chain_ids: List[str] = []
    for diff_id in diff_ids:
        if not chain_ids:
            chain_ids.append(diff_id)
        else:
            combined = f"{chain_ids[-1]} {diff_id}".encode("utf-8")
            chain_ids.append("sha256:" + hashlib.sha256(combined).hexdigest())
    return chain_ids


# ---------------------------------------------------------------------------
# 2. OverlayFS Union Mount Simulator (Inode Sharing, Copy-Up, Whiteouts)
# ---------------------------------------------------------------------------
@dataclass
class Inode:
    ino: int
    data: bytes
    is_whiteout: bool = False  # True represents char device (0, 0)


class OverlayFSMount:
    _next_ino = 1000

    @classmethod
    def alloc_inode(cls, data: bytes, is_whiteout: bool = False) -> Inode:
        cls._next_ino += 1
        return Inode(ino=cls._next_ino, data=data, is_whiteout=is_whiteout)

    def __init__(self, lowerdirs: List[Dict[str, Inode]]):
        # lowerdirs[0] is topmost lower layer; lowerdirs[-1] is base layer
        self.lowerdirs = lowerdirs
        self.upperdir: Dict[str, Inode] = {}
        self.opaque_dirs: set[str] = set()
        self.copy_up_bytes_total = 0

    def _is_hidden_by_opaque(self, path: str) -> bool:
        parts = path.strip("/").split("/")
        for i in range(1, len(parts)):
            prefix = "/".join(parts[:i])
            if prefix in self.opaque_dirs:
                return True
        return False

    def lookup_inode(self, path: str) -> Optional[Inode]:
        if path in self.upperdir:
            inode = self.upperdir[path]
            return None if inode.is_whiteout else inode
        if self._is_hidden_by_opaque(path):
            return None
        for layer in self.lowerdirs:
            if path in layer:
                inode = layer[path]
                return None if inode.is_whiteout else inode
        return None

    def open_read(self, path: str) -> Inode:
        inode = self.lookup_inode(path)
        if inode is None:
            raise FileNotFoundError(path)
        return inode

    def write_file(self, path: str, offset: int, patch: bytes) -> Inode:
        # If file is not yet in upperdir, check if it exists in lowerdir -> trigger Copy-Up!
        if path not in self.upperdir or self.upperdir[path].is_whiteout:
            lower_inode = self.lookup_inode(path)
            if lower_inode is not None:
                # Copy-up entire file from lowerdir to upperdir before applying small patch
                self.copy_up_bytes_total += len(lower_inode.data)
                copied_buf = bytearray(lower_inode.data)
                copied_buf[offset : offset + len(patch)] = patch
                self.upperdir[path] = self.alloc_inode(bytes(copied_buf))
                return self.upperdir[path]
            # Brand-new file in upperdir
            self.upperdir[path] = self.alloc_inode(patch)
            return self.upperdir[path]

        buf = bytearray(self.upperdir[path].data)
        buf[offset : offset + len(patch)] = patch
        self.upperdir[path].data = bytes(buf)
        return self.upperdir[path]

    def unlink(self, path: str) -> None:
        if self.lookup_inode(path) is None:
            raise FileNotFoundError(path)
        # Create a (0,0) whiteout character device in upperdir
        self.upperdir[path] = self.alloc_inode(b"", is_whiteout=True)

    def recreate_opaque_dir(self, dir_path: str) -> None:
        clean = dir_path.strip("/")
        self.opaque_dirs.add(clean)
        # Remove any prior upperdir entries under that directory
        for k in [k for k in self.upperdir if k.startswith(clean + "/")]:
            del self.upperdir[k]


def main() -> None:
    print("=== 1. OCI Layer Digest vs. DiffID vs. ChainID Verification ===")
    _, l0_digest, l0_diff = build_oci_layer(
        {
            "bin/busybox": b"ELF_BINARY_SHARED_LIBC" * 1024,
            "etc/app/default.conf": b"port=8080\n",
            "var/lib/db/seed.dat": b"X" * (256 * 1024),  # 256 KiB lowerdir data file
        }
    )
    _, l1_digest, l1_diff = build_oci_layer({"etc/app/prod.conf": b"workers=4\n"})
    chain_ids = compute_chain_ids([l0_diff, l1_diff])

    print(f"  Layer 0: compressed={l0_digest[:23]}...  diff_id={l0_diff[:23]}...")
    print(f"  Layer 1: compressed={l1_digest[:23]}...  diff_id={l1_diff[:23]}...")
    print(f"  ChainID[0] = {chain_ids[0][:23]}...")
    print(f"  ChainID[1] = {chain_ids[1][:23]}...")
    assert l0_digest != l0_diff, "Compressed digest and uncompressed DiffID must be distinct"
    assert chain_ids[0] == l0_diff and chain_ids[1] != l1_diff

    print("\n=== 2. OverlayFS Page Cache Sharing, Copy-Up Cliff & Whiteout Verification ===")
    shared_lower_l0 = {
        "bin/busybox": OverlayFSMount.alloc_inode(b"ELF_BINARY_SHARED_LIBC" * 1024),
        "etc/app/default.conf": OverlayFSMount.alloc_inode(b"port=8080\n"),
        "var/lib/db/seed.dat": OverlayFSMount.alloc_inode(b"X" * (256 * 1024)),
    }
    shared_lower_l1 = {
        "etc/app/prod.conf": OverlayFSMount.alloc_inode(b"workers=4\n"),
    }
    # Two separate containers mounted over the exact same read-only lowerdirs
    c1 = OverlayFSMount(lowerdirs=[shared_lower_l1, shared_lower_l0])
    c2 = OverlayFSMount(lowerdirs=[shared_lower_l1, shared_lower_l0])

    # Both containers read /bin/busybox -> verify they hit the exact same kernel inode!
    ino_c1 = c1.open_read("bin/busybox").ino
    ino_c2 = c2.open_read("bin/busybox").ino
    print(f"  [Read /bin/busybox] Container 1 ino={ino_c1}, Container 2 ino={ino_c2} (shared={ino_c1 == ino_c2})")
    assert ino_c1 == ino_c2

    # Container 1 modifies just 4 bytes inside the 256 KiB lowerdir file var/lib/db/seed.dat
    old_db_ino = c1.open_read("var/lib/db/seed.dat").ino
    new_db_inode = c1.write_file("var/lib/db/seed.dat", offset=0, patch=b"HEAD")
    print(
        f"  [4-Byte Write on 256 KiB lowerdir file] copy_up_bytes={c1.copy_up_bytes_total}, "
        f"old_ino={old_db_ino} -> new_upper_ino={new_db_inode.ino}"
    )
    assert c1.copy_up_bytes_total == 256 * 1024
    assert new_db_inode.ino != old_db_ino
    assert c2.open_read("var/lib/db/seed.dat").data[:4] == b"XXXX", "Container 2 lowerdir must remain untouched"

    # Container 1 deletes a lowerdir file and recreates /etc/app as an opaque directory
    c1.unlink("var/lib/db/seed.dat")
    assert c1.lookup_inode("var/lib/db/seed.dat") is None
    assert c1.upperdir["var/lib/db/seed.dat"].is_whiteout is True

    c1.recreate_opaque_dir("etc/app")
    assert c1.lookup_inode("etc/app/default.conf") is None
    assert c1.lookup_inode("etc/app/prod.conf") is None
    print("  [Whiteout & Opaque Dir] char(0,0) whiteout and trusted.overlay.opaque verified.")
    print("\nAll Lab 02 OCI & OverlayFS invariants verified.")


if __name__ == "__main__":
    main()
```

## Key Takeaways

1. **Content addressing separates transfer from extraction**: OCI Manifests list *compressed* blob digests for network transfer and registry deduplication, while the Image Configuration lists *uncompressed* `DiffID`s and `containerd` computes cumulative `ChainID`s for unpacked snapshots.
2. **Read-only layers share RAM; writable layers pay Copy-Up**: Unmodified binaries and libraries in `lowerdir` share physical Page Cache pages across every container on the host, but opening any `lowerdir` file for writing triggers a synchronous full-file `copy-up` into `upperdir`.
3. **Single-node clusters don't need a registry round-trip**: Importing OCI archives directly into `containerd` (`k3s ctr images import`) paired with `imagePullPolicy: Never` eliminates external registry dependencies while failing fast on tag drift.
