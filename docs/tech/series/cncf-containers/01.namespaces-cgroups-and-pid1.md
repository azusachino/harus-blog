There is no object called a "container" inside the Linux kernel source tree. If you grep the kernel for `struct container`, you will only find generic C macro helpers (`container_of`) used for intrusive linked lists.

At the operating-system boundary, a Linux container is an ordinary process (`struct task_struct`) that shares the host kernel with every other task on the machine, but whose resource visibility and hardware consumption are shaped by three orthogonal kernel subsystems:

1. **Namespaces (`task->nsproxy` & `task->cred->user_ns`)** — virtualize *what the process can see* (process trees, mount tables, network interfaces, hostnames, IPC queues, UIDs/GIDs, cgroup roots, and monotonic clocks).
2. **Control Groups v2 (`task->cgroups`)** — meter and throttle *how much hardware the process can consume* (CPU bandwidth quotas, physical RAM and swap limits, block I/O weights, and Pressure Stall Information).
3. **Filesystem & Credential Isolation (`pivot_root(2)`, Capabilities, Seccomp-BPF, LSMs)** — restrict *which files and system calls the process may invoke*.

```text
                      struct task_struct (Host PID 48219)
                      ===================================
                                       |
       +-------------------------------+-------------------------------+
       |                               |                               |
       v                               v                               v
+--------------+               +---------------+               +---------------+
|  nsproxy     |               | css_set       |               | fs_struct &   |
| (Visibility) |               | (Cgroup v2)   |               | cred / seccomp|
+--------------+               +---------------+               +---------------+
| mnt_ns       |               | cpu.max       |               | pivot_root()  |
| pid_ns_for.. |               | memory.high   |               | CapBnd/CapEff |
| net_ns       |               | memory.max    |               | seccomp_filter|
| uts / ipc_ns |               | io.max / pids |               | AppArmor/SELin|
+--------------+               +---------------+               +---------------+
```

This opening chapter strips away the high-level CLI wrappers (`docker`, `podman`, `kubectl`) and builds a container from first principles at the syscall boundary.

## Before you start

This series is for programmers who know one language and the basics of a Linux shell but have only used containers through `docker run`. The chapters build on each other, so start here.

A container looks like a small virtual machine, but it is just a normal Linux process that the kernel has been told to treat specially. Run `docker run --rm alpine ps` and you will see the process list contain a single entry with PID 1, even though the host is running hundreds of processes. The kernel did two things: it gave the process its own view of the system (what it can see), and it set limits on how much CPU and memory it can use. This chapter builds both by hand and explains why the first process in a container behaves oddly when you try to stop it.

You do not need to know kernel internals first. Being comfortable with `ps`, signals such as `kill -TERM`, and the idea of a parent process is enough. Chapter 2 picks up from here with the files inside a container.

Terms used in this chapter:

- **namespace**: a kernel feature that gives a process its own private copy of one system view, such as the process list, network interfaces or hostname.
- **cgroup**: a kernel mechanism that groups processes and limits or measures the CPU, memory and I/O they use.
- **PID 1**: the first process in a process-ID namespace; the kernel treats it specially for signals and for adopting orphaned children.
- **zombie**: a finished process whose parent has not yet collected its exit status, so it still occupies a process-table entry.
- **SIGTERM**: the polite "please shut down" signal that `docker stop` and Kubernetes send first.
- **pivot_root**: a system call that swaps a process's root mount, so the old host filesystem is no longer reachable.

## 1. The Eight Linux Namespaces & `nsproxy`

Every process on a Linux system holds a pointer `task->nsproxy` to a kernel `struct nsproxy`, plus a user namespace pointer inside `task->cred->user_ns`. When a task is cloned without special flags, child and parent share the exact same `nsproxy` pointers.

Linux exposes eight namespace types via three system calls:

- `clone3(struct clone_args *cl_args, size_t size)` (or legacy `clone(2)`) — creates a new child process placed directly into any combination of new namespaces specified by `CLONE_NEW*` bitmask flags.
- `unshare(int flags)` — detaches the *calling* process from shared namespaces and creates fresh namespace instances without immediately forking (except for `CLONE_NEWPID` and `CLONE_NEWTIME`, which take effect on the next forked child).
- `setns(int fd, int nstype)` — joins an *existing* namespace identified by an open file descriptor to `/proc/<pid>/ns/<type>` (this is how `docker exec`, `kubectl exec`, and `nsenter` step inside a running container).

| Namespace | Flag | `/proc/<pid>/ns/*` | Virtualized Kernel Resource |
| :--- | :--- | :--- | :--- |
| **Mount** | `CLONE_NEWNS` | `mnt` | VFS mount table (`vfsmount` tree); isolates filesystem mounts |
| **PID** | `CLONE_NEWPID` | `pid`, `pid_for_children` | Process ID number space starting at `PID 1` inside the container |
| **Network** | `CLONE_NEWNET` | `net` | Network devices (`lo`, `veth`), IPv4/IPv6 routing tables, sockets, `nftables`/`iptables` |
| **IPC** | `CLONE_NEWIPC` | `ipc` | System V IPC objects and POSIX message queues (`mq_overview`) |
| **UTS** | `CLONE_NEWUTS` | `uts` | `nodename` (hostname) and `nisdomainname` returned by `uname(2)` |
| **User** | `CLONE_NEWUSER` | `user` | UID/GID number mappings (`uid_map`, `gid_map`) and namespace-scoped capabilities |
| **Cgroup** | `CLONE_NEWCGROUP` | `cgroup` | Virtualizes the root directory seen in `/proc/self/cgroup` and `/sys/fs/cgroup` |
| **Time** | `CLONE_NEWTIME` | `time`, `time_for_children` | Per-namespace offsets for `CLOCK_MONOTONIC` and `CLOCK_BOOTTIME` |

### Namespace Lifecycle & Bind-Mounted Handles

A subtle kernel invariant governs namespace lifetimes: **a namespace remains alive as long as at least one process belongs to it OR at least one open file descriptor or bind mount references its `/proc/<pid>/ns/<type>` inode**.

Container networking tools such as `ip netns add <name>` and CNI plugins exploit this directly: they create a network namespace, bind-mount `/proc/self/ns/net` onto `/var/run/netns/<id>`, and let the setup process exit. Even with zero running processes inside it, the network namespace (along with its `veth` interface, IP address, and routing table) stays alive in kernel memory until `umount2("/var/run/netns/<id>", MNT_DETACH)` is called.

## 2. The `CLONE_NEWPID` Subtlety & the PID 1 Contract

Two operational traps inside `CLONE_NEWPID` cause real production incidents:

### Trap 1: `unshare(CLONE_NEWPID)` Does Not Change the Caller's PID

A process's own PID is fixed at `fork`/`clone` time and cached by user-space libraries (`getpid()`). Therefore, calling `unshare(CLONE_NEWPID)` does **not** move the calling process into the new PID namespace. Instead, it sets `task->nsproxy->pid_ns_for_children`. Only the **first child forked after `unshare(CLONE_NEWPID)`** enters the new namespace and becomes **PID 1** (`init`) of that namespace.

Furthermore, `/proc` is not updated automatically when entering a PID namespace. Because `/proc` is a filesystem mount showing the PID namespace of whichever process mounted it, a new container must also enter a new mount namespace (`CLONE_NEWNS`) and mount a fresh `proc` instance (`mount("proc", "/proc", "proc", MS_NOSUID|MS_NOEXEC|MS_NODEV, NULL)`) so tools like `ps` and `top` see container PIDs instead of host PIDs.

### Trap 2: Why Container PID 1 Ignores `SIGTERM` and Leaks Zombies

In Linux (`kernel/signal.c`), the process with `PID 1` in any PID namespace is marked with `SIGNAL_UNKILLABLE`. This kernel flag enforces two special rules:

1. **Unhandled signals with `SIG_DFL` are silently dropped**: If you send `SIGTERM` (`docker stop` or `kubectl delete pod`) to a container whose PID 1 has not explicitly registered a `sigaction(SIGTERM, ...)` signal handler, **the kernel drops `SIGTERM`**. Even sending `SIGKILL` *from inside the same PID namespace* is ignored by PID 1! (Only the ancestor host namespace can terminate container PID 1 via `SIGKILL` after the 10-second or 30-second grace period expires.)
   - *Symptom*: Your Node.js, Python, or shell-wrapped container (`ENTRYPOINT ["/bin/sh", "-c", "my-server"]`) always takes exactly 30 seconds to stop and exits with code `137` (`128 + SIGKILL`) instead of shutting down gracefully.
2. **Orphan reparenting and zombie accumulation**: Whenever an intermediate process inside the container forks a child (for example, a health check probe, a subprocess worker, or a crash reporter) and exits before its child, the orphaned child is **reparented to container PID 1**. When that child eventually exits, it remains a zombie (`EXIT_ZOMBIE`, shown as `Z`) entry in the kernel task table holding a PID slot until PID 1 calls `waitpid(-1, &status, WNOHANG)`.

```text
  Bad Container Entrypoint                     Good Container Entrypoint
  ========================                     =========================
  PID 1: /bin/sh -c "python app.py"            PID 1: tini -- python app.py
    |                                            |  (or exec python app.py with SIGTERM handler)
    +-- PID 2: python app.py                     +-- PID 2: python app.py
          |                                            |
          +-- forks worker (PID 3) and dies            +-- forks worker (PID 3) and dies
                                                       |
  Result:                                      Result:
  1. kubectl sends SIGTERM to PID 1 (/bin/sh)  1. tini catches SIGTERM, forwards to PID 2
  2. /bin/sh does NOT forward SIGTERM to PID 2 2. tini loops waitpid(-1, WNOHANG) on SIGCHLD
  3. Reparented PID 3 becomes un-reaped Zombie 3. Zero zombies; sub-second graceful shutdown
```

To satisfy the **PID 1 Contract**, always:

- Use `exec` form in Dockerfiles (`ENTRYPOINT ["my-binary"]`), or `exec "$@"` at the end of wrapper scripts so `/bin/sh` replaces itself via `execve(2)` instead of staying as PID 1.
- Inject a minimal init reaper such as [`tini`](https://github.com/krallin/tini) (`docker run --init`) or enable `shareProcessNamespace: true` in Kubernetes Pods (where the CRI pause container acts as PID 1 and reaps all zombies).

## 3. Why `pivot_root(2)` Replaces `chroot(2)`

Beginners often equate container filesystem isolation with `chroot(2)`. However, `chroot(2)` only modifies `task->fs->root` (the path resolution starting point for leading `/`); it leaves the entire host mount table (`vfsmount`) attached and reachable. A root process inside a `chroot` can trivially escape to the host root filesystem by calling `chdir("..")` after a second `chroot("sub")`, or by reading raw block device nodes if `CAP_SYS_ADMIN` / `CAP_MKNOD` is retained.

OCI runtimes (`runc` and `youki`) instead execute **`pivot_root(2)`** inside a private mount namespace (`CLONE_NEWNS`):

1. Ensure the parent mount propagation is private (`mount(NULL, "/", NULL, MS_REC | MS_PRIVATE, NULL)`) so container mount events never leak back to the host.
2. Bind-mount the container's new `rootfs` onto itself (`mount(rootfs, rootfs, "bind", MS_BIND | MS_REC, NULL)`) because `pivot_root` requires `new_root` to be a mount point.
3. Call `pivot_root(new_root, put_old)` (or `pivot_root(".", ".")`), which swaps the mount namespace's root mount with `new_root` and attaches the old host root at `put_old`.
4. Immediately detach the old host root (`umount2(".", MNT_DETACH)`) and `chdir("/")`. Once detached, the host root filesystem no longer exists anywhere in the container's `vfsmount` graph.

## 4. Control Groups v2 (`cgroup2`): Unified Resource Governance

While namespaces isolate visibility, **cgroups v2** (`mount -t cgroup2 none /sys/fs/cgroup`) enforce resource limits and accounting in a single unified hierarchy. Unlike legacy cgroup v1 (where a process could belong to completely different trees for `cpu` and `memory`, breaking page-cache writeback accounting), cgroup v2 enforces two structural rules:

1. **Single Unified Hierarchy**: Every container corresponds to a single directory `/sys/fs/cgroup/kubepods.slice/.../cri-containerd-<id>.scope` with `cgroup.controllers` enabled down the tree via `cgroup.subtree_control`.
2. **No Internal Processes Rule**: Non-root cgroups cannot both hold tasks directly in `cgroup.procs` *and* enable domain controllers for child cgroups; tasks must live strictly at the leaf nodes.

### Key Cgroup v2 Control Files for Containers

| Cgroup v2 File | Format / Example | Kernel Enforcement Mechanism |
| :--- | :--- | :--- |
| **`cpu.weight`** | `100` (range `1..10000`) | Proportional CPU share under contention (maps from Kubernetes `resources.requests.cpu`) |
| **`cpu.max`** | `200000 100000` (`$QUOTA $PERIOD` in $\mu\text{s}$) | Hard CFS/EEVDF bandwidth ceiling (`200ms` per `100ms` = `2.0` cores). Excess usage increments `nr_throttled` and `throttled_usec` in `cpu.stat` |
| **`memory.high`** | `512M` | Soft throttle threshold: processes crossing `memory.high` are forced into synchronous direct page reclaim before returning from allocation, slowing them down without immediate OOM kill |
| **`memory.max`** | `536870912` (`512 MiB`) | Hard limit: if reclaim cannot bring `memory.current` below `memory.max`, the kernel invokes the cgroup OOM killer (`oom_kill` in `memory.events`) |
| **`pids.max`** | `1024` | Fork-bomb defense: `clone3()` / `fork()` fails with `-EAGAIN` once live tasks in the cgroup reach `pids.max` |
| **`memory.pressure` / `cpu.pressure`** | `some avg10=...` / `full avg10=...` | **PSI (Pressure Stall Information)**: measures the exact percentage of wall-clock time tasks in the container are stalled waiting for CPU, memory reclaim, or block I/O |

## 5. Verification Lab: PID 1 Signal/Zombie Dynamics & Cgroup v2 Throttling

The following self-contained Python 3 verification script models and verifies all three core mechanisms from this chapter:

1. **`CLONE_NEWPID` & PID 1 Signal / Zombie Contract**: Compares a naive `/bin/sh` PID 1 entrypoint (which drops `SIGTERM` under `SIGNAL_UNKILLABLE` and accumulates zombie entries when orphaned grandchildren exit) against an init-reaper (`tini`) PID 1.
2. **Cgroup v2 `cpu.max` CFS Bandwidth Controller**: Simulates a multi-threaded bursty container running under a `100ms` period (`cpu.max = "200000 100000"` vs. `"50000 100000"`) and verifies tail-latency spikes caused by token-bucket quota exhaustion (`nr_throttled`).
3. **Cgroup v2 `memory.high` vs. `memory.max` Accounting**: Models anonymous RSS + shared Page Cache charges against `memory.high` synchronous reclaim vs. `memory.max` OOM kill (`oom_kill` counter).

```python
#!/usr/bin/env python3
"""
Verification Lab 01: PID 1 Signal/Zombie Contract & Cgroup v2 Bandwidth/Memory Controllers
Run directly: python3 lab01_container_primitives.py
"""
from dataclasses import dataclass, field
from typing import Dict, List, Optional


# ---------------------------------------------------------------------------
# 1. PID Namespace & SIGNAL_UNKILLABLE / Zombie Reaper Simulator
# ---------------------------------------------------------------------------
@dataclass
class TaskStruct:
    host_pid: int
    ns_pid: int
    ppid: int
    comm: str
    state: str = "TASK_RUNNING"  # TASK_RUNNING, EXIT_ZOMBIE, REAPED
    has_sigterm_handler: bool = False
    is_subreaper: bool = False


class PidNamespaceSimulator:
    def __init__(self, pid1_comm: str, pid1_handles_sigterm: bool, pid1_reaps_children: bool):
        self.tasks: Dict[int, TaskStruct] = {}
        self.next_host_pid = 40000
        self.next_ns_pid = 1
        self.pid1_reaps = pid1_reaps_children
        # Spawn container PID 1
        self.spawn(ppid=0, comm=pid1_comm, has_sigterm_handler=pid1_handles_sigterm)

    def spawn(self, ppid: int, comm: str, has_sigterm_handler: bool = False) -> int:
        ns_pid = self.next_ns_pid
        host_pid = self.next_host_pid
        self.next_ns_pid += 1
        self.next_host_pid += 1
        self.tasks[ns_pid] = TaskStruct(
            host_pid=host_pid,
            ns_pid=ns_pid,
            ppid=ppid,
            comm=comm,
            has_sigterm_handler=has_sigterm_handler,
        )
        return ns_pid

    def exit_process(self, ns_pid: int) -> None:
        task = self.tasks[ns_pid]
        task.state = "EXIT_ZOMBIE"
        # Reparent any living or zombie children of ns_pid to container PID 1
        for child in self.tasks.values():
            if child.ppid == ns_pid and child.ns_pid != 1:
                child.ppid = 1
        # If PID 1 has a SIGCHLD waitpid(-1, WNOHANG) loop, reap zombies parented to PID 1
        if self.pid1_reaps:
            self.reap_zombies_at_pid1()

    def reap_zombies_at_pid1(self) -> int:
        reaped = 0
        for child in list(self.tasks.values()):
            if child.ppid == 1 and child.state == "EXIT_ZOMBIE":
                child.state = "REAPED"
                reaped += 1
        return reaped

    def deliver_sigterm_to_pid1(self, grace_period_sec: int = 30) -> Dict[str, object]:
        pid1 = self.tasks[1]
        # Linux kernel/signal.c: SIGNAL_UNKILLABLE drops SIG_DFL signals sent to namespace PID 1
        if not pid1.has_sigterm_handler:
            return {
                "graceful": False,
                "stop_duration_sec": grace_period_sec,
                "exit_code": 137,  # 128 + SIGKILL from host kubelet/dockerd after timeout
                "reason": "SIGNAL_UNKILLABLE dropped unhandled SIGTERM on PID 1",
            }
        pid1.state = "REAPED"
        return {
            "graceful": True,
            "stop_duration_sec": 1,
            "exit_code": 143,  # 128 + SIGTERM clean shutdown
            "reason": "PID 1 caught SIGTERM, forwarded to process group, and reaped children",
        }


# ---------------------------------------------------------------------------
# 2. Cgroup v2 cpu.max Bandwidth & memory.high / memory.max Simulator
# ---------------------------------------------------------------------------
@dataclass
class CgroupV2Controller:
    cpu_quota_us: int
    cpu_period_us: int = 100_000
    memory_high_bytes: int = 256 * 1024 * 1024
    memory_max_bytes: int = 512 * 1024 * 1024
    # Runtime counters (cpu.stat & memory.events)
    nr_periods: int = 0
    nr_throttled: int = 0
    throttled_usec: int = 0
    memory_high_events: int = 0
    oom_kill_events: int = 0

    def run_cpu_periods(self, thread_demands_us_per_period: List[List[int]]) -> None:
        """
        thread_demands_us_per_period: list of periods, each containing CPU microseconds
        demanded by each worker thread inside the container during that 100ms window.
        """
        for demands in thread_demands_us_per_period:
            self.nr_periods += 1
            total_demand = sum(demands)
            if total_demand > self.cpu_quota_us:
                self.nr_throttled += 1
                # Threads are stalled for the remainder of the period once quota is exhausted
                fraction_served = self.cpu_quota_us / total_demand
                stalled_wall_us = int(self.cpu_period_us * (1.0 - fraction_served))
                self.throttled_usec += stalled_wall_us

    def allocate_memory(self, anon_rss_bytes: int, page_cache_bytes: int) -> str:
        current = anon_rss_bytes + page_cache_bytes
        if current > self.memory_max_bytes:
            # Try synchronous reclaim of half the evictable page cache first
            reclaimed_cache = page_cache_bytes // 2
            current -= reclaimed_cache
            if current > self.memory_max_bytes:
                self.oom_kill_events += 1
                return "OOM_KILLED"
        if current > self.memory_high_bytes:
            self.memory_high_events += 1
            return "THROTTLED_DIRECT_RECLAIM"
        return "OK"


def main() -> None:
    print("=== 1. PID Namespace & PID 1 Contract Verification ===")
    # Case A: Bad shell wrapper (/bin/sh without SIGTERM trap or waitpid loop)
    bad_ns = PidNamespaceSimulator("/bin/sh -c app", pid1_handles_sigterm=False, pid1_reaps_children=False)
    app_pid = bad_ns.spawn(ppid=1, comm="python3 app.py")
    worker_pid = bad_ns.spawn(ppid=app_pid, comm="healthcheck-worker")
    # Intermediate parent exits before worker, then worker exits -> reparented to PID 1
    bad_ns.exit_process(app_pid)
    bad_ns.exit_process(worker_pid)
    zombies_bad = [t for t in bad_ns.tasks.values() if t.state == "EXIT_ZOMBIE"]
    stop_bad = bad_ns.deliver_sigterm_to_pid1(grace_period_sec=30)

    # Case B: Good tini init process as PID 1
    good_ns = PidNamespaceSimulator("tini -- app", pid1_handles_sigterm=True, pid1_reaps_children=True)
    app_pid_g = good_ns.spawn(ppid=1, comm="python3 app.py")
    worker_pid_g = good_ns.spawn(ppid=app_pid_g, comm="healthcheck-worker")
    good_ns.exit_process(app_pid_g)
    good_ns.exit_process(worker_pid_g)
    zombies_good = [t for t in good_ns.tasks.values() if t.state == "EXIT_ZOMBIE"]
    stop_good = good_ns.deliver_sigterm_to_pid1(grace_period_sec=30)

    print(f"  [Bad Entrypoint (/bin/sh)]  un-reaped zombies={len(zombies_bad)}, stop={stop_bad}")
    print(f"  [Good Entrypoint (tini)]    un-reaped zombies={len(zombies_good)}, stop={stop_good}")
    assert len(zombies_bad) == 2 and stop_bad["exit_code"] == 137
    assert len(zombies_good) == 0 and stop_good["exit_code"] == 143

    print("\n=== 2. Cgroup v2 cpu.max Multi-Threaded Throttling Verification ===")
    # 8-thread Go/Java service bursts for 20ms per thread (160,000 us total) in a 100ms period,
    # but container cpu.max is set to 50,000 us (0.5 CPU limit).
    cg_tight = CgroupV2Controller(cpu_quota_us=50_000, cpu_period_us=100_000)
    cg_tight.run_cpu_periods([[20_000] * 8 for _ in range(5)])
    print(
        f"  [cpu.max = 50000 100000]  nr_periods={cg_tight.nr_periods}, "
        f"nr_throttled={cg_tight.nr_throttled}, throttled_usec={cg_tight.throttled_usec}"
    )
    assert cg_tight.nr_throttled == 5 and cg_tight.throttled_usec > 300_000

    print("\n=== 3. Cgroup v2 memory.high vs. memory.max Verification ===")
    mib = 1024 * 1024
    cg_mem = CgroupV2Controller(cpu_quota_us=200_000, memory_high_bytes=256 * mib, memory_max_bytes=512 * mib)
    s1 = cg_mem.allocate_memory(anon_rss_bytes=180 * mib, page_cache_bytes=40 * mib)
    s2 = cg_mem.allocate_memory(anon_rss_bytes=240 * mib, page_cache_bytes=80 * mib)
    s3 = cg_mem.allocate_memory(anon_rss_bytes=520 * mib, page_cache_bytes=20 * mib)
    print(f"  220 MiB total -> {s1}")
    print(f"  320 MiB total -> {s2} (memory.events.high={cg_mem.memory_high_events})")
    print(f"  540 MiB anon  -> {s3} (memory.events.oom_kill={cg_mem.oom_kill_events})")
    assert (s1, s2, s3) == ("OK", "THROTTLED_DIRECT_RECLAIM", "OOM_KILLED")
    print("\nAll Lab 01 container primitive invariants verified.")


if __name__ == "__main__":
    main()
```

## Key Takeaways

1. **A container is a kernel view, not a hypervisor**: Ordinary containers run as standard host `task_struct` threads executing directly on the host kernel, partitioned by `nsproxy` pointers and `cgroup2` controllers.
2. **`CLONE_NEWPID` requires an init contract**: Because namespace PID 1 carries `SIGNAL_UNKILLABLE` and inherits all orphaned descendants in its namespace, container images must either run an explicit init process (`tini`) or ensure the application binary runs directly as PID 1 (`exec` form) and handles `SIGTERM` and `SIGCHLD`.
3. **Always inspect Cgroup v2 `/sys/fs/cgroup` metrics**: On a cgroup v2 host, legacy cgroup v1 files (`cpu.cfs_quota_us`, `memory.limit_in_bytes`) no longer exist. Diagnose CPU tail latency via `cpu.stat` (`nr_throttled`) and memory pressure via `memory.events` (`high`, `oom_kill`) and `memory.pressure` (PSI).
