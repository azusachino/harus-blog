In the previous chapter, our network packet passed through an edge router, underwent NAPT translation to acquire a public source IP and port, and traversed local switching fabric. The packet has now reached the physical boundary of the private local area network.

Crossing this threshold brings the packet into the wide-area domain of the global internet. In this concluding chapter of the *How Networks Work* series, we trace how **packets traverse fiber-optic access networks via PON and PPPoE, how internet service providers (ISPs) route terabits of traffic across core backbones via DWDM and MPLS, and how independent autonomous systems interconnect through Internet Exchange Points (IXPs) and BGP to form a cohesive worldwide network**.

## Departing the LAN: Crossing the Access Network

Local area networks generally span dozens of meters under private administrative control. To reach remote web servers across continents, packets must traverse the communication lines connecting subscriber premises to an Internet Service Provider (ISP)—a segment known as the **Access Network** (or the "last mile").

Unlike private building wiring, access networks span kilometers over public rights-of-way, requiring specialized telecommunications plant and carrier-grade infrastructure.

### The Evolution of Access Technologies: Copper to FTTH

Over the past four decades, access network infrastructure has evolved through distinct technological epochs:

1. **Dial-Up and ADSL (Asymmetric Digital Subscriber Line)**:
   - Early broadband repurposed twisted-pair copper telephone lines. A frequency splitter separated low-frequency voice channels (below 4 kHz) from high-frequency digital signals (26 kHz to 1.1 MHz).
   - ADSL modems modulated digital bits into analog radio-frequency signals. Due to copper's high-frequency electrical attenuation, bandwidth decayed sharply beyond several kilometers from the central office, and available bandwidth was heavily asymmetric (favoring downstream downloads over upstream uploads).
2. **Fiber to the Home (FTTH)**:
   - The contemporary standard for high-speed fixed broadband. Optical fibers utilize hair-thin cores made of ultra-pure synthetic fused silica glass, surrounded by a cladding layer with a slightly lower refractive index.
   - **Total Internal Reflection**: Light pulses launched into the core at shallow incident angles reflect continuously along the core-cladding boundary without escaping. Attenuation in silica glass is extraordinarily low (~0.2 dB/km at 1550 nm), completely impervious to electromagnetic interference and capable of transmitting gigabit data streams across dozens of kilometers without active amplification.

### Passive Optical Network (PON) Architecture

Running a dedicated point-to-point fiber strand from the carrier's central office to every individual household would overwhelm municipal conduit space. Modern FTTH deployments universally employ a **Passive Optical Network (PON)** point-to-multipoint topology:

- **OLT (Optical Line Terminal)**: Located at the ISP's central office, the OLT serves as the carrier-side optical aggregation engine, orchestrating upstream time-division multiple access (TDMA) time slots and downstream broadcasting across optical channels.
- **Optical Splitters**: Unpowered optical components installed in neighborhood distribution cabinets or building risers. Built from fused biconical tapers or planar lightwave circuits, splitters divide a single incoming feeder fiber from the central office into 32 or 64 distribution lines without requiring electrical power or active electronics.
- **ONU / ONT (Optical Network Unit / Terminal)**: The customer-premises equipment (commonly called an optical modem) installed inside the home. It converts incoming optical laser pulses into standard Ethernet electrical signals for the local router.

## Access Authentication and Encapsulation: PPPoE

Once the physical optical link is established, the service provider faces an operational requirement: **how can the network authenticate subscriber accounts, meter bandwidth usage, and dynamically assign valid IP addresses across shared Ethernet frames?**

Ethernet was designed for local, open broadcast networks and lacks native account credentials or session management. To bridge this gap, network engineers developed **PPPoE (Point-to-Point Protocol over Ethernet)**.

### Tunneling PPP Inside Ethernet

During the dial-up era, modems communicated via the **Point-to-Point Protocol (PPP)**, which featured robust authentication protocols (PAP/CHAP) and network configuration negotiation (IPCP).

PPPoE embeds standard PPP session frames directly inside Ethernet payload fields, establishing a logical point-to-point link over shared Layer 2 infrastructure:

1. **Discovery Phase**: The residential router broadcasts a PPPoE Active Discovery Initiation (PADI) packet across the local link. The ISP's **BAS (Broadband Access Server)** or BNG (Broadband Network Gateway) responds with an offer (PADO), and the router requests a dedicated session ID (PADR/PADS).
2. **Authentication Phase**: The router and BAS establish a point-to-point tunnel. The router submits its credentials, which the BAS validates against back-end RADIUS or Diameter authentication servers.
3. **Network Configuration (IPCP)**: Once authenticated, the BAS uses the Internet Protocol Control Protocol (IPCP) to assign the subscriber router a public IPv4 address (or delegated IPv6 prefix) and the addresses of the ISP's primary recursive DNS resolvers.

### The Impact on MTU and MSS

Standard Ethernet frames support a Maximum Transmission Unit (MTU) of 1500 bytes. However, running PPPoE introduces protocol encapsulation overhead:

- The PPPoE header occupies **6 bytes**.
- The encapsulated PPP protocol ID occupies **2 bytes**.

Consequently, the maximum allowable IP packet size over PPPoE shrinks:
$$\text{MTU}_{\text{PPPoE}} = 1500 - 6 - 2 = 1492\text{ bytes}$$

To prevent fragmentation, the maximum TCP segment size must also be adjusted downward:
$$\text{MSS} = 1492 - 20(\text{IPv4}) - 20(\text{TCP}) = 1452\text{ bytes}$$

If a residential gateway does not enforce automatic MSS Clamping, client devices attempting to send standard 1500-byte packets will experience packet drops at the carrier edge whenever the Don't Fragment (DF) flag is set, resulting in silent connection stalls known as Path MTU black holes.

## ISP Backbone Networks: The Continental Highways

Once a packet passes through the BAS, its PPPoE encapsulation is stripped away. The bare IP datagram now enters the internal backbone of a major telecommunications operator (such as AT&T, NTT, Lumen, China Telecom, or Deutsche Telekom).

Carrier networks are architected in distinct tiers:

### 1. Point of Presence (POP)

Carrier facilities situated in major metropolitan areas. A POP aggregates lines from thousands of regional access nodes and houses high-capacity aggregation switches, edge routers, and local caching servers.

### 2. Network Operations Center (NOC)

The operational nerve center of the provider. Engineering teams monitor real-time traffic volumes, packet loss trends, fiber cuts, and denial-of-service anomalies around the clock, managing routing policies and capacity reallocations.

### 3. Core Routers and Optical Transport Networks

Between metropolitan centers, traffic flows across high-capacity intercity fiber corridors:

- **DWDM (Dense Wavelength Division Multiplexing)**: Rather than sending a single laser channel per fiber, DWDM multiplexes up to 80–160 distinct wavelengths of light into a single microscopic fiber strand. With each wavelength carrying 100G, 400G, or 800Gbps, a single fiber pair can achieve aggregate capacities exceeding tens of terabits per second.
- **Core Routers**: Massive, chassis-based multi-rack routing systems featuring custom ASICs, high-speed packet processors, and non-blocking optical switching fabrics. Core routers execute wire-speed lookups across hundreds of millions of packets per second.
- **MPLS (Multi-Protocol Label Switching)**: Within the core, routers avoid performing repetitive Longest Prefix Match lookups against massive routing tables. Instead, edge routers assign short, fixed-length numerical labels to packets. Core routers swap these labels at wire speed through label-forwarding information bases (LFIBs), providing deterministic QoS, traffic engineering, and sub-50ms failover routing.

## The Global Internet: A Network of Networks

The internet is not a monolithic network controlled by a single entity. It is a worldwide federation of tens of thousands of independently operated **Autonomous Systems (AS)**. Every commercial ISP, university network, cloud hyperscaler (AWS, Microsoft, Google), and content delivery network (Cloudflare, Akamai) operates as an autonomous system identified by a unique Autonomous System Number (ASN).

Autonomous systems interconnect through two primary economic relationships and dedicated exchange facilities:

### 1. Peering

Two network operators of comparable size and symmetric traffic volume agree to interconnect their networks to exchange traffic directly:

- **Settlement-Free Peering**: Neither party charges the other for transit. Both operators exchange traffic destined for each other's downstream customers at mutual physical interconnection points.
- Peering bypasses third-party intermediaries, reducing network hops, latency, and transit expenditures.

### 2. Transit

Smaller regional ISPs, enterprise networks, and hosting providers cannot peer directly with every network across the globe. They purchase **IP Transit** from Tier-1 transit providers (carriers whose networks reach the entire global routing table without purchasing transit from anyone else). The buyer pays a recurring fee for global reachability.

### 3. Internet Exchange Points (IXPs)

Connecting thousands of networks via direct point-to-point fiber cables would lead to an $O(N^2)$ physical cabling bottleneck. To solve this, operators meet at **Internet Exchange Points (IXPs)**.

An IXP is a neutral datacenter facility housing a massive Layer 2 switching fabric:

- Any carrier, cloud provider, or CDN can run a single optical connection to the IXP switch fabric.
- Once connected, a member can establish bilateral or multilateral peering relationships with hundreds of other participating networks over a shared switching infrastructure, drastically flattening internet routing topology and reducing global transit costs.

### Border Gateway Protocol (BGP-4)

The protocol binding these thousands of autonomous systems together is the **Border Gateway Protocol (BGP)**.

Running atop TCP port 179, BGP is a path-vector routing protocol operating at global scale:

- Edge routers advertise network reachability: *"Autonomous System 13335 (Cloudflare) can reach prefix `104.16.0.0/13`."*
- **AS-Path Attribute**: As route advertisements propagate across the globe, each transit AS prepends its own ASN to the advertisement's `AS_PATH` attribute (e.g., `AS15169 -> AS2914 -> AS701`). BGP routers use this sequence to detect and discard routing loops, selecting optimal paths based on commercial agreements, path length, and local routing policies.

## The Complete Odyssey: From Keystroke to Rendered Page

When a user hits Enter in a web browser, a synchronized sequence of human-engineered systems activates across the globe within tens of milliseconds:

```text
[ Web Browser (Client) ]
   │  1. Parse URL to extract scheme, hostname, and request URI
   │  2. Format standard HTTP/1.1 or HTTP/2 request headers
   │  3. Invoke OS resolver (getaddrinfo); traverse DNS hierarchy to resolve target IP
   ▼
[ OS Kernel Protocol Stack ]
   │  4. Allocate socket; execute TCP 3-way handshake (SYN -> SYN+ACK -> ACK)
   │  5. Negotiate MSS and sliding window parameters for reliable byte delivery
   │  6. Consult kernel routing table (Longest Prefix Match) for egress interface
   │  7. Resolve next-hop MAC via ARP broadcast and cache lookup
   │  8. Encapsulate IP header (TTL, source/destination IP) and Ethernet MAC header
   ▼
[ Network Interface Card (NIC) ]
   │  9. Append 56-bit preamble for clock sync; compute CRC-32 Frame Check Sequence
   │ 10. PHY transceiver modulates bits into differential electrical waveforms
   ▼
[ Local Area Network (LAN) ]
   │ 11. Twisted copper pairs reject ambient noise through differential signaling
   │ 12. Layer 2 switch inspects source MAC (learning) and destination MAC (unicast forwarding)
   │ 13. Router receives frame, verifies FCS, strips L2 MAC header, and checks routing table
   │ 14. Router executes NAPT: rewrites private source IP/port to WAN public coordinates
   ▼
[ Access Network (FTTH) ]
   │ 15. Optical Network Terminal (ONT) converts electrical signals to laser pulses
   │ 16. Light pulses traverse passive optical splitters (PON) over silica glass fibers
   │ 17. Broadband Access Server (BAS) terminates PPPoE tunnel (MTU 1492)
   ▼
[ Carrier Core & Global Internet (ISP & BGP) ]
   │ 18. Core routers switch MPLS labels and transport packets via DWDM wavelengths
   │ 19. Packet traverses Autonomous System boundaries at an Internet Exchange Point (IXP)
   │ 20. BGP path-vector routing delivers datagram to target datacenter gateway
   ▼
[ Destination Server & Client Rendering ]
   │ 21. Server firewall validates 5-tuple; load balancer delivers request to web process
   │ 22. Server transmits HTTP response along reverse path; browser renders DOM and paint tree
```
