上一篇我们梳理了 TCP 协议如何在不可靠的网络中建立连接与切分数据。当 TCP 将切分好的段（Segment）准备就绪后，就会调用内核中的 **IP 模块**。

本篇我们将跟随数据包离开操作系统的传输层，进入网络层与网络接口层，观察 **IP 头部、MAC 头部如何封装，ARP 协议如何寻找下一跳，以及网卡硬件如何将内存中的数字比特转换为在网线上奔跑的电信号**。

## 双重头部封装：为什么同时需要 IP 和 MAC？

在计算机网络中，数据包必须被套上两层不同的寻址信封：**IP 头部** 与 **MAC 头部**。

![Network package](/assets/images/2022/02/network-package.webp)

初学者往往会产生疑问：既然已经有了全世界唯一的 IP 地址，为什么链路层还需要一个 MAC 地址？

| 寻址层级 | 对应头部 | 职责范围 | 形象比喻 |
| :--- | :--- | :--- | :--- |
| **网络层（L3）** | **IP 头部** | **端到端（End-to-End）**：指示数据包最初从哪里发出，最终要送到全球网络中的哪台目标主机。在跨网传输中，源 IP 与目的 IP 始终保持不变。 | 信件封皮上的**终点收件人地址** |
| **数据链路层（L2）** | **MAC 头部** | **跳到跳（Hop-by-Hop）**：指示当前数据包在局域网内部下一步该交给哪一台物理设备（主机、交换机或网关路由器）。每跨越一台路由器，MAC 头部都会被重新剥掉并换成下一跳的 MAC 地址。 | 快递在中转站之间交接的**下一站货运车编号** |

## IP 头部与路由表判断

当 IP 模块收到上层 TCP 的数据段后，首先在其前面加上包含控制信息的 **IP 头部**（IPv4 通常为 20 字节）：

![Network ip header](/assets/images/2022/02/network-ip-header.webp)

IP 头部的核心字段包括：

- **版本（Version）**：IPv4（4）或 IPv6（6）。
- **TTL (Time to Live，生存时间)**：数据包每经过一台路由器，TTL 值便会减 1。当 TTL 减至 0 时，路由器将丢弃该包并向源地址发送 ICMP 超时报文，防止数据包在网络路由环路中无限游荡。
- **协议号（Protocol）**：标识上层协议载荷（6 代表 TCP，17 代表 UDP，1 代表 ICMP）。
- **源 IP 地址 与 目的 IP 地址**：32 位发送方与接收方地址。

### 如何决定由哪张网卡发出？——路由表查表

计算机可能同时拥有多张网卡（如同时插着有线网线并连着 Wi-Fi，或者运行着 Docker 虚拟网桥）。在填充源 IP 地址前，操作系统必须决定：**这个包应该从哪张物理网卡发送给谁？**

负责决断的工具就是操作系统内核的 **路由表（Routing Table）**。在 Windows 下可通过 `route print` 命令查看，在 Linux 下可通过 `ip route` 查看：

![Network route](/assets/images/2022/02/network-route.webp)

路由匹配遵循 **最长前缀匹配原则（Longest Prefix Match）**：

1. 操作系统将目标 IP 与每一行的子网掩码（Netmask）进行“按位与”运算，若运算结果与该行的目标网络一致，则该行匹配成功。
2. 在所有匹配项中，选择子网掩码最长（即网络范围最具体）的一条规则作为出口路径。
3. **默认网关（Default Gateway）**：目标网络和子网掩码均为 `0.0.0.0` 的条目。当路由表中所有具体网段都无法命中目标 IP 时，便兜底走默认网关，将数据包发往家用路由器或局域网核心网关。

确定了出口网卡后，该网卡的分配 IP 就填入了 IP 头部的“源 IP 地址”字段。

## MAC 头部与 ARP 协议

选定了下一跳的 IP 地址后，IP 模块紧接着在前面追加 **以太网 MAC 头部**（14 字节）：

![Network mac header](/assets/images/2022/02/network-mac-header.webp)

MAC 头部包含三个要素：

- **发送方 MAC 地址**：本网卡出厂时固化在 ROM 中的 48 位全球唯一物理地址。
- **接收方 MAC 地址**：**下一跳路由器或目标主机的 MAC 地址**。
- **以太类型（EtherType）**：说明其后的数据载荷类型（`0x0800` 代表 IPv4，`0x0806` 代表 ARP）。

### ARP 协议：如何知道下一跳的 MAC 地址？

协议栈此时只知道下一跳的 IP 地址，如何得知对方的 MAC 地址？这需要借由 **ARP (Address Resolution Protocol)** 协议在局域网内进行查询。

![Network arp](/assets/images/2022/02/network-arp.webp)

以太网具备广播特性：

1. **ARP 请求（Broadcast）**：发送方组装一个 ARP 查询包，将以太网目的 MAC 填为全 1（`FF:FF:FF:FF:FF:FF`，广播地址），大喊一声：“谁拥有这个 IP 地址？请把你的 MAC 地址告诉我！”
2. **所有设备接收**：同一局域网下的所有主机网卡都会收到并解开这个广播包。只有 IP 与查询匹配的主机才会响应，其余设备直接丢弃。
3. **ARP 应答（Unicast）**：目标主机向发起方单独发送一个单播 ARP 响应：“我是这个 IP，我的 MAC 地址是 `xx:xx:xx:xx:xx:xx`。”
4. **ARP 缓存**：为了避免每次发包都全网广播，操作系统会将查询结果写入 **ARP 缓存表**（在终端输入 `arp -a` 可查看），通常保留数分钟后自动淘汰更新。

## 以太网与网卡：将数据转换为物理信号

封装好 IP 头部和 MAC 头部的完整以太网帧（Ethernet Frame），现在依然只是存放在操作系统内核内存中的一串 0 和 1 比特。接下来，控制权正式移交至计算机的硬件设备——**网卡（NIC, Network Interface Card）**。

![Network signal process](/assets/images/2022/02/network-signal-process.webp)

网卡由两个核心模块协同工作：

- **MAC 模块**：运行在数据链路层，负责帧的起始定界、校验和收发逻辑控制。
- **PHY (Physical Layer Device) 模块 / 收发器**：运行在物理层，负责将纯粹的二进制电平转换为可以在双绞线或光纤上传播的高频电信号或光脉冲。

### 包装帧结构：报头与 FCS

当网卡驱动程序将内存中的数据包复制到网卡板载缓冲区后，MAC 模块会在开头和结尾补齐物理传输所需的关键控制字段：

![Network package ctrl](/assets/images/2022/02/network-package-ctrl.webp)

1. **前导码（Preamble）与帧起始界定符（SFD）**：
   - 在数据帧的最前端附加一段 56 比特形如 `10101010...` 的波形，用于使接收端网卡的物理时钟与发送端的波形节奏快速锁定同步。
   - 随后的 8 比特为 `10101011`（SFD），最后两位连续的 `11` 标志着前导码结束，之后紧接着的就是合法的以太网帧。
2. **帧校验序列（FCS, Frame Check Sequence）**：
   - 在整个以太网帧的尾部追加 4 字节的 CRC-32 循环冗余校验码。
   - 接收端网卡收到电信号并解码为比特后，会重新运用多项式计算校验值。若网络中的噪声导致波形失真、翻转了哪怕 1 个比特，计算出的校验和便无法对齐，网卡会**直接在硬件层面丢弃该坏帧**，绝不让脏数据污染上层操作系统。

### 信号发送：半双工与全双工

- **半双工（Half-Duplex）**：老式同轴电缆或经典集线器共享介质的时代，发送与接收无法同时进行。为了避免电信号在物理导线上互相碰撞，必须采用 **CSMA/CD（载波侦听多路访问/冲突检测）**：发前先听网线有无信号，发中持续监听是否发生冲突；一旦冲突立即停发并随机退避等待重试。
- **全双工（Full-Duplex）**：现代双绞线拥有专用的双向导线对，配合交换机实现端到端独占通道，发送线与接收线互不干扰，完全消除了碰撞的概念，传输速率大幅跃升。

## 对比：轻量级的 UDP 协议

在本篇的结尾，有必要对照一下传输层的另一位主角——**UDP 协议**。

与严阵以待的 TCP 相比，UDP 放弃了三次握手、滑动窗口、序列号、ACK 确认和重传逻辑。应用层给它什么，它便直接在前面塞上一个只有 **8 个字节** 的极简头部，然后立刻下发给 IP 模块封装成包：

![Network udp header](/assets/images/2022/02/network-udp-header.webp)

UDP 首部只记录四个信息：

1. 源端口号（16 位）
2. 目的端口号（16 位）
3. 包长度（16 位）
4. 校验和（16 位）

因为没有任何握手与确认开销，UDP 具备“即写即发、延迟极低”的特性。这也正是 DNS 查询、音视频连麦、实时竞技游戏以及现代 HTTP/3（QUIC）选择在 UDP 之上自建协议的原因。

## 总结

第三篇记录了网络包在计算机内部完成的最后一步准备：**从内核抽象的逻辑概念，蜕变为网线上一串真正的物理信号**。

- **IP 负责宏观寻址**：跨越互联网、端到端指引目的地，路由表根据最长前缀匹配选择下一跳。
- **MAC 负责微观传递**：每经过一个局域网跳步便重新重写一次，ARP 协议在广播中解析物理身份。
- **网卡完成数模转换**：同步时钟的前导码确保波形同步，CRC 硬件校验守卫数据完整性。

当电信号从 RJ45 接口喷薄而出、顺着双绞线飞奔出去之后，它就彻底告别了本机的计算机主机。下一站，这束电信号将抵达局域网中的第一台网络设备——**集线器、交换机与路由器**。
