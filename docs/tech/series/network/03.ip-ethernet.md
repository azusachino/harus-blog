In the previous chapter, we observed how the TCP protocol segments data streams, tracks acknowledgments, and coordinates connection lifecycles within kernel space. Once TCP has structured a segment, it hands the payload to the operating system's **IP module**.

In this chapter, we follow the packet as it exits the transport layer and descends through the network and data link layers. We examine **why packets require dual headers (IP and MAC), how kernel routing tables determine the next hop, how the Address Resolution Protocol (ARP) translates logical addresses into physical MAC identifiers, and how the network interface card (NIC) converts digital bytes into electrical waveforms on the physical wire**.

## Before you start

TCP hands over segments, but something must carry them to the right machine, possibly many networks away. This chapter covers the two addressing systems involved. IP addresses say which machine in the world a packet is for. MAC addresses say which device on the local cable or Wi-Fi gets it next. Every packet carries both, and the MAC part is rewritten at each hop.

The post office gives an analogy. The street address on the parcel stays the same from sender to recipient. The truck that carries it changes at each depot, and each truck has its own next-stop instruction. The IP address is the street address; the MAC address is the next stop.

Read [chapter 2](/tech/series/network/02.tcp/) first. If you have a Linux shell, `ip route` and `ip neigh` show the tables discussed later.

Terms used in this chapter:

- **Packet**: a unit of data with an IP header, sent across networks.
- **Frame**: a unit of data with an Ethernet header, sent across one local link.
- **MAC address**: a hardware address identifying a network interface on the local link.
- **Routing table**: the list a machine uses to decide where to send a packet for each destination range.
- **Longest prefix match**: choosing the most specific matching route; for example 10.1.2.0/24 beats 10.0.0.0/8.
- **Default gateway**: the router a machine uses when no more specific route matches.
- **ARP**: the protocol for finding the MAC address that belongs to an IPv4 address on the local network.
- **NIC**: the network interface card, which converts frames to and from electrical or optical signals.

## Dual-Header Encapsulation: Why Both IP and MAC?

Every standard network packet transmitted across an Ethernet network carries two distinct addressing wrappers: an **IP Header** and an **Ethernet MAC Header**:

![Network package](/assets/images/2022/02/network-package.webp)

A common question among network engineers is: if every internet host possesses a globally unique IP address, why does the data link layer require a separate 48-bit MAC address?

The answer lies in the separation of **end-to-end routing** from **hop-by-hop delivery**:

| Protocol Layer | Encapsulation Header | Addressing Scope | Real-World Analogy |
| :--- | :--- | :--- | :--- |
| **Network Layer (L3)** | **IP Header** | **End-to-End**: Identifies the original source host and ultimate destination host across the global internet. Across standard routing hops, source and destination IP addresses remain constant. | The **recipient mailing address** on an envelope. |
| **Data Link Layer (L2)** | **MAC Header** | **Hop-by-Hop**: Directs the packet across a single local physical segment to the immediate next device (host, switch port, or router interface). At every routing hop, the old MAC header is stripped and replaced with the next hop's MAC address. | The **delivery truck manifest** passed between sorting hubs. |

## The IP Header and Kernel Routing Tables

When the IP module receives a TCP segment, it prefixes an **IP Header** (20 bytes for standard IPv4):

![Network ip header](/assets/images/2022/02/network-ip-header.webp)

Core fields of the IPv4 header include:

- **Version**: Identifies the IP protocol version (IPv4 = 4, IPv6 = 6).
- **TTL (Time to Live)**: An 8-bit hop counter decremented by 1 at every transit router. If the TTL reaches 0 before reaching the destination, the packet is discarded and an ICMP `Time to Live exceeded in transit` message is returned to the source, preventing orphan packets from looping indefinitely in routing anomalies.
- **Protocol**: Specifies the encapsulated transport protocol (6 for TCP, 17 for UDP, 1 for ICMP).
- **Source and Destination IP Addresses**: The 32-bit addresses identifying the original sender and target host.

### Determining the Egress Interface: Routing Table Lookup

Modern computing systems often host multiple network interfaces concurrently—such as an Ethernet adapter, a Wi-Fi card, and multiple virtual bridge interfaces (e.g., Docker or WireGuard). Before filling in the source IP address, the kernel must resolve a foundational question: **which physical interface and gateway should transmit this packet?**

The decision is governed by the operating system's internal **Routing Table**, inspectable via `ip route` on Linux or `route print` on Windows:

![Network route](/assets/images/2022/02/network-route.webp)

Route selection enforces the **Longest Prefix Match (LPM)** principle:

1. The kernel performs a bitwise logical AND between the destination IP and the subnet mask of each routing table entry. If the computed network prefix matches the entry's destination network, the rule qualifies as a candidate.
2. Among all matching candidates, the kernel chooses the entry with the longest prefix (the most specific subnet mask).
3. **Default Gateway (`0.0.0.0/0`)**: If no specific subnet matches the destination, the packet falls back to the default gateway entry, dispatching the packet to the local router.

Once the egress interface is resolved, its assigned IP address is populated into the IP header's `Source Address` field.

## The MAC Header and ARP Resolution

Once the IP datagram is prepared and the next-hop IP is determined, the kernel prepends an **Ethernet MAC Header** (14 bytes):

![Network mac header](/assets/images/2022/02/network-mac-header.webp)

The MAC header consists of three components:

- **Source MAC Address**: The 48-bit hardware address burned into the local network interface card's ROM.
- **Destination MAC Address**: **The physical MAC address of the immediate next-hop router or destination host on the local link**.
- **EtherType**: Indicates the encapsulated payload protocol (`0x0800` for IPv4, `0x0806` for ARP, `0x86DD` for IPv6).

### Address Resolution Protocol (ARP)

The protocol stack knows the next-hop IP address from the routing table, but how does it discover that device's physical MAC address? It queries the local broadcast domain using **ARP (Address Resolution Protocol)**:

![Network arp](/assets/images/2022/02/network-arp.webp)

ARP leverages the broadcast capabilities of Ethernet:

1. **ARP Request (Broadcast)**: The sender constructs an ARP query frame with the destination MAC set to `FF:FF:FF:FF:FF:FF` (the broadcast address), announcing to the entire local segment: *"Who owns IP address X.X.X.X? Tell MAC YY:YY:YY:YY:YY:YY."*
2. **Segment Delivery**: Every host and switch port within the local broadcast domain receives and processes the frame. Hosts whose IP does not match silently discard it.
3. **ARP Reply (Unicast)**: The target host recognizes its own IP and responds with a direct unicast frame: *"I own that IP. My MAC address is ZZ:ZZ:ZZ:ZZ:ZZ:ZZ."*
4. **ARP Cache**: To avoid saturating the local link with broadcasts, operating systems cache resolved IP-to-MAC associations in an internal **ARP Cache Table** (viewable via `ip neigh` or `arp -a`), expiring stale entries after several minutes.

## Ethernet and Network Interface Cards: Converting Bits to Signals

At this juncture, the assembled Ethernet frame—carrying its MAC header, IP header, TCP segment, and HTTP payload—remains an abstract sequence of bytes in host memory. Transmission onto the wire requires physical hardware: the **Network Interface Card (NIC)**.

![Network signal process](/assets/images/2022/02/network-signal-process.webp)

A network interface card coordinates two primary components:

- **MAC Controller (Media Access Control)**: Operates at the data link layer, handling frame delimitation, cyclic redundancy checking (CRC), and queue management.
- **PHY (Physical Layer) Transceiver**: Operates at the physical layer, converting digital binary states into modulated high-frequency electrical signals, optical pulses, or radio waves.

### Framing Additions: Preamble and FCS

When the device driver transfers the packet buffer into on-chip NIC memory, the MAC controller encloses the frame between physical synchronization boundaries:

![Network package ctrl](/assets/images/2022/02/network-package-ctrl.webp)

1. **Preamble and Start Frame Delimiter (SFD)**:
   - Prepends a 56-bit alternating bit pattern (`10101010...`) that allows the receiving PHY clock to synchronize with incoming waveform timings.
   - Concludes with the 8-bit sequence `10101011` (SFD). The two trailing consecutive `1`s signal that valid frame data immediately follows.
2. **Frame Check Sequence (FCS)**:
   - Appends a 4-byte CRC-32 (Cyclic Redundancy Check) checksum to the tail of the frame.
   - When the receiving NIC decodes the incoming signal, it recalculates the CRC polynomial. If line attenuation, interference, or impedance mismatches flipped even a single bit, the checksum calculation fails and the hardware **discards the frame immediately**, shielding host operating systems from corrupted data.

### Half-Duplex vs. Full-Duplex Transmission

- **Half-Duplex (CSMA/CD)**: In legacy coax networks or hub-based topologies, devices share a single electrical medium. Devices cannot send and receive concurrently without signal collisions. They rely on **CSMA/CD (Carrier Sense Multiple Access with Collision Detection)**: listen before transmitting, listen during transmission, and back off exponentially when collisions occur.
- **Full-Duplex**: Modern twisted-pair cables feature dedicated, independent physical transmit and receive conductor pairs. Paired with Layer 2 switches, collisions are physically eliminated, allowing continuous bidirectional throughput.

## Contrast: The Lightweight UDP Protocol

Before concluding this layer, it is instructive to compare TCP's heavy machinery with the transport layer's lightweight alternative: **UDP (User Datagram Protocol)**.

In contrast to TCP's connection handshakes, sequence tracking, and retransmission logic, UDP imposes an ultra-minimal **8-byte header**:

![Network udp header](/assets/images/2022/02/network-udp-header.webp)

The UDP header consists of only four fields:

1. **Source Port** (16 bits)
2. **Destination Port** (16 bits)
3. **Length** (16 bits)
4. **Checksum** (16 bits)

With zero handshake delay and minimal header overhead, UDP provides immediate, packet-oriented transmission. It powers DNS lookups, real-time voice and video streams, and modern protocols like HTTP/3 (QUIC), which implements reliability, encryption, and stream multiplexing entirely in user space.

## Hands-On Kernel Inspection: Querying the FIB and ARP Neighbor Cache

On Linux, you can trace the exact Longest Prefix Match routing decision (`ip route get`) and inspect the kernel's Layer 2 neighbor table (`ip neigh show`) before a single packet leaves the host:

```bash
# 1. Ask the kernel FIB which egress interface, source IP, and gateway a destination will use
$ ip route get 93.184.216.34
93.184.216.34 via 192.168.1.1 dev eth0 src 192.168.1.100 uid 1000
    cache

# 2. Inspect the ARP / NUD (Neighbor Unreachability Detection) cache for the next-hop gateway MAC
$ ip neigh show dev eth0
192.168.1.1 lladdr 00:1a:2b:3c:4d:5e REACHABLE
192.168.1.25 lladdr 52:54:00:8a:9b:1c STALE
```

- **`via 192.168.1.1 dev eth0 src 192.168.1.100`**: Confirms that `93.184.216.34` matched the default route (`0.0.0.0/0`), selecting local interface `eth0` and next-hop gateway IP `192.168.1.1`.
- **`lladdr 00:1a:2b:3c:4d:5e REACHABLE`**: Shows that the ARP resolution for `192.168.1.1` is cached and actively verified by kernel Neighbor Unreachability Detection, allowing the Ethernet MAC header to be stamped immediately without an ARP broadcast stall.

## Summary

This chapter highlighted the final preparatory stages inside the sender's host system:

- **Dual-Header Architecture**: IP headers guide packets across global network boundaries end-to-end, while MAC headers control hop-by-hop transfer within each local link.
- **Kernel Routing Logic**: Longest Prefix Match selects the appropriate egress interface and gateway IP.
- **ARP Resolution**: Dynamic broadcast discovery resolves the next-hop hardware MAC address.
- **Physical Signal Synthesis**: The NIC's MAC controller adds preambles and CRC-32 checksums, while the PHY transceiver transmits modulated electrical voltages across copper twisted pairs.

As physical electrical impulses travel out of the RJ45 port and down the cable, they depart the personal computer. In the next chapter, we will follow these signals as they enter their first intermediate hardware stops: **Ethernet hubs, Layer 2 switches, and Layer 3 routers**.
