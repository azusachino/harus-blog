## 仔细区别 pointers 和 references

在很多现代高级语言中，“指针”与“引用”往往只是同一个概念在不同语法糖下的代称；但在 C++ 中，两者在编译器层面对应着截然不同的语义约束与机器码生成策略。

### 1. 引用必须总代表着一个有效对象

**不存在所谓的“空引用（Null Reference）”**。引用在定义的一瞬间，必须绑定到一个已存在的合法对象身上：

```cpp
char* pc = nullptr;        // 合法的空指针
char& rc = *pc;            // 未定义行为（Undefined Behavior）！严重违背语言规约

std::string& rs;           // 编译报错：引用必须被初始化！
std::string s("Nancy");
std::string& rs = s;       // 合法：rs 成为 s 的别名
```

因为引用保证非空，所以在函数参数中使用引用传递时，**根本不需要做防御性的空指针校验**：

```cpp
// 使用指针：每次调用都必须承受一次 nullptr 检查与分支预测开销
void printDouble(const double* pd) {
    if (pd != nullptr) {
        std::cout << *pd;
    }
}

// 使用引用：契约保证参数必然指向有效内存，调用更直接且高效
void printDouble(const double& d) {
    std::cout << d;
}
```

### 2. 重新赋值的语义分歧

指针可以随时改指不同的内存地址，而**引用从诞生到销毁，始终且只能绑定最初获得的对象**：

```cpp
std::string s1("Nancy");
std::string s2("Clancy");

std::string& rs = s1;
std::string* ps = &s1;

rs = s2; // 警告：这并不是让 rs 改为引用 s2，而是把 s2 的内容赋值给 s1！
ps = &s2; // 合法：ps 改变指针值，改指向 s2 的地址
```

### 选型基准

- **使用引用的场景**：
  1. 明确知道需要指向某个已存在对象，且生命周期内绝不改变指向。
  2. 实现必须支持左值语法赋值的操作符（例如 `operator[]`、`operator=`、`operator<<`）。
- **使用指针的场景**：
  1. 允许存在“未指向任何东西”的语义（即 `nullptr`，在现代 C++ 中也可结合 `std::optional`）。
  2. 需要在不同时机指向不同的对象（动态重定向）。

## 最好使用 C++ 转型操作符

C 语言遗留下来的旧式强制转型 `(T)expression` 充斥着严重缺陷：它语法隐蔽，在海量代码中极难被搜索定位；同时其粗暴的二进制强制覆盖能力抹杀了编译器的类型安全审查。

C++ 引入了四个语义精准的显式转型操作符：

```cpp
// 1. static_cast：执行良性的隐式转换逆向操作与数值精度转换
double result = static_cast<double>(firstNum) / secondNum;

// 2. const_cast：唯一能移除常量性（constness）或易变性（volatileness）的操作符
void update(SpecialWidget* psw);
const SpecialWidget& csw = sw;
update(const_cast<SpecialWidget*>(&csw));

// 3. dynamic_cast：安全沿继承体系向下转型或跨系转型（必须依赖多态虚表与 RTTI）
if (SpecialWidget* psw = dynamic_cast<SpecialWidget*>(pw)) {
    psw->specialMethod(); // 仅当真实类型匹配时执行，否则返回 nullptr
}

// 4. reinterpret_cast：底层的非标准二进制重解释（如函数指针或硬件地址映射）
typedef void (*FuncPtr)();
FuncPtr funcPtrArray[10];
int doSomething();
funcPtrArray[0] = reinterpret_cast<FuncPtr>(&doSomething);
```

强制使用 C++ 风格转型的最大工程价值在于：**代码审查（Code Review）人员可以极轻易地利用 `grep` 扫描出所有具有潜在风险的转型点**，并迫使开发者必须在代码中明确阐述转型的具体意图。

## 绝对不要以多态方式处理数组

这是 C++ 面向对象与底层指针算术相碰撞时最致命的暗礁之一。

假设我们有一个基类及其派生类：

```cpp
class BST { ... }; // 二叉搜索树节点

class BalancedBST : public BST { ... }; // 平衡二叉树节点，内含平衡因子，体积大于 BST
```

我们编写了一个打印数组的工具函数：

```cpp
void printBSTArray(std::ostream& os, const BST array[], int numElements) {
    for (int i = 0; i < numElements; ++i) {
        os << array[i]; // 数组寻址计算！
    }
}
```

当我们传入 `BST` 数组时，一切工作正常；但如果我们将一个派生类 `BalancedBST` 数组传入：

```cpp
BalancedBST bArray[10];
printBSTArray(std::cout, bArray, 10); // 编译顺利通过，但运行期必然崩溃或输出垃圾！
```

### 内存布局与指针算术的真相

在 C++ 中，`array[i]` 纯粹是指针算术表达式 `*(array + i)` 的语法糖。为了计算出第 `i` 个元素的内存偏移，编译器执行的公式是：

$$\text{Address} = \text{array} + i \times \operatorname{sizeof}(\text{静态类型})$$

因为函数形参的静态类型是 `BST`，编译器在每一次循环跳转时，**严格跨越 $\operatorname{sizeof}(\text{BST})$ 字节的步长**！

然而派生类 `BalancedBST` 因为增加了额外字段，其体积必然满足：

$$\operatorname{sizeof}(\text{BalancedBST}) > \operatorname{sizeof}(\text{BST})$$

这意味着除了第 0 个元素首地址偶然重合之外，从第 1 个元素开始，指针跳转到的根本不是合法的对象起始边界，而是切入到了前一个对象的成员变量内部！随之而来的虚表指针错位与内存越界直接引发未定义崩溃。

同理，经由基类指针执行 `delete[] array` 更是双重灾难：不仅释放地址失准，析构循环也会错位摧毁内存。

**准则**：多态（Polymorphism）与数组指针算术天然不兼容。永远不要通过基类指针或引用操作由派生类构成的原生数组。在现代工程中，**全面采用 `std::vector<std::unique_ptr<Base>>`** 替代原生对象数组。

## 非必要不提供 default constructor

许多初学者存在误区，认为每个类都必须提供一个不带参数的默认构造函数（Default Constructor）。但从领域建模的视角来看，许多实体在缺乏必要业务信息的情况下，根本无法无中生有地建立起合法的不变量：

```cpp
class EquipmentPiece {
public:
    EquipmentPiece(int idNumber); // 必须具有唯一 ID，否则设备在系统中无意义
};
```

如果一个类没有默认构造函数，它在面对原生数组初始化时会受到严厉限制：

```cpp
EquipmentPiece bestPieces[10]; // 编译错误！无法调用默认构造函数
EquipmentPiece* pPieces = new EquipmentPiece[10]; // 同样报错
```

### 规避方案与成本考量

1. **显式使用非堆数组的大括号初值表**：

   ```cpp
   EquipmentPiece bestPieces[] = { EquipmentPiece(1), EquipmentPiece(2), EquipmentPiece(3) };
   ```

2. **指针数组替代对象数组**：

   ```cpp
   std::vector<std::unique_ptr<EquipmentPiece>> pieces;
   pieces.reserve(10);
   for (int i = 0; i < 10; ++i) {
       pieces.push_back(std::make_unique<EquipmentPiece>(i));
   }
   ```

3. **分配原始内存并结合 Placement New 手动构造**（标准库容器内部的实现基石）：

   ```cpp
   void* rawMemory = operator new[](10 * sizeof(EquipmentPiece));
   EquipmentPiece* pPieces = static_cast<EquipmentPiece*>(rawMemory);
   for (int i = 0; i < 10; ++i) {
       new (&pPieces[i]) EquipmentPiece(i); // 定位 new 构造
   }
   // 必须手动逆序显式调用析构函数
   for (int i = 9; i >= 0; --i) {
       pPieces[i].~EquipmentPiece();
   }
   operator delete[](rawMemory);
   ```

如果强行为了“支持原生数组”而给类硬塞一个没有实际意义的默认构造（例如将 ID 设为 `-1`），那么类的所有成员函数都不得不增加防御性校验：“检查当前 ID 是否有效”。这不仅降低了运行效率，更将潜在的未初始化 Bug 扩散到了系统的每个角落。
