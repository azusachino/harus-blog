Where *Effective C++* establishes core conventions and idioms, Scott Meyers' *More Effective C++* dives deeper into the language's micro-mechanics. From the physical differences between pointers and references, to the real runtime cost of casting, the memory misalignment of polymorphic arrays, and the invariant tradeoffs of default constructors, this chapter explores the balance between runtime efficiency and type correctness.

---

## Before you start

This series is for programmers who know one language and basic command-line use, and have started on C++. It is the follow-up to *Effective C++*, and the chapters build on each other.

The first chapter looks at things that seem too basic to need a chapter. A pointer and a reference both let you reach an object without copying it, yet they behave differently: a pointer can be null and can be re-aimed, a reference can do neither. Casts have the same kind of trap. `(int)x` hides which of several different conversions actually happens, which is why C++ has named casts. Then there is a classic bug in which a `Derived` array is treated as a `Base` array, and the program reads objects from the wrong addresses because the two types differ in size.

It helps to have read the first chapter of [Effective C++](/tech/series/effective-cpp/01.accustom/), but you only need to know what a class and a constructor are.

Terms used in this chapter:

- **pointer**: a variable holding the address of an object; it may be null and may be changed to point elsewhere.
- **reference**: another name for an existing object; it must be bound when created and cannot be re-bound.
- **cast**: an explicit conversion from one type to another.
- **`static_cast`, `const_cast`, `dynamic_cast`, `reinterpret_cast`**: the four C++ casts, each meant for one kind of conversion, so that the intent is visible and searchable.
- **polymorphic**: used through a base-class pointer or reference while the real type is a derived class.
- **pointer arithmetic**: `p + 1` moves by the size of the pointed-to type, so a wrong type means a wrong address.
- **default constructor**: a constructor that can be called with no arguments.

## Item 1: Distinguish Between Pointers and References

In many high-level languages, "pointers" and "references" are interchangeable labels for the same concept. In C++, they represent distinct compiler abstractions with divergent machine-code semantics.

### 1. References Must Always Refer to an Object

**There is no such thing as a null reference in C++**. A reference must be bound to a valid object upon creation:

```cpp
char* pc = nullptr;        // Legal: valid null pointer
// char& rc = *pc;         // UNDEFINED BEHAVIOR: dereferencing nullptr to bind a reference!

// std::string& rs;        // COMPILE ERROR: references must be initialized upon declaration!
std::string s("Nancy");
std::string& rs = s;       // Legal: rs becomes an immutable alias for s
```

Because references guarantee non-nullness, functions accepting reference parameters do not need defensive null checks:

```cpp
// Pointer parameter: requires runtime null checks and branch prediction overhead
void printDouble(const double* pd) {
    if (pd != nullptr) {
        std::cout << *pd << '\n';
    }
}

// Reference parameter: contract guarantees valid memory; direct and efficient
void printDouble(const double& d) {
    std::cout << d << '\n';
}
```

### 2. Reassignment Semantics

Pointers can be reseated to point to different addresses throughout their lifetime. **References, once initialized, can never be reseated to bind to another object**:

```cpp
std::string s1("Nancy");
std::string s2("Clancy");

std::string& rs = s1;
std::string* ps = &s1;

rs = s2;  // WARNING: Does NOT reseat rs to s2! Copies s2's content into s1!
ps = &s2; // Legal: reseats pointer ps to point to s2
```

### When to Use Which

- **Use References When**:
  1. You know an object exists and the binding must never change.
  2. Implementing overloaded operators that require lvalue syntax (e.g., `operator[]`, `operator=`, `operator<<`).
- **Use Pointers When**:
  1. "Pointing to nothing" is a valid semantic state (`nullptr`, or combine with `std::optional`).
  2. You need to redirect the target dynamically at runtime.

## Item 2: Prefer C++-Style Casts

Legacy C-style casts (`(T)expression`) hide critical flaws: they are difficult to find via text search tools (`grep`), and their brute-force overriding suppresses compiler warnings across unrelated categories.

C++ introduces four explicit, intention-revealing cast operators:

```cpp
// 1. static_cast: Inverts implicit conversions and handles arithmetic conversions
double result = static_cast<double>(firstNum) / secondNum;

// 2. const_cast: The ONLY cast capable of stripping const or volatile qualifiers
void update(SpecialWidget* psw);
const SpecialWidget& csw = sw;
update(const_cast<SpecialWidget*>(&csw));

// 3. dynamic_cast: Safely navigates inheritance hierarchies using RTTI
if (SpecialWidget* psw = dynamic_cast<SpecialWidget*>(pw)) {
    psw->specialMethod(); // Executes only if pw is truly a SpecialWidget; returns nullptr otherwise
}

// 4. reinterpret_cast: Low-level bit reinterpretation (e.g., function pointers or hardware MMIO)
using FuncPtr = void (*)();
FuncPtr funcPtrArray[10];
int doSomething();
funcPtrArray[0] = reinterpret_cast<FuncPtr>(&doSomething);
```

Using C++-style casts enables automated code audits and security scanners to flag high-risk conversions immediately.

## Item 3: Never Treat Arrays Polymorphically

Treating arrays of derived objects polymorphically through base-class pointers is one of the most dangerous traps in C++.

Consider a binary search tree node hierarchy:

```cpp
class BST { /* ... base fields ... */ };

class BalancedBST : public BST {
    int balanceFactor{0}; // Extra field: sizeof(BalancedBST) > sizeof(BST)
};
```

Suppose a utility function prints an array of nodes:

```cpp
void printBSTArray(std::ostream& os, const BST array[], int numElements) {
    for (int i = 0; i < numElements; ++i) {
        os << array[i] << '\n'; // Pointer arithmetic!
    }
}
```

Passing a `BST` array works as expected. But passing an array of `BalancedBST`:

```cpp
BalancedBST bArray[10];
printBSTArray(std::cout, bArray, 10); // Compiles cleanly; crashes or corrupts memory at runtime!
```

### Pointer Arithmetic and Memory Offsets

In C++, array indexing `array[i]` is syntactic sugar for pointer arithmetic: `*(array + i)`.

The compiler calculates the byte address using the pointer's **static type**:

$$\text{Address} = \text{array} + i \times \operatorname{sizeof}(\text{StaticType})$$

Because the parameter's static type is `BST`, the loop advances memory in strides of $\operatorname{sizeof}(\text{BST})$:

```text
Memory Layout of BalancedBST[2]:
[   BST subobject   | balanceFactor ][   BST subobject   | balanceFactor ]
^                                   ^
Offset 0: Element 0 valid           Offset sizeof(BST): Jumps into middle of Element 0!
```

Because $\operatorname{sizeof}(\text{BalancedBST}) > \operatorname{sizeof}(\text{BST})$, step $i = 1$ lands directly inside the private fields of element 0! Subsequent virtual table calls and member accesses corrupt memory and trigger segmentation faults.

Calling `delete[] array` through a base pointer causes identical disaster: destructors run against misaligned addresses, followed by heap deallocation errors.

**Guideline**: Polymorphism and array pointer arithmetic are fundamentally incompatible. Never manipulate arrays of derived objects through base pointers. Use **`std::vector<std::unique_ptr<Base>>`** instead.

## Item 4: Avoid Gratuitous Default Constructors

A common assumption is that every class should provide a parameterless default constructor. However, for entities that require domain identity or resources, meaningless default states undermine class invariants:

```cpp
class EquipmentPiece {
public:
    EquipmentPiece(int idNumber); // Mandatory ID: an equipment piece without an ID is invalid!
};
```

Without a default constructor, instantiating raw arrays fails to compile:

```cpp
// EquipmentPiece bestPieces[10]; // COMPILE ERROR: no default constructor available!
// EquipmentPiece* pPieces = new EquipmentPiece[10]; // COMPILE ERROR!
```

### Safe Alternatives to Forced Default Constructors

1. **Braced Initialization for Local Arrays**:

   ```cpp
   EquipmentPiece bestPieces[] = { EquipmentPiece(1), EquipmentPiece(2), EquipmentPiece(3) };
   ```

2. **Vectors of Smart Pointers (Recommended)**:

   ```cpp
   std::vector<std::unique_ptr<EquipmentPiece>> pieces;
   pieces.reserve(10);
   for (int i = 0; i < 10; ++i) {
       pieces.push_back(std::make_unique<EquipmentPiece>(i));
   }
   ```

3. **Raw Memory Allocation with Placement New** (How `std::vector` operates internally):

   ```cpp
   void* rawMemory = ::operator new[](10 * sizeof(EquipmentPiece));
   EquipmentPiece* pPieces = static_cast<EquipmentPiece*>(rawMemory);

   for (int i = 0; i < 10; ++i) {
       new (&pPieces[i]) EquipmentPiece(i); // Placement new constructs in-place
   }

   // Explicit destruction in reverse order
   for (int i = 9; i >= 0; --i) {
       pPieces[i].~EquipmentPiece();
   }
   ::operator delete[](rawMemory);
   ```

Forcing a meaningless default constructor (such as setting `id = -1`) forces every member function to execute defensive checks (`if (id == -1)`), degrading runtime performance and spreading uninitialized-state hazards across the codebase.

## Summary Checklist

| Principle | Guideline | Hazard to Avoid |
| :--- | :--- | :--- |
| **Pointers vs. References** | Use references for non-null immutable aliases; pointers for reseatable/optional state | Dereferencing null pointers to bind references |
| **Explicit Casts** | Prefer `static_cast`, `const_cast`, `dynamic_cast`, and `reinterpret_cast` | Silent bugs obscured by brute-force C-style casts |
| **Polymorphic Arrays** | Never pass derived class arrays to base array parameters | Pointer arithmetic stride mismatches corrupting memory |
| **Default Constructors** | Only provide default constructors when valid default invariants exist | Adding sentinel states (`id = -1`) that require runtime checking |
