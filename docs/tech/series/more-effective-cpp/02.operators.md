操作符重载（Operator Overloading）是 C++ 最具表现力也最容易被滥用的双刃剑。适度重载能让复数、矩阵和迭代器的运算像内置算术一样自然；但若忽视了编译器隐式调用的机制，就会引发意想不到的幽灵类型转换、短路求值失效以及生命周期错位。本章聚焦于**自增自减语义契约、逻辑短路保护、以及辨析语言中不同层级的 new 和 delete**。

---

## 对定制的“类型转换函数”保持警觉

C++ 允许通过两种途径定义自定义类型转换，供编译器在遇到类型不匹配时隐式调用：

1. **单实参构造函数（Single-argument Constructors）**：允许将其他类型隐式包装为当前类。
2. **隐式类型转换操作符（Implicit Type Conversion Operators）**：允许将当前类隐式转换为目标类型。

```cpp
class Rational {
public:
    Rational(int numerator = 0, int denominator = 1); // 可将 int 隐式转换为 Rational
    operator double() const; // 可将 Rational 隐式转换为 double
};

Rational r(1, 2);
double d = 0.5 * r; // 隐式转换发生：r 被静默转换为 0.5，随后执行浮点乘法
```

### 隐式转换引发的灾难性歧义

当类型转换过于自由时，编译器的“自作聪明”常常会吞掉本该报警的严重笔误：

```cpp
template<class T>
class Array {
public:
    Array(int size); // 单参构造函数，未加 explicit！
    T& operator[](int index);
};

bool operator==(const Array<int>& lhs, const Array<int>& rhs);

Array<int> a(10);
Array<int> b(10);

for (int i = 0; i < 10; ++i) {
    if (a == b[i]) { ... } // 程序员笔误：本意是比较 a[i] == b[i]
}
```

在上述循环中，`b[i]` 是一个 `int`。按照常理，拿一个 `Array<int>` 和一个 `int` 比较应当当场编译报错。然而编译器发现 `Array` 具有一个接收 `int` 的单参构造函数，于是它**默默把 `b[i]` 构造为一个临时的 `Array<int>` 实例**，随后执行了代价昂贵的数组深度比对！

### 治本之策：explicit 与显式命名函数

1. **为单参构造函数加上 `explicit`**：杜绝一切未经许可的隐式入参构造。

   ```cpp
   explicit Array(int size);
   ```

2. **用显式命名成员函数替换类型转换操作符**：

   ```cpp
   class Rational {
   public:
       double asDouble() const; // 显式调用，意图清晰可见
   };

   std::cout << r.asDouble(); // 安全无歧义
   ```

在现代 C++11 之后，`explicit` 更被进一步拓展到了类型转换操作符上（例如 `explicit operator bool() const noexcept`），使得类型只有在条件判断语句中才允许求值，彻底终结了历史包袱。

## 自增、自减操作符的前置与后置形式

自增（`++`）与自减（`--`）操作符存在两种截然不同的形态：

- **前置式（Prefix）**：先累加，再取值（Increment and Fetch）。
- **后置式（Postfix）**：先取值，再累加（Fetch and Increment）。

### 语法契约与函数签名设计

为了让编译器在语法重载时区分两者，C++ 制定了一条人为的语法规则：**后置版本接收一个匿名的伪整型实参（`int`）**，编译器在调用后置版本时会自动传入一个字面量 `0`：

```cpp
class UPInt { // 假定一个大整数类
public:
    UPInt& operator++();         // 前置式：++i
    const UPInt operator++(int); // 后置式：i++

    UPInt& operator--();         // 前置式：--i
    const UPInt operator--(int); // 后置式：i--

    UPInt& operator+=(int);
};
```

### 规范实现与返回值考量

```cpp
// 前置式：返回当前对象的引用
UPInt& UPInt::operator++() {
    *this += 1;
    return *this; // 高效：零临时对象产生
}

// 后置式：必须以深拷贝暂存旧状态，并由前置式驱动
const UPInt UPInt::operator++(int) {
    UPInt oldValue = *this; // 暂存旧值：触发一次拷贝构造
    ++(*this);              // 关键：复用前置式逻辑，保持唯一真实逻辑源
    return oldValue;        // 按值返回旧值副本：再承受一次拷贝/移动开销
}
```

两点至关重要的设计细节：

1. **后置式复用前置式**：后置版本永远应当调用前置版本来执行真实的数值递增，确保累加算法的实现只有单一真相来源。
2. **后置式返回 `const UPInt`**：如果返回普通非常量对象，使用者写出 `i++++` 就能合法编译。但那第二次自增只是作用在第一次返回的**临时对象**身上，原始变量 `i` 根本没有递增两次！返回 `const` 可以在编译期直接封杀这一荒谬语法。

> **性能准则**：对于类类型（尤其是 STL 迭代器），后置递增为了暂存旧值，必然在栈上分配并构造临时副本。**在没有特殊读取旧值需求的所有循环中，永远优先使用 `++iter` 而非 `iter++`**。

## 千万不要重载 &&、|| 和逗号操作符

C++ 允许重载绝大多数操作符，但逻辑与（`&&`）、逻辑或（`||`）和逗号（`,`）属于绝对不应触碰的高压线。

### 短路求值（Short-Circuit Evaluation）的丧失

内置的 `&&` 与 `||` 依赖严格的短路求值特性：

- `if (p != nullptr && p->isValid())`：如果 `p` 是空指针，右侧的解引用**绝对不会被执行**。
- `if (isCached || fetchFromRemote())`：如果命中缓存，右侧的昂贵网络 IO **绝对不会被触发**。

一旦你为自定义类重载了 `operator&&`，语法语义会瞬间退化为普通的函数调用：

```cpp
if (expression1 && expression2)
// 等价于：
if (expression1.operator&&(expression2)) // 或者是非成员函数 operator&&(expression1, expression2)
```

在 C++ 函数调用规范中：

1. **所有实参必须在进入函数体之前全部完成求值**。短路机制荡然无存！即使 `p == nullptr`，右侧的 `p->isValid()` 依然被强制执行，瞬间导致段错误崩溃！
2. **C++ 不保证函数参数的求值顺序**。编译器完全有可能先计算右侧的 `expression2`，再计算左侧的 `expression1`。这彻底颠覆了人类逻辑的直觉。

同理，内置逗号操作符保证左侧先求值、右侧后求值且整个表达式返回右侧结果；重载逗号操作符同样无法保证左侧先于右侧执行的顺序点（Sequence Point）契约。

## 了解各种不同意义的 new 和 delete

在 C++ 面向对象中，“new” 这个词在不同上下文指代三套完全不同的概念：

### 1. new operator（新建操作符）

这是 C++ 内置的关键字指令，绝不允许被重载或改变其语义：

```cpp
std::string* ps = new std::string("Hello");
```

它的物理执行过程由两个铁打的步骤组成：

1. 分配足够的堆内存以容纳 `std::string`。
2. 在该内存地址上调用 `std::string` 的构造函数初始化对象。

### 2. operator new（内存分配函数）

这是纯粹负责在堆上分配原始字节的底层函数，等价于 C 语言的 `malloc`。它可以被全局或在类内自由重载：

```cpp
void* operator new(size_t size); // 声明形式

void* rawMemory = operator new(sizeof(std::string)); // 仅分配内存，不调用任何构造函数！
```

### 3. Placement new（定位 new）

在已经分配好的一块现有内存上调用构造函数：

```cpp
#include <new>

// 在 rawMemory 地址上显式构造 string 对象
new (rawMemory) std::string("Hello");
```

### 对应层级的 delete 解析

- **delete operator**：用户手写的 `delete ps;`，先调用析构函数，随后调用底层 `operator delete` 回收内存。
- **operator delete**：底层的内存释放函数（等价于 `free`），仅回收裸内存：

  ```cpp
  void operator delete(void* memoryToBeDeallocated) noexcept;
  ```

- **显式析构**：对于由 Placement new 构造的对象，绝不能执行普通 `delete`，必须显式调用其析构函数，并手动释放原始内存：

  ```cpp
  ps->~basic_string(); // 手动析构
  operator delete(rawMemory); // 回收原始内存
  ```
