C++ 是一门以高度表达自由著称的语言。当语言原生的语法规则无法直接满足复杂的工程约束时，一代代 C++ 先驱凭借对类型系统与对象模型的深刻洞察，开创出了一批被称为**惯用法（Idioms）**的高阶设计技巧。从虚构造函数的克隆演进、受控对象生成、智能引用计数、到多重分发（Double Dispatch），本章全面揭示这些经典手法的物理实现与架构精髓。

## 将 constructor 和 non-member functions 虚化

在语法规则上，C++ 构造函数绝不能为 `virtual`（对象尚未诞生，虚表指针尚不存在）；非成员函数同样无法直接声明为 `virtual`（没有接收调用的 `this` 虚表指针）。然而在现实系统架构中，我们常常需要这两个特性的语义支持。

### 1. 虚拷贝构造函数（Virtual Copy Constructor / Clone Idiom）

在图形界面设计中，当用户选中画布上的一个未知形状并按下 `Ctrl+C` 复制时，系统只持有一个基类指针 `Shape*`。如何精准克隆出一个完全相同的派生类副本？

通过定义一个纯虚的 `clone()` 成员函数：

```cpp
class Shape {
public:
    virtual ~Shape() = default;
    virtual std::unique_ptr<Shape> clone() const = 0; // 虚构造函数语义！
};

class Circle : public Shape {
public:
    virtual std::unique_ptr<Shape> clone() const override {
        return std::make_unique<Circle>(*this); // 借助内部拷贝构造函数克隆自身！
    }
};

void duplicateShape(const Shape* s) {
    auto newShape = s->clone(); // 完美多态克隆，无需关心具体是圆还是矩形
}
```

### 2. 虚化非成员函数（Virtual Non-member Functions）

非成员函数（例如标准输出流操作符 `operator<<`）无法直接成为虚函数，但我们可以在内部将其委托给一个虚成员函数：

```cpp
class Shape {
public:
    virtual void print(std::ostream& os) const = 0; // 虚核心实现
};

// 非成员函数外观（Facade）
inline std::ostream& operator<<(std::ostream& os, const Shape& s) {
    s.print(os); // 动态多态分发！
    return os;
}
```

## 限制某个 class 的对象实例数量

在系统编程中，有些资源在物理上是唯一的（例如系统打印机驱动、硬件温度传感器），或者具有明确的并发实例上限。

### 1. 阻止生成任何实例（纯静态工具类）

将所有构造函数声明为 `private` 或在现代 C++ 中直接 `= delete`。

### 2. 单例模式（Singleton：至多产生一个实例）

Meyers' Singleton 惯用法：

```cpp
class Printer {
public:
    static Printer& getInstance() {
        static Printer instance; // C++11 保证局部静态变量初始化线程安全
        return instance;
    }
private:
    Printer() = default;
    Printer(const Printer&) = delete;
    Printer& operator=(const Printer&) = delete;
};
```

### 3. 受控阈值实例计数器（Threshold Limiter）

如果某个类最多只允许并发创建 5 个实例，可以借助静态计数器并在构造/析构中进行生命周期记账：

```cpp
class LimitedInstance {
public:
    class TooManyObjects : public std::runtime_error {
        using std::runtime_error::runtime_error;
    };

    LimitedInstance() {
        if (numObjects >= maxObjects) {
            throw TooManyObjects("Exceeded max instance limit of 5");
        }
        ++numObjects;
    }

    ~LimitedInstance() {
        --numObjects;
    }
private:
    static inline size_t numObjects{0};
    static constexpr size_t maxObjects{5};
};
```

## 要求（或禁止）对象产生于 heap 之中

### 1. 要求对象必须产生于 Heap 之中（Heap-Only）

如果类对象体积过大，放在栈上极易引发栈溢出（Stack Overflow），我们希望强制使用者只能通过 `new` 在堆上创建它。

**实现关键**：将析构函数声明为 `private`（或 `protected`），并提供一个专属的清理成员函数（伪析构函数）：

```cpp
class HeapOnlyWidget {
public:
    void destroy() {
        delete this; // 合法：在成员函数内部调用 private 析构函数
    }
private:
    ~HeapOnlyWidget() = default; // 阻止在栈上定义对象！
};

HeapOnlyWidget w; // 编译报错！栈上对象离开作用域时编译器无法调用 private 析构函数
auto* pw = new HeapOnlyWidget(); // 编译通过！
pw->destroy(); // 安全销毁
```

### 2. 禁止对象产生于 Heap 之中（Non-Heap）

有些具有极高实时性要求或局部生命周期绑定的对象，严禁承受堆分配的延迟与碎片风险。

**实现关键**：将 `operator new` 与 `operator new[]` 声明为 `private` 或直接 `= delete`：

```cpp
class NonHeapWidget {
public:
    static void* operator new(size_t) = delete;   // 禁止单个对象堆分配
    static void* operator new[](size_t) = delete; // 禁止数组堆分配
};

NonHeapWidget w; // 栈上分配：完美合法
auto* pw = new NonHeapWidget(); // 编译报错！拒绝 operator new
```

## Proxy Classes（替身类/代理类）

Proxy 模式通过一个轻量级的包装对象，在客户端与真实目标之间建立一层拦截钩子。它在 C++ 中有两个极其经典的高级应用：

### 1. 区分操作符 `[]` 的读操作与写操作

在前面讨论 Copy-On-Write 时，我们遇到过一个核心困境：普通的 `char& operator[](size_t pos)` 返回的是字符的非常量引用，编译器根本无法分清外部代码究竟是在**读取**字符（如 `char c = s[0]`）还是在**修改**字符（如 `s[0] = 'x'`）。

解决方案是让 `operator[]` 返回一个代理类 `CharProxy`：

```cpp
class String {
public:
    class CharProxy {
    public:
        CharProxy(String& str, size_t index) : theString(str), theIndex(index) {}

        // 左值写拦截：s[0] = 'x'
        CharProxy& operator=(char c) {
            theString.detachAndMutate(theIndex, c); // 真正触发写时复制！
            return *this;
        }

        // 右值读拦截：char c = s[0]
        operator char() const {
            return theString.readDirectly(theIndex); // 零多余分配，纯读
        }
    private:
        String& theString;
        size_t theIndex;
    };

    CharProxy operator[](size_t index) {
        return CharProxy(*this, index);
    }
};
```

### 2. 模拟二维多维数组下标 `matrix[i][j]`

C++ 原生并不支持重载两个参数的 `operator[][](i, j)`。通过让外层矩阵的 `operator[](i)` 返回一个代表“行向量”的轻量 `RowProxy` 对象，再在其上调用第二个 `operator[](j)`，即可完美还原多维数组的自然语法。

## 让函数根据多于一个对象类型决定多态行为（Double Dispatch）

经典的 C++ 虚函数机制是**单一分发（Single Dispatch）**：调用哪个重写版本，完全取决于调用宿主指针（`this`）这单一对象的动态类型。

但在许多复杂的交互场景中，操作的行为必须取决于**两个（甚至多个）参与对象的具体派生类型**。最典型的例子是太空飞行游戏中的碰撞检测：

```cpp
class GameObject { ... };
class SpaceShip : public GameObject { ... };
class SpaceStation : public GameObject { ... };
class Asteroid : public GameObject { ... };

void checkCollision(GameObject& obj1, GameObject& obj2);
```

飞船撞击空间站（可能触发对接）、空间站撞击小行星（可能引发毁灭爆炸），每一种组合的物理计算逻辑完全不同。

### 双重分发（Double Dispatch）的优雅解析

通过两次虚函数跳跃（类似设计模式中的 **Visitor 模式**），在完全不需要编写脆弱且低效的 `dynamic_cast` 级联 `if-else` 的前提下，优雅分发至目标实现：

<Archify src="./diagrams/double-dispatch.sequence.json" />

```cpp
class SpaceShip;
class SpaceStation;
class Asteroid;

class GameObject {
public:
    virtual ~GameObject() = default;
    // 第一次分发：解析自身类型
    virtual void collide(GameObject& other) = 0;

    // 第二次分发钩子：反向暴露具体派生类型
    virtual void collideWith(SpaceShip& other) = 0;
    virtual void collideWith(SpaceStation& other) = 0;
    virtual void collideWith(Asteroid& other) = 0;
};

class SpaceShip : public GameObject {
public:
    virtual void collide(GameObject& other) override {
        other.collideWith(*this); // 关键跳跃：传入强类型的 *this (SpaceShip&)！
    }

    virtual void collideWith(SpaceShip& other) override {
        // 执行飞船撞飞船的具体物理逻辑
    }
    virtual void collideWith(SpaceStation& other) override {
        // 执行飞船对接空间站的具体物理逻辑
    }
    virtual void collideWith(Asteroid& other) override {
        // 执行飞船撞击小行星的具体物理逻辑
    }
};
```

执行分析：

1. 第一次调用 `obj1.collide(obj2)`：虚函数分发精确落入 `SpaceShip::collide`。
2. 在该函数内部，`this` 指针的静态类型已确认为 `SpaceShip`。紧接着调用 `other.collideWith(*this)`，触发**第二次虚函数分发**。
3. 第二次虚函数精确根据 `obj2` 的动态类型，分发至 `obj2.collideWith(SpaceShip&)`。两次纯虚函数跳转，在 $O(1)$ 时间内以最高效率完成了双对象类型的完全多态绑定。
