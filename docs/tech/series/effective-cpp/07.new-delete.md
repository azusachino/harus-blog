C++ 赋予了系统开发者直接接管内存底层生命周期的终极控制权。你可以绕过通用堆分配器，为高频对象编写专属的内存池、植入越界检测守卫、或是为高并发场景定制无锁分配器。然而，接管内存的自由伴随着极高的契约成本：**一旦替换了 `new` 与 `delete`，你就必须百分之百履行语言规范制定的隐蔽惯例**。

---

## 了解 new-handler 的行为

当 `operator new` 无法在系统中满足某一次内存分配需求时，在抛出 `std::bad_alloc` 异常之前，它会先调用一个客户指定的错误处理函数——**new-handler**：

```cpp
#include <new>

namespace std {
    typedef void (*new_handler)();
    new_handler set_new_handler(new_handler p) noexcept;
}
```

调用 `set_new_handler` 可以登记全局的内存耗尽回调：

```cpp
void outOfMemory() {
    std::cerr << "Fatal: Unable to allocate memory! Aborting...\n";
    std::abort();
}

int main() {
    std::set_new_handler(outOfMemory);
    int* pBigData = new int[1000000000000000ULL]; // 触发 new-handler
}
```

### 一个合格的 new-handler 必须履行的契约

一个被良好设计的 new-handler 绝不能仅仅打印日志后返回。当它返回时，`operator new` 会立刻**重新尝试分配内存**。如果内存依然不足，它会陷入无穷死循环！因此，一个合格的 new-handler 必须做到以下五件事之一：

1. **让更多内存可被使用**：例如在程序启动时预分配一大块备用应急缓冲区，当 handler 被触发时释放该缓冲区，给后续清理或保存核心数据留出喘息之机。
2. **安装另一个新的 new-handler**：如果当前 handler 发现自己无力回天，可以安装一个能采取不同补救策略的 handler 来接力。
3. **卸除 new-handler**：向 `set_new_handler` 传入 `nullptr`。这样在下一次尝试分配失败时，系统将直接抛出 `std::bad_alloc`。
4. **抛出 `bad_alloc`（或派生自它的）异常**：跳出无穷重试循环，让外层 `try-catch` 接管。
5. **绝不返回（不正常退出）**：直接调用 `std::abort()` 或 `std::exit()` 快速失败，防止带病运行导致数据损坏。

### 为特定类定制专属 new-handler 与 CRTP 混入类

如果希望为某个特定的高内存开销类定制 handler，可以使用 RAII 结合 **CRTP（Curiously Recurring Template Pattern，奇异递归模板模式）**：

```cpp
// RAII 暂存器：自动在作用域退出时恢复旧的全局 handler
class NewHandlerHolder {
public:
    explicit NewHandlerHolder(std::new_handler nh) : handler(nh) {}
    ~NewHandlerHolder() { std::set_new_handler(handler); }

    NewHandlerHolder(const NewHandlerHolder&) = delete;
    NewHandlerHolder& operator=(const NewHandlerHolder&) = delete;
private:
    std::new_handler handler;
};

// CRTP 泛型混入基类
template<typename T>
class NewHandlerSupport {
public:
    static std::new_handler set_new_handler(std::new_handler nh) noexcept;
    static void* operator new(std::size_t size);
private:
    static std::new_handler currentHandler;
};

template<typename T>
std::new_handler NewHandlerSupport<T>::currentHandler = nullptr;

template<typename T>
std::new_handler NewHandlerSupport<T>::set_new_handler(std::new_handler nh) noexcept {
    std::new_handler oldHandler = currentHandler;
    currentHandler = nh;
    return oldHandler;
}

template<typename T>
void* NewHandlerSupport<T>::operator new(std::size_t size) {
    NewHandlerHolder h(std::set_new_handler(currentHandler));
    return ::operator new(size); // 内部发生分配失败时，自动路由到专属 handler
}

// 使用方式：任何类只要继承该模板，即刻获得专属 new-handler 支持！
class Widget : public NewHandlerSupport<Widget> {};
```

## 了解何时真的适合替换 new 和 delete

在绝大多数日常业务中，系统默认的内存管理器（如 glibc malloc、jemalloc、mimalloc）已经经过高度优化。只有在面临以下明确指标或架构痛点时，定制内存分配器才是值得的：

1. **检测内存越界与使用错误**：在分配的内存块头部与尾部注入特殊的签名魔数（Byte Signatures / Guard Canaries），在释放时校验魔数是否被破坏，精准捕获缓冲区溢出（Buffer Overflow）。
2. **收集遥测与性能统计**：统计运行期对象分配的生命周期分布、峰值内存消耗、内存碎片化比率以及分配尺寸直方图。
3. **追求极致的分配速度（内存池技术）**：系统级 `malloc` 必须考虑通用性与线程并发锁，如果你的应用频繁创建并销毁同一固定尺寸的小对象（如红黑树或图的节点），基于固定尺寸空闲链表（Fixed-Size Chunk Pool）的无锁分配器能带来数倍的速度提升。
4. **降低空间额外开销（Header Overhead）**：通用分配器为了维护区块大小，往往在每个分配内存前附加 8~16 字节的元数据头。对于海量微小对象，元数据可能占据过半的真实内存。
5. **满足特定的硬件对齐要求（Memory Alignment）**：例如利用 SIMD 指令集（SSE/AVX）时，指令强制要求内存地址按 16/32/64 字节严格对齐。
6. **优化 CPU 缓存局部性（Cache Locality）**：将常常需要一同遍历的相关对象成簇集中存放在相邻的连续内存页上，大幅压降 L1/L2 Cache Miss。

## 编写 new 和 delete 时需坚守常规

自定义 `operator new` 与 `operator delete` 不是自由发挥的散文，而是一套严丝合缝的规约实现。

### 自定义 operator new 的规范

```cpp
void* operator new(std::size_t size) {
    using namespace std;

    // 规约 1：处理 0 字节的分配请求
    if (size == 0) {
        size = 1; // C++ 规定哪怕请求 0 字节，也必须返回一个合法的独立指针！
    }

    // 规约 2：进入无限重试循环，尝试分配
    while (true) {
        void* pMem = malloc(size);
        if (pMem) return pMem; // 分配成功，直接返回

        // 分配失败：获取当前激活的 new-handler
        new_handler globalHandler = set_new_handler(nullptr);
        set_new_handler(globalHandler);

        if (globalHandler) {
            (*globalHandler)(); // 调用 handler 尝试筹措内存
        } else {
            throw bad_alloc();  // 没有任何 handler，坚决抛出异常
        }
    }
}
```

### 处理类继承时的尺寸畸变

当为类编写成员版本的 `operator new` 时，必须防范派生类的错位调用：

```cpp
class Base {
public:
    static void* operator new(std::size_t size) {
        if (size != sizeof(Base)) {
            // 关键：如果派生类没有重载 operator new 并继承了此函数，size 会大于 Base
            return ::operator new(size); // 必须无条件转交给全局分配器处理！
        }
        // ...执行专属于 Base 的固定大小内存池分配...
    }
};
```

### 自定义 operator delete 的规范

C++ 保证对空指针（`nullptr`）执行 `delete` 是绝对安全的无操作（No-op）。自定义的 `operator delete` 必须忠实履行此契约：

```cpp
void operator delete(void* rawMemory) noexcept {
    if (rawMemory == nullptr) return; // 规约：收到 nullptr 时绝不做任何事

    // 回收内存...
    free(rawMemory);
}
```

## 写了 placement new 也要写 placement delete

所谓 **Placement New**，是指接收额外参数的 `operator new`。最常见的形式是标准库自带的定位 new（在指定已有内存地址上构造对象）：

```cpp
void* pMemory = allocateBuffer();
Widget* pw = new (pMemory) Widget(); // placement new
```

你也可以设计接收额外参数的自定义版本：

```cpp
void* operator new(std::size_t size, std::ostream& logStream);
```

### 异常回滚时的内存泄漏危机

考虑如下表达式的执行过程：

```cpp
Widget* pw = new (std::cerr) Widget();
```

该调用在底层分为两步：

1. 调用自定义的 placement `operator new(sizeof(Widget), std::cerr)` 成功分配内存。
2. 调用 `Widget` 的构造函数。

**如果在第 2 步，`Widget` 的构造函数突然抛出了异常**：

- 构造未完成，用户根本拿不到返回的指针，因此外部代码绝无可能主动执行 `delete`。
- C++ 运行时系统必须自动回滚并释放第 1 步分配的内存。
- 此时运行时系统会寻找**参数列表与 placement new 完全一一对应**的 **placement delete**！

如果类中只写了自定义的 placement new，而没有提供对应签名的 placement delete：

```cpp
void operator delete(void* rawMemory, std::ostream& logStream) noexcept;
```

运行时系统将**束手无策，直接放弃释放内存**，发生静默的内存泄漏！

> **掩盖常态名称警惕**：在类内声明任何形式的 `operator new`，都会遮掩全局范围的普通 `new` 签名。如果需要让你的类既支持自定义形式，又支持常规用法，必须同时显式声明标准形式的 `operator new`、`operator delete`，或者通过 `using` 声明式将它们引入作用域。

## 杂项讨论与现代技术演进

### 认真对待编译器警告

将所有编译器的警告级别开到最高（如 GCC/Clang 的 `-Wall -Wextra -Wpedantic`，MSVC 的 `/W4`），并在 CI/CD 流程中强制开启 **`-Werror`（将警告视为错误）**。编译器警告往往精准揭示了潜在的未初始化成员、隐式类型窄化、有符号/无符号数比较错位与非虚基类析构漏洞。

### 拥抱现代 C++ 标准演进

《Effective C++》初版撰写于 C++03 / TR1 时代，书中预言的许多技术早已成为现代 C++ 标准的支柱：

- **TR1 的遗产**：`tr1::shared_ptr`、`tr1::function`、`tr1::unordered_map`、`tr1::tuple` 在 C++11 中正式升级为标准库核心组件。
- **现代特性**：C++11/14/17/20 引入的移动语义（`std::move`）、完美转发（`std::forward`）、智能指针套件（`std::unique_ptr`、`std::make_shared`）、`constexpr` 与 `Concepts`，在保留极致运行性能的同时，大幅削减了手工编写样板代码的负担。
- **Boost 的角色**：Boost 从始至终是 C++ 标准库的先导孵化器。在触碰前沿技术需求（如高性能网络 ASIO、协程、高级图算法）时，Boost 依然是极具工程价值的参考坐标。
