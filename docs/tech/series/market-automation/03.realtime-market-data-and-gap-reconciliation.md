## Real-Time Market Data: WebSockets, Snapshots & Gap Reconciliation

To make execution decisions—such as pricing a limit order, calculating spread slippage, or triggering a stop-loss—an automated trading system must maintain an **accurate, in-memory copy of the exchange's order book**.

Polling REST endpoints (e.g. `GET /api/v3/depth` every 500ms) is too slow:

- You quickly exhaust IP-based REST rate limits.
- The snapshot is already dozens or hundreds of milliseconds stale by the time it traverses the public internet.

Instead, production trading bots stream incremental delta updates over persistent **WebSockets**. However, streaming deltas introduces a subtle distributed systems problem: **how do you establish an initial book without missing events that occur while the snapshot is in transit, and how do you recover if a packet is dropped?**

This chapter details the canonical synchronization protocol used by tier-1 exchanges (like Binance and OKX) to maintain a synchronized local Level 2 order book with zero sequence gaps.

---

### 1. The Market Data Stream Architecture

Exchanges publish market data over high-throughput WebSocket streams:

```text
[ Exchange Matching Engine ]
             |
             +---> Emits L2 Delta Events (Every 100ms or tick-by-tick)
             |
             v
[ WebSocket Gateway (wss://stream.binance.com:9443/ws/...) ]
             |
             | Persistent TCP Stream
             v
[ Client Trading Bot ]
  ├── 1. WebSocket Buffer (Collects incoming diffs)
  ├── 2. Local L2 Book (In-memory B-Tree Bids & Asks)
  └── 3. Gap Detector (Monitors sequence IDs [U, u, pu])
```

#### Real-World Sample: Binance `depthUpdate` Event

When subscribed to `btcusdt@depth@100ms`:

```json
{
  "e": "depthUpdate",
  "E": 1730800000123,
  "s": "BTCUSDT",
  "U": 1027021450,
  "u": 1027021455,
  "pu": 1027021449,
  "b": [
    [ "94999.00", "1.50000000" ],
    [ "94998.00", "0.00000000" ]
  ],
  "a": [
    [ "95001.00", "0.80000000" ]
  ]
}
```

- **`U` (First Update ID)**: The starting sequence number of this batch.
- **`u` (Final Update ID)**: The ending sequence number of this batch.
- **`pu` (Previous Final Update ID)**: The `u` of the immediate predecessor event.
- **`b` / `a`**: Bids and Asks deltas. **Crucial rule**: if the quantity is `"0.00000000"`, that price level has been completely filled or canceled and must be **deleted** from your local book.

### 2. The L2 Order Book Synchronization Protocol

The challenge is timing: if you fetch a REST snapshot first and *then* open a WebSocket, you will miss events that occurred during connection handshake. If you open the WebSocket first, how do you align the incoming stream with the snapshot?

The standard industry recipe proceeds in strict phases:

```text
Timeline:
t0: Open WebSocket -> Subscribe to btcusdt@depth
t1: WebSocket connects -> Immediately buffer incoming diffs in memory (DO NOT APPLY!)
t2: Send REST request: GET /api/v3/depth?symbol=BTCUSDT&limit=1000
t3: REST Snapshot arrives with `lastUpdateId = 1027021452`
t4: Drop all buffered events where `u <= lastUpdateId`
t5: Find first event where `U <= lastUpdateId + 1` AND `u >= lastUpdateId + 1`
t6: Apply that event and all subsequent buffered events
t7: Transition to live stream; verify `pu == previous_u` on every new event!
```

### 4. Sequence Gap Detection & Fail-Safe Recovery

What happens if network congestion, a Wi-Fi drop, or an OS buffer overrun drops a WebSocket packet?

Suppose your last applied event had `u = 100`. The next event arriving from the socket has:

```json
{ "U": 105, "u": 110, "pu": 104 }
```

Your system expected `pu = 100`, but received `pu = 104`. **Updates 101 through 104 were lost!**

A naive bot would continue applying updates, leading to a "ghost" order book where phantom bids or stale asks mislead your trading strategy into submitting bad orders.

#### The Fail-Closed Recovery Rule

When `event.pu != local_book.last_u`:

1. **Trigger Alert**: Log `CRITICAL: Order book sequence gap detected`.
2. **Halt Trading**: Temporarily suspend active order submission for that symbol.
3. **Flush Local Book**: Discard all bids and asks in local memory.
4. **Re-initialize**: Reconnect the WebSocket, clear the buffer, and request a fresh REST snapshot.

### 5. Verification Lab: Implementing a Resilient L2 Order Book Reconciler

The following Python script implements the full Binance/OKX synchronization engine:

- Buffers incoming WebSocket `depthUpdate` events.
- Accepts an asynchronous REST depth snapshot.
- Filters stale events, aligns the initial snapshot boundary, and replays buffered diffs.
- Maintains live B-Tree depth (including `"0"` quantity price level deletions).
- Injects a simulated dropped packet to verify immediate gap detection and safe state reset.

```python
#!/usr/bin/env python3
"""
Lab: Level-2 Order Book WebSocket Synchronizer & Sequence Gap Reconciler
Verifies REST snapshot alignment, delta replay, zero-qty deletion, and packet gap handling.
"""

from dataclasses import dataclass
from typing import Dict, List, Optional, Tuple

@dataclass
class DepthUpdateEvent:
    first_update_id: int    # U
    final_update_id: int    # u
    prev_final_id: int      # pu
    bids: List[Tuple[float, float]]  # [(price, qty)]
    asks: List[Tuple[float, float]]

@dataclass
class RestDepthSnapshot:
    last_update_id: int
    bids: List[Tuple[float, float]]
    asks: List[Tuple[float, float]]

class LocalL2OrderBook:
    def __init__(self, symbol: str):
        self.symbol = symbol
        self.bids: Dict[float, float] = {}  # price -> qty
        self.asks: Dict[float, float] = {}
        self.last_update_id: int = 0
        self.is_synced: bool = False
        self._buffer: List[DepthUpdateEvent] = []

    def handle_ws_event(self, event: DepthUpdateEvent):
        if not self.is_synced:
            # Phase 1: Buffer events while waiting for REST snapshot
            self._buffer.append(event)
            return

        # Phase 2: Live stream processing with strict sequence gap check
        if event.prev_final_id != self.last_update_id:
            print(
                f"  [GAP DETECTED] Expected pu={self.last_update_id}, got pu={event.prev_final_id}! Resetting."
            )
            self.reset()
            return

        self._apply_diffs(event.bids, event.asks)
        self.last_update_id = event.final_update_id

    def apply_snapshot(self, snapshot: RestDepthSnapshot):
        """Aligns buffered events against REST snapshot and transitions to synced state."""
        self.bids = {p: q for p, q in snapshot.bids if q > 0}
        self.asks = {p: q for p, q in snapshot.asks if q > 0}
        self.last_update_id = snapshot.last_update_id

        print(f"  [snapshot] Applied REST snapshot with lastUpdateId={snapshot.last_update_id}")

        # Drop events where u <= lastUpdateId
        valid_buffer = [e for e in self._buffer if e.final_update_id > snapshot.last_update_id]

        if not valid_buffer:
            print("  [sync] Buffer empty or expired. Awaiting fresh events...")
            self.is_synced = True
            return

        # Verify first event bridges snapshot: U <= lastUpdateId + 1 <= u
        first = valid_buffer[0]
        if not (first.first_update_id <= snapshot.last_update_id + 1 <= first.final_update_id):
            print("  [sync error] First event does not overlap snapshot! Resetting.")
            self.reset()
            return

        # Replay buffered events
        for ev in valid_buffer:
            self._apply_diffs(ev.bids, ev.asks)
            self.last_update_id = ev.final_update_id

        self._buffer.clear()
        self.is_synced = True
        print(f"  [synced] Successfully replayed buffer. Book synced at updateId={self.last_update_id}")

    def _apply_diffs(self, bid_diffs: List[Tuple[float, float]], ask_diffs: List[Tuple[float, float]]):
        for p, q in bid_diffs:
            if q == 0.0:
                self.bids.pop(p, None)  # Delete price level
            else:
                self.bids[p] = q

        for p, q in ask_diffs:
            if q == 0.0:
                self.asks.pop(p, None)  # Delete price level
            else:
                self.asks[p] = q

    def reset(self):
        """Fail-safe state reset upon gap detection."""
        self.bids.clear()
        self.asks.clear()
        self._buffer.clear()
        self.last_update_id = 0
        self.is_synced = False

    def get_bbo(self) -> Tuple[Optional[float], Optional[float]]:
        best_bid = max(self.bids.keys()) if self.bids else None
        best_ask = min(self.asks.keys()) if self.asks else None
        return best_bid, best_ask

def test_l2_reconciliation():
    book = LocalL2OrderBook("BTCUSDT")

    # 1. Step 1: WebSocket events start arriving and are buffered
    ev1 = DepthUpdateEvent(first_update_id=100, final_update_id=105, prev_final_id=99,
                           bids=[(95000.0, 1.0)], asks=[(95005.0, 1.0)])
    ev2 = DepthUpdateEvent(first_update_id=106, final_update_id=110, prev_final_id=105,
                           bids=[(95000.0, 2.5)], asks=[(95005.0, 0.0)]) # ask deleted!
    ev3 = DepthUpdateEvent(first_update_id=111, final_update_id=115, prev_final_id=110,
                           bids=[(95001.0, 0.5)], asks=[(95006.0, 2.0)])

    print("=== 1. Buffering WebSocket Events in Advance ===")
    book.handle_ws_event(ev1)
    book.handle_ws_event(ev2)
    book.handle_ws_event(ev3)
    assert book.is_synced is False
    assert len(book._buffer) == 3

    # 2. Step 2: REST Snapshot arrives with lastUpdateId = 104 (falls inside ev1)
    print("\n=== 2. Applying REST Snapshot & Replaying Buffer ===")
    snapshot = RestDepthSnapshot(
        last_update_id=104,
        bids=[(94998.0, 5.0), (95000.0, 0.8)],
        asks=[(95005.0, 1.0), (95010.0, 3.0)]
    )
    book.apply_snapshot(snapshot)

    # Invariants after replay:
    # ev1: U=100 <= 105 <= u=105 (bids 95000->1.0)
    # ev2: bids 95000->2.5, ask 95005->0.0 (deleted!)
    # ev3: bids 95001->0.5, ask 95006->2.0
    assert book.is_synced is True
    assert book.last_update_id == 115
    best_bid, best_ask = book.get_bbo()
    print(f"  Current BBO: Best Bid = {best_bid}, Best Ask = {best_ask}")
    assert best_bid == 95001.0
    assert best_ask == 95006.0
    assert 95005.0 not in book.asks, "Price 95005.0 should be deleted by zero qty diff!"

    # 3. Step 3: Normal Live Event
    print("\n=== 3. Continuous Live Event Stream ===")
    ev4 = DepthUpdateEvent(first_update_id=116, final_update_id=120, prev_final_id=115,
                           bids=[(95002.0, 1.0)], asks=[])
    book.handle_ws_event(ev4)
    assert book.last_update_id == 120
    assert book.get_bbo()[0] == 95002.0

    # 4. Step 4: Injected Packet Drop / Sequence Gap
    print("\n=== 4. Sequence Gap Detection & Safety Reset ===")
    # Missing updates 121..125! Next event has pu=125 instead of expected 120
    gap_event = DepthUpdateEvent(first_update_id=126, final_update_id=130, prev_final_id=125,
                                 bids=[(95003.0, 1.0)], asks=[])
    book.handle_ws_event(gap_event)

    # Invariant: book must detect gap, reset immediately, and unmark is_synced!
    assert book.is_synced is False
    assert len(book.bids) == 0
    assert len(book.asks) == 0
    print("  Book cleanly reset to un-synced state. Ready for fresh snapshot re-bootstrap.")

    print("\nAll L2 Order Book & Gap Reconciliation tests PASSED!")

if __name__ == "__main__":
    test_l2_reconciliation()
```

### 6. Summary & Key Takeaways

1. **Buffer First, Fetch Second**: Always subscribe and buffer WebSocket deltas before issuing the REST depth snapshot to guarantee zero missing events during transmission.
2. **The Zero-Quantity Deletion Rule**: In L2 diff feeds, receiving `qty = 0` means the price level was eliminated; failing to remove it leaves dangerous phantom liquidity in your book.
3. **Fail-Closed on Gaps**: Never ignore sequence gaps (`pu != last_u`). A corrupted order book leads to bad fills and capital loss; resetting and re-fetching the snapshot takes milliseconds and guarantees truth.
