## Before you start

Once your program sends an order, you cannot take it back from the wire. A bug, a typo in a price or a loop that keeps submitting can lose real money before you notice. Pre-trade risk checks are small functions that every order must pass before it is sent, and that reject it if it looks wrong. This chapter lists the common checks: a price too far from the market, an order too large, too many orders per second, or the same order sent twice.

It also covers what happens when your program or its connection dies with orders still resting on the exchange. A dead man's switch is the trick of telling the exchange "cancel everything of mine if you stop hearing from me".

An example: a limit buy at 5,000 when the market is at 50,000 should be rejected by a price collar, which allows only a narrow band around the market price.

Read [chapter 2](/tech/series/market-automation/02.order-types-and-financial-precision/) first for how orders are built, and [chapter 4](/tech/series/market-automation/04.perpetual-contracts-and-funding-rates/) for margin and leverage.

Terms used in this chapter:

- **pre-trade risk check**: a validation run on an order before it is sent to the exchange.
- **fail-closed**: when a check cannot decide or breaks, the order is rejected rather than allowed through.
- **price collar**: a limit on how far an order's price may be from a reference price.
- **notional**: the value of an order, price multiplied by quantity.
- **idempotent client order ID**: an ID you choose for each order so that a retry of the same order is recognized as a duplicate and not executed twice.
- **kill switch**: a control that stops all trading at once.
- **cancel-on-disconnect (dead man's switch)**: an exchange or client feature that cancels open orders when the connection drops or heartbeats stop.

## Pre-Trade Risk Controls & The Dead Man's Switch

In electronic trading, **post-trade risk is an autopsy; pre-trade risk is prevention**.

History is littered with catastrophic algorithm failures: Knight Capital losing \$440 million in 45 minutes due to a deployed flag bug, or amateur bots getting liquidated overnight because a misplaced decimal point placed buy orders $50\%$ above market price.

Once an order message leaves your network interface card and crosses the exchange wire, **it cannot be recalled**. If your trading strategy hallucinates, suffers a race condition, or loops infinitely, your pre-trade risk engine is the single barrier standing between your capital and total wipeout.

This chapter details the architecture of **fail-closed pre-trade risk controls**: how to construct zero-allocation in-memory filters, enforce price collars and notional caps, prevent duplicate executions with idempotent client order IDs, and safeguard open orders using **Cancel-on-Disconnect (The Dead Man's Switch)**.

---

### 1. The Pre-Trade Risk Architecture

A production risk engine must satisfy three strict architectural constraints:

1. **Synchronous & In-Line**: Risk checks must execute directly in the execution hot-path *before* the serialization layer transmits bytes to the exchange socket.
2. **Zero Network / Disk Roundtrips**: Querying an external database (like PostgreSQL or Redis) adds milliseconds of latency and introduces connection failure modes. All risk state (positions, open notional, order rates) must live in-memory.
3. **Fail-Closed**: If a risk check encounters uninitialized state, corrupted telemetry, or missing market data, it must **reject the order by default**.

```text
[ Strategy Signal Engine ]
            |
            | Emits NewOrderIntent(symbol, side, price, qty, cloid)
            v
+-------------------------------------------------------------+
|               In-Memory Pre-Trade Risk Guard                |
|                                                             |
|  1. Idempotency Check      -> Duplicate cloid? Reject       |
|  2. Price Collar Guard     -> Price > 2% from mid? Reject   |
|  3. Max Notional Limit     -> Value > $50,000? Reject       |
|  4. Portfolio Exposure Cap -> Breaches position cap? Reject |
|  5. Rate Limiter (Token)   -> Out of order-rate budget? Reject |
+-------------------------------------------------------------+
            |
            | All Checks PASSED
            v
[ Exchange Gateway (Wire Serialization -> TCP/WebSocket) ]
```

### 2. Core Risk Filters

#### 1. The Fat-Finger Price Collar

A common algorithmic failure occurs when a bot calculates a limit price from stale data or corrupted floating-point math:

- Submitting a BUY order at \$105,000 when market is at \$95,000.
- Submitting a SELL order at \$10 when market is at \$95,000.

An exchange matching engine will happily cross these orders, sweeping the entire book and handing massive windfall profits to opposing market makers.

**The Price Collar Rule**:
$$\left| \frac{\text{Order Price} - \text{Mid Price}}{\text{Mid Price}} \right| \le \text{Max Deviation (e.g. 2\%) }$$

Any order deviating further than $2.0\%$ from the current Best Bid/Ask midpoint is rejected immediately.

#### 2. Idempotent Client Order IDs (`cloid`)

In distributed networks, **network timeouts are ambiguous**:

- You submit an order over HTTP or WebSocket.
- The connection drops before the exchange sends back a response.
- *Did the exchange execute the trade or drop it?*

If your bot blindly retries with a fresh order, it might execute twice, accidentally doubling your position!

To prevent this, exchanges support **Client Order IDs** (Binance `newClientOrderId`, OKX `clOrdId`):

- You assign a deterministic, unique string to the order intent (e.g. `algostrat120261105001`). Length and charset limits differ by venue (OKX allows up to 32 letters and digits; Binance allows up to 36 characters).
- If you resubmit the same `cloid` after a timeout, the exchange rejects it as a duplicate instead of creating a second position, and you query the order by its client ID to learn what happened to the original.

### 3. The Dead Man's Switch (Cancel-on-Disconnect)

What happens if your trading server loses power, suffers an OS kernel panic, or loses its fiber optic internet connection while holding **50 resting limit orders** in the market?

While your bot is dead, the market continues moving. If a flash crash occurs, your stale buy orders will fill at high prices, leaving you with massive unmanaged inventory that you cannot hedge.

```text
Normal Operation:
[ Client Bot ] ─── Heartbeat Ping (Every 5s) ───> [ Exchange Risk Daemon ]
                                                     (Resets 10s countdown timer)

Failure Mode (Bot Crashes / Cable Cut):
[ Client Bot (DEAD) ]     X                       [ Exchange Risk Daemon ]
                                                     (Countdown timer expires: 10s... 0s!)
                                                     -> AUTOMATIC MASS CANCELLATION!
                                                     -> All open orders purged from book!
```

#### Real-World Exchange Implementation

- **Binance Futures (`countdownCancelAll`)**:
  Client sends `POST /fapi/v1/countdownCancelAll` with `countdownTime: 10000` (10 seconds). The client must periodically refresh this countdown. If the timer reaches zero, Binance automatically cancels all open orders for that symbol (the countdown is set per symbol).
- **OKX (`/api/v5/trade/cancel-all-after`)**:
  Takes a `timeOut` in seconds; if you do not call it again before the timer expires, the exchange cancels your open orders.

### 5. Verification Lab: Implementing an In-Memory Pre-Trade Risk Engine

The following Python script implements a small pre-trade risk engine. It runs the cheap idempotency and rate checks before the price checks; the order of these independent checks changes which reason an order is rejected with, not which orders pass:

- Price collar validation relative to live BBO mid-price.
- Max order notional threshold enforcement.
- Portfolio net position and exposure bounds.
- Token-bucket rate limiter tracking orders-per-second quotas.
- Idempotent `cloid` deduplication cache.
- Dead Man's Switch heartbeat monitor that cancels all registered resting orders if a heartbeat is missed.

```python
#!/usr/bin/env python3
"""
Lab: Pre-Trade Risk Guard Engine, Idempotent Cloid & Dead Man's Switch
Verifies fat-finger collars, notional limits, rate throttling, and heartbeat timeouts.
"""

from dataclasses import dataclass, field
from typing import Dict, Optional, Set, Tuple
import time

@dataclass
class OrderIntent:
    cloid: str
    symbol: str
    side: str
    price: float
    qty: float

@dataclass
class RiskLimits:
    max_price_deviation: float = 0.02   # Max 2% away from mid-market
    max_order_notional: float = 50000.0 # Max $50,000 per single order
    max_position_qty: float = 5.0       # Max 5.0 BTC net exposure
    max_orders_per_sec: int = 10        # Rate limit token bucket

class PreTradeRiskEngine:
    def __init__(self, limits: RiskLimits):
        self.limits = limits
        self.seen_cloids: Set[str] = set()
        self.current_position_qty: float = 0.0
        self.rate_tokens: float = float(limits.max_orders_per_sec)
        self.last_rate_update: float = time.time()
        # Simulated live order book state
        self.active_open_orders: Dict[str, OrderIntent] = {}

    def _replenish_tokens(self, now: float):
        elapsed = now - self.last_rate_update
        self.rate_tokens = min(
            float(self.limits.max_orders_per_sec),
            self.rate_tokens + elapsed * self.limits.max_orders_per_sec
        )
        self.last_rate_update = now

    def evaluate_order(
        self,
        order: OrderIntent,
        best_bid: float,
        best_ask: float,
        now: Optional[float] = None
    ) -> Tuple[bool, str]:
        if now is None:
            now = time.time()

        # 1. Idempotency Check
        if order.cloid in self.seen_cloids:
            return False, f"REJECT_DUPLICATE_CLOID: {order.cloid} already processed"

        # 2. Rate Limit Token Bucket
        self._replenish_tokens(now)
        if self.rate_tokens < 1.0:
            return False, "REJECT_RATE_LIMIT_EXCEEDED"

        # 3. Fat-Finger Price Collar Guard
        mid_price = (best_bid + best_ask) / 2.0
        deviation = abs(order.price - mid_price) / mid_price
        if deviation > self.limits.max_price_deviation:
            return False, (
                f"REJECT_PRICE_COLLAR: Price {order.price} deviates {deviation*100:.2f}% "
                f"from mid {mid_price:.2f} (Max {self.limits.max_price_deviation*100:.1f}%)"
            )

        # 4. Max Single Order Notional Limit
        notional = order.price * order.qty
        if notional > self.limits.max_order_notional:
            return False, (
                f"REJECT_MAX_NOTIONAL: Order value ${notional:.2f} "
                f"exceeds limit ${self.limits.max_order_notional:.2f}"
            )

        # 5. Position & Exposure Cap Check
        projected_qty = self.current_position_qty + (order.qty if order.side == "BUY" else -order.qty)
        if abs(projected_qty) > self.limits.max_position_qty:
            return False, (
                f"REJECT_EXPOSURE_BREACH: Projected position {projected_qty} BTC "
                f"exceeds max limit {self.limits.max_position_qty} BTC"
            )

        # All checks passed! Deduct token and register cloid
        self.rate_tokens -= 1.0
        self.seen_cloids.add(order.cloid)
        self.active_open_orders[order.cloid] = order
        return True, "APPROVED"

class DeadMansSwitchDaemon:
    """Simulates exchange-side Cancel-on-Disconnect countdown timer."""
    def __init__(self, timeout_sec: float = 10.0):
        self.timeout_sec = timeout_sec
        self.last_heartbeat: float = time.time()

    def receive_heartbeat(self, now: float):
        self.last_heartbeat = now

    def check_timeout(self, now: float, active_orders: Dict[str, OrderIntent]) -> Tuple[bool, int]:
        """If countdown expires, cancels all open orders."""
        if now - self.last_heartbeat > self.timeout_sec:
            canceled_count = len(active_orders)
            active_orders.clear()
            return True, canceled_count
        return False, 0

def test_risk_controls():
    limits = RiskLimits(
        max_price_deviation=0.02,   # 2%
        max_order_notional=50000.0, # $50,000
        max_position_qty=5.0,       # 5.0 BTC
        max_orders_per_sec=5
    )
    engine = PreTradeRiskEngine(limits)

    current_bid = 95000.0
    current_ask = 95002.0  # Mid = $95,001.00

    # 1. Normal Valid Order
    print("=== 1. Validating Compliant Order ===")
    valid_order = OrderIntent("cloid_001", "BTCUSDT", "BUY", price=95000.0, qty=0.2)
    ok, reason = engine.evaluate_order(valid_order, current_bid, current_ask)
    assert ok is True
    print(f"  Order {valid_order.cloid}: {reason}")

    # 2. Idempotency Duplicate Reject
    print("\n=== 2. Idempotent Duplicate Rejection ===")
    ok_dup, reason_dup = engine.evaluate_order(valid_order, current_bid, current_ask)
    assert ok_dup is False
    assert "REJECT_DUPLICATE_CLOID" in reason_dup
    print(f"  Duplicate Submission: {reason_dup}")

    # 3. Fat-Finger Price Collar Reject (Order at $98,000 > 2% away from mid $95,001)
    print("\n=== 3. Fat-Finger Price Collar Guard ===")
    fat_finger_order = OrderIntent("cloid_002", "BTCUSDT", "BUY", price=98000.0, qty=0.1)
    ok_collar, reason_collar = engine.evaluate_order(fat_finger_order, current_bid, current_ask)
    assert ok_collar is False
    assert "REJECT_PRICE_COLLAR" in reason_collar
    print(f"  Fat-Finger Order: {reason_collar}")

    # 4. Max Notional Limit Reject (1.0 BTC @ $95,000 = $95,000 > $50,000 max)
    print("\n=== 4. Maximum Notional Limit Guard ===")
    large_order = OrderIntent("cloid_003", "BTCUSDT", "BUY", price=95000.0, qty=1.0)
    ok_notional, reason_notional = engine.evaluate_order(large_order, current_bid, current_ask)
    assert ok_notional is False
    assert "REJECT_MAX_NOTIONAL" in reason_notional
    print(f"  Giant Order: {reason_notional}")

    # 5. Exposure Breach Reject (Projected 5.3 BTC > 5.0 BTC max limit)
    print("\n=== 5. Max Exposure & Position Breach Guard ===")
    engine.current_position_qty = 4.8  # Already holding 4.8 BTC
    breach_order = OrderIntent("cloid_004", "BTCUSDT", "BUY", price=95000.0, qty=0.5)
    ok_exp, reason_exp = engine.evaluate_order(breach_order, current_bid, current_ask)
    assert ok_exp is False
    assert "REJECT_EXPOSURE_BREACH" in reason_exp
    print(f"  Exposure Breach: {reason_exp}")

    # 6. Dead Man's Switch Heartbeat Timeout
    print("\n=== 6. Dead Man's Switch (Cancel-on-Disconnect) ===")
    daemon = DeadMansSwitchDaemon(timeout_sec=10.0)
    now = 1000.0
    daemon.receive_heartbeat(now)

    # 5 seconds later: heartbeat received, orders safe
    daemon.receive_heartbeat(now + 5.0)
    timed_out, canceled = daemon.check_timeout(now + 8.0, engine.active_open_orders)
    assert timed_out is False
    assert len(engine.active_open_orders) == 1

    # 16 seconds after the last heartbeat, with none since (Client bot crashed!):
    timed_out_crash, canceled_count = daemon.check_timeout(now + 21.0, engine.active_open_orders)
    assert timed_out_crash is True
    assert canceled_count == 1
    assert len(engine.active_open_orders) == 0
    print(f"  Heartbeat Lost! Emergency Mass Cancellation Triggered: {canceled_count} orders purged.")

    print("\nAll Pre-Trade Risk Control & Dead Man's Switch tests PASSED!")

if __name__ == "__main__":
    test_risk_controls()
```

### 6. Summary & Key Takeaways

1. **Synchronous Zero-Allocation Gate**: Pre-trade risk filters must reside directly in the memory hot path; never rely on external databases or post-trade reconciliations to catch order anomalies.
2. **Price Collars Prevent Disasters**: Fat-finger collars bound execution prices to a tight band around the BBO, blocking the market-sweeping orders a mispriced bot would send.
3. **Idempotent Identifiers (`cloid`)**: Every order must carry a unique client order ID so that network timeouts can be safely retried without risk of duplicate execution.
4. **Heartbeat Fail-Safe**: Configure Cancel-on-Disconnect with exchange gateways so that unexpected client disconnects automatically wipe resting orders before stale quotes are picked off.
