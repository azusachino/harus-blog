The model from chapter 05 is trained and saved. It has only ever done one thing: given some tokens, output a score for every possible next token. Making it write is a matter of using that answer in a loop. This chapter shows the loop, explains the choices you have when picking the next token (always the likeliest, or a random draw, and how to shape the draw), and runs calc's `make sample` to see what a tiny model produces. You have a file of trained weights, `artifacts/model.pt`, from the previous chapter.

## 1. The generation loop

Generation repeats five steps:

```text
1. Feed the tokens so far into the model.
2. Take the logits at the last position (the scores for "what comes next").
3. Turn them into probabilities with softmax.
4. Pick one token from those probabilities.
5. Append it to the tokens and go back to step 1.
```

The word for this is **autoregressive**: the model's own output becomes part of its next input. Each new token needs a full forward pass, so 500 new tokens means 500 passes one after another. Training did not have this limit, since every position's answer was known in advance and all were checked in parallel.

## 2. calc's `generate`

The loop is a method of `LanguageModel` in `calc/core/model.py`:

```python
@torch.no_grad()
def generate(self, tokens: torch.Tensor, max_new_tokens: int) -> torch.Tensor:
    for _ in range(max_new_tokens):
        context = tokens[:, -self.block_size :]
        logits, _ = self(context)
        next_token = torch.multinomial(logits[:, -1].softmax(dim=-1), num_samples=1)
        tokens = torch.cat((tokens, next_token), dim=1)
    return tokens
```

- `@torch.no_grad()` turns off gradient tracking; we are not training.
- `tokens` has shape `[batch, length]`, starting with whatever prompt you give. `tokens[:, -self.block_size :]` keeps only the last `block_size` (64) tokens, because the position table from chapter 02 has no rows beyond that. Older text is forgotten.
- `self(context)` runs the model. No targets are passed, so the loss is `None`, which we ignore. `logits` is `[batch, length, vocab]`.
- `logits[:, -1]` selects the last position for every sentence: `[batch, vocab]`. `.softmax(dim=-1)` converts each row to probabilities.
- `torch.multinomial(probs, num_samples=1)` draws one token ID at random, where each ID's chance equals its probability. A token with probability 0.64 is picked 64% of the time.
- `torch.cat((tokens, next_token), dim=1)` appends the new ID to each sentence.

Note what is not here: no stopping rule other than the count, and no temperature or top-k. `generate` always draws from the model's raw probabilities. The next sections show what those options would change, and you can add them in the exercise.

## 3. Greedy versus random draw

Suppose the probabilities for the next token are `[0.64, 0.23, 0.10, 0.03]`.

The **greedy** choice always takes the largest, token 0. It is deterministic: the same prompt gives the same text every time. For open-ended prose that tends to go badly, because a phrase that makes itself likely tends to keep making itself likely, and the output can settle into a loop like "in other words, in other words, ...". Greedy is the right choice when you want one stable answer, such as extracting structured data.

The random draw in calc's `generate` picks token 0 about 64% of the time, token 1 about 23%, and so on, so the text varies and rarely loops. The risk is the other direction: a 3% token gets picked every 33 steps on average, and in a 500-token passage unlikely choices add up. The two controls below, temperature and truncation, trade between these.

## 4. Temperature

**Temperature** divides the logits by a number T before the softmax. Using the logits `[2.0, 1.0, 0.1, -1.0]` from the last chapter:

```text
T = 0.5   ->  [0.86, 0.12, 0.02, 0.00]   sharper
T = 1.0   ->  [0.64, 0.23, 0.10, 0.03]   the model's own probabilities
T = 2.0   ->  [0.45, 0.27, 0.17, 0.10]   flatter
```

Low temperature concentrates probability on the leader, approaching greedy as T gets small. High temperature spreads it out so unlikely tokens get a chance. T=1 leaves things as trained, which is what calc does. A very high temperature produces word salad.

## 5. Top-k and top-p

Even at T=1, a vocabulary of tens of thousands of tokens has a long tail of nonsense options that together hold some probability. Two filters cut the tail before drawing. Both keep the likeliest tokens, set the rest to zero, and rescale so the survivors add up to 1.

**Top-k** keeps a fixed number of tokens. With k=2 on our example, tokens 0 and 1 survive, and rescaling gives `[0.74, 0.26]`.

**Top-p** (also called nucleus sampling) keeps the smallest group of top tokens whose probabilities add up to at least p. With p=0.9: 0.64 alone is not enough, 0.64 + 0.23 = 0.87 is still short, 0.87 + 0.10 = 0.97 passes. So three tokens survive, rescaled to `[0.66, 0.24, 0.10]`. The advantage over top-k is that the group size adapts: when the model is sure, one or two tokens suffice, and when it is unsure, many remain.

calc does not implement either. They are a few lines each; the exercise below does temperature.

## 6. Running it

`make sample` runs `calc/core/sample.py`: it loads `artifacts/model.pt`, rebuilds the model from the saved settings, starts from a newline character as the prompt, seeds the random generator (so repeated runs match), and generates 500 characters. The start of the output from calc's default run:

```text
Tharneow wareier ve nizey ave. Cove ce scounge ound impatw dsolitesetes quers. W, f reanthe buea s thandextie sten. Ool Thivenit moming mar in std ine geroguerigil fomesse wdeses oy eslinokes w owthed f olllthe. A ur uothtul mpess. Widullibrymos bod aneasy.
```

This is a 110,126-parameter model trained for 17 seconds on 2,350 characters, and it reads like English at a glance and falls apart when you try to read it. It has picked up word lengths, capital letters after periods, sentence-ending periods, and a few real short words (`the`, `in`, `a`). It has no idea what any of it means. For anything coherent you need far more text, a bigger model and many more steps; the code does not change much, only the scale.

## Going deeper (optional)

You can skip this section; the series is complete without it.

**Repetition penalty.** Some systems lower the logits of tokens that already appeared, to discourage loops (Keskar et al., 2019).

**KV cache.** Look at the loop again: every step feeds the whole context back in, so the keys and values of earlier tokens (chapter 03) are recomputed each time. Because of the causal mask they never change, so real inference code stores them and processes only the newest token at each step. That makes each step much cheaper but uses memory that grows with the length. calc skips this for simplicity.

**After pre-training.** What you built is a base model, which continues text. If you give a base model a question it may continue with more questions. Chat assistants are made by further training on instruction-and-answer examples (supervised fine-tuning) and on human preference comparisons. The architecture and the generation loop stay as they are here.

## Try it

1. Add temperature to `generate`. Hint: add a `temperature: float = 1.0` parameter and divide the logits before the softmax:

   ```python
   probs = (logits[:, -1] / temperature).softmax(dim=-1)
   ```

   Pass `temperature=0.5` and then `1.5` in the `generate` call in `calc/core/sample.py` and run `make sample`. Expect cleaner but more repetitive text at 0.5 and more gibberish at 1.5.
2. Try greedy: replace the `multinomial` line with `next_token = logits[:, -1].argmax(dim=-1, keepdim=True)`. Predict, then check, whether the output loops.
