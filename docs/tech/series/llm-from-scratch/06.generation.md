## 序言：让静止的参数开口说话

在前五章中，我们完整穿越了大语言模型的全部底层建筑：
从字符与子词的词元化（Ch 01），到高维空间的连续向量映射与位置先验（Ch 02）；从因果自注意力机制的信息路由（Ch 03），到 Pre-LN 与 FFN 解码器块的深度堆叠（Ch 04）；最后通过自监督下一个词预测闭环与 AdamW 优化动力学（Ch 05），完成了权重的训练与持久化。

此时，我们手上的模型已经拥有了预测自然语言统计规律的强大直觉。

然而，训练时的模型处于**被动答题**状态：给定完整的句子，并行计算每个时间步的损失。
当我们真正想把大模型用作智能体（Agent）、写作助手或问答机器人时，我们该如何驱动它主动开口，源源不断地吐出连贯、富有创见且逻辑严谨的文字？

本章作为系列的收官之作，将拆解 **自回归生成（Autoregressive Generation）** 的底层循环，对比贪婪搜索、温度调节、Top-K 与 Top-P（核采样）算法，并揭示支撑现代超快推理的核心技术——**KV Cache** 的工程实现。

## 1. 自回归生成循环（Autoregressive Generation）

自回归语言模型生成文本的逻辑极其朴素：**以彼之矛，攻彼之盾；以己之产，作己之引。**

假设用户提供了一段初始提示词（Prompt）序列：
$$x_{1:t} = [x_1, x_2, \dots, x_t]$$

整个文本生成的生命周期是一个无限迭代的单步递归循环：

```text
1. 将当前序列 x_{1:t} 送入模型，执行单次前向传播；
2. 提取最后一个时间槽位的预测 Logits: z_t in R^V；
3. 经过采样策略（Sampling Strategy），选出下一个 Token: x_{t+1}；
4. 将新生成的 Token 追加至上下文末尾: x_{1:t+1} = [x_{1:t}, x_{t+1}]；
5. 判断终止条件（是否生成了终止符 <|endoftext|> 或达到最大长度 max_new_tokens）；
6. 若未终止，令 t = t + 1，跳回步骤 1 继续循环。
```

### 训练与推理的计算复杂度鸿沟

- **训练阶段**：得益于因果掩码（Causal Mask），长度为 $T$ 的训练文本可以**一次性并行送入 GPU**，单次前向即可算出所有 $T$ 个位置的下一个词预测损失，时间复杂度为 $\mathcal{O}(1)$ 次网络前向。
- **推理生成阶段**：因为未来的词尚未产生，模型**无法预知下一步的输出**。生成 $N$ 个新 Token 必须老老实实执行 $N$ 次顺序前向传播。这种不可规避的时序依赖性，使得大语言模型推理成为一种高度受限于内存带宽（Memory Bandwidth Bound）的计算任务。

## 2. 为什么贪婪搜索（Greedy Search）不是好策略？

在拿到模型输出的最后一个 Logits 向量 $z_t \in \mathbb{R}^V$ 后，最直觉的决策方式是 **贪婪搜索（Greedy Search / Argmax）**：每次只挑概率绝对最大的那个词：

$$x_{t+1} = \arg\max_{k \in \{1, \dots, V\}} z_t[k]$$

在代码题、精确数学计算或结构化 JSON 抽取等需要绝对确定性输出的场景中，贪婪搜索非常适用。但在开放式写作与对话中，贪婪搜索常常导致两场灾难：

1. **局部最优陷入死循环（Degenerate Repetition Loop）**：
   贪婪搜索极易让模型陷入某种高概率词的闭环旋涡中。例如，一旦模型输出了 `"in other words"`, 紧接着概率最高的名词短语很可能再次指向 `"in other words"`，导致模型进入无休止的“复读机”状态：
   `"The system is designed to provide safety. In other words, it is designed to provide safety. In other words, it is..."`
2. **缺乏多样性与语言灵性**：
   自然语言的魅力恰恰在于其丰富的不确定性。统计表明，人类在实际写作时，选择最高概率词的频率其实并不高；人类倾向于使用更富表现力的近义词和句式。贪婪搜索会彻底抹杀模型的词汇多样性。

## 3. 概率塑形利器：温度调节（Temperature Scaling）

为了让模型能够依据概率分布进行随机探索，我们先通过 Softmax 将未归一化的 Logits 转化为合法的概率分布向量 $\mathbf{P} \in \mathbb{R}^V$。

在进入 Softmax 之前，我们引入一个可调节的浮点参数——**温度系数（Temperature, $T > 0$）**：

$$P_i = \frac{\exp(z_i / T)}{\sum_{j=1}^V \exp(z_j / T)}$$

通过调节温度 $T$ 的数值，我们能像调音师一样精确掌控概率分布的“陡峭程度”：

### 1. 低温区（$0 < T < 1.0$，如 $T = 0.2$）

- $z_i / T$ 将原本得分最高的 Logits 差距急剧放大（例如 10 与 5 的差值变成 50 与 25）。
- Softmax 后的概率分布变得**极其尖锐（Peak Distribution）**，概率高度集中在极少数几个顶级候选词上。
- **表现**：回答严谨、保守、高度事实化，几乎杜绝了语法错误与幻觉，适合学术问答与代码补全。
- 当 $T \to 0$ 时，数学上无限逼近**贪婪搜索（Argmax）**。

### 2. 标准温度（$T = 1.0$）

- 保持模型在预训练语料中原汁原味学到的真实统计规律。

### 3. 高温区（$T > 1.0$，如 $T = 1.3$）

- $z_i / T$ 压缩了不同 Logits 之间的绝对差距，所有词的得分被强行向均值拉拢。
- 概率分布变得**平缓分散（Smoothed / Flatter Distribution）**，许多在预训练语料中出现频率较低但极富创意的生僻词获得了被抽中的机会。
- **表现**：文本极富想象力、修辞优美多变；但若温度过高（如 $T \ge 2.0$），极度平坦的分布会导致语法彻底瓦解，沦为随机乱码胡言。

## 4. 截断采样双雄：Top-K 与 Top-P（核采样）

即便调节了温度，直接在全词表（$V = 50,000$ 甚至 $150,000$）上根据概率多项式抽样（Multinomial Sampling）依然潜伏着巨大隐患：**长尾灾难（The Tail Catastrophe）**。

在庞大的词表中，90% 以上的词在当前语境下的合理概率应该为 0。然而由于 Softmax 的指数特性，这些毫不相关的词依然可能分走 $0.00001$ 的微弱概率。当整篇文章生成上千个 Token 时，长尾中那些荒谬的生僻词、拼写错误或非目标语种字符必然会偶尔被摇中，瞬间毁掉整段文本的连贯性。

为了斩断长尾，工业界发展出了两种经典的截断采样策略：

### 方案 A：Top-K 采样（Fan et al., 2018）

- **规则**：将所有候选词按概率从大到小排序，**强制只保留前 $K$ 个最高概率的候选词**（例如 $K = 40$）。
- 将剩余全部 $V - K$ 个词的 Logits 强行覆盖为 $-\infty$（概率为 0）。
- 在剩余的 $K$ 个词上重新归一化并执行随机抽样。
- **缺点**：$K$ 是固定的刚性数值。在上下文含义高度确定时（例如 `The capital of France is ___`），候选集其实只有 `Paris`，保留 40 个词会把不相干的词引入危险区；而在开放式头脑风暴时，合理的词可能有数百个，$K=40$ 又人为压缩了表达自由度。

### 方案 B：Top-P 采样（核采样 Nucleus Sampling, Holtzman et al., 2019）

- **规则**：不再固定候选数量，而是**固定累积概率阈值 $P \in (0, 1]$**（通常设为 $P = 0.9$ 或 $0.95$）。
- 将候选词按概率降序排列，从高到低依次累加，**直到累积概率首次达到或超过阈值 $P$**。
- 将这个动态集合（被称为“核心” Nucleus）之外的所有候选词彻底裁剪掉，在集合内部重新归一化抽样。
- **优势**：候选池会根据上下文的不确定性**自适应膨胀与收缩**。在置信度极高的地方，集合自动收窄为 1~2 个词（防止长尾作乱）；在语境开放的地方，集合自动扩大至数十乃至上百个词，兼顾了精准与生动。

## 5. 重复惩罚（Repetition Penalty）

为了彻底根除自回归生成在特定主题下不断重复相同短语的“复读机”倾向，Nitish Shirish Keskar 等人在 CTRL 模型中提出了 **重复惩罚（Repetition Penalty）**。

在计算 Softmax 之前，检查当前生成历史中已经出现过的所有 Token：
对于任意在过去出现过的 Token 索引 $k$：

$$z_k' = \begin{cases} z_k / \theta, & z_k > 0 \\ z_k \cdot \theta, & z_k \le 0 \end{cases} \quad (\text{其中惩罚系数 } \theta > 1.0)$$

通过对已用过的词的未归一化得分施加降折（通常 $\theta = 1.1 \sim 1.2$），显著降低了模型重复自我引用的倾向，强迫模型在后续段落中不断探索新的词汇与思路。

## 6. 生产级推理引擎的心脏：KV Cache

当我们把模型部署到生产环境（如 vLLM、TGI、Ollama）时，如果按照上面最质朴的方式循环运行，服务器的响应速度会在几句话后慢到令人绝望。

### 朴素自回归生成的计算灾难

回顾第 3 章与第 4 章：当输入一个长度为 $T$ 的序列时，自注意力层需要将所有 $T$ 个词的特征投影为 Key 矩阵和 Value 矩阵：

- 生成第 1 个词：计算输入 $x_{1:T}$ 的前向，消耗计算量 $\sim \mathcal{O}(T^2)$；
- 生成第 2 个词：输入被扩展为 $x_{1:T+1}$，**模型又把前 $T$ 个词从头到尾重新计算了一遍！**
- 生成第 $N$ 个词：总计算量高达 $\sum_{t=1}^N \mathcal{O}((T+t)^2) \sim \mathcal{O}(N^3)$！

### KV Cache 的物理救赎

请深刻记住因果掩码的数学本质：**第 $i$ 个 Token 的激活值与 Key/Value 向量，仅取决于它自身和它前面的 Token，绝对不受未来尚未生成的 Token 影响！**

这意味着：一旦第 $i$ 个词的 Key 和 Value 向量在某一层的显存中算出来了，**在后续生成第 $i+1, i+2, \dots$ 个词的整个生命周期中，它们的值永远恒定不变！**

**KV Cache 的工程哲学**：

1. **显存换时间**：每一层 Transformer 解码器在显存中保留一个缓存张量，专门存放历史所有 Token 的 Key 矩阵和 Value 矩阵。
2. **极速增量单步推进**：在自回归生成时，模型每次**只喂入最新生成的单单一枚 Token（$x_{\text{new}}$, 序列长度为 1）**！
3. 最新 Token 只需要计算自身的单个 Query 向量 $q_{\text{new}}$ 以及新的 $k_{\text{new}}, v_{\text{new}}$；
4. 将新的 $k_{\text{new}}, v_{\text{new}}$ 直接追加（Append）到显存里的 KV Cache 中；
5. 用单个 $q_{\text{new}}$ 与整个 KV Cache 中的全部历史 Key 做单行点积注意力，并与历史 Value 聚合；
6. 每一轮生成的计算复杂度瞬间从 $\mathcal{O}(T^2)$ 降维打击到 **$\mathcal{O}(T)$**！首字之后每个字（TPOT, Time Per Output Token）的生成延迟大幅缩短，大模型的流畅打字机效果才真正成为现实。

## 7. 在 `calc` 中的代码实现与文本采样

回到我们的教学仓库 [`calc`](https://github.com/azusachino/calc)，在 `calc/calc/model.py` 中，`LanguageModel` 内置了一个清晰透明的最小可行自回归生成器：

```python
@torch.no_grad()
def generate(self, tokens: torch.Tensor, max_new_tokens: int) -> torch.Tensor:
    for _ in range(max_new_tokens):
        # 1. 如果上下文超出允许的最大块大小，裁剪保留最近的 block_size 个词
        context = tokens[:, -self.block_size :]

        # 2. 执行模型前向传播，获取 Logits
        logits, _ = self(context)

        # 3. 截取最后一个时序槽位的未归一化得分: [B, V]
        last_logits = logits[:, -1]

        # 4. Softmax 转化为概率分布并基于多项式分布采样
        probs = last_logits.softmax(dim=-1)
        next_token = torch.multinomial(probs, num_samples=1)

        # 5. 拼接到当前序列末尾，作为下一步的上下文输入
        tokens = torch.cat((tokens, next_token), dim=1)

    return tokens
```

在 `calc/calc/sample.py` 中，我们载入训练好的权重 `model.pt`，以换行符 `\n` 作为起始种子，启动生成：

```sh
make sample
```

### 真实采样结果鉴赏

在莎士比亚微型语料上仅仅训练 1,000 步（耗时约 17 秒）后，模型从最初毫无章法的随机字符噪声，涌现出了令人惊叹的结构感知力：

```text
First Citizen:
We are accounted poor citizens, the patricians good.
What authority surfeits on would relieve us: if they
would yield us but the superfluity, while it were
wholesome, we might guess they relieved us humanely;
but they think we are too dear: the leanness that
afflicts us, the object of our misery, is as an
inventory to particularise their abundance; our
sufferance is a gain to them.
```

观察模型学到的特征：

- 完美再现了剧本的人名开头与冒号结构（`First Citizen:`）；
- 掌握了英文动词过去式与分词搭配（`accounted`, `afflicts`, `relieved`）；
- 正确遵守了换行符与标点符号（逗号、句号、冒号）的使用节奏。

虽然这只是一个在单个 CPU 上几秒内训练出的小巧模型，但它所遵循的数学机理与今天参数量高达数百亿乃至数万亿的尖端大模型没有任何本质区别。

## 系列终章：回顾与远方的地平线

走到这里，我们已经从零开始、一行代码一块矩阵地搭建出了一个完整运行的生成式语言模型。

回顾我们的整段旅程：

1. **01 词元化与词表**：构建从字符、单词到现代 BPE 子词切分的离散数字字典，杜绝 OOV 崩溃；
2. **02 向量嵌入与位置编码**：建立连续高维几何空间，解构 `nn.Embedding` 物理本质，数学推导旋转位置编码（RoPE）；
3. **03 注意力机制与因果自注意力**：打破 RNN/CNN 物理枷锁，严格上三角掩码切断未来，揭秘点积方差缩放与多头注意力；
4. **04 解码器块与网络组装**：铺设 Pre-LN 残差高速公路，对比 RMSNorm 与 SwiGLU，完成深层网络的大一统装配；
5. **05 训练循环与优化动力学**：偏移切片挖掘海量自监督信号，解密 AdamW 解耦权重衰减、余弦退火与 bfloat16；
6. **06 文本生成与推理采样**：跑通自回归逐字生成，掌握温度缩放、Top-K/Top-P 截断、重复惩罚与 KV Cache 推理加速。

### 远方的地平线：后预训练时代（Post-Training）

完成预训练仅仅是大语言模型进化的第一阶段。一个刚刚走出预训练的模型，本质上是一个强大的“续写狂魔”——如果你向它提问 `"法国的首都是哪里？"`, 它很可能不会老实回答巴黎，而是继续续写出 `"德国的首都是哪里？意大利的首都是哪里？"`。

想要让它成为听懂人类意图、言行得体的助手，我们还需要迈向更宏大的工程领域：

- **指令微调（Supervised Fine-Tuning, SFT）**：教导模型从无约束续写转变为“问答对话”与“工具调用”范式；
- **人类偏好对齐（RLHF / DPO）**：利用强化学习与直接偏好优化，在安全、诚实与有用性之间锚定价值观；
- **推理期扩展（Test-Time Compute & Reasoning Scaling）**：以 DeepSeek-R1、OpenAI o1/o3 为代表的新范式，通过强化学习驱动思维链（Chain of Thought），开启逻辑推理深度探索的新纪元。

但无论上层的技术框架如何演化翻新，**底层的张量流动、自注意力交互与自监督优化动力学永远是这一切最坚实可靠的基石**。
