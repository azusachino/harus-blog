## Bytecode VMs 02: Stack vs Register Machine Architectures

When designing a virtual machine, the single most fundamental architectural choice is how instructions identify their operands. Every computation requires inputs and writes an output:

$$c = a + b$$

In hardware CPUs (such as x86-64 or ARM64), physical silicon registers (`rax`, `rbx`, `x0`, `x1`) hold operands. But inside software-emulated virtual machines running on host hardware, language runtimes diverge into two competing paradigms:

1. **Stack-Based Virtual Machines**: Operands reside on an evaluation stack. Instructions pop inputs from the top of the stack and push the result back.
2. **Register-Based Virtual Machines**: Operands reside in a virtual register file (a contiguous array of value slots). Instructions specify source and destination register indices directly.

Prominent real-world implementations reflect this architectural divide:

| Runtime | Architecture | Instruction Format | Typical Instruction Size |
|---|---|---|---|
| **CPython** (Python) | Stack-based | Opcode + 1-byte / 2-byte operand | 2 bytes (wordcode) |
| **HotSpot JVM** (Java) | Stack-based | Variable (0 to 4+ bytes) | 1 byte opcode + variable operands |
| **WebAssembly (Wasm)** | Stack-based | Variable LEB128 encodings | Structured byte stream |
| **Lua 5.0 - 5.4** | Register-based | Fixed 32-bit instruction words | 4 bytes (Opcode, A, B, C / Bx) |
| **Android Dalvik / ART** | Register-based | Sequences of 16-bit code units | 2 to 10 bytes |
| **LuaJIT** (bytecode) | Register-based | Fixed 32-bit instruction words | 4 bytes (8-bit opcode, A, B, C / D) |

---

### 1. The Stack-Based Model: Simplicity and Code Density

In a stack machine, intermediate values live on a Last-In, First-Out (LIFO) operand stack.

For the arithmetic expression `res = (a + b) * (c - d)`, a stack machine emits:

```text
LOAD_FAST    0  (a)      # Stack: [a]
LOAD_FAST    1  (b)      # Stack: [a, b]
BINARY_ADD   0           # Stack: [a + b]
LOAD_FAST    2  (c)      # Stack: [a + b, c]
LOAD_FAST    3  (d)      # Stack: [a + b, c, d]
BINARY_SUB   0           # Stack: [a + b, c - d]
BINARY_MUL   0           # Stack: [(a + b) * (c - d)]
STORE_FAST   4  (res)    # Stack: []
```

#### Advantages of Stack Machines

1. **High Code Density**: Because instruction operands are implicit (always `stack[top]` and `stack[top-1]`), instructions need not encode destination or source registers. An opcode like `BINARY_ADD` requires only a single byte.
2. **Trivial Compiler Frontend**: Generating stack bytecode from an AST requires nothing more than a standard depth-first, post-order recursive traversal. The compiler needs no register allocation algorithms, graph coloring, or live-range analysis.
3. **Hardware Independence**: The stack model assumes zero physical CPU registers, simplifying target portability.

#### Bottlenecks of Stack Machines

1. **Instruction Explosion**: Computing `(a + b) * (c - d)` required **8 separate bytecode instructions**.
2. **Memory Traffic (Stack Churn)**: Every computation involves repeated pushes and pops to memory (or C stack arrays). Even though the operand stack usually fits within CPU L1 cache, pointer increments, decrements, and memory writes create continuous pipeline dependencies.
3. **Dispatch Overhead Dominance**: In an interpreter, the cost of the decode-dispatch loop (fetching the opcode, branching to the handler, updating the program counter) frequently exceeds the cost of the actual computation (`a + b`). Having 8 instructions means paying the dispatch penalty 8 times.

---

### 2. The Register-Based Model: Eliminating Dispatch Overhead

Brought into mainstream scripting languages by Lua 5.0 (2003, Roberto Ierusalimschy and colleagues), register-based virtual machines replace the operand stack with an array of virtual registers, in Lua's case a window onto the per-call Lua stack.

In Lua's 3-address format (the layout of Lua 5.0 to 5.3; 5.4 moved to a 7-bit opcode with 8-bit B and C), instructions are fixed 32-bit words partitioned into bitfields:

```text
 31             23 22            14 13             6 5             0
+-----------------+----------------+----------------+---------------+
|     B (9 bits)  |   C (9 bits)   |   A (8 bits)   | Opcode (6 bit)|
+-----------------+----------------+----------------+---------------+
```

Where `A` is the destination register, and `B` and `C` are source register (or constant pool) indices.

For the exact same expression `res = (a + b) * (c - d)`, assuming variables `a, b, c, d` already reside in virtual registers `R0, R1, R2, R3`:

```text
ADD   R4, R0, R1    # R4 = a + b
SUB   R5, R2, R3    # R5 = c - d
MUL   R6, R4, R5    # res (R6) = R4 * R5
```

The register machine executes the computation in **3 instructions** rather than 8 (the stack version also pays for loading and storing the variables, so this assumes the operands are already in registers).

#### Advantages of Register Machines

1. **Drastically Fewer Dispatches**: The paper *Virtual Machine Showdown: Stack Versus Registers* (Shi et al., 2005) translated JVM stack bytecode into register bytecode and reported roughly 47% fewer executed VM instructions and an average speedup of about a quarter to a third, depending on the CPU. Treat the numbers as specific to that experiment: dispatch is a large cost in an interpreter, so cutting the instruction count by nearly half shows up in wall-clock time, though by less than half.
2. **Reduced Data Movement**: Intermediate temporary values are written directly to their target registers without redundant push/pop shuffling.
3. **Closer Match to Physical Hardware**: Modern CPU architectures (x86-64, AArch64) are register-based. A JIT compiler translating register-based bytecode to machine code has a much smaller semantic gap to bridge than one translating stack pushes and pops.

#### Trade-offs of Register Machines

1. **Larger Instruction Footprint**: Each instruction must encode operand identifiers (`A`, `B`, `C`), swelling individual instruction size from 1 or 2 bytes to 4 bytes.
2. **Complex Compiler**: The compiler must manage virtual register allocation, determining when temporary registers can be reused to avoid unbounded frame sizes.

### 3. Quantitative Architectural Comparison

Let us compare how both architectures execute the expression:

$$\text{output} = (v_1 \times v_2) + (v_3 \times v_4) - (v_5 \times v_6)$$

```text
Stack Machine (1-Address / 0-Address):
1.  LOAD_FAST   v1       Stack: [v1]
2.  LOAD_FAST   v2       Stack: [v1, v2]
3.  BINARY_MUL           Stack: [p1]
4.  LOAD_FAST   v3       Stack: [p1, v3]
5.  LOAD_FAST   v4       Stack: [p1, v3, v4]
6.  BINARY_MUL           Stack: [p1, p2]
7.  BINARY_ADD           Stack: [sum1]
8.  LOAD_FAST   v5       Stack: [sum1, v5]
9.  LOAD_FAST   v6       Stack: [sum1, v5, v6]
10. BINARY_MUL           Stack: [sum1, p3]
11. BINARY_SUB           Stack: [output]
12. STORE_FAST  output   Stack: []
Total Dispatches: 12

Register Machine (3-Address):
1.  MUL  R7, v1, v2      R7 = v1 * v2
2.  MUL  R8, v3, v4      R8 = v3 * v4
3.  ADD  R7, R7, R8      R7 = R7 + R8
4.  MUL  R8, v5, v6      R8 = v5 * v6
5.  SUB  output, R7, R8  output = R7 - R8
Total Dispatches: 5 (58.3% reduction in dispatch overhead; the lab below stores into `res` explicitly, giving 6)
```

### 4. Verification Lab: Dual-Architecture Simulator and Profiler

The following self-contained Python lab implements both a **Stack-Based Virtual Machine** and a **Register-Based Virtual Machine**. It compiles identical AST expressions into both instruction formats, executes them, and measures instruction dispatches and memory stack operations while verifying exact numeric equivalence.

```python
"""
Bytecode VMs Lab 02 - Stack vs Register Machine Architectures
Simulates and benchmarks identical arithmetic expressions under both models.
"""

from typing import List, Tuple, Dict, Any
from enum import Enum, auto

# -------------------------------------------------------------
# 1. Stack Machine Architecture
# -------------------------------------------------------------
class StackOp(Enum):
    LOAD_VAL = auto()
    BINARY_ADD = auto()
    BINARY_SUB = auto()
    BINARY_MUL = auto()
    STORE_VAL = auto()

class StackVM:
    def __init__(self, code: List[Tuple[StackOp, Any]]):
        self.code = code
        self.stack: List[float] = []
        self.environment: Dict[str, float] = {}
        # Metrics
        self.dispatch_count = 0
        self.stack_push_count = 0
        self.stack_pop_count = 0

    def push(self, val: float):
        self.stack.append(val)
        self.stack_push_count += 1

    def pop(self) -> float:
        self.stack_pop_count += 1
        return self.stack.pop()

    def run(self, initial_env: Dict[str, float]) -> Dict[str, float]:
        self.environment = dict(initial_env)
        pc = 0
        while pc < len(self.code):
            op, arg = self.code[pc]
            self.dispatch_count += 1
            pc += 1

            if op == StackOp.LOAD_VAL:
                val = self.environment[arg] if isinstance(arg, str) else float(arg)
                self.push(val)
            elif op == StackOp.BINARY_ADD:
                right = self.pop()
                left = self.pop()
                self.push(left + right)
            elif op == StackOp.BINARY_SUB:
                right = self.pop()
                left = self.pop()
                self.push(left - right)
            elif op == StackOp.BINARY_MUL:
                right = self.pop()
                left = self.pop()
                self.push(left * right)
            elif op == StackOp.STORE_VAL:
                val = self.pop()
                self.environment[arg] = val
        return self.environment

# -------------------------------------------------------------
# 2. Register Machine Architecture (3-Address)
# -------------------------------------------------------------
class RegOp(Enum):
    LOAD_IMM = auto()  # R[dst] = imm
    LOAD_VAR = auto()  # R[dst] = env[var]
    ADD = auto()       # R[dst] = R[src1] + R[src2]
    SUB = auto()       # R[dst] = R[src1] - R[src2]
    MUL = auto()       # R[dst] = R[src1] * R[src2]
    STORE_VAR = auto() # env[var] = R[src]

class RegisterVM:
    def __init__(self, code: List[Tuple[RegOp, Tuple]]):
        self.code = code
        self.registers: List[float] = [0.0] * 32
        self.environment: Dict[str, float] = {}
        # Metrics
        self.dispatch_count = 0
        self.register_reads = 0
        self.register_writes = 0

    def read_reg(self, idx: int) -> float:
        self.register_reads += 1
        return self.registers[idx]

    def write_reg(self, idx: int, val: float):
        self.register_writes += 1
        self.registers[idx] = val

    def run(self, initial_env: Dict[str, float]) -> Dict[str, float]:
        self.environment = dict(initial_env)
        pc = 0
        while pc < len(self.code):
            op, args = self.code[pc]
            self.dispatch_count += 1
            pc += 1

            if op == RegOp.LOAD_VAR:
                dst, var_name = args
                self.write_reg(dst, self.environment[var_name])
            elif op == RegOp.LOAD_IMM:
                dst, imm_val = args
                self.write_reg(dst, float(imm_val))
            elif op == RegOp.ADD:
                dst, s1, s2 = args
                self.write_reg(dst, self.read_reg(s1) + self.read_reg(s2))
            elif op == RegOp.SUB:
                dst, s1, s2 = args
                self.write_reg(dst, self.read_reg(s1) - self.read_reg(s2))
            elif op == RegOp.MUL:
                dst, s1, s2 = args
                self.write_reg(dst, self.read_reg(s1) * self.read_reg(s2))
            elif op == RegOp.STORE_VAR:
                src, var_name = args
                self.environment[var_name] = self.read_reg(src)
        return self.environment

def run_lab():
    # Program to evaluate:
    # res = (v1 * v2) + (v3 * v4) - (v5 * v6)
    inputs = {
        "v1": 3.0, "v2": 4.0,   # v1 * v2 = 12.0
        "v3": 5.0, "v4": 6.0,   # v3 * v4 = 30.0 (sum = 42.0)
        "v5": 7.0, "v6": 2.0    # v5 * v6 = 14.0 (res = 28.0)
    }

    # 1. Stack Machine Program
    stack_bytecode: List[Tuple[StackOp, Any]] = [
        (StackOp.LOAD_VAL, "v1"),
        (StackOp.LOAD_VAL, "v2"),
        (StackOp.BINARY_MUL, None),
        (StackOp.LOAD_VAL, "v3"),
        (StackOp.LOAD_VAL, "v4"),
        (StackOp.BINARY_MUL, None),
        (StackOp.BINARY_ADD, None),
        (StackOp.LOAD_VAL, "v5"),
        (StackOp.LOAD_VAL, "v6"),
        (StackOp.BINARY_MUL, None),
        (StackOp.BINARY_SUB, None),
        (StackOp.STORE_VAL, "res"),
    ]

    stack_vm = StackVM(stack_bytecode)
    stack_result = stack_vm.run(inputs)
    assert stack_result["res"] == 28.0
    assert stack_vm.dispatch_count == 12
    assert stack_vm.stack_push_count == 11
    assert stack_vm.stack_pop_count == 11

    # 2. Register Machine Program
    # Map: R0=v1, R1=v2, R2=v3, R3=v4, R4=v5, R5=v6, R6=temp1, R7=temp2
    reg_bytecode: List[Tuple[RegOp, Tuple]] = [
        (RegOp.LOAD_VAR, (0, "v1")),
        (RegOp.LOAD_VAR, (1, "v2")),
        (RegOp.LOAD_VAR, (2, "v3")),
        (RegOp.LOAD_VAR, (3, "v4")),
        (RegOp.LOAD_VAR, (4, "v5")),
        (RegOp.LOAD_VAR, (5, "v6")),
        (RegOp.MUL, (6, 0, 1)),       # R6 = v1 * v2 = 12
        (RegOp.MUL, (7, 2, 3)),       # R7 = v3 * v4 = 30
        (RegOp.ADD, (6, 6, 7)),       # R6 = 12 + 30 = 42
        (RegOp.MUL, (7, 4, 5)),       # R7 = v5 * v6 = 14
        (RegOp.SUB, (6, 6, 7)),       # R6 = 42 - 14 = 28
        (RegOp.STORE_VAR, (6, "res")),
    ]

    reg_vm = RegisterVM(reg_bytecode)
    reg_result = reg_vm.run(inputs)
    assert reg_result["res"] == 28.0

    # If variables are already in registers (e.g. function call argument frame):
    compute_only_reg_code: List[Tuple[RegOp, Tuple]] = [
        (RegOp.MUL, (6, 0, 1)),       # R6 = v1 * v2 = 12
        (RegOp.MUL, (7, 2, 3)),       # R7 = v3 * v4 = 30
        (RegOp.ADD, (6, 6, 7)),       # R6 = 12 + 30 = 42
        (RegOp.MUL, (7, 4, 5)),       # R7 = v5 * v6 = 14
        (RegOp.SUB, (6, 6, 7)),       # R6 = 42 - 14 = 28
        (RegOp.STORE_VAR, (6, "res")),
    ]
    pure_compute_vm = RegisterVM(compute_only_reg_code)
    # Preload registers 0..5
    for i, k in enumerate(["v1", "v2", "v3", "v4", "v5", "v6"]):
        pure_compute_vm.registers[i] = inputs[k]
    pure_compute_result = pure_compute_vm.run(inputs)
    assert pure_compute_result["res"] == 28.0
    assert pure_compute_vm.dispatch_count == 6  # 50% fewer dispatches than stack VM

    print(f"Stack VM Dispatches: {stack_vm.dispatch_count}, Stack Ops: {stack_vm.stack_push_count + stack_vm.stack_pop_count}")
    print(f"Register VM Dispatches: {pure_compute_vm.dispatch_count}, Reg Writes: {pure_compute_vm.register_writes}")
    print("Bytecode VM Lab 02 passed: Dual-architecture stack vs register simulation verified.")

if __name__ == "__main__":
    run_lab()
```
