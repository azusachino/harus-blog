## Bytecode VMs 06: Memory Management and Garbage Collection in Dynamic Runtimes

In low-level systems programming languages like C, C++, and Rust, memory management is explicit or governed by compile-time lifetimes. In dynamic virtual machines (Python, JavaScript, Ruby, Lua, Java), developers create millions of transient objects without manual `free()` or `delete` calls. The virtual machine must automatically reclaim unreachable memory while preventing memory leaks, dangling pointers, and long Stop-The-World (STW) pauses.

Modern runtimes achieve this through two broad methodologies:

1. **Reference Counting**: Tracks how many active pointers reference each object, deallocating the memory immediately when the count reaches zero.
2. **Tracing Garbage Collection**: Periodically discovers reachable objects by traversing the object graph starting from a root set (global variables, call stack frames, CPU registers), sweeping away unreachable blocks.

Many high-performance runtimes combine both: CPython and PHP use reference counting as the primary immediate collector, backed by a **Cyclic Garbage Collector** using trial deletion to clean up circular reference cycles.

---

### 1. Reference Counting: Strengths and the Fatal Flaw

In reference counting, every object header embeds a counter (`ob_refcnt`):

- When a variable or container references an object: `Py_INCREF(op)` increments the counter.
- When a variable goes out of scope or is reassigned: `Py_DECREF(op)` decrements the counter.
- When `ob_refcnt == 0`: The object is deallocated immediately.

#### Strengths of Reference Counting

1. **Deterministic Finalization**: Memory is freed the exact microsecond the last reference drops. Resource cleanup (closing file descriptors, releasing network sockets, unlocking mutexes) happens immediately without waiting for a periodic GC pass.
2. **Smooth, Pause-Free Execution**: Because reclamation occurs incrementally across normal opcode execution, there are no unpredictable, multi-millisecond Stop-The-World pauses.

#### The Fatal Flaw: Circular References

Consider two objects pointing to one another:

```text
Node A (refcnt: 1) ──next──► Node B (refcnt: 1)
       ▲                             │
       └────────────prev─────────────┘
```

If the external variables pointing to `Node A` and `Node B` are deleted:

```text
del a
del b
```

Their reference counts drop from 2 to 1, **not zero**. Both nodes are completely unreachable from any variable in the program, yet they will never be freed by reference counting alone. In long-running servers, uncollected cyclic graphs cause memory to leak indefinitely.

### 2. Tracing Collectors: Mark-and-Sweep vs Copying

Tracing collectors ignore reference counters entirely and determine liveness via **graph reachability**:

#### Mark-and-Sweep

1. **Root Set Enumeration**: Pause user mutator threads and assemble the root set: global variables, local variables on all call frames, and runtime constants.
2. **Mark Phase**: Traverse the object graph starting from roots, setting a `marked` bit on every reached object.
3. **Sweep Phase**: Iterate over the entire heap. Reclaim all objects whose `marked` bit is 0; reset the `marked` bit to 0 for surviving objects.

*Disadvantage*: Can leave the heap fragmented, requiring free-list searching for subsequent allocations.

#### Cheney's Copying Collector (Semi-Space)

The heap is divided into two halves: **From-Space** and **To-Space**:

1. When From-Space fills up, the collector copies all live reachable objects contiguously into To-Space.
2. Object pointers are forwarded to their new addresses.
3. The entire From-Space is cleared in a single operation.

*Advantage*: Eliminates memory fragmentation and enables ultra-fast bump allocation (`ptr += size`), used extensively in the young generation of JVM collectors (Eden space).

### 3. CPython's Generational Cyclic GC: The Trial Deletion Algorithm

To resolve reference cycles without abandoning the latency benefits of immediate reference counting, CPython implements a **Generational Cyclic Garbage Collector** (`Modules/gcmodule.c`).

Every container object that can hold references to other objects (`list`, `dict`, `tuple`, `set`, custom class instances) is prefixed with a `PyGC_Head` struct and linked into a doubly-linked ring:

```c
typedef struct {
    uintptr_t _gc_next;
    uintptr_t _gc_prev;
} PyGC_Head;
```

#### The 3 Generations

Objects are partitioned into three generations based on survival age:

- **Generation 0**: Newly allocated container objects. Collected frequently (e.g. after every 700 net allocations).
- **Generation 1**: Objects that survived at least one Gen 0 collection.
- **Generation 2**: Long-lived objects (e.g. global singletons, module configurations). Collected infrequently.

#### The Trial Deletion Algorithm (Four Steps)

When Generation 0 exceeds its allocation threshold, the cyclic collector runs a four-step trial deletion pass over the candidate list:

1. **Step 1: Copy Reference Counts (`update_refs`)**
   For every candidate object in the collection ring, copy its real `ob_refcnt` into a temporary trial field `gc_refs`:
   $$\text{gc\_refs} = \text{ob\_refcnt}$$

2. **Step 2: Subtract Internal References (`subtract_refs`)**
   For every candidate object in the ring, invoke its traversal hook (`tp_traverse`). For every child object referenced by the container that also belongs to the candidate ring, **decrement the child's `gc_refs` by 1**:
   $$\text{child}->\text{gc\_refs} -= 1$$
   *Crucial Insight*: If an isolated group of objects only reference each other (a circular cycle), their `gc_refs` will all drop to exactly zero, because every single reference came from inside the cycle!

3. **Step 3: Rescue Reachable Objects (`move_unreachable`)**
   Any object whose `gc_refs > 0` has at least one reference originating from *outside* the candidate ring (e.g. a local variable on the call stack or a global variable).
   These objects are **true roots**. The collector marks them as reachable and transitively visits all their children, restoring their `gc_refs` and rescuing them from collection.

4. **Step 4: Reclaim the Garbage (`delete_garbage`)**
   Any objects that still have `gc_refs == 0` after the rescue pass are genuine unreachable cycles. The collector breaks their reference cycles (`tp_clear`) and immediately frees their memory.

### 4. Verification Lab: Dual Reference Counting & Cyclic GC Simulator

The following self-contained Python lab implements a complete memory manager:

- Direct **Reference Counting** (`incref` / `decref`) with immediate deallocation of acyclic objects.
- A doubly-linked **Candidate Tracking Pool**.
- The exact **Trial Deletion Algorithm** (`subtract_refs`, `rescue_external_roots`, and `collect_cycles`), proving that isolated circular structures are detected and collected while externally reachable graphs are preserved.

```python
"""
Bytecode VMs Lab 06 - Reference Counting and Generational Cyclic GC
Tests immediate reclamation of acyclic objects and trial-deletion cyclic collection.
"""

from typing import List, Dict, Set, Optional, Any

class GCObject:
    _id_counter = 0

    def __init__(self, name: str):
        GCObject._id_counter += 1
        self.obj_id = GCObject._id_counter
        self.name = name
        self.refcnt = 0
        self.gc_refs = 0
        # Outgoing pointers to other GC objects
        self.references: List['GCObject'] = []
        self.is_alive = True

    def add_reference(self, other: 'GCObject'):
        self.references.append(other)
        other.refcnt += 1

    def __repr__(self):
        return f"GCObject({self.name}, id={self.obj_id}, refcnt={self.refcnt})"

class MemoryManager:
    def __init__(self):
        # All tracked container objects
        self.tracked_objects: Set[GCObject] = set()
        # External roots (active variables on call frames, globals)
        self.external_roots: Set[GCObject] = set()
        # Metrics
        self.immediate_freed = 0
        self.cyclic_freed = 0

    def allocate(self, name: str) -> GCObject:
        obj = GCObject(name)
        self.tracked_objects.add(obj)
        return obj

    def add_root(self, obj: GCObject):
        if obj not in self.external_roots:
            self.external_roots.add(obj)
            obj.refcnt += 1

    def remove_root(self, obj: GCObject):
        if obj in self.external_roots:
            self.external_roots.remove(obj)
            self.decref(obj)

    def incref(self, obj: GCObject):
        obj.refcnt += 1

    def decref(self, obj: GCObject):
        obj.refcnt -= 1
        if obj.refcnt == 0:
            self._immediate_deallocate(obj)

    def _immediate_deallocate(self, obj: GCObject):
        obj.is_alive = False
        self.immediate_freed += 1
        if obj in self.tracked_objects:
            self.tracked_objects.remove(obj)
        # Recursively decref outgoing references
        for child in obj.references:
            self.decref(child)
        obj.references.clear()

    # -------------------------------------------------------------
    # CPython Trial Deletion Algorithm for Cyclic GC
    # -------------------------------------------------------------
    def collect_cyclic_garbage(self) -> int:
        if not self.tracked_objects:
            return 0

        # Step 1: Copy actual refcnt into trial gc_refs
        for obj in self.tracked_objects:
            obj.gc_refs = obj.refcnt

        # Step 2: Subtract internal references (subtract_refs)
        for obj in self.tracked_objects:
            for child in obj.references:
                if child in self.tracked_objects:
                    child.gc_refs -= 1

        # Step 3: Rescue objects reachable from external roots
        unreachable: Set[GCObject] = set()
        reachable: Set[GCObject] = set()

        # Partition based on trial gc_refs
        for obj in self.tracked_objects:
            if obj.gc_refs > 0:
                reachable.add(obj)
            else:
                unreachable.add(obj)

        # Transitive rescue: if any object in reachable points to an unreachable object,
        # that unreachable object is rescued!
        rescue_queue = list(reachable)
        while rescue_queue:
            curr = rescue_queue.pop()
            for child in curr.references:
                if child in unreachable:
                    unreachable.remove(child)
                    reachable.add(child)
                    rescue_queue.append(child)

        # Step 4: Reclaim unreachable cycles
        freed_count = len(unreachable)
        for dead in list(unreachable):
            dead.is_alive = False
            self.tracked_objects.remove(dead)
            self.cyclic_freed += 1
            # Break references to avoid dangling memory
            dead.references.clear()

        return freed_count

def run_lab():
    mm = MemoryManager()

    # -------------------------------------------------------------
    # Test 1: Immediate Reference Counting (Acyclic Graph)
    # Root -> NodeA -> NodeB -> NodeC
    # -------------------------------------------------------------
    node_a = mm.allocate("A")
    node_b = mm.allocate("B")
    node_c = mm.allocate("C")

    mm.add_root(node_a)
    node_a.add_reference(node_b)
    node_b.add_reference(node_c)

    assert node_a.refcnt == 1  # 1 from root
    assert node_b.refcnt == 1  # 1 from A
    assert node_c.refcnt == 1  # 1 from B

    # Dropping root should trigger immediate cascade deallocation of A, B, and C
    mm.remove_root(node_a)
    assert not node_a.is_alive
    assert not node_b.is_alive
    assert not node_c.is_alive
    assert mm.immediate_freed == 3
    assert len(mm.tracked_objects) == 0

    # -------------------------------------------------------------
    # Test 2: Cyclic Reference Isolated Island
    # Root -> Cycle1 <-> Cycle2
    # -------------------------------------------------------------
    c1 = mm.allocate("Cycle1")
    c2 = mm.allocate("Cycle2")

    mm.add_root(c1)
    c1.add_reference(c2)
    c2.add_reference(c1)

    assert c1.refcnt == 2  # 1 from root + 1 from c2
    assert c2.refcnt == 1  # 1 from c1

    # Remove root: c1.refcnt becomes 1, c2.refcnt remains 1
    # Both are > 0, so immediate ref counting CANNOT free them!
    mm.remove_root(c1)
    assert c1.is_alive and c1.refcnt == 1
    assert c2.is_alive and c2.refcnt == 1
    assert len(mm.tracked_objects) == 2

    # Run Cyclic GC: trial deletion detects isolated cycle and reclaims both!
    reclaimed = mm.collect_cyclic_garbage()
    assert reclaimed == 2
    assert not c1.is_alive
    assert not c2.is_alive
    assert mm.cyclic_freed == 2
    assert len(mm.tracked_objects) == 0

    # -------------------------------------------------------------
    # Test 3: Complex Graph with Cycle Reachable from Active Root
    # Root -> LiveNode -> CycleA <-> CycleB
    # -------------------------------------------------------------
    live_root = mm.allocate("LiveRoot")
    mm.add_root(live_root)

    cycle_a = mm.allocate("CycleA")
    cycle_b = mm.allocate("CycleB")

    live_root.add_reference(cycle_a)
    cycle_a.add_reference(cycle_b)
    cycle_b.add_reference(cycle_a)

    # In trial deletion:
    # cycle_a.gc_refs = 2 - 1 = 1 (1 incoming from live_root!)
    # cycle_b.gc_refs = 1 - 1 = 0
    # Because cycle_a is reachable (gc_refs > 0), it rescues cycle_b!
    reclaimed = mm.collect_cyclic_garbage()
    assert reclaimed == 0  # Nothing should be freed
    assert live_root.is_alive
    assert cycle_a.is_alive
    assert cycle_b.is_alive

    # Now drop the external root:
    mm.remove_root(live_root)
    # live_root freed immediately; cycle_a and cycle_b now form an isolated island
    assert not live_root.is_alive
    assert cycle_a.is_alive and cycle_b.is_alive

    # Next cyclic GC pass sweeps the orphaned cycle
    reclaimed = mm.collect_cyclic_garbage()
    assert reclaimed == 2
    assert not cycle_a.is_alive
    assert not cycle_b.is_alive

    print(f"Immediate Ref Counting Freed: {mm.immediate_freed} acyclic objects")
    print(f"Cyclic GC Trial Deletion Freed: {mm.cyclic_freed} cyclic objects")
    print("Bytecode VM Lab 06 passed: Reference counting and cyclic GC verified.")

if __name__ == "__main__":
    run_lab()
```
