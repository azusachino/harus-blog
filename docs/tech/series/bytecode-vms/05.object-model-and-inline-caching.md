## Bytecode VMs 05: Object Model, Dynamic Typing, and Inline Caching

Dynamic programming languages (Python, JavaScript, Ruby, Lua) grant developers immense expressive power: variables have no static type annotations, objects can dynamically gain new attributes at runtime, and methods can be monkey-patched on the fly:

```text
point.x = 10
point.y = 20
point.color = "blue"
```

Yet this flexibility poses a severe performance crisis for virtual machine implementers. In a statically typed compiled language like C++ or Rust, accessing `point.x` compiles to a single CPU memory read at a compile-time fixed offset (`mov eax, [rdi + 0]`). In a naive dynamic runtime, accessing `point.x` requires hashing the string `"x"`, probing `point`'s internal dictionary, checking the object's class dictionary, and recursively traversing the Method Resolution Order (MRO).

If every property access incurred a full hash table search, dynamic languages would run 50 to 100 times slower than C. The mechanisms that close this gap are **Hidden Classes (Shapes)** and **Inline Caching (IC)**.

---

### 1. Value Representation in Memory

Before an interpreter can operate on an object, it must represent the value in memory. Runtimes employ three primary value representations:

#### 1. Uniform Pointer Boxing (CPython)

Every value—even a simple integer like `42`—is a heap-allocated struct prefixed with a standard object header:

```text
CPython PyObject (16 bytes minimum on 64-bit systems):
+---------------------------------------+
|  ob_refcnt (8 bytes: reference count) |
+---------------------------------------+
|  ob_type   (8 bytes: pointer to Type) |
+---------------------------------------+
|  payload... (e.g. 8 bytes for long)   |
+---------------------------------------+
```

While uniform and simple, boxing every integer introduces massive pointer dereferencing and cache bloat.

#### 2. Pointer Tagging (Ruby MRI, OCaml, V8 Smis)

Because heap memory addresses on 64-bit architectures are aligned to 8-byte boundaries, the least significant 3 bits of any valid heap pointer are always `000`. Runtimes take advantage of these unused bits:

- If the lowest bit is `1`, the word is not a pointer at all; the remaining 63 bits are treated as an unboxed **Small Integer (Smi)**.
- If the lowest bit is `0`, it is a true heap pointer.

Arithmetic on small integers requires only bit-shifting, completely eliminating heap allocation.

#### 3. NaN-Boxing (LuaJIT, JavaScriptCore SpiderMonkey)

According to the IEEE-754 double-precision floating-point specification, any 64-bit word where bits 62..52 are all `1` and the mantissa is non-zero represents a **Quiet NaN (Not-a-Number)**:

```text
 63 62         52 51 48 47                                     0
+--+-------------+-----+----------------------------------------+
|S | 11111111111 | Tag | Payload (48-bit canonical pointer)     |
+--+-------------+-----+----------------------------------------+
```

Because 64-bit pointers on modern operating systems only use the lower 48 bits of virtual address space, a single 64-bit `uint64_t` can represent:

- Any double-precision float natively.
- Any 48-bit object pointer with a specific tag.
- Booleans, integers, and null with dedicated tag patterns.

All values fit into a single CPU register, drastically improving memory locality and register allocation.

### 2. From Dictionaries to Shapes (Hidden Classes)

If an object stores its attributes inside a hash table dictionary (`obj.__dict__`), memory overhead is enormous (hundreds of bytes per instance) and lookup latency is high.

Invented by the Self VM team and popularized by Lars Bak in V8, **Shapes** (also known as *Hidden Classes* or *Maps*) decouple an object's schema from its values:

1. **Shape**: An immutable descriptor representing the transition graph of field names to slot indices:

   ```text
   Shape 0 (Empty) ──+ 'x'──► Shape 1 (x: slot 0) ──+ 'y'──► Shape 2 (x: slot 0, y: slot 1)
   ```

2. **Instance**: Contains only a pointer to its current `Shape` and a contiguous array of values:

   ```text
   Point Instance:
   [ Shape* ──► Shape 2 ]
   [ slots: [ 10.0, 20.0 ] ]
   ```

Two thousand `Point` objects with properties `x` and `y` all share the exact same `Shape 2` descriptor. Their properties reside at fixed array indices (`slot 0` and `slot 1`).

---

### 3. Inline Caching (IC) Mechanics

Even with shapes, looking up which slot holds property `"x"` still requires checking the shape descriptor. **Inline Caching** eliminates even this check by caching the result directly at the bytecode callsite.

<Archify src="./diagrams/inline-cache-lookup-waterfall.workflow.json" />

An inline cache progresses through three operational states:

#### State 1: Uninitialized (Cold)

The bytecode instruction `LOAD_ATTR 'x'` begins in an uninitialized state. When executed for the first time, it drops into the slow path: it resolves `"x"` via shape descriptor traversal, finds that `"x"` lives at `slot 0`, and caches:

- `cached_shape = receiver->shape`
- `cached_slot = 0`

#### State 2: Monomorphic (Fast Path)

On subsequent executions, the callsite executes a **Shape Guard**:

```c
if (receiver->shape == ic->cached_shape) {
    // 1 CPU instruction: direct array load!
    return receiver->slots[ic->cached_slot];
}
```

If the incoming object has the same shape, property access executes in a single clock cycle without string hashing or dictionary traversal. In real-world software, **over 90% of all call sites are strictly monomorphic**.

#### State 3: Polymorphic & Megamorphic

If an object with a different shape arrives at the callsite (e.g. `Point2D` vs `Point3D`), the monomorphic cache misses.

- **Polymorphic (2 to 4 Shapes)**: The IC expands into a small linear table of `(shape, slot)` pairs.
- **Megamorphic (> 4 Shapes)**: If the callsite observes too many distinct shapes, maintaining the cache table becomes slower than a general lookup. The callsite transitions to megamorphic, abandoning caching and falling back to a global hash dictionary.

### 4. Verification Lab: Shapes and Inline Cache Simulator

The following self-contained Python lab implements a complete shape-based object model with monomorphic, polymorphic, and megamorphic inline caching. It executes property lookups across distinct object populations, verifies shape transitions, and measures exact cache hit rates.

```python
"""
Bytecode VMs Lab 05 - Object Model, Shapes, and Inline Caching
Tests shape transitions, monomorphic/polymorphic IC hit rates, and megamorphic fallback.
"""

from typing import Dict, List, Optional, Tuple, Any

# -------------------------------------------------------------
# 1. Shapes (Hidden Classes)
# -------------------------------------------------------------
class Shape:
    _id_counter = 0

    def __init__(self, parent: Optional['Shape'] = None, property_name: Optional[str] = None):
        Shape._id_counter += 1
        self.shape_id = Shape._id_counter
        self.parent = parent
        self.property_name = property_name
        self.transitions: Dict[str, Shape] = {}
        # Mapping of property name to fixed array slot offset
        self.slots: Dict[str, int] = {}
        if parent:
            self.slots = dict(parent.slots)
            if property_name is not None:
                self.slots[property_name] = len(parent.slots)

    def transition(self, prop: str) -> 'Shape':
        if prop in self.transitions:
            return self.transitions[prop]
        new_shape = Shape(parent=self, property_name=prop)
        self.transitions[prop] = new_shape
        return new_shape

ROOT_SHAPE = Shape()

class DynamicObject:
    def __init__(self):
        self.shape: Shape = ROOT_SHAPE
        self.slots: List[Any] = []

    def set_property(self, name: str, value: Any):
        if name in self.shape.slots:
            slot_idx = self.shape.slots[name]
            self.slots[slot_idx] = value
        else:
            # Transition to next shape
            new_shape = self.shape.transition(name)
            self.shape = new_shape
            self.slots.append(value)

# -------------------------------------------------------------
# 2. Inline Cache (IC) Implementation
# -------------------------------------------------------------
class InlineCacheState:
    UNINITIALIZED = "UNINITIALIZED"
    MONOMORPHIC = "MONOMORPHIC"
    POLYMORPHIC = "POLYMORPHIC"
    MEGAMORPHIC = "MEGAMORPHIC"

class InlineCache:
    MAX_POLYMORPHIC_ENTRIES = 3

    def __init__(self, property_name: str):
        self.property_name = property_name
        self.state = InlineCacheState.UNINITIALIZED
        # Cache entries: list of (shape_id, slot_offset)
        self.entries: List[Tuple[int, int]] = []
        # Metrics
        self.hits = 0
        self.misses = 0

    def load_property(self, obj: DynamicObject) -> Any:
        obj_shape_id = obj.shape.shape_id

        # 1. Monomorphic Fast Path
        if self.state == InlineCacheState.MONOMORPHIC:
            cached_shape_id, slot_offset = self.entries[0]
            if obj_shape_id == cached_shape_id:
                self.hits += 1
                return obj.slots[slot_offset]
            # Cache miss: fall through to slow path / state expansion
            self.misses += 1

        # 2. Polymorphic Table Scan
        elif self.state == InlineCacheState.POLYMORPHIC:
            for cached_shape_id, slot_offset in self.entries:
                if obj_shape_id == cached_shape_id:
                    self.hits += 1
                    return obj.slots[slot_offset]
            # Miss: fall through
            self.misses += 1

        # 3. Megamorphic or Uninitialized
        elif self.state == InlineCacheState.MEGAMORPHIC:
            self.misses += 1
            # Direct shape slot lookup without caching new entries
            if self.property_name in obj.shape.slots:
                return obj.slots[obj.shape.slots[self.property_name]]
            raise AttributeError(f"Object has no property {self.property_name!r}")
        else:
            # UNINITIALIZED
            self.misses += 1

        # ---------------------------------------------------------
        # Slow Path: Resolve property from shape and update IC
        # ---------------------------------------------------------
        if self.property_name not in obj.shape.slots:
            raise AttributeError(f"Object has no property {self.property_name!r}")
        slot_offset = obj.shape.slots[self.property_name]

        if self.state == InlineCacheState.UNINITIALIZED:
            self.entries.append((obj_shape_id, slot_offset))
            self.state = InlineCacheState.MONOMORPHIC
        elif self.state == InlineCacheState.MONOMORPHIC:
            self.entries.append((obj_shape_id, slot_offset))
            self.state = InlineCacheState.POLYMORPHIC
        elif self.state == InlineCacheState.POLYMORPHIC:
            if len(self.entries) < self.MAX_POLYMORPHIC_ENTRIES:
                self.entries.append((obj_shape_id, slot_offset))
            else:
                self.state = InlineCacheState.MEGAMORPHIC
                self.entries.clear()

        return obj.slots[slot_offset]

def run_lab():
    # -------------------------------------------------------------
    # Test 1: Shape Identity Sharing
    # -------------------------------------------------------------
    p1 = DynamicObject()
    p1.set_property("x", 10)
    p1.set_property("y", 20)

    p2 = DynamicObject()
    p2.set_property("x", 100)
    p2.set_property("y", 200)

    # Both objects transitioned along the same path: ROOT -> x -> y
    assert p1.shape is p2.shape
    assert p1.shape.slots == {"x": 0, "y": 1}
    assert p1.slots == [10, 20]
    assert p2.slots == [100, 200]

    # -------------------------------------------------------------
    # Test 2: Monomorphic Inline Cache Hit Rate
    # Accessing p.x on 10,000 instances sharing identical shape
    # -------------------------------------------------------------
    ic_mono = InlineCache("x")
    instances = []
    for i in range(1000):
        obj = DynamicObject()
        obj.set_property("x", i)
        obj.set_property("y", i * 2)
        instances.append(obj)

    # First access causes cold miss and promotes to MONOMORPHIC
    val0 = ic_mono.load_property(instances[0])
    assert val0 == 0
    assert ic_mono.state == InlineCacheState.MONOMORPHIC
    assert ic_mono.misses == 1
    assert ic_mono.hits == 0

    # Remaining 999 accesses hit the monomorphic fast path
    for i in range(1, 1000):
        val = ic_mono.load_property(instances[i])
        assert val == i

    assert ic_mono.hits == 999
    assert ic_mono.misses == 1
    hit_rate = ic_mono.hits / (ic_mono.hits + ic_mono.misses)
    assert hit_rate > 0.998  # 99.9% hit rate

    # -------------------------------------------------------------
    # Test 3: Polymorphic Cache Transition
    # Alternating between 2 distinct shapes: Point2D(x, y) and Point3D(z, x, y)
    # -------------------------------------------------------------
    ic_poly = InlineCache("x")
    # Shape A: (x: 0, y: 1)
    obj_a = DynamicObject()
    obj_a.set_property("x", 42)
    obj_a.set_property("y", 99)

    # Shape B: (z: 0, x: 1) -> property 'x' is at slot 1, not slot 0!
    obj_b = DynamicObject()
    obj_b.set_property("z", 7)
    obj_b.set_property("x", 84)

    assert obj_a.shape is not obj_b.shape
    assert obj_a.shape.slots["x"] == 0
    assert obj_b.shape.slots["x"] == 1

    # Access alternating shapes
    for _ in range(500):
        assert ic_poly.load_property(obj_a) == 42
        assert ic_poly.load_property(obj_b) == 84

    assert ic_poly.state == InlineCacheState.POLYMORPHIC
    assert len(ic_poly.entries) == 2
    # Misses should be exactly 2 (initial cold miss for obj_a, then miss for obj_b)
    assert ic_poly.misses == 2
    assert ic_poly.hits == 998

    # -------------------------------------------------------------
    # Test 4: Megamorphic Fallback
    # Flooding with 5 distinct shapes exceeds MAX_POLYMORPHIC_ENTRIES (3)
    # -------------------------------------------------------------
    for extra_idx in range(5):
        obj_extra = DynamicObject()
        obj_extra.set_property(f"prop_{extra_idx}", extra_idx)
        obj_extra.set_property("x", 1000 + extra_idx)
        val = ic_poly.load_property(obj_extra)
        assert val == 1000 + extra_idx

    assert ic_poly.state == InlineCacheState.MEGAMORPHIC
    assert len(ic_poly.entries) == 0  # Cache flushed in megamorphic mode

    print(f"Monomorphic IC Hit Rate: {hit_rate * 100:.2f}% (999 hits / 1 miss)")
    print(f"Polymorphic IC handled 2 distinct shapes successfully ({ic_poly.hits} hits)")
    print(f"Megamorphic fallback triggered after shape overflow")
    print("Bytecode VM Lab 05 passed: Shapes and Inline Caching verified.")

if __name__ == "__main__":
    run_lab()
```
