## Before you start

When you write `class Bag: def __len__(self): return 3` and call `len(Bag())`, Python gets 3. But a built-in list has no Python-level `__len__` function running anywhere, and `len` is fast on it. Both cases go through the same C entry point. This chapter explains how: each type carries a table of C function pointers, and for classes written in Python the interpreter fills in a small C wrapper that looks up your `__len__` and calls it.

One consequence surprises people. `len(x)` ignores a `__len__` you assign on the instance, because C consults the type, not the instance.

Read [chapter 01](/tech/series/cpython-internals/01.map-and-len/) first, where `PyObject_Size` reads a function pointer from the object's type.

Terms used in this chapter:

- **dunder method**: a method with double underscores on both sides, like `__len__` or `__add__`, that Python calls for built-in syntax.
- **type slot**: a field in a type's C struct holding a function pointer, such as `sq_length`.
- **function pointer**: a C variable that holds the address of a function, so the function can be chosen at run time.
- **slotdefs**: the table in `Objects/typeobject.c` that pairs each dunder name with its slot.
- **wrapper**: a small function that adapts one calling convention to another, here C slot to Python method and back.
- **instance `__dict__`**: the per-object dictionary of attributes; special-method lookup by C skips it.

## CPython Internals 03: Connecting Python Dunder Methods to C Type Slots

In Chapter 01, we saw how `PyObject_Size(o)` in `Objects/abstract.c` computes `len(o)` by reading a C function pointer from the object's type:

```c
PySequenceMethods *m = Py_TYPE(o)->tp_as_sequence;
if (m && m->sq_length) {
    Py_ssize_t len = m->sq_length(o);
    return len;
}
```

For a built-in `list`, `m->sq_length` points directly to the C function `list_length`.

Wait: what happens when you write a **pure-Python class** with `def __len__(self):`? You didn't write a C function returning `Py_ssize_t`, yet `PyObject_Size(o)` executes the **exact same C code** (`m->sq_length(o)`)! How does a Python method written with `def` turn into a C function pointer stored inside `tp_as_sequence->sq_length`?

---

### 1. The Bridge in `Objects/typeobject.c`: `slotdefs` and `slot_sq_length`

When Python executes a `class Box:` block, the `type` metaclass (`type_new` in `Objects/typeobject.c`) allocates a new heap type (`PyHeapTypeObject`, which embeds `PyTypeObject` plus the sub-tables `PyNumberMethods`, `PySequenceMethods`, `PyMappingMethods`, etc.) and scans the class namespace for special dunder names (`__len__`, `__getitem__`, `__add__`, `__repr__`).

#### 1.1 The Master Mapping Table (`slotdefs` in `Objects/typeobject.c`)

Inside `Objects/typeobject.c`, a static table named `slotdefs` maps every dunder attribute name to:

1. Its target C slot offset inside `PyTypeObject` (or its sub-tables `tp_as_sequence` / `tp_as_mapping`).
2. A **C trampoline function** (`slot_*`) whose signature matches the C slot (`Py_ssize_t (*lenfunc)(PyObject *)`) and whose body invokes the Python method!

```c
/* Objects/typeobject.c */
    MPSLOT(__len__, mp_length, slot_mp_length, wrap_lenfunc,
           "__len__($self, /)\n--\n\nReturn len(self)."),
    /* ... */
    SQSLOT(__len__, sq_length, slot_sq_length, wrap_lenfunc,
           "__len__($self, /)\n--\n\nReturn len(self)."),
```

When `Box` defines `def __len__(self):`, `update_one_slot()` in `Objects/typeobject.c` sees `"__len__"` in `Box.__dict__` and writes the C function pointer **`slot_sq_length`** into `Box.tp_as_sequence->sq_length` (and `slot_mp_length` into `Box.tp_as_mapping->mp_length`)!

```text
Built-in Type (list)                          User-Defined Python Class (class Box)
┌───────────────────────────────┐             ┌───────────────────────────────────┐
│ PyList_Type                   │             │ Box (PyHeapTypeObject)            │
│   tp_as_sequence              │             │   tp_as_sequence                  │
│     └── sq_length ────────────┼──┐          │     └── sq_length ────────────────┼──┐
└───────────────────────────────┘  │          └───────────────────────────────────┘  │
                                   ▼                                                 ▼
                        ┌─────────────────────┐                           ┌─────────────────────┐
                        │ C: list_length(a)   │                           │ C: slot_sq_length() │
                        │  returns ob_size    │                           │  1. vectorcall_method│
                        └─────────────────────┘                           │     ("__len__")     │
                                                                          │  2. Validate int >=0│
                                                                          │  3. Return Py_ssize_t
                                                                          └─────────────────────┘
```

#### 1.2 Why `len(x)` Bypasses Instance Attributes (`x.__dict__`)

Because `PyObject_Size(x)` reads `Py_TYPE(x)->tp_as_sequence->sq_length` directly from the **type (`class`)**, it never looks in the **instance dictionary (`x.__dict__`)**!

Consider what happens if you attach a `__len__` lambda to an *instance* rather than its *class*:

```python
class Empty:
    pass

e = Empty()
e.__len__ = lambda: 42

e.__len__()  # Returns 42 (normal instance attribute lookup!)
len(e)       # Raises TypeError: object of type 'Empty' has no len()!
```

Why did `len(e)` raise `TypeError` even though `e.__len__()` returned `42`?

1. When `class Empty:` was created, it had no `__len__` method, so `Empty.tp_as_sequence->sq_length` remained `NULL`.
2. Setting `e.__len__ = ...` only inserted the key `"__len__"` into the instance dictionary `e.__dict__`; it did not modify the `Empty` class or its C type slots.
3. When `len(e)` ran, `PyObject_Size(e)` checked `Py_TYPE(e)->tp_as_sequence->sq_length`, saw `NULL`, and raised `TypeError` in nanoseconds without ever touching `e.__dict__`!

Conversely, if you dynamically attach `__len__` to the **class** (`Empty.__len__ = lambda self: 42`), `type_setattro()` intercepts the attribute assignment on the type object, calls `update_slot(type, &_Py_ID(__len__))`, and populates `Empty.tp_as_sequence->sq_length = slot_sq_length` on the fly!

### 2. Inside `slot_sq_length`: Enforcing the Python-to-C Contract

What if a user-defined `__len__` method returns a negative number (`-2`), a string (`"2"`), a `float` (`2.5`), a boolean (`True`), or a 200-digit integer (`10**100`)?

Remember from Chapter 01 that `PyObject_Size` returns a signed C `Py_ssize_t`, where negative values (`-1`) mean "an exception occurred." If a Python `__len__` returned `-1` and CPython blindly passed `-1` back to `builtin_len`, `builtin_len` would see `res < 0` with **no exception set on the thread state**, triggering `assert(PyErr_Occurred())` in a debug build or crashing the interpreter in a release build!

Open `slot_sq_length` in `Objects/typeobject.c` to see how `slot_sq_length` enforces every edge case of the `__len__` contract:

```c
/* Objects/typeobject.c */
static Py_ssize_t
slot_sq_length(PyObject *self)
{
    PyObject* stack[1] = {self};
    PyObject *res = vectorcall_method(&_Py_ID(__len__), stack, 1);
    Py_ssize_t len;

    if (res == NULL)
        return -1;

    Py_SETREF(res, _PyNumber_Index(res));
    if (res == NULL)
        return -1;

    assert(PyLong_Check(res));
    if (_PyLong_IsNegative((PyLongObject *)res)) {
        Py_DECREF(res);
        PyErr_SetString(PyExc_ValueError,
                        "__len__() should return >= 0");
        return -1;
    }

    len = PyNumber_AsSsize_t(res, PyExc_OverflowError);
    assert(len >= 0 || PyErr_ExceptionMatches(PyExc_OverflowError));
    Py_DECREF(res);
    return len;
}
```

Trace every branch of `slot_sq_length` line by line:

1. **`vectorcall_method(&_Py_ID(__len__), stack, 1)`**: Looks up `__len__` on `Py_TYPE(self)` (using the pre-interned static identifier `_Py_ID(__len__)`) and invokes it using CPython's fast `vectorcall` calling convention with `self` on a 1-element C stack array (zero tuple allocation!). If `__len__` itself raised an exception, `res` is `NULL` and `slot_sq_length` returns `-1`.
2. **`Py_SETREF(res, _PyNumber_Index(res))`**: Calls `nb_index` (`__index__`) to coerce `res` into an exact `PyLongObject` (`int`), releasing the old `res` reference via `Py_SETREF`.
   - If `__len__` returned `"2"` or `2.5` (which do not implement `__index__`), `_PyNumber_Index` sets `TypeError: 'str' object cannot be interpreted as an integer` and returns `NULL` $\rightarrow$ `slot_sq_length` returns `-1`.
3. **`if (_PyLong_IsNegative((PyLongObject *)res))`**: If `__len__` returned `-2`, `slot_sq_length` decrements `res`, explicitly sets **`ValueError: __len__() should return >= 0`**, and returns `-1`. That guarantees a negative Python return value never masquerades as a C `-1` error sentinel without an exception!
4. **`PyNumber_AsSsize_t(res, PyExc_OverflowError)`**: Converts the arbitrary-precision Python `int` into a machine-word `Py_ssize_t`. If `__len__` returned `10**100` (larger than `PY_SSIZE_T_MAX`, $2^{63}-1$), it sets `OverflowError: cannot fit 'int' into an index-sized integer` and returns `-1`.
5. **`Py_DECREF(res)`**: Releases the temporary Python `int` object owned by `slot_sq_length` before returning the raw `Py_ssize_t len`.

### 3. Two-Way Bridging: How `list.__len__` Wraps C `list_length` Back into Python

We just saw how a **Python method** (`Box.__len__`) is wrapped into a **C slot** (`slot_sq_length`). What about the reverse direction?

A built-in `list` only defines the C function `static Py_ssize_t list_length(PyObject *a)` in `list_as_sequence`. It does **not** manually define a `"__len__"` entry in `list_methods[]`! Yet in Python, you can still call `[10, 20, 30].__len__()` directly as a method. Where does `list.__dict__["__len__"]` come from?

Look back at the 4th parameter of the `SQSLOT` macro in `Objects/typeobject.c`:

```c
SQSLOT(__len__, sq_length, slot_sq_length, wrap_lenfunc,
       "__len__($self, /)\n--\n\nReturn len(self)."),
```

When `PyType_Ready(&PyList_Type)` initializes the built-in `list` type at interpreter startup, `add_operators()` scans `slotdefs`. Seeing that `PyList_Type.tp_as_sequence->sq_length` is non-NULL (`list_length`), it automatically creates a **Slot Wrapper Descriptor (`wrapper_descriptor`)** around `list_length` using `wrap_lenfunc` and inserts it into `list.__dict__["__len__"]`!

| Direction | Mechanism in `Objects/typeobject.c` | Runtime Effect |
| :--- | :--- | :--- |
| **Python `def __len__` $\rightarrow$ C slot** | `update_one_slot()` installs `slot_sq_length` into `tp_as_sequence->sq_length`. | Allows C code (`PyObject_Size`) to call Python classes via C function pointers. |
| **C slot `list_length` $\rightarrow$ Python `list.__len__`** | `add_operators()` wraps `list_length` in a `wrapper_descriptor` (`wrap_lenfunc`). | Allows Python code (`[1, 2].__len__()`) to call C type slots as attributes. |

### 4. Verification Lab: Proving all Five `slot_sq_length` Branches & Live Slot Syncing

The script below tests all five branches of `slot_sq_length` in `Objects/typeobject.c` (`>= 0` success, negative `ValueError`, non-index `TypeError`, `PY_SSIZE_T_MAX + 1` `OverflowError`, and dynamic class slot synchronization vs. instance dictionary bypass).

```python
#!/usr/bin/env python3
"""
Verify the exact C behaviors of slot_sq_length and update_one_slot
in Objects/typeobject.c.
"""
import ctypes
import sys


class ConfigurableLen:
    def __init__(self, value):
        self.value = value

    def __len__(self):
        return self.value


def verify_slot_sq_length_contracts() -> None:
    print("=== [1] Verifying slot_sq_length() Validation Branches ===")
    cases = [
        (3, "valid non-negative int"),
        (True, "bool is a subclass of int (__index__ -> 1)"),
        (-2, "negative int -> _PyLong_IsNegative raises ValueError"),
        ("2", "str has no __index__ -> _PyNumber_Index raises TypeError"),
        (sys.maxsize + 1, "> PY_SSIZE_T_MAX -> PyNumber_AsSsize_t raises OverflowError"),
    ]
    for ret_val, reason in cases:
        obj = ConfigurableLen(ret_val)
        try:
            res = len(obj)
            print(f"  return {ret_val!r:22s} -> len() = {res!r} ({reason})")
        except Exception as exc:
            print(f"  return {ret_val!r:22s} -> raised {type(exc).__name__}: {exc}")


def verify_instance_vs_type_slot_dispatch() -> None:
    print("\n=== [2] Verifying Type Slot Dispatch vs Instance __dict__ ===")

    class DynamicBox:
        pass

    box = DynamicBox()
    # 1. Attach __len__ to the INSTANCE dictionary only
    box.__len__ = lambda: 99
    try:
        len(box)
    except TypeError as exc:
        print(f"  Instance box.__len__ set -> len(box) raised TypeError: {exc}")

    # 2. Attach __len__ to the CLASS: type_setattro triggers update_one_slot()!
    DynamicBox.__len__ = lambda self: 77
    print(f"  Class DynamicBox.__len__ set -> len(box) = {len(box)}")

    # 3. Verify built-in wrapper_descriptor vs Python function on __len__
    print(f"  type(list.__dict__['__len__'])       = {type(list.__dict__['__len__'])}")
    print(f"  type(DynamicBox.__dict__['__len__']) = {type(DynamicBox.__dict__['__len__'])}")


if __name__ == "__main__":
    verify_slot_sq_length_contracts()
    verify_instance_vs_type_slot_dispatch()
```
