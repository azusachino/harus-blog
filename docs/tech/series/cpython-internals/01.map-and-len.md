## CPython Internals 01: Mapping the Repository, Building PyDebug & Tracing `len()` into C

Most Python engineers treat the CPython runtime as a black box: Python source goes in, C magic happens underneath, and objects come out. Yet CPython is one of the cleanest, most readable production C codebases in existence. You do not need to memorize a million lines of C or read the entire bytecode compiler before you can trace—and fix—real interpreter behavior.

The secret is **orienting by question rather than directory size**, starting from a single Python expression you already understand (`len([10, 20, 30])`), and following its exact five-hop execution path across the C source tree.

---

### 1. Navigating the CPython Tree by Question

When you first clone [`python/cpython`](https://github.com/python/cpython), the directories below hold most of what you will read (there are others, such as `Parser/`, `Programs/` and `Tools/`):

```text
cpython/
├── Doc/       ──► ReStructuredText official documentation & C API specs
├── Grammar/   ──► PEG grammar definition (python.gram)
├── Include/   ──► Public/internal C headers (object.h, listobject.h, pycore_*.h)
├── Lib/       ──► Standard library modules written in pure Python + Lib/test/
├── Modules/   ──► Standard library modules written in C (_json.c, _collectionsmodule.c)
├── Objects/   ──► Built-in object types & abstract protocols (listobject.c, dictobject.c)
└── Python/    ──► Core runtime: compiler, bytecode eval loop, builtins (ceval.c, bltinmodule.c)
```

Instead of browsing directories top-down, map your question directly to the owning subsystem:

| When You Ask... | Start in This Directory | Key Files to Inspect First |
| :--- | :--- | :--- |
| "Where is the public contract specified?" | `Doc/` | `Doc/library/`, `Doc/c-api/` |
| "What regression tests verify this behavior?" | `Lib/test/` | `Lib/test/test_<topic>.py` |
| "How is a pure-Python stdlib module written?" | `Lib/` | `Lib/collections/`, `Lib/asyncio/` |
| "How does a builtin function (`len`, `print`, `iter`) work?" | `Python/` | `Python/bltinmodule.c` |
| "How does the generic object protocol (`PyObject_Size`) dispatch?" | `Objects/` | `Objects/abstract.c` |
| "How does a built-in type (`list`, `dict`, `str`, `int`) work?" | `Objects/` | `Objects/listobject.c`, `Objects/dictobject.c`, `Objects/unicodeobject.c` |
| "Where are `PyObject` structs and inline macros declared?" | `Include/` | `Include/object.h`, `Include/cpython/`, `Include/internal/` |
| "How is a C-accelerated stdlib module (`math`, `itertools`) built?" | `Modules/` | `Modules/mathmodule.c`, `Modules/itertoolsmodule.c` |

### 2. The Minimum C Reading Kit for CPython

You only need seven C idioms to read 90% of `Objects/` and `Python/`:

| C Expression in CPython | How to Read It | Runtime Role |
| :--- | :--- | :--- |
| `PyObject *obj` | `obj` is a pointer to a heap-allocated Python object header. | Every Python value (`int`, `list`, `type`, module) is passed around as `PyObject *`. |
| `obj->field` | Follow pointer `obj` to its struct and read `field`. | Used to traverse object headers and type slot tables (`Py_TYPE(o)->tp_as_sequence`). |
| `static` on a function | Symbol visibility is private to this `.c` translation unit. | Type slot implementations (`static Py_ssize_t list_length(...)`) are `static` and exposed only via function-pointer tables. |
| `Py_ssize_t` | Signed machine word (`int64_t` on 64-bit platforms). | Used for container lengths and indices; `-1` serves as the error sentinel. |
| `NULL` | Zero pointer (`0x0`). | Returned by `PyObject *`-returning C functions to signal that an exception is now pending on the thread state. |
| `assert(cond)` | Debug-build invariant check (compiled out in release builds unless `--with-pydebug`). | Documents core developer preconditions and catches broken refcount/exception contracts immediately. |
| `goto error;` | Structured forward jump to a single cleanup block at the bottom of a C function. | CPython's standard equivalent of `try ... finally` for releasing temporary `Py_DECREF` references on failure. |

#### Building CPython with `--with-pydebug`

Whenever you explore CPython internals, compile with `--with-pydebug`. A debug build enables every internal `assert()`, tracks total live reference counts (`sys.gettotalrefcount()`), fills freshly freed memory with poison byte patterns (`0xDD` / `0xFD`) so use-after-free bugs crash immediately at the offending line, and preserves full DWARF symbols (`-g -Og`) for GDB/LLDB:

```bash
# Configure and compile a debug build of CPython
./configure --with-pydebug
make -j"$(nproc)"

# Note: on case-insensitive filesystems (macOS), the binary is named ./python.exe
# because the directory './Python/' already exists! On Linux, it is ./python.
./python -VV
```

### 3. Following `len([10, 20, 30])` Across Five C Stops

How does `len([10, 20, 30])` return `3` in $O(1)$ constant time, and how does the exact same `len()` function also work on a `dict` (`{"x": 1}`) while raising `TypeError` on `object()`?

The key architectural principle of CPython is **dispatch via C function-pointer tables (type slots)**:

<Archify src="./diagrams/cpython-slot-dispatch.sequence.json" />

```text
  Python Expression: len([10, 20, 30])
            │
            ▼
┌────────────────────────────────────────────────────────────┐
│ Stop 1: builtin_len(module, obj)                           │
│         [Python/bltinmodule.c]                             │
│   Calls Py_ssize_t res = PyObject_Size(obj);               │
│   If res < 0 -> return NULL; else PyLong_FromSsize_t(res)  │
└───────────────────────────┬────────────────────────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────────┐
│ Stop 2: PyObject_Size(PyObject *o)                         │
│         [Objects/abstract.c]                               │
│   Inspects PySequenceMethods *m = Py_TYPE(o)->tp_as_sequence│
│   If m && m->sq_length -> calls m->sq_length(o)            │
│   Otherwise falls back to PyMapping_Size(o)                │
└───────────────────────────┬────────────────────────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────────┐
│ Stop 3: PyList_Type.tp_as_sequence -> &list_as_sequence    │
│         [Objects/listobject.c]                             │
│   Maps slot .sq_length = list_length                       │
└───────────────────────────┬────────────────────────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────────┐
│ Stop 4: list_length(PyObject *a)                           │
│         [Objects/listobject.c]                             │
│   Returns PyList_GET_SIZE(a)                               │
└───────────────────────────┬────────────────────────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────────┐
│ Stop 5: PyList_GET_SIZE(op)                                │
│         [Include/cpython/listobject.h]                     │
│   Reads ((PyVarObject *)list)->ob_size -> returns 3!       │
└────────────────────────────────────────────────────────────┘
```

Let's read the actual C code at each of those five stops in CPython (`ee1bbf037f`).

#### Stop 1: `builtin_len` (`Python/bltinmodule.c`)

When Python calls the built-in `len(obj)`, execution enters `builtin_len` in `Python/bltinmodule.c`:

```c
/* Python/bltinmodule.c */
static PyObject *
builtin_len(PyObject *module, PyObject *obj)
{
    Py_ssize_t res;

    res = PyObject_Size(obj);
    if (res < 0) {
        assert(PyErr_Occurred());
        return NULL;
    }
    return PyLong_FromSsize_t(res);
}
```

Look at how much this 10-line function reveals:

1. `builtin_len` knows **nothing** about lists, tuples, dicts, or strings. It delegates immediately to the abstract object protocol `PyObject_Size(obj)`.
2. `PyObject_Size(obj)` returns a raw C signed integer (`Py_ssize_t`), **not** a `PyObject *`.
3. Why is `Py_ssize_t` signed if a container's length can never be negative? Because **negative values (`-1`) are reserved as the C error sentinel**! If `res < 0`, `assert(PyErr_Occurred())` verifies in debug builds that the callee already recorded a Python exception on the current thread state, and `builtin_len` returns `NULL` to propagate that exception.
4. On success (`res >= 0`), `PyLong_FromSsize_t(res)` boxes the raw C integer `3` into a heap-allocated (or small-int cached) Python `int` object (`PyObject *`) and returns it.

#### Stop 2: `PyObject_Size` (`Objects/abstract.c`)

Next, open `Objects/abstract.c` to see how `PyObject_Size` dispatches across arbitrary types:

```c
/* Objects/abstract.c */
Py_ssize_t
PyObject_Size(PyObject *o)
{
    if (o == NULL) {
        null_error();
        return -1;
    }

    PySequenceMethods *m = Py_TYPE(o)->tp_as_sequence;
    if (m && m->sq_length) {
        Py_ssize_t len = m->sq_length(o);
        assert(_Py_CheckSlotResult(o, "__len__", len >= 0));
        return len;
    }

    return PyMapping_Size(o);
}
```

Trace the pointer chain `Py_TYPE(o)->tp_as_sequence`:

1. `Py_TYPE(o)` reads `o->ob_type`, which for `[10, 20, 30]` points to the global `PyList_Type` struct.
2. `tp_as_sequence` is a pointer to a sub-table of sequence function pointers (`PySequenceMethods`).
3. If the type defines `tp_as_sequence` and its `sq_length` slot is non-NULL, `PyObject_Size` calls the function pointer `m->sq_length(o)` directly!
4. What if `o` is a `dict` (`{"x": 1}`)? A dictionary's `tp_as_sequence` has `sq_length == 0` (it only implements `sq_contains` for the `key in d` operator), so `if (m && m->sq_length)` is false and `PyObject_Size` falls back to `PyMapping_Size(o)`:

```c
/* Objects/abstract.c */
Py_ssize_t
PyMapping_Size(PyObject *o)
{
    if (o == NULL) {
        null_error();
        return -1;
    }

    PyMappingMethods *m = Py_TYPE(o)->tp_as_mapping;
    if (m && m->mp_length) {
        Py_ssize_t len = m->mp_length(o);
        assert(_Py_CheckSlotResult(o, "__len__", len >= 0));
        return len;
    }

    if (Py_TYPE(o)->tp_as_sequence && Py_TYPE(o)->tp_as_sequence->sq_length) {
        type_error("%.200s is not a mapping", o);
        return -1;
    }
    /* PyMapping_Size() can be called from PyObject_Size(). */
    type_error("object of type '%.200s' has no len()", o);
    return -1;
}
```

Notice how `PyMapping_Size(o)` explains all three cases:

- **List (`[10, 20, 30]`)**: Handled immediately by `tp_as_sequence->sq_length` in `PyObject_Size`.
- **Dict (`{"x": 1}`)**: Falls through to `PyMapping_Size`, which calls `tp_as_mapping->mp_length` (`dict_length` in `Objects/dictobject.c`).
- **Plain `object()`**: Has neither `sq_length` nor `mp_length`. `PyMapping_Size` formats `TypeError: object of type 'object' has no len()` and returns `-1`, which `builtin_len` turns into `return NULL`.

#### Stops 3, 4 & 5: `list_as_sequence` $\rightarrow$ `list_length` $\rightarrow$ `PyList_GET_SIZE`

In `Objects/listobject.c`, `PyList_Type` wires its `tp_as_sequence` pointer to `list_as_sequence`, which registers `list_length` in the first slot (`sq_length`):

```c
/* Objects/listobject.c */
static Py_ssize_t
list_length(PyObject *a)
{
    return PyList_GET_SIZE(a);
}

static PySequenceMethods list_as_sequence = {
    list_length,                                /* sq_length */
    _PyList_Concat,                             /* sq_concat */
    list_repeat,                                /* sq_repeat */
    list_item,                                  /* sq_item */
    /* ... */
};
```

And in `Include/cpython/listobject.h`, `PyList_GET_SIZE` reads the cached `ob_size` field from the list's `PyVarObject` header in a single memory load (using a relaxed atomic load when compiled for PEP 703 free-threading):

```c
/* Include/cpython/listobject.h */
static inline Py_ssize_t PyList_GET_SIZE(PyObject *op) {
    PyListObject *list = _PyList_CAST(op);
#ifdef Py_GIL_DISABLED
    return _Py_atomic_load_ssize_relaxed(&(_PyVarObject_CAST(list)->ob_size));
#else
    return Py_SIZE(list);
#endif
}
```

That is why `len(my_list)` is $O(1)$ regardless of whether `my_list` has 3 elements or 30 million elements: CPython never walks the array to count items; it simply reads the pre-maintained `ob_size` word from the object header.

### 4. Verification Lab: Inspecting Type Slots and Live C Calls with `ctypes` & GDB

You don't have to guess which C slot a built-in type populates. Using Python's built-in `ctypes`, we can read the live `PyTypeObject` memory of `list`, `dict`, and `object` in the current process to inspect their `tp_as_sequence` and `tp_as_mapping` pointers directly!

```python
#!/usr/bin/env python3
"""
Inspect live CPython PyTypeObject slot pointers (tp_as_sequence->sq_length and
tp_as_mapping->mp_length) for list, dict, and object using ctypes.
"""
import ctypes


class PySequenceMethods(ctypes.Structure):
    _fields_ = [
        ("sq_length", ctypes.c_void_p),
        ("sq_concat", ctypes.c_void_p),
        ("sq_repeat", ctypes.c_void_p),
        ("sq_item", ctypes.c_void_p),
    ]


class PyMappingMethods(ctypes.Structure):
    _fields_ = [
        ("mp_length", ctypes.c_void_p),
        ("mp_subscript", ctypes.c_void_p),
        ("mp_ass_subscript", ctypes.c_void_p),
    ]


def find_slot_offsets() -> tuple[int, int]:
    """
    Locate tp_as_sequence and tp_as_mapping pointer offsets inside PyTypeObject
    by scanning for the known relation on list and dict types.
    """
    ptr_size = ctypes.sizeof(ctypes.c_void_p)
    list_addr = id(list)
    dict_addr = id(dict)
    obj_addr = id(object)

    # In PyTypeObject, tp_as_number, tp_as_sequence, tp_as_mapping are 3 consecutive pointers:
    # - object has (0, 0, 0)
    # - list has (0, non-zero, non-zero) where sq_length == mp_length == list_length!
    # - dict has (0, non-zero, non-zero) where sq_length == 0 and mp_length != 0!
    for word_idx in range(10, 30):
        offset = word_idx * ptr_size
        obj_seq = ctypes.c_void_p.from_address(obj_addr + offset).value
        obj_map = ctypes.c_void_p.from_address(obj_addr + offset + ptr_size).value
        if obj_seq is not None or obj_map is not None:
            continue

        list_seq = ctypes.c_void_p.from_address(list_addr + offset).value
        list_map = ctypes.c_void_p.from_address(list_addr + offset + ptr_size).value
        dict_seq = ctypes.c_void_p.from_address(dict_addr + offset).value
        dict_map = ctypes.c_void_p.from_address(dict_addr + offset + ptr_size).value

        if list_seq and list_map and dict_seq and dict_map:
            l_sq = PySequenceMethods.from_address(list_seq).sq_length
            l_mp = PyMappingMethods.from_address(list_map).mp_length
            d_sq = PySequenceMethods.from_address(dict_seq).sq_length
            d_mp = PyMappingMethods.from_address(dict_map).mp_length
            if l_sq and l_sq == l_mp and d_sq is None and d_mp:
                return offset, offset + ptr_size

    raise RuntimeError("Could not locate tp_as_sequence / tp_as_mapping offsets")


def inspect_type(cls: type, seq_off: int, map_off: int) -> None:
    addr = id(cls)
    seq_ptr = ctypes.c_void_p.from_address(addr + seq_off).value
    map_ptr = ctypes.c_void_p.from_address(addr + map_off).value

    sq_len = PySequenceMethods.from_address(seq_ptr).sq_length if seq_ptr else None
    mp_len = PyMappingMethods.from_address(map_ptr).mp_length if map_ptr else None

    print(f"Type '{cls.__name__:6s}' (PyTypeObject @ {hex(addr)}):")
    print(f"  tp_as_sequence -> {hex(seq_ptr) if seq_ptr else 'NULL':>14s} | sq_length = {hex(sq_len) if sq_len else 'NULL'}")
    print(f"  tp_as_mapping  -> {hex(map_ptr) if map_ptr else 'NULL':>14s} | mp_length = {hex(mp_len) if mp_len else 'NULL'}")


if __name__ == "__main__":
    seq_offset, map_offset = find_slot_offsets()
    for t in (list, dict, object):
        inspect_type(t, seq_offset, map_offset)
```

Running this script prints the exact function pointer addresses inside your live Python interpreter:

- `list` populates **`sq_length`** (and `mp_length` with the exact same `list_length` pointer).
- `dict` leaves **`sq_length = NULL`** and populates **`mp_length`** (`dict_length`).
- `object` leaves both `tp_as_sequence` and `tp_as_mapping` `NULL`, triggering `TypeError: object of type 'object' has no len()`.
