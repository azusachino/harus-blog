## Before you start

Your machines sit behind different home routers and office firewalls, with no fixed public addresses. The old answer was a VPN server in the middle that every packet passes through. This chapter covers a mesh instead: each machine runs Tailscale, which builds encrypted WireGuard tunnels directly between pairs of machines and gives every one a stable private address.

Getting two machines behind NAT to talk directly is the hard part, and the chapter explains how it is done and what happens when it fails (traffic goes through a relay). The second half is access control. Instead of "anything on the VPN can reach anything", a policy file says which tagged machines may reach which ports on which others.

A small example: `tailscale ping server-a` tells you whether you reached it directly or through a relay.

Read [chapter 3](/tech/series/nix-declarative-fleet/03.secrets-management-with-sops-and-age/) first if you want the key-handling background; the machine descriptions come from [chapter 2](/tech/series/nix-declarative-fleet/02.multi-platform-fleet-and-home-manager/).

Terms used in this chapter:

- **WireGuard**: a modern VPN protocol that creates encrypted tunnels between peers identified by public keys.
- **mesh**: a network where nodes connect directly to each other instead of through one central hub.
- **NAT**: a router feature that lets many private-address machines share one public address, which blocks unsolicited incoming connections.
- **STUN**: a protocol for a machine to learn its public address and port as seen from the internet.
- **DERP**: Tailscale's relay servers, used when a direct connection cannot be made.
- **ACL**: an access control list; here a policy file that allows or denies connections between machines.
- **tag**: a label such as `tag:server` applied to machines so ACLs can refer to groups.
- **zero trust**: the policy that being on the network grants nothing by itself; each connection is checked.

## Zero-Trust Mesh Networking with Tailscale & ACLs

Managing a fleet of workstations, servers, and edge devices across multiple physical networks—home LANs, office Wi-Fi, cloud VPCs, and mobile hotspots—traditionally relied on legacy hub-and-spoke VPNs (like OpenVPN or IPsec).

Hub-and-spoke architectures have three structural problems:

1. **Bandwidth Bottleneck & Latency Penalty**: All traffic between two machines sitting in the same room must trombone through a remote central VPN concentrator in a datacenter.
2. **Single Point of Failure**: If the central gateway experiences a DDoS attack or network outage, all cross-fleet communication collapses.
3. **Perimeter-Based Security**: Once a machine connects to the VPN subnet, it typically gains broad network-level visibility across all other connected devices.

**Tailscale** solves this by establishing a **zero-trust, peer-to-peer encrypted mesh network** on top of the WireGuard protocol. Every node receives a stable, non-routable IP address (`100.64.0.0/10`) and communicates directly with peers over encrypted UDP tunnels.

This chapter breaks down the mechanics of WireGuard mesh coordination, STUN/DERP NAT traversal, declarative tag-based Access Control Lists (ACLs), and secure tailnet ingress via Tailscale Serve.

---

### 1. Peer-to-Peer WireGuard Mesh vs. Hub-and-Spoke

WireGuard provides kernel-level cryptographic encapsulation using modern ciphers:

- **ChaCha20** for symmetric encryption.
- **Poly1305** for message authentication.
- **Curve25519** for elliptic curve Diffie-Hellman key exchange.

In standard WireGuard, each peer is configured by hand with the public keys and, for at least one side of every tunnel, the reachable endpoint (IP and port) of its peers (`wg0.conf`). In dynamic fleets with roaming laptops, NAT-restricted home routers, and dynamic cellular IPs, maintaining static configuration files is practically impossible.

```text
Traditional Hub-and-Spoke:
[ Laptop ] ----------------> [ Central VPN Gateway ] ----------------> [ Homelab Server ]
  (Home)                          (Datacenter)                              (Office)

Tailscale Direct Mesh:
[ Laptop ] ================= Direct Encrypted UDP Tunnel ===============> [ Homelab Server ]
    |                                                                             |
    +---- Control Plane Sync ----> [ Coordination Server ] <--- Control Sync -----+
```

Tailscale separates the **Control Plane** from the **Data Plane**:

- **Control Plane**: The coordination server exchanges node public keys, endpoints, and access policies. It **never sees or relays packet payload data**.
- **Data Plane**: Encrypted traffic flows directly point-to-point between devices via WireGuard tunnels.

### 2. NAT Traversal & The Disco Protocol

Connecting two machines that both sit behind carrier-grade NATs (CGNAT) or stateful firewalls requires sophisticated NAT traversal:

```text
[ Node A (Behind NAT 1) ]                               [ Node B (Behind NAT 2) ]
          |                                                       |
          +---> STUN Request to DERP: Discover external IP:Port <-+
          |                                                       |
          +---> Coordination Server: Exchange Disco Endpoints <---+
          |                                                       |
     [ Phase 1: Temporary relay via DERP relay while probing ]
          |                                                       |
     [ Phase 2: Disco UDP packet sent simultaneously from both sides ]
          |     (Stateful NAT firewalls open outbound pinholes)   |
          v                                                       v
     ================== Direct P2P UDP WireGuard Established ==================
```

1. **STUN (Session Traversal Utilities for NAT)**: Each node queries a public STUN server to discover its public-facing IP address and external UDP mapping port.
2. **The Disco (Discovery) Protocol**: Nodes exchange cryptographic discovery packets authenticated with their WireGuard public keys.
3. **Simultaneous UDP Hole Punching**: Both nodes send UDP packets to each other's discovered public endpoints at the same time. The outgoing packet creates a stateful entry in Node A's NAT router, permitting Node B's incoming reply to pass through.
4. **DERP (Designated Encrypted Relay for Packets)**: If a firewall uses aggressive symmetric NAT that prevents hole punching, Tailscale routes packets through the geographically closest DERP relay over TLS. The relay sees only encrypted WireGuard payloads, preserving zero-trust end-to-end encryption. Once direct path probing succeeds, traffic switches from the relay to the direct path.

### 4. Declarative Tag-Based ACLs

In a production fleet, access must not depend on personal user identities (e.g. `alice@example.com`). If an engineer changes teams or leaves the organization, reconfiguring access for dozens of services is error-prone.

Tailscale enforces **Tag-Based ACLs**:

- Nodes authenticate using auth keys tagged with roles: `tag:server`, `tag:workstation`, `tag:ci`.
- Tags are owned by designated administrators.
- Access rules strictly define traffic matrix permissions:

```json
{
  "tagOwners": {
    "tag:server": ["group:admin"],
    "tag:workstation": ["group:admin"]
  },
  "acls": [
    // Workstations can access SSH (22) and Kubernetes API (6443) on servers
    {
      "action": "accept",
      "src": ["tag:workstation"],
      "dst": ["tag:server:22", "tag:server:6443"]
    },
    // Workstations can access internal web services & preview ports on servers
    {
      "action": "accept",
      "src": ["tag:workstation"],
      "dst": ["tag:server:80", "tag:server:443", "tag:server:8443"]
    }
  ]
}
```

Because ACLs are declarative, any connection attempt not explicitly permitted by a rule is dropped by the packet filter on the destination node (the Tailscale client enforces the ACL on ingress).

### 5. Tailscale Serve: Zero-Config Ingress & TLS

Running internal web dashboards, blog previews, or microservices historically required configuring Nginx reverse proxies, setting up port-forwarding on residential routers, and managing DynDNS.

**Tailscale Serve** embeds reverse proxying and automated TLS directly into the node daemon:

```bash
# Expose local preview server (port 3000) as a tailnet HTTPS service
tailscale serve --bg --https=8443 127.0.0.1:3000
```

1. **Automatic Let's Encrypt TLS**: With HTTPS certificates enabled for the tailnet, Tailscale provisions a trusted Let's Encrypt certificate for `server-a.example.ts.net`.
2. **Loopback Reverse Proxy**: Incoming HTTPS traffic on port `8443` is decrypted by the Tailscale daemon and forwarded to localhost `http://127.0.0.1:3000`.
3. **Tailnet-Only Exposure**: The service is completely invisible to the public internet, accessible only to authenticated devices on your private tailnet.

### 6. Verification Lab: Implementing a Mesh Router & Tag ACL Engine

The following Python script simulates:

1. **STUN Discovery & NAT Traversal**: Probes external endpoints, evaluates direct P2P hole punching compatibility, and falls back to DERP relays when NAT conditions require it.
2. **Declarative Tag ACL Engine**: Evaluates source tag, destination tag and port against ordered rules with an implicit default deny.

```python
#!/usr/bin/env python3
"""
Lab: Tailscale WireGuard Mesh, STUN NAT Hole-Punching & Tag ACL Engine
Verifies peer coordination, direct vs relay fallback, and zero-trust ACL filtering.
"""

from dataclasses import dataclass, field
from typing import Dict, List, Optional, Set, Tuple
import hashlib

@dataclass
class NetworkEndpoint:
    internal_ip: str
    internal_port: int
    nat_type: str  # "cone" (easy hole-punching) or "symmetric" (hostile NAT)
    external_ip: str = ""
    external_port: int = 0

    def resolve_stun(self, stun_server_ip: str) -> Tuple[str, int]:
        """Simulates STUN discovery."""
        h = hashlib.sha256(f"{self.internal_ip}:{self.internal_port}".encode()).hexdigest()
        self.external_ip = f"198.51.100.{int(h[:2], 16) % 250 + 1}"
        self.external_port = 10000 + (int(h[2:6], 16) % 50000)
        return (self.external_ip, self.external_port)

@dataclass
class TailscaleNode:
    hostname: str
    tailnet_ip: str  # e.g. 100.64.0.10
    tags: List[str]
    endpoint: NetworkEndpoint
    public_key: str = ""

    def __post_init__(self):
        self.public_key = f"wg_pub_{hashlib.sha256(self.hostname.encode()).hexdigest()[:16]}"

@dataclass
class ACLRule:
    action: str  # "accept" or "drop"
    src_tags: List[str]
    dst_tag: str
    allowed_ports: List[int]

class TailscaleMeshController:
    """Simulates Tailscale control plane, NAT traversal negotiation, and ACL checks."""
    def __init__(self):
        self.nodes: Dict[str, TailscaleNode] = {}
        self.acl_rules: List[ACLRule] = []

    def register_node(self, node: TailscaleNode):
        node.endpoint.resolve_stun("1.1.1.1")
        self.nodes[node.hostname] = node

    def add_acl_rule(self, rule: ACLRule):
        self.acl_rules.append(rule)

    def negotiate_connection(self, src_host: str, dst_host: str) -> str:
        """Determines whether peers connect direct P2P or via DERP relay."""
        src = self.nodes[src_host]
        dst = self.nodes[dst_host]

        # If both nodes sit behind symmetric NAT, hole-punching fails -> DERP relay
        if src.endpoint.nat_type == "symmetric" and dst.endpoint.nat_type == "symmetric":
            return "DERP_RELAY (Symmetric NAT both sides)"
        else:
            return f"DIRECT_P2P ({src.endpoint.external_ip}:{src.endpoint.external_port} <-> {dst.endpoint.external_ip}:{dst.endpoint.external_port})"

    def evaluate_packet(self, src_host: str, dst_host: str, port: int) -> bool:
        """Evaluates whether ingress packet is authorized under declarative ACLs."""
        src = self.nodes[src_host]
        dst = self.nodes[dst_host]

        # Scan ACL rules (default deny)
        for rule in self.acl_rules:
            # Check source tag intersection
            src_match = any(t in rule.src_tags for t in src.tags) or "*" in rule.src_tags
            # Check destination tag match
            dst_match = (rule.dst_tag in dst.tags) or (rule.dst_tag == "*")
            # Check port
            port_match = (port in rule.allowed_ports) or (0 in rule.allowed_ports)

            if src_match and dst_match and port_match:
                return rule.action == "accept"

        return False  # Implicit drop

def test_tailscale_mesh_and_acls():
    controller = TailscaleMeshController()

    # 1. Register fleet nodes
    laptop = TailscaleNode(
        hostname="laptop-a",
        tailnet_ip="100.64.0.1",
        tags=["tag:workstation"],
        endpoint=NetworkEndpoint("192.168.1.50", 41641, nat_type="cone")
    )
    server = TailscaleNode(
        hostname="server-a",
        tailnet_ip="100.64.0.2",
        tags=["tag:server"],
        endpoint=NetworkEndpoint("10.0.0.100", 41641, nat_type="cone")
    )
    camera = TailscaleNode(
        hostname="iot-camera",
        tailnet_ip="100.64.0.3",
        tags=["tag:iot"],
        endpoint=NetworkEndpoint("192.168.2.99", 41641, nat_type="symmetric")
    )

    controller.register_node(laptop)
    controller.register_node(server)
    controller.register_node(camera)

    # 2. Test NAT Traversal Path Selection
    print("=== 1. NAT Traversal & Hole-Punching Evaluation ===")
    p2p_path = controller.negotiate_connection("laptop-a", "server-a")
    print(f"  Laptop <-> Server: {p2p_path}")
    assert p2p_path.startswith("DIRECT_P2P")

    # Symmetric to symmetric falls back to DERP
    camera2 = TailscaleNode(
        hostname="iot-sensor",
        tailnet_ip="100.64.0.4",
        tags=["tag:iot"],
        endpoint=NetworkEndpoint("10.1.1.5", 41641, nat_type="symmetric")
    )
    controller.register_node(camera2)
    relay_path = controller.negotiate_connection("iot-camera", "iot-sensor")
    print(f"  IoT Camera <-> IoT Sensor: {relay_path}")
    assert relay_path.startswith("DERP_RELAY")

    # 3. Configure Declarative Tag ACLs
    print("\n=== 2. Declarative Tag-Based ACL Enforcement ===")
    # Allow workstations to access server SSH (22) and Preview port (8443)
    controller.add_acl_rule(ACLRule(
        action="accept",
        src_tags=["tag:workstation"],
        dst_tag="tag:server",
        allowed_ports=[22, 8443]
    ))
    # Allow servers to access IoT cameras on RTSP port 554
    controller.add_acl_rule(ACLRule(
        action="accept",
        src_tags=["tag:server"],
        dst_tag="tag:iot",
        allowed_ports=[554]
    ))

    # 4. Verify Access Permissions
    # Laptop -> Server: 22 (SSH) -> ACCEPT
    assert controller.evaluate_packet("laptop-a", "server-a", 22) is True
    print("  laptop-a -> server-a:22 (SSH)      : ACCEPT")

    # Laptop -> Server: 8443 (Preview) -> ACCEPT
    assert controller.evaluate_packet("laptop-a", "server-a", 8443) is True
    print("  laptop-a -> server-a:8443 (Preview): ACCEPT")

    # Laptop -> Server: 3306 (MySQL) -> BLOCKED (implicit drop)
    assert controller.evaluate_packet("laptop-a", "server-a", 3306) is False
    print("  laptop-a -> server-a:3306 (MySQL)  : BLOCKED (Default Deny)")

    # IoT Camera -> Server: 22 -> BLOCKED (IoT devices cannot SSH to servers!)
    assert controller.evaluate_packet("iot-camera", "server-a", 22) is False
    print("  iot-camera -> server-a:22 (SSH)    : BLOCKED (Untrusted Tag)")

    # Server -> IoT Camera: 554 (RTSP) -> ACCEPT
    assert controller.evaluate_packet("server-a", "iot-camera", 554) is True
    print("  server-a -> iot-camera:554 (RTSP)  : ACCEPT")

    print("\nAll Tailscale WireGuard mesh & Tag ACL tests PASSED!")

if __name__ == "__main__":
    test_tailscale_mesh_and_acls()
```

### 7. Summary & Operational Takeaways

1. **Decoupled Control vs Data Plane**: Tailscale's coordination server negotiates public keys and NAT endpoints, while WireGuard streams packets directly between machines with minimal latency.
2. **Resilient NAT Traversal**: Simultaneous STUN hole punching establishes direct P2P connections through residential and corporate firewalls, with DERP relays as the fallback when no direct path can be established.
3. **Role-Based Security via Tags**: Tag-based ACLs anchor firewall permissions to machine roles rather than transient user accounts, enforcing zero-trust default-deny isolation.
4. **Frictionless Ingress**: Tailscale Serve provides zero-configuration local reverse proxying with valid Let's Encrypt certificates without opening ports to the public internet.
