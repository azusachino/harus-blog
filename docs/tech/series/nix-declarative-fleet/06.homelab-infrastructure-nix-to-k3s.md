## Before you start

Kubernetes runs your containers, but something still has to set up the machine underneath: the kernel settings, the mounts, the services and the firewall. If you do that by hand, an `apt upgrade` or a forgotten setting can break the cluster in ways that are hard to trace. This closing chapter uses Nix to describe the host, installs k3s (a lightweight Kubernetes distribution that is a single binary) on it, passes secrets into the cluster, and makes the API reachable only over Tailscale.

A small picture: instead of SSH-ing in to run the k3s installer, you add `services.k3s.enable = true;` to the host's configuration and rebuild.

This chapter pulls together everything earlier, so read [chapter 3](/tech/series/nix-declarative-fleet/03.secrets-management-with-sops-and-age/) for secrets and [chapter 4](/tech/series/nix-declarative-fleet/04.zero-trust-mesh-with-tailscale/) for Tailscale first. If Kubernetes is new, a pod is a group of containers, and a Secret is a Kubernetes object that holds sensitive values.

Terms used in this chapter:

- **k3s**: a small, single-binary Kubernetes distribution aimed at edge and homelab machines.
- **control plane**: the Kubernetes components, including the API server, that manage the cluster.
- **kubeconfig**: the file holding the address and credentials a client needs to talk to a cluster.
- **Kubernetes Secret**: a Kubernetes object that stores sensitive data such as passwords for pods to use.
- **GitOps**: keeping the desired cluster state in Git and having a controller apply it.
- **sysctl**: a kernel setting adjustable at runtime, such as network forwarding.
- **ingress**: a way to expose a cluster service to clients outside it.

## Homelab Infrastructure: Nix to Kubernetes (k3s)

In modern infrastructure engineering, Kubernetes has become the universal standard for deploying and scaling containerized microservices. However, Kubernetes alone cannot manage the physical or virtual machines it runs on: the host operating system, Linux kernel flags, filesystem mounts, cgroup hierarchies, systemd services, and networking devices must all be provisioned, secured, and kept up to date.

Running Kubernetes on top of an imperatively managed host creates an unstable foundation: a manual `apt upgrade` or missing `sysctl` parameter can silently break container networking, kubelet resource limits, or storage drivers.

This final chapter of the *Declarative Fleet Engineering* series brings together every layer we have explored: how to use **Nix** to declare the underlying host environment, bootstrap a lightweight **k3s** Kubernetes cluster on `server-a`, securely bridge **SOPS-nix** secrets into Kubernetes namespaces, and expose the control plane exclusively over **Tailscale**.

### 1. Declarative Host Foundations for Kubernetes

Before a kubelet can schedule pods, the underlying Linux kernel must meet strict container orchestration prerequisites:

- **Cgroups v2**: Enabled system-wide via `systemd.unified_cgroup_hierarchy=1` for accurate memory tracking and OOM killer isolation.
- **Kernel Networking & IP Forwarding**: Forwarding IPv4 packets across container network interface (CNI) bridges.
- **Firewall & Ingress Bridges**: Permitting VXLAN or WireGuard flannel traffic through iptables / nftables.

In a Nix-managed host (`machines/server-a.nix`), these prerequisites are declared as pure code:

```nix
# machines/server-a.nix
{ pkgs, ... }: {
  # 1. Enable IP forwarding and bridge filtering
  boot.kernel.sysctl = {
    "net.ipv4.ip_forward" = 1;
    "net.bridge.bridge-nf-call-iptables" = 1;
    "net.bridge.bridge-nf-call-ip6tables" = 1;
    "fs.inotify.max_user_watches" = 524288;
    "fs.inotify.max_user_instances" = 8192;
  };

  # 2. Kernel modules required for overlayfs and wireguard CNI
  boot.kernelModules = [ "overlay" "br_netfilter" "wireguard" ];
}
```

Because these kernel parameters are declared in Nix, every host rebuild or rollback deterministically applies the exact required network stack, eliminating runtime host drift.

### 2. Declarative k3s Bootstrap & Configuration

Rather than deploying a heavyweight multi-node control plane with external etcd clusters, homelabs and edge environments benefit from **k3s** (a lightweight, certified Kubernetes distribution packaged as a single binary):

```nix
# modules/k3s-server.nix
{ config, pkgs, ... }: {
  services.k3s = {
    enable = true;
    role = "server";
    package = pkgs.k3s;

    extraFlags = toString [
      # Disable embedded components to allow custom GitOps management
      "--disable=traefik"
      "--disable=servicelb"
      "--disable=local-storage"

      # Encrypt internal pod-to-pod traffic via WireGuard CNI
      "--flannel-backend=wireguard-native"

      # Advertise the Tailnet address and add the MagicDNS name to the API certificate
      "--advertise-address=100.64.0.2"
      "--tls-san=server-a.example.ts.net"

      # Secure kubeconfig file permissions
      "--write-kubeconfig-mode=0640"
      "--write-kubeconfig-group=users"
    ];
  };

  # Only the Tailscale interface may reach the API server port
  networking.firewall.interfaces."tailscale0".allowedTCPPorts = [ 6443 ];

  # Ensure k3s binary and CLI utilities are available in system PATH
  environment.systemPackages = with pkgs; [
    k3s
    kubectl
    kubernetes-helm
    k9s
  ];
}
```

#### Automatic Add-on Manifests via `/nix/store`

k3s includes an auto-deploy mechanism: any manifest dropped into `/var/lib/rancher/k3s/server/manifests/` is automatically applied to the cluster.

The NixOS k3s module can populate this directory from files in your flake; they end up as symlinks into immutable `/nix/store/` paths:

```nix
services.k3s.manifests.coredns-config.source = ./manifests/coredns-config.yaml;
```

When you edit the manifest in your Git repository and run `nixos-rebuild switch`, Nix atomically updates the target symlink, and k3s re-applies the updated configuration in real time.

### 3. The Secrets Bridge: SOPS-nix to Kubernetes Secrets

A persistent challenge in cloud-native operations is getting secrets into the cluster without checking plaintext Kubernetes `Secret` manifests into Git.

By combining `sops-nix` on the host with Kubernetes GitOps:

```text
[ Git: secrets/cluster.yaml (Encrypted with Age) ]
                    |
                    | 1. sops-nix host activation
                    v
[ Host RAM: /run/secrets/cluster_env (Mode 0400) ]
                    |
                    | 2. Post-activation script / Systemd ExecStartPost
                    v
[ kubectl apply -f - (Direct in-memory pipe) ]
                    |
                    v
[ Kubernetes Namespace: Secret/app-credentials ]
```

A declarative activation script reads the decrypted values directly from `/run/secrets/` and streams them via `stdin` into `kubectl apply`:

```nix
systemd.services.k3s-secrets-sync = {
  description = "Sync SOPS-nix host secrets into Kubernetes namespaces";
  after = [ "k3s.service" ];
  requires = [ "k3s.service" ];
  wantedBy = [ "multi-user.target" ];
  serviceConfig = { Type = "oneshot"; RemainAfterExit = true; };

  script = ''
    export KUBECONFIG=/etc/rancher/k3s/k3s.yaml

    # Read decrypted tokens from RAM tmpfs and apply to cluster
    ${pkgs.kubectl}/bin/kubectl create secret generic cloud-api-tokens \
      --from-file=api_key=/run/secrets/cloud_api_key \
      --dry-run=client -o yaml | ${pkgs.kubectl}/bin/kubectl apply -f -
  '';
};
```

This guarantees:

1. Secret values are never committed to Git in plaintext.
2. On the host, decrypted values exist only under `/run/secrets/` (RAM-backed). Once applied, Kubernetes stores them in the k3s datastore on disk, so enable `--secrets-encryption` if that matters.
3. Rotation is a rebuild followed by a restart of this unit, which re-applies the Secret.

### 4. Zero-Trust Access: Tailscale Ingress for the Control Plane

Exposing a Kubernetes API server (`port 6443`) to the public internet attracts constant port scanning, credential stuffing, and unauthenticated exploit attempts.

By advertising the Tailscale address and opening port 6443 only on the `tailscale0` interface, the Kubernetes API server is reachable **only through the tailnet**. (Binding the API server to the Tailscale IP alone is tempting, but it also breaks the local `127.0.0.1` kubeconfig that k3s generates and that the sync service above uses.)

```text
[ Remote laptop (100.64.0.1) ]
                 |
                 | (Encrypted WireGuard Tunnel over Tailnet)
                 v
[ Homelab Server (server-a: 100.64.0.2:6443) ]
                 |
                 +---> Authenticates client via WireGuard key & TLS client cert
                 +---> Enforces Tailscale Tag ACLs (tag:workstation -> tag:server:6443)
```

From any workstation in the fleet:

```yaml
# kubeconfig references canonical Tailscale MagicDNS name
clusters:
- cluster:
    server: https://server-a.example.ts.net:6443
    certificate-authority-data: ...
```

Whether you are connected to home Wi-Fi, working from a coffee shop, or roaming on mobile data, `kubectl` connects instantly and securely over your WireGuard mesh with zero port-forwarding on your home router.

### 5. Verification Lab: Implementing a Declarative GitOps Host-Cluster Controller

The following Python script simulates:

1. **Host Kernel Prerequisites Validator**: Verifies that required sysctl settings and kernel modules are declared before cluster initialization.
2. **Declarative k3s Manifest Reconciler**: Compares desired state (declared in simulated `/nix/store/` manifests) against live cluster state, creating missing deployments, updating drifted specs, and pruning unmanaged resources.
3. **RAM Secret Injector**: Streams secrets from `/run/secrets/` into Kubernetes `Secret` definitions without writing plaintext to disk.

```python
#!/usr/bin/env python3
"""
Lab: Declarative Host-Cluster Bridge (Nix to k3s Reconciler)
Verifies host sysctl prerequisites, atomic manifest synchronization, and secret injection.
"""

from dataclasses import dataclass, field
from typing import Dict, List, Optional, Set, Tuple
import hashlib

@dataclass
class HostSystemState:
    sysctl: Dict[str, int]
    loaded_modules: Set[str]
    ram_secrets: Dict[str, str]  # /run/secrets/ paths

@dataclass
class KubeResource:
    kind: str
    name: str
    namespace: str
    spec_hash: str
    data: Dict[str, str] = field(default_factory=dict)

class DeclarativeClusterReconciler:
    """Simulates declarative GitOps manifest reconciliation on k3s."""
    def __init__(self, host: HostSystemState):
        self.host = host
        self.live_cluster: Dict[str, KubeResource] = {}  # "kind/namespace/name" -> resource

    def validate_host_prerequisites(self) -> bool:
        """Verifies kernel sysctls and modules required by k3s."""
        required_sysctls = {
            "net.ipv4.ip_forward": 1,
            "net.bridge.bridge-nf-call-iptables": 1
        }
        for k, v in required_sysctls.items():
            if self.host.sysctl.get(k) != v:
                raise SystemError(f"Missing required kernel sysctl: {k}={v}")

        required_modules = {"overlay", "br_netfilter", "wireguard"}
        missing = required_modules - self.host.loaded_modules
        if missing:
            raise SystemError(f"Missing required kernel modules: {missing}")

        return True

    def sync_manifests(self, desired_manifests: List[Dict]) -> Tuple[int, int, int]:
        """
        Reconciles desired manifests against live cluster state.
        Returns (created_count, updated_count, deleted_count).
        """
        self.validate_host_prerequisites()

        desired_keys: Set[str] = set()
        created = 0
        updated = 0

        for manifest in desired_manifests:
            kind = manifest["kind"]
            name = manifest["name"]
            namespace = manifest.get("namespace", "default")
            key = f"{kind}/{namespace}/{name}"
            desired_keys.add(key)

            # Compute spec hash
            spec_str = str(sorted(manifest["spec"].items()))
            spec_hash = hashlib.sha256(spec_str.encode()).hexdigest()[:16]

            if key not in self.live_cluster:
                self.live_cluster[key] = KubeResource(
                    kind=kind,
                    name=name,
                    namespace=namespace,
                    spec_hash=spec_hash,
                    data=manifest.get("data", {})
                )
                created += 1
                print(f"  [create] {key} (hash={spec_hash})")
            else:
                existing = self.live_cluster[key]
                if existing.spec_hash != spec_hash:
                    existing.spec_hash = spec_hash
                    existing.data = manifest.get("data", {})
                    updated += 1
                    print(f"  [update] {key} (reconciled drift to {spec_hash})")

        # Prune dead unmanaged resources
        deleted = 0
        dead_keys = [k for k in self.live_cluster.keys() if k not in desired_keys]
        for dk in dead_keys:
            del self.live_cluster[dk]
            deleted += 1
            print(f"  [prune]  {dk} (removed from declarative spec)")

        return created, updated, deleted

    def inject_sops_secret(self, secret_name: str, namespace: str, ram_secret_path: str):
        """Simulates pipe from /run/secrets/ into Kubernetes Secret."""
        if ram_secret_path not in self.host.ram_secrets:
            raise FileNotFoundError(f"Secret path {ram_secret_path} not found in host RAM!")

        secret_value = self.host.ram_secrets[ram_secret_path]
        key = f"Secret/{namespace}/{secret_name}"
        spec_hash = hashlib.sha256(secret_value.encode()).hexdigest()[:16]

        self.live_cluster[key] = KubeResource(
            kind="Secret",
            name=secret_name,
            namespace=namespace,
            spec_hash=spec_hash,
            data={"value": secret_value}
        )
        print(f"  [secret-bridge] Injected {key} from RAM {ram_secret_path}")

def test_homelab_nix_k3s():
    # 1. Initialize Host State with valid sysctls and RAM secrets
    host = HostSystemState(
        sysctl={
            "net.ipv4.ip_forward": 1,
            "net.bridge.bridge-nf-call-iptables": 1,
            "fs.inotify.max_user_watches": 524288
        },
        loaded_modules={"overlay", "br_netfilter", "wireguard"},
        ram_secrets={
            "/run/secrets/api_token": "SUPER_SECRET_BEARER_TOKEN_9999",
            "/run/secrets/db_password": "CLUSTER_POSTGRES_PASSWORD"
        }
    )

    reconciler = DeclarativeClusterReconciler(host)

    # 2. Verify Host Prerequisites
    print("=== 1. Validating Host Prerequisites for k3s ===")
    assert reconciler.validate_host_prerequisites() is True
    print("  Host kernel sysctls and modules verified successfully.")

    # 3. Synchronize Initial Manifests (Generation 1)
    print("\n=== 2. Reconciling Generation 1 Cluster Manifests ===")
    gen1_manifests = [
        {
            "kind": "Deployment",
            "name": "blog-preview",
            "namespace": "web",
            "spec": {"image": "harus-blog:v1", "replicas": 1}
        },
        {
            "kind": "Service",
            "name": "blog-service",
            "namespace": "web",
            "spec": {"port": 3000, "targetPort": 3000}
        }
    ]
    created, updated, deleted = reconciler.sync_manifests(gen1_manifests)
    assert created == 2 and updated == 0 and deleted == 0
    assert len(reconciler.live_cluster) == 2

    # 4. Bridge Host RAM Secret into Kubernetes
    print("\n=== 3. SOPS-nix RAM Secret Bridge ===")
    reconciler.inject_sops_secret("app-token", "web", "/run/secrets/api_token")
    secret_res = reconciler.live_cluster["Secret/web/app-token"]
    assert secret_res.data["value"] == "SUPER_SECRET_BEARER_TOKEN_9999"

    # 5. Apply Generation 2 Manifests (Update image, prune service, add redis)
    print("\n=== 4. Reconciling Generation 2 Manifests (Drift & Prune) ===")
    gen2_manifests = [
        {
            "kind": "Deployment",
            "name": "blog-preview",
            "namespace": "web",
            "spec": {"image": "harus-blog:v2", "replicas": 2}  # Updated image and replicas!
        },
        {
            "kind": "Deployment",
            "name": "redis-cache",
            "namespace": "web",
            "spec": {"image": "redis:7.2", "replicas": 1}      # New deployment!
        }
        # Notice: Service/web/blog-service was removed from the desired state!
    ]
    # The injected Secret is not in this list, so this toy reconciler prunes it too
    created, updated, deleted = reconciler.sync_manifests(gen2_manifests)
    assert created == 1  # redis-cache
    assert updated == 1  # blog-preview
    assert deleted == 2  # blog-service + app-token (unmanaged in manifest list)

    assert "Deployment/web/blog-preview" in reconciler.live_cluster
    assert "Deployment/web/redis-cache" in reconciler.live_cluster
    assert "Service/web/blog-service" not in reconciler.live_cluster

    print("\nAll Homelab Nix-to-k3s Declarative Bridge tests PASSED!")

if __name__ == "__main__":
    test_homelab_nix_k3s()
```
