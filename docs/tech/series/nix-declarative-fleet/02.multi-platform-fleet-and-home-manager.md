## Before you start

If you use a Mac at work, a Linux box at home and a small ARM server, you probably set each one up by hand and keep a `setup.sh` full of `if [ "$(uname)" = Darwin ]` branches. They drift. This chapter shows how one Nix repository can describe all of them: it declares which packages, shell settings and dotfiles each machine gets, and one command applies the result.

Home Manager is the piece that manages your home directory. Rather than copying `.gitconfig` into place, it builds the file in the Nix store and creates a symlink from `~/.gitconfig` to it. Switching to a new configuration swaps the symlinks, and the old configuration stays available to roll back to.

Read [chapter 1](/tech/series/nix-declarative-fleet/01.nix-functional-model-and-flakes/) first; this chapter assumes you know what a store path and a flake are.

Terms used in this chapter:

- **fleet**: the set of machines managed from the one repository.
- **system triple**: a label such as `aarch64-darwin` or `x86_64-linux` naming a CPU architecture and operating system.
- **Home Manager**: a Nix tool that manages per-user packages and dotfiles declaratively.
- **generation**: one saved, numbered result of applying a configuration; you can switch back to an earlier one.
- **symlink forest**: a tree of symbolic links, here from your home directory into the Nix store, that Home Manager creates.
- **overlay**: a Nix function that modifies or adds packages to the package set.
- **channel**: a named release stream of the package collection, such as stable or unstable.

## Multi-Platform Fleet Architecture & Home Manager

Engineering teams and infrastructure practitioners rarely work on a single homogenous operating system. A representative workstation fleet often spans:

- High-performance Apple Silicon laptops (`aarch64-darwin`) for interactive development.
- M-series desktop workstations (`desktop-a`).
- Dedicated x86_64 Linux servers (`server-a`) hosting containers, storage, and homelab clusters.
- Edge ARM micro-servers (`edge-a` running `aarch64-linux`).
- Windows WSL2 instances (`wsl-a`).

Traditionally, managing dotfiles, developer toolchains, shells, and system packages across such diversity required brittle shell scripts (`setup.sh`, Ansible playbooks, or Brewfiles) loaded with `uname -s` conditional branches that drifted over time.

This chapter breaks down how **Nix Flakes** combined with **Home Manager** enables a unified, declarative configuration repository (`harus-nix`) that delivers bit-for-bit reproducible user environments across Darwin and Linux machines.

### 1. Heterogeneous Fleet Matrix Design

In a flake-based fleet configuration, the flake root serves as the single source of truth. Rather than maintaining separate Git repositories for each computer, we structure the fleet as a parameterized matrix:

```text
harus-nix/
├── flake.nix              # Flake inputs, follows, and system outputs
├── machines/              # Host-specific hardware and network bindings
│   ├── laptop-a.nix
│   ├── server-a.nix
│   ├── edge-a.nix
│   └── wsl-a.nix
├── modules/               # Reusable modular capabilities
│   ├── base.nix           # Common CLI tools, zsh, git configs
│   ├── dev-rust.nix       # Rust toolchains and LLVM headers
│   └── dev-cloud.nix      # kubectl, helm, k9s, awscli
└── users/                 # Declarative user profiles
    └── haru/
        ├── default.nix
        └── packages.nix
```

#### Pure System Parameterization

In `flake.nix`, the outputs define home-manager configurations keyed by `username@hostname`:

```nix
{
  outputs = { self, nixpkgs, nixpkgs-unstable, home-manager, ... }:
  let
    # Reusable multi-system helper
    mkHome = { system, username, hostname, extraModules ? [] }:
      home-manager.lib.homeManagerConfiguration {
        pkgs = import nixpkgs {
          inherit system;
          config.allowUnfree = true;
          overlays = [ (final: prev: {
            unstable = import nixpkgs-unstable { inherit system; config.allowUnfree = true; };
          }) ];
        };
        extraSpecialArgs = { inherit inputs username hostname; };
        modules = [
          ./users/${username}
          ./machines/${hostname}.nix
        ] ++ extraModules;
      };
  in {
    homeConfigurations = {
      "haru@laptop-a" = mkHome { system = "aarch64-darwin"; username = "haru"; hostname = "laptop-a"; };
      "haru@server-a" = mkHome { system = "x86_64-linux";  username = "haru"; hostname = "server-a"; };
      "haru@edge-a"   = mkHome { system = "aarch64-linux"; username = "haru"; hostname = "edge-a"; };
    };
  };
}
```

### 3. Home Manager: Declarative Dotfiles & Symlink Forests

While NixOS manages whole-system kernels and systemd services, **Home Manager** brings declarative management to the user's `$HOME` directory on *any* operating system, including macOS and non-NixOS Linux.

#### Symlink Forests vs Imperative Copying

Traditional dotfile managers copy files into `~/.config/` or `~/.zshrc`. This creates immediate configuration drift: editing a config directly in your home directory causes your local environment to diverge silently from version control.

Home Manager enforces strict immutability through **Symlink Forests**:

```text
~/.zshrc 
    -> /nix/store/h1a9...-home-manager-files/.zshrc 
    -> /nix/store/z98m...-zshrc

~/.config/nvim/init.lua 
    -> /nix/store/h1a9...-home-manager-files/.config/nvim/init.lua 
    -> /nix/store/c741...-init.lua
```

1. **Read-Only Targets**: The symlinks point to read-only paths inside `/nix/store/`. Attempting to save an ad-hoc edit in Vim throws a write-permission error, forcing engineers to record modifications in the flake repository.
2. **Atomic Generational Switching**: When you run `home-manager switch --flake .#<host>`:
   - A new generation directory `/nix/store/<hash>-home-manager-generation` is built.
   - An activation script diffs the old symlink forest against the new generation.
   - Obsolete symlinks are unlinked, updated symlinks are atomically repointed, and new files are created.
   - The `home-manager` profile link (under the Nix profiles directory, e.g. `~/.local/state/nix/profiles/` with current Nix) is atomically swapped to the new generation.

### 4. The Dual-Channel Overlay Pattern

A major friction in production infrastructure management is balancing **system stability** with **developer velocity**:

- Base development libraries (`glibc`, `openssl`, Python interpreters) should remain on the well-tested, battle-hardened stable channel (`nixos-26.05`).
- Fast-evolving developer CLI tools (`ast-grep`, `neovim`, `bun`, `uv`, `claude-code`) should track bleeding-edge upstream releases without waiting six months for the next NixOS release.

Nix solves this cleanly using the **Overlay Pattern**:

```nix
# modules/overlays.nix
{ inputs, ... }: {
  nixpkgs.overlays = [
    (final: prev: {
      # Expose bleeding-edge packages under `pkgs.unstable.<name>`
      unstable = import inputs.nixpkgs-unstable {
        system = prev.stdenv.hostPlatform.system;
        config.allowUnfree = true;
      };
    })
  ];
}
```

In any package list:

```nix
home.packages = [
  # Stable rock-solid core
  pkgs.git
  pkgs.tmux
  pkgs.htop

  # Bleeding-edge tools from master channel
  pkgs.unstable.neovim
  pkgs.unstable.bun
  pkgs.unstable.ripgrep
];
```

Because Nix paths are input-addressed, `pkgs.unstable.neovim` links against its own bleeding-edge dependencies without altering or destabilizing the shared `pkgs.git` binary.

### 5. Verification Lab: Multi-Platform Fleet & Generation Switch Simulator

The following Python script simulates:

1. Multi-platform machine configuration dispatch across Darwin and Linux.
2. Declarative package resolution with stable vs. unstable channel overlays.
3. Home Manager generation builds, atomic symlink forest updates in a target `$HOME`.
4. Generational rollback: reverting `$HOME` symlinks to a previous generation instantly.

```python
#!/usr/bin/env python3
"""
Lab: Multi-Platform Fleet Dispatcher, Home Manager Symlink Engine & Rollback
Verifies cross-platform matrix configuration, atomic symlinks, and generation rollback.
"""

from dataclasses import dataclass, field
from typing import Dict, List, Optional
import os
import hashlib

@dataclass
class Package:
    name: str
    version: str
    channel: str  # "stable" or "unstable"
    store_path: str = ""

    def __post_init__(self):
        h = hashlib.sha256(f"{self.channel}:{self.name}:{self.version}".encode()).hexdigest()[:16]
        self.store_path = f"/nix/store/{h}-{self.name}-{self.version}"

class MockChannel:
    def __init__(self, name: str, pkg_versions: Dict[str, str]):
        self.name = name
        self.pkg_versions = pkg_versions

    def get_package(self, pkg_name: str) -> Package:
        if pkg_name not in self.pkg_versions:
            raise KeyError(f"Package '{pkg_name}' not found in channel {self.name}")
        return Package(name=pkg_name, version=self.pkg_versions[pkg_name], channel=self.name)

class HostConfiguration:
    def __init__(self, hostname: str, system: str, stable_channel: MockChannel, unstable_channel: MockChannel):
        self.hostname = hostname
        self.system = system
        self.stable = stable_channel
        self.unstable = unstable_channel
        self.packages: List[Package] = []
        self.dotfiles: Dict[str, str] = {}  # target relative path -> file content

    def add_package(self, name: str, use_unstable: bool = False):
        channel = self.unstable if use_unstable else self.stable
        pkg = channel.get_package(name)
        self.packages.append(pkg)

    def add_dotfile(self, rel_path: str, content: str):
        self.dotfiles[rel_path] = content

@dataclass
class Generation:
    gen_id: int
    store_hash: str
    symlink_map: Dict[str, str]  # target_path -> store_target

class MockHomeManager:
    """Simulates Home Manager activation, symlink tree generation, and rollbacks."""
    def __init__(self, home_dir: str):
        self.home_dir = home_dir
        self.generations: List[Generation] = []
        self.current_gen_idx: int = -1
        self.virtual_filesystem: Dict[str, str] = {}  # path -> symlink_target or content

    def switch(self, host_config: HostConfiguration) -> int:
        gen_id = len(self.generations) + 1
        
        # Build generation store artifact hash
        hasher = hashlib.sha256()
        for p in sorted(host_config.packages, key=lambda x: x.name):
            hasher.update(p.store_path.encode())
        for path, content in sorted(host_config.dotfiles.items()):
            hasher.update(f"{path}:{content}".encode())
        gen_hash = hasher.hexdigest()[:16]

        # Build symlink map
        symlink_map = {}
        for rel_path, content in host_config.dotfiles.items():
            content_hash = hashlib.sha256(content.encode()).hexdigest()[:12]
            store_file_path = f"/nix/store/{content_hash}-{os.path.basename(rel_path)}"
            target_path = os.path.join(self.home_dir, rel_path)
            symlink_map[target_path] = store_file_path

        # Perform atomic activation: remove old generation symlinks not in new generation
        if self.current_gen_idx >= 0:
            old_gen = self.generations[self.current_gen_idx]
            for old_target in old_gen.symlink_map.keys():
                if old_target not in symlink_map:
                    self.virtual_filesystem.pop(old_target, None)

        # Apply new symlinks
        for target, store_target in symlink_map.items():
            self.virtual_filesystem[target] = f"SYMLINK->{store_target}"

        gen = Generation(gen_id=gen_id, store_hash=gen_hash, symlink_map=symlink_map)
        self.generations.append(gen)
        self.current_gen_idx = len(self.generations) - 1
        return gen_id

    def rollback(self, target_gen_id: int):
        target_idx = next((i for i, g in enumerate(self.generations) if g.gen_id == target_gen_id), None)
        if target_idx is None:
            raise ValueError(f"Generation {target_gen_id} not found!")

        old_gen = self.generations[self.current_gen_idx]
        new_gen = self.generations[target_idx]

        # Unlink obsolete paths
        for p in old_gen.symlink_map.keys():
            if p not in new_gen.symlink_map:
                self.virtual_filesystem.pop(p, None)

        # Re-point symlinks to target generation targets
        for target, store_target in new_gen.symlink_map.items():
            self.virtual_filesystem[target] = f"SYMLINK->{store_target}"

        self.current_gen_idx = target_idx

def test_fleet_and_home_manager():
    # 1. Setup stable and unstable channels
    stable = MockChannel("nixos-26.05", {
        "git": "2.44.0",
        "tmux": "3.4",
        "neovim": "0.9.5",
        "ripgrep": "14.1.0"
    })
    unstable = MockChannel("nixos-unstable", {
        "git": "2.45.1",
        "neovim": "0.10.0",  # Unstable has newer Neovim
        "bun": "1.4.2"
    })

    # 2. Configure two distinct fleet hosts: a laptop (Darwin) and a server (Linux)
    macbook = HostConfiguration("laptop-a", "aarch64-darwin", stable, unstable)
    macbook.add_package("git", use_unstable=False)
    macbook.add_package("neovim", use_unstable=True)  # Bleeding-edge on laptop!
    macbook.add_dotfile(".zshrc", "export ARCH=darwin\nalias ll='ls -la'")
    macbook.add_dotfile(".config/nvim/init.lua", "vim.opt.number = true")

    mini = HostConfiguration("server-a", "x86_64-linux", stable, unstable)
    mini.add_package("git", use_unstable=False)
    mini.add_package("neovim", use_unstable=False)  # Conservative on server!
    mini.add_dotfile(".zshrc", "export ARCH=linux\nalias ll='ls -la'")

    # Verify channel pinning
    print("=== 1. Package Channel Pinning Verification ===")
    mac_nvim = next(p for p in macbook.packages if p.name == "neovim")
    server_nvim = next(p for p in mini.packages if p.name == "neovim")
    print(f"  Laptop neovim: {mac_nvim.version} ({mac_nvim.channel})")
    print(f"  Server neovim: {server_nvim.version} ({server_nvim.channel})")
    assert mac_nvim.version == "0.10.0" and mac_nvim.channel == "nixos-unstable"
    assert server_nvim.version == "0.9.5" and server_nvim.channel == "nixos-26.05"

    # 3. Test Home Manager Generation Switch & Symlink Forest
    print("\n=== 2. Home Manager Activation & Symlink Forest ===")
    hm = MockHomeManager(home_dir="/var/user/alice")
    gen1 = hm.switch(macbook)
    assert gen1 == 1

    zshrc_path = "/var/user/alice/.zshrc"
    nvim_path = "/var/user/alice/.config/nvim/init.lua"
    assert zshrc_path in hm.virtual_filesystem
    assert nvim_path in hm.virtual_filesystem
    assert hm.virtual_filesystem[zshrc_path].startswith("SYMLINK->/nix/store/")
    print(f"  ~/.zshrc -> {hm.virtual_filesystem[zshrc_path]}")

    # 4. Modify configuration to trigger Generation 2 (remove nvim config, update zshrc)
    print("\n=== 3. Generation 2 Switch & Obsolete Symlink Cleanup ===")
    macbook_v2 = HostConfiguration("laptop-a", "aarch64-darwin", stable, unstable)
    macbook_v2.add_dotfile(".zshrc", "export ARCH=darwin\nalias ll='eza -la'")
    # Notice: .config/nvim/init.lua was removed!
    gen2 = hm.switch(macbook_v2)
    assert gen2 == 2
    # nvim_path should be unlinked!
    assert nvim_path not in hm.virtual_filesystem, "Obsolete dotfile must be unlinked in new generation!"

    # 5. Atomic Rollback to Generation 1
    print("\n=== 4. Instant Generation Rollback ===")
    hm.rollback(target_gen_id=1)
    assert nvim_path in hm.virtual_filesystem, "Rollback must restore previous generation symlinks!"
    print(f"  Successfully rolled back to Gen 1. Restored: {nvim_path}")

    print("All Multi-Platform Fleet & Home Manager tests PASSED!")

if __name__ == "__main__":
    test_fleet_and_home_manager()
```

### 6. Summary & Key Takeaways

1. **Matrix Fleet Convergence**: Structuring hosts as parameter matrices under `flake.nix` eliminates snowflake configurations across Darwin and Linux systems.
2. **Symlink Forest Discipline**: Home Manager guarantees that dotfiles are pure projections of the Nix store, preventing uncommitted configuration drift.
3. **Dual-Channel Flexibility**: Overlays allow bleeding-edge developer tools (`pkgs.unstable.<tool>`) to move at high velocity without compromising core system library stability.
4. **Instantaneous Rollbacks**: If a newly switched configuration breaks shell startup or toolchains, rolling back to the previous generation restores working state in seconds.
