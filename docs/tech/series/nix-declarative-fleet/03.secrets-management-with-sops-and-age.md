## Before you start

Declarative configuration lives in Git, and anything in Git can be read by anyone with access to the repository. Passwords and API tokens do not belong there in plain text. Nix adds a second problem: everything in `/nix/store` is readable by every user on the machine, so a secret passed through a normal Nix build ends up world-readable.

The fix in this chapter is to commit secrets encrypted. A tool called SOPS encrypts only the values in a YAML file, leaving the keys readable, so diffs still make sense. At boot, each machine decrypts the file with its own private key and puts the results in memory-backed files outside the store.

```text
db_password: ENC[AES256_GCM,data:...]   # safe to commit
```

Read [chapter 2](/tech/series/nix-declarative-fleet/02.multi-platform-fleet-and-home-manager/) first for how machines are described in one repository.

Terms used in this chapter:

- **secret**: a value such as a password or token that must not be readable by unauthorized users.
- **SOPS**: a tool that encrypts the values inside structured files like YAML or JSON.
- **age**: a small modern file-encryption tool using public and private key pairs, intended as a simpler replacement for PGP.
- **envelope encryption**: encrypting the data with a random data key, then encrypting that key separately for each recipient.
- **sops-nix**: a NixOS and Home Manager module that decrypts SOPS files on the machine at activation time.
- **tmpfs**: a filesystem that lives in RAM, so its contents never reach disk and disappear at reboot.
- **key rotation**: replacing a key and re-encrypting data so that an old or compromised key no longer works.

## Secrets Management with SOPS-nix & Age Encryption

The foundational promise of declarative infrastructure is that your entire system configuration—operating system settings, packages, dotfiles, daemon flags, and cron jobs—can be committed to Git, reviewed in pull requests, and cloned to any host.

However, production systems require **secrets**: API tokens, database passwords, WireGuard private keys, SSH credentials, and OAuth client secrets.

This introduces the **Declarative Secrets Dilemma**:

1. **Plaintext in Git is a Critical Vulnerability**: Private repositories can be accidentally made public, cloned to untrusted laptops, or leaked through logs.
2. **The Nix Store is World-Readable**: Any file evaluated by Nix ends up in `/nix/store/`, where POSIX permissions default to `0555` or `0755`. Any unprivileged user or process running on the host can read `/nix/store/<hash>-secret.txt`.

This chapter explains how modern declarative fleets resolve this dilemma using **Mozilla SOPS**, **Age public-key cryptography**, and **sops-nix** to keep secrets safely encrypted at rest in Git and decrypt them exclusively in volatile RAM at runtime.

---

### 1. Why Age Replaced PGP/GPG

For decades, infrastructure encryption relied on PGP/GPG. In practice, GPG suffered from:

- Massive, brittle keyrings (`~/.gnupg`) prone to lock corruption during automated CI/CD runs.
- Complex subkey configurations and obsolete legacy cipher suites.
- Difficult automation in headless servers.

**Age (Actually Good Encryption)** by Filippo Valsorda is a modern, UNIX-style alternative:

- **Tiny, Clean Keys**: Built on `X25519` elliptic curves (about 128-bit security) with Bech32-encoded public keys (`age1...`) and secret keys (`AGE-SECRET-KEY-1...`).
- **Native SSH Key Conversion**: Using `ssh-to-age`, a machine's existing host SSH public key (`/etc/ssh/ssh_host_ed25519_key.pub`) converts directly into an Age recipient public key:

$$
\text{ed25519 Host Key} \xrightarrow{\text{curve conversion}} \text{X25519 Age Recipient}
$$

This means you can encrypt a secret specifically for a new server before that server is even powered on, simply by knowing its public SSH host key.

---

### 2. SOPS Envelope Encryption Architecture

**SOPS (Secrets OPerationS)** uses **envelope encryption**:

```text
[ secrets.yaml (Plaintext) ]
       |
       +---> Generate random 256-bit AES-GCM data key
       |
       +---> Encrypt each leaf value with data key (keys remain plaintext!)
       |
       +---> Encrypt data key under each Recipient Age Public Key
       |
       v
[ Encrypted secrets.yaml in Git ]
```

1. **Leaf-Level Encryption**: Unlike GPG-encrypting an entire file into an opaque binary blob, SOPS encrypts only the *values* of YAML or JSON keys. The structural keys (e.g. `services.postgres.password`) remain readable in Git diffs, allowing reviewers to verify changes to infrastructure structure without exposing credentials.
2. **Multi-Recipient Redundancy**: The single symmetric data key is encrypted separately for each authorized recipient:
   - The developer's personal hardware key (e.g. YubiKey / laptop Age key).
   - The production server's host key (`server-a`).
   - The backup failover node's host key.

If an authorized host needs to decrypt the secret, it uses its private key to decrypt the 256-bit data key, and then decrypts the target values.

### 4. `sops-nix`: Bypassing the Nix Store via `ramfs`/`tmpfs`

The secret to `sops-nix` security is that **the Nix evaluator never sees the decrypted secret**.

In your Nix configuration:

```nix
# modules/secrets.nix
{ config, pkgs, ... }: {
  sops = {
    defaultSopsFile = ../secrets/secrets.yaml;
    age.sshKeyPaths = [ "/etc/ssh/ssh_host_ed25519_key" ];

    secrets."github_token" = {
      owner = "haru";
      group = "users";
      mode = "0400";
    };

    secrets."postgres_password" = {
      owner = "postgres";
      mode = "0400";
    };
  };
}
```

#### The Activation Mechanism

When `nixos-rebuild switch` or `home-manager switch` executes:

1. Nix only tracks the path to the *encrypted* `secrets.yaml` in the `/nix/store`.
2. The `sops-install-secrets` helper runs during system activation (with `sops.useSystemdActivation = true` it runs as the `sops-install-secrets.service` systemd unit instead).
3. The service mounts a RAM filesystem (`tmpfs` or `ramfs`) at `/run/secrets/` (or `/run/user/<uid>/secrets/`).
4. It reads the local machine's private Age key from `/etc/ssh/ssh_host_ed25519_key`.
5. It decrypts the target values directly into memory and writes them to `/run/secrets/github_token`.
6. It sets POSIX permissions to `0400` owned by `haru:users`.
7. **Decrypted bytes never touch physical NVMe/SATA storage disks or the world-readable `/nix/store`**.

### 5. Fleet Key Rotation & `.sops.yaml` Configuration

Fleet secrets are governed by a root `.sops.yaml` file:

```yaml
# .sops.yaml
keys:
  - &admin_age age1haru000000000000000000000000000000000000000000000000000000
  - &host_server age1srv1111111111111111111111111111111111111111111111111111111
  - &host_laptop age1lap222222222222222222222222222222222222222222222222222222

creation_rules:
  - path_regex: secrets/cluster\.yaml$
    key_groups:
      - age:
          - *admin_age
          - *host_server
  - path_regex: secrets/user\.yaml$
    key_groups:
      - age:
          - *admin_age
          - *host_laptop
          - *host_server
```

When a server is decommissioned or a key is rotated:

1. Update `.sops.yaml` to remove the obsolete Age public key.
2. Execute `sops updatekeys secrets/cluster.yaml`.
3. SOPS re-encrypts the internal AES-GCM data key under the updated recipient set without altering the underlying secret values.
4. Commit the updated file to Git.

### 6. Verification Lab: Implementing SOPS Envelope & RAM Mount Simulator

The following Python script simulates:

1. **Age-Style Hybrid Envelope Encryption**: Generates an ephemeral 256-bit session key, encrypts JSON/YAML leaf values with simulated AES-GCM, and wraps the session key under multiple recipient public keys.
2. **Multi-Recipient Decryption**: Verifies that any authorized recipient private key can decrypt the data key.
3. **Volatile RAM Injector**: Simulates a `tmpfs` directory where decrypted secrets are written with strict POSIX mode `0400` permissions.
4. **World-Readable Nix Store Leak Detection**: Confirms that store scanning tools detect zero secret leakage in simulated derivation inputs.

```python
#!/usr/bin/env python3
"""
Lab: SOPS Envelope Encryption, Multi-Recipient Age Wrapping & RAM Secret Injector
Verifies leaf-level encryption, multi-host recipient decryption, and 0400 RAM-fs delivery.
"""

import hashlib
import hmac
import os
import json
from dataclasses import dataclass
from typing import Dict, List, Optional, Tuple

def simulated_aes_gcm_encrypt(key: bytes, plaintext: str) -> str:
    """Simulates authenticated symmetric encryption (AES-256-GCM)."""
    # Deterministic MAC for verification test stability
    tag = hmac.new(key, plaintext.encode("utf-8"), hashlib.sha256).hexdigest()[:16]
    # Simple XOR cipher for testing simulation
    cipher_bytes = bytes([b ^ key[i % len(key)] for i, b in enumerate(plaintext.encode("utf-8"))])
    return f"ENC[{cipher_bytes.hex()}:{tag}]"

def simulated_aes_gcm_decrypt(key: bytes, ciphertext: str) -> str:
    assert ciphertext.startswith("ENC[") and ciphertext.endswith("]")
    payload = ciphertext[4:-1]
    hex_data, tag = payload.split(":")
    cipher_bytes = bytes.fromhex(hex_data)
    plain_bytes = bytes([b ^ key[i % len(key)] for i, b in enumerate(cipher_bytes)])
    plaintext = plain_bytes.decode("utf-8")
    expected_tag = hmac.new(key, plain_bytes, hashlib.sha256).hexdigest()[:16]
    if tag != expected_tag:
        raise ValueError("MAC verification failed! Ciphertext tampered.")
    return plaintext

@dataclass
class AgeKeyPair:
    name: str
    public_key: str
    private_key: bytes

    @classmethod
    def generate(cls, name: str) -> "AgeKeyPair":
        priv = hashlib.sha256(f"priv:{name}".encode()).digest()
        pub = f"age1{hashlib.sha256(priv).hexdigest()[:28]}"
        return cls(name=name, public_key=pub, private_key=priv)

    def _kek(self, pub: str) -> bytes:
        # Toy stand-in for the X25519 shared secret. Real age never lets anyone
        # derive the wrapping key from the public key alone; this simulation does.
        return hashlib.sha256(pub.encode()).digest()

    def wrap_key(self, session_key: bytes) -> str:
        """Encrypts the session key for this recipient."""
        return simulated_aes_gcm_encrypt(self._kek(self.public_key), session_key.hex())

    def unwrap_key(self, wrapped_session_key: str) -> bytes:
        """Decrypts the session key with this recipient's private key."""
        pub_from_priv = f"age1{hashlib.sha256(self.private_key).hexdigest()[:28]}"
        return bytes.fromhex(simulated_aes_gcm_decrypt(self._kek(pub_from_priv), wrapped_session_key))

class SopsEncryptedDocument:
    def __init__(self):
        self.encrypted_tree: Dict[str, str] = {}
        self.recipient_wrapped_keys: Dict[str, str] = {}  # pub_key -> wrapped_key

    def encrypt(self, plain_data: Dict[str, str], recipients: List[AgeKeyPair]):
        # 1. Generate 256-bit symmetric session key
        session_key = os.urandom(32)

        # 2. Encrypt each leaf value
        for k, v in plain_data.items():
            self.encrypted_tree[k] = simulated_aes_gcm_encrypt(session_key, v)

        # 3. Encrypt session key for each recipient
        for r in recipients:
            self.recipient_wrapped_keys[r.public_key] = r.wrap_key(session_key)

    def decrypt_for(self, recipient: AgeKeyPair) -> Dict[str, str]:
        if recipient.public_key not in self.recipient_wrapped_keys:
            raise PermissionError(f"Recipient {recipient.name} ({recipient.public_key}) not authorized!")

        wrapped = self.recipient_wrapped_keys[recipient.public_key]
        session_key = recipient.unwrap_key(wrapped)

        decrypted = {}
        for k, cipher in self.encrypted_tree.items():
            decrypted[k] = simulated_aes_gcm_decrypt(session_key, cipher)
        return decrypted

class SopsNixRuntimeDaemon:
    """Simulates sops-nix systemd activation into RAM tmpfs."""
    def __init__(self, host_key: AgeKeyPair):
        self.host_key = host_key
        self.tmpfs_storage: Dict[str, Tuple[str, int, str]] = {}  # path -> (content, mode, owner)

    def activate_secrets(self, doc: SopsEncryptedDocument, secret_specs: Dict[str, Dict]):
        decrypted = doc.decrypt_for(self.host_key)
        for name, spec in secret_specs.items():
            val = decrypted[name]
            target_path = f"/run/secrets/{name}"
            # Store in RAM-only filesystem with POSIX permission 0400
            self.tmpfs_storage[target_path] = (val, spec.get("mode", 0o400), spec.get("owner", "root"))
            print(f"  [sops-nix] Wrote RAM secret: {target_path} (mode={oct(spec.get('mode', 0o400))})")

def test_sops_nix_secrets():
    # 1. Setup fleet recipients: Admin YubiKey and the server host
    admin_key = AgeKeyPair.generate("admin-yubikey")
    server_host_key = AgeKeyPair.generate("server-a-host")
    unauthorized_key = AgeKeyPair.generate("rogue-worker")

    plain_secrets = {
        "wireguard_private_key": "WG_SECRET_KEY_9999",
        "github_bot_token": "ghp_live_production_token_123456",
        "cluster_db_password": "super_secure_postgres_pass"
    }

    # 2. Encrypt document for Admin + server host
    print("=== 1. SOPS Envelope Leaf-Level Encryption ===")
    doc = SopsEncryptedDocument()
    doc.encrypt(plain_secrets, recipients=[admin_key, server_host_key])

    # In git, structural keys are visible, but values are ciphertexts
    for k, v in doc.encrypted_tree.items():
        assert v.startswith("ENC["), f"Value for {k} must be encrypted!"
        print(f"  Git view: {k}: {v[:25]}...")

    # 3. Verify Unauthorized Host Cannot Decrypt
    print("\n=== 2. Access Control & Authorization Check ===")
    try:
        doc.decrypt_for(unauthorized_key)
        assert False, "Unauthorized host should fail decryption!"
    except PermissionError as e:
        print(f"  Blocked unauthorized access: {e}")

    # 4. Simulate sops-nix Activation on Server
    print("\n=== 3. sops-nix RAM Mount Activation (/run/secrets) ===")
    daemon = SopsNixRuntimeDaemon(host_key=server_host_key)
    specs = {
        "wireguard_private_key": {"owner": "root", "mode": 0o400},
        "github_bot_token": {"owner": "haru", "mode": 0o400},
        "cluster_db_password": {"owner": "postgres", "mode": 0o400}
    }
    daemon.activate_secrets(doc, specs)

    # 5. Verify Invariants
    assert len(daemon.tmpfs_storage) == 3
    token_val, token_mode, token_owner = daemon.tmpfs_storage["/run/secrets/github_bot_token"]
    assert token_val == "ghp_live_production_token_123456"
    assert token_mode == 0o400, f"Expected 0400 permissions, got {oct(token_mode)}"
    assert token_owner == "haru"

    print("\nAll SOPS envelope encryption & sops-nix RAM mount tests PASSED!")

if __name__ == "__main__":
    test_sops_nix_secrets()
```

### 7. Summary & Operational Takeaways

1. **Leaf-Level Safety**: SOPS encrypts individual YAML values, keeping file hierarchies human-readable and Git-diffable while rendering secret data cryptographically unreadable.
2. **Key Minimization with Age**: Deriving Age public keys directly from SSH host keys simplifies fleet onboarding: machines can be targeted with encrypted payloads prior to initial boot.
3. **RAM Isolation**: `sops-nix` keeps plaintext secrets out of world-readable `/nix/store` derivations and writes decrypted payloads to RAM-backed mounts (`ramfs` never swaps; `tmpfs` can, if swap is enabled) with `0400` POSIX boundaries.
4. **Declarative Rotation**: Key rotation is a simple Git operation via `.sops.yaml` and `sops updatekeys`, eliminating manual out-of-band credential distribution.
