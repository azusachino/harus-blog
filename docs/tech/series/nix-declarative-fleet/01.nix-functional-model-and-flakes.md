## Before you start

This series is for programmers who maintain more than one machine and are tired of setup scripts that drift. The chapters build on each other, starting with the Nix package model here.

Most package managers install files into shared directories like `/usr/bin` and overwrite them on upgrade, so the state of a machine depends on the order of past commands. Nix instead builds each package into its own directory named after a hash of everything that went into it, for example `/nix/store/<hash>-hello-2.12`. Two versions never collide, and the same inputs give the same path. A **flake** pins all of a project's inputs in a lock file so that the same repository builds the same result on every machine.

A two-line taste: `nix run nixpkgs#hello` fetches and runs a pinned build of `hello` without installing it.

You only need basic command-line use. Nix's own language is introduced as the chapter goes; it is a small functional language where files are mostly expressions that return values.

Terms used in this chapter:

- **Nix store**: the read-only directory `/nix/store` where every build result lives under a hash-based name.
- **derivation**: a recipe, written to a `.drv` file, that names the inputs, build command and outputs of one build.
- **closure**: a package plus everything it depends on, transitively.
- **sandbox**: the isolated environment a build runs in, with no network and only the declared inputs visible.
- **flake**: a project with a `flake.nix` that declares its inputs and outputs in a fixed structure.
- **lock file**: `flake.lock`, which records the exact revision and hash of each flake input.
- **hermetic / pure**: depending only on declared inputs, not on the machine's ambient state like environment variables or the clock.

## The Nix Functional Model, Store Derivations & Flakes

In conventional operating systems—whether Debian, Arch, macOS, or Windows—package managers operate via **destructive global mutation**. Installing, upgrading, or removing a package executes imperative post-install scripts that overwrite shared directories like `/usr/bin`, `/usr/lib`, or `/Library`. If two applications depend on incompatible minor versions of `glibc`, `openssl`, or Python, system administrators face dependency hell, broken symlinks, and non-reproducible snowflake machines.

**Nix** treats system configuration as a **pure mathematical function**:

$$
\text{System State} = F(\text{Source Code}, \text{Compiler Toolchain}, \text{Dependencies}, \text{Environment Flags})
$$

Given identical inputs, the function deterministically yields identical filesystem outputs. Every package and configuration artifact resides in an isolated, immutable directory under `/nix/store/`.

This first chapter examines the underlying architecture of Nix: how high-level Nix expressions evaluate into low-level derivation files (`.drv`), how the daemon builds packages inside network-isolated hermetic sandboxes, and how **Nix Flakes** eliminate mutable ambient state to ensure reproducible fleet deployments.

### 1. The Immutable Nix Store & Hash Addressing

At the core of Nix is the store: `/nix/store/`. Unlike traditional hierarchies where binaries intermingle in `/bin`, every artifact in `/nix/store/` is named using a unique cryptographic hash prefix:

```text
/nix/store/s66mzxpvicwk0735ipq8j17sf2jh52zh-ripgrep-14.1.0/
├── bin/
│   └── rg
└── share/
    └── man/
```

#### Input-Addressed Store Paths

In standard Nix, store paths are **input-addressed**. The 32-character prefix is a base-32 encoding of a 160-bit hash (SHA-256 compressed down to 160 bits) computed over all inputs required to build that package:

- Exact source code tarball hash.
- The build script and compiler flags.
- The exact store paths of all transitive build dependencies (compilers, libraries, headers).

Because the path incorporates all dependencies, installing `openssl-3.0` does not touch or invalidate an application compiled against `openssl-1.1`. Both versions coexist on the same filesystem without collision.

#### Content-Addressed Derivations (`ca-derivations`, experimental)

In input-addressed storage, changing a single comment in a base C compiler forces every downstream package in the dependency tree to recompile, even if the resulting binary output is byte-for-byte identical.

**Content-addressed Nix** calculates the store hash from the **cryptographic hash of the built output artifacts** rather than the inputs. If an upstream rebuild produces bit-identical machine code, Nix recognizes that the content hash matches and halts downstream recompilation cascades.

### 2. Derivations: The Contract Between Evaluation and Build

Nix strictly decouples **Evaluation** (interpreting the Nix language) from **Realisation** (compiling code and creating filesystem artifacts).

```text
[ .nix Source Files ]
         |
         |  Phase 1: nix-instantiate (Evaluation)
         v
[ .drv Derivation File in /nix/store ]  (ATerm representation of build DAG)
         |
         |  Phase 2: nix-store --realise (Sandboxed Execution)
         v
[ /nix/store/<hash>-<pkg> Outputs ]     (Read-only runtime binaries & libraries)
```

#### The Anatomy of a `.drv`

When you evaluate a Nix expression, the Nix evaluator writes a `.drv` file into `/nix/store/`. This file is an ATerm (Abstract Term) serialization detailing the explicit build recipe:

```nix
Derive([("out","/nix/store/abc...-my-tool","","")],
  [("/nix/store/xyz...-glibc-2.38.drv",["out"])],
  ["/nix/store/123...-builder.sh"],
  "x86_64-linux",
  "/nix/store/456...-bash-5.2/bin/bash",
  ["-e","/nix/store/123...-builder.sh"],
  [("buildInputs","..."),("name","my-tool-1.0.0"),("out","/nix/store/abc...-my-tool"),("system","x86_64-linux")])
```

1. **Outputs**: List of output names and predicted store paths.
2. **Input Derivations**: Dependencies that must be built *before* this derivation can execute.
3. **Builder & Arguments**: The executable (usually `bash`) and flags invoked to run the build.
4. **Environment Variables**: Key-value pairs passed directly to the builder process.

#### Hermetic Sandboxing

When `nix-daemon` executes a derivation:

- **Mount & User Namespaces**: The build executes inside a clean Linux container namespace with a private `/tmp` and isolated PID space.
- **Network Isolation**: Network access is completely disabled (the loopback interface is down). A package cannot fetch undeclared dependencies from the internet during compilation.
- **Time Freezing**: File modification times in build outputs are reset to a fixed value after the build, and `stdenv` exports `SOURCE_DATE_EPOCH=315532800` (1980-01-01 00:00:00 UTC) so tools that embed timestamps in ZIPs or tarballs stay deterministic.
- **Fixed-Output Derivations (FOD)**: When network access *is* required (e.g. downloading source code via `fetchurl` or `fetchFromGitHub`), the derivation must declare an expected cryptographic hash (`hash = "sha256-..."`). The sandbox allows network access for downloading, but immediately validates the output against the declared hash before admitting it to the store.

### 3. Nix Flakes: Hermetic, Pure Composition

Historically, Nix relied on **channels** (`nix-channel --update`) and search paths (`<nixpkgs>`). This introduced hidden ambient state: running `nix-build` on two machines could yield different results if one machine had updated its channels a week later.

Introduced in Nix 2.4, **Flakes** solve this by enforcing:

1. **Purity by Default**: Flake evaluation cannot read arbitrary files outside the repository root or read environment variables without explicit opt-in.
2. **Deterministic Version Pinning**: A `flake.lock` file records the exact Git commit SHA, tree hash, and revision of every external dependency.

#### Anatomy of `flake.nix`

```nix
{
  description = "harus-nix — personal multi-machine fleet configuration";

  inputs = {
    nixpkgs.url = "github:nixos/nixpkgs/nixos-26.05";
    nixpkgs-unstable.url = "github:nixos/nixpkgs/nixos-unstable";

    home-manager = {
      url = "github:nix-community/home-manager/release-26.05";
      inputs.nixpkgs.follows = "nixpkgs";
    };
  };

  outputs = { self, nixpkgs, nixpkgs-unstable, home-manager, ... }: {
    # System & user configurations exported across fleet
  };
}
```

#### The Power of `inputs.<name>.follows`

When managing complex multi-module fleets, nested inputs can pull in conflicting versions of `nixpkgs`:

```text
Fleet Flake
  ├── nixpkgs (rev: abc1)
  └── home-manager
        └── nixpkgs (rev: def2)  <-- Duplicate dependency tree!
```

By configuring `inputs.home-manager.inputs.nixpkgs.follows = "nixpkgs"`, Nix forces `home-manager` to evaluate against the top-level flake's pinned `nixpkgs`. This eliminates hundreds of redundant derivation evaluations and gigabytes of duplicate package builds.

### 4. Verification Lab: Implementing a Pure Derivation & Store Engine

To cement the principles of pure input-addressed derivations, store path hashing, and sandboxed DAG builds, the following Python script implements a self-contained Nix store engine:

- Computes Nix-style truncated base-32 SHA-256 store paths from input attributes.
- Validates Fixed-Output Derivation (FOD) output hashes.
- Builds a topological dependency graph (DAG) of derivations, rejecting circular dependencies.
- Simulates hermetic builds and skips derivations whose output path is already in the store.

```python
#!/usr/bin/env python3
"""
Lab: Nix Store Path Hashing, Pure Derivation Evaluator & Hermetic DAG Builder
Verifies input-addressed path generation, dependency ordering, and store immutability.
"""

import hashlib
import os
from dataclasses import dataclass, field
from typing import Dict, List, Set, Optional

# Nix uses a specific 32-character alphabet (digits and lowercase letters excluding e, o, u, t)
NIX_BASE32_ALPHABET = "0123456789abcdfghijklmnpqrsvwxyz"

def nix_base32_encode(digest: bytes) -> str:
    """Encodes bytes into Nix-compatible base32 (32 characters from 160 bits)."""
    # Nix hashes truncated to 160 bits (20 bytes) for store path naming
    truncated = digest[:20]
    num = int.from_bytes(truncated, byteorder="big")
    chars = []
    for _ in range(32):
        chars.append(NIX_BASE32_ALPHABET[num & 0x1F])
        num >>= 5
    return "".join(chars)

def compute_store_path(name: str, input_hash_str: str) -> str:
    """
    Computes Nix input-addressed store path:
    /nix/store/<hash>-<name>
    """
    s = f"input-addressed:{input_hash_str}:{name}".encode("utf-8")
    digest = hashlib.sha256(s).digest()
    hash_prefix = nix_base32_encode(digest)
    return f"/nix/store/{hash_prefix}-{name}"

@dataclass
class Derivation:
    name: str
    builder_fn: str  # Simulated builder command
    env: Dict[str, str] = field(default_factory=dict)
    input_drvs: List["Derivation"] = field(default_factory=list)
    output_hash: Optional[str] = None  # Non-empty for Fixed-Output Derivations (FOD)

    def compute_drv_hash(self) -> str:
        """Computes deterministic hash representing all build inputs."""
        hasher = hashlib.sha256()
        hasher.update(self.name.encode("utf-8"))
        hasher.update(self.builder_fn.encode("utf-8"))
        for k in sorted(self.env.keys()):
            hasher.update(f"{k}={self.env[k]}".encode("utf-8"))
        for dep in sorted(self.input_drvs, key=lambda d: d.name):
            hasher.update(dep.compute_drv_hash().encode("utf-8"))
        if self.output_hash:
            hasher.update(f"outputHash={self.output_hash}".encode("utf-8"))
        return hasher.hexdigest()

    def get_out_path(self) -> str:
        drv_hash = self.compute_drv_hash()
        return compute_store_path(self.name, drv_hash)

class MockNixStore:
    def __init__(self):
        self.store: Dict[str, Dict[str, str]] = {}  # store_path -> {filename: content}

    def realise(self, drv: Derivation) -> str:
        """Topologically resolves and builds derivation DAG into store."""
        build_order = self._toposort(drv)

        for current in build_order:
            out_path = current.get_out_path()
            if out_path in self.store:
                continue  # Already realised (cached)

            # Build in isolated sandbox
            build_outputs = self._execute_sandboxed_builder(current)

            # Validate FOD if required
            if current.output_hash:
                combined = "".join(build_outputs.values()).encode("utf-8")
                actual_hash = hashlib.sha256(combined).hexdigest()
                if actual_hash != current.output_hash:
                    raise ValueError(
                        f"FOD hash mismatch on {current.name}: expected {current.output_hash}, got {actual_hash}"
                    )

            # Register in store as immutable
            self.store[out_path] = build_outputs
            print(f"  [realise] Built: {out_path}")

        return drv.get_out_path()

    def _toposort(self, root: Derivation) -> List[Derivation]:
        visited: Set[str] = set()
        visiting: Set[str] = set()
        order: List[Derivation] = []

        def dfs(d: Derivation):
            if d.name in visiting:
                raise ValueError(f"Cyclic dependency detected involving {d.name}")
            if d.name in visited:
                return
            visiting.add(d.name)
            for dep in d.input_drvs:
                dfs(dep)
            visiting.remove(d.name)
            visited.add(d.name)
            order.append(d)

        dfs(root)
        return order

    def _execute_sandboxed_builder(self, drv: Derivation) -> Dict[str, str]:
        """Simulates hermetic builder execution without network access."""
        outputs = {}
        if drv.builder_fn == "fetchurl":
            outputs["source.tar.gz"] = drv.env.get("RAW_CONTENT", "source_archive_bytes")
        elif drv.builder_fn == "gcc":
            dep_paths = [dep.get_out_path() for dep in drv.input_drvs]
            outputs["bin/app"] = f"ELF_BINARY_LINKED_AGAINST:{':'.join(dep_paths)}"
        else:
            outputs["out"] = f"BUILD_RESULT:{drv.name}"
        return outputs

def test_nix_store_engine():
    store = MockNixStore()

    # 1. Fixed-Output Derivation (fetching source tarball)
    src_content = "tarball_payload_v1.0"
    src_hash = hashlib.sha256(src_content.encode("utf-8")).hexdigest()
    src_drv = Derivation(
        name="ripgrep-source-14.1.0",
        builder_fn="fetchurl",
        env={"RAW_CONTENT": src_content},
        output_hash=src_hash
    )

    # 2. Dependency: C Runtime / glibc
    glibc_drv = Derivation(
        name="glibc-2.38",
        builder_fn="gcc",
        env={"CFLAGS": "-O2"}
    )

    # 3. Target application depending on source and glibc
    ripgrep_drv = Derivation(
        name="ripgrep-14.1.0",
        builder_fn="gcc",
        input_drvs=[src_drv, glibc_drv],
        env={"CARGO_BUILD_TARGET": "x86_64-unknown-linux-gnu"}
    )

    print("=== 1. Derivation Output Path Determination ===")
    rg_out = ripgrep_drv.get_out_path()
    print(f"  Target store path: {rg_out}")
    assert rg_out.startswith("/nix/store/")
    hash_part = os.path.basename(rg_out).split("-")[0]
    assert len(hash_part) == 32, f"Expected 32-char Nix base32 hash, got {hash_part} ({len(hash_part)})"

    print("\n=== 2. Realising Derivation DAG in Dependency Order ===")
    built_path = store.realise(ripgrep_drv)
    assert built_path == rg_out
    assert len(store.store) == 3, f"Expected 3 packages in store, found {len(store.store)}"

    # 4. Verify immutability & cache hit
    print("\n=== 3. Store Deduplication / Idempotent Realise ===")
    cached_path = store.realise(ripgrep_drv)
    assert cached_path == built_path

    # 5. Verify input-addressed cascade: modifying glibc CFLAGS produces distinct store path
    glibc_modified = Derivation(
        name="glibc-2.38",
        builder_fn="gcc",
        env={"CFLAGS": "-O3 -march=native"}
    )
    rg_rebuilt = Derivation(
        name="ripgrep-14.1.0",
        builder_fn="gcc",
        input_drvs=[src_drv, glibc_modified],
        env={"CARGO_BUILD_TARGET": "x86_64-unknown-linux-gnu"}
    )
    assert rg_rebuilt.get_out_path() != rg_out, "Modifying dependency must alter target store path!"

    print("All Nix functional model and derivation tests PASSED!")

if __name__ == "__main__":
    test_nix_store_engine()
```

### 5. Summary & Key Takeaways

1. **Pure Store Architecture**: Every package lives under `/nix/store/<hash>-<name>`, preventing version clashes and enabling atomic rollbacks.
2. **Two-Phase Decoupling**: High-level Nix expressions evaluate purely into low-level `.drv` DAGs (`nix-instantiate`) before the sandbox compiles binaries (`nix-store --realise`).
3. **Hermetic Build Sandboxes**: Builds run isolated from host networking and environment noise with standardized timestamps, guaranteeing reproducible binary outputs.
4. **Flakes Lock the World**: `flake.nix` and `flake.lock` replace mutable channels with explicit Git revision pins and `follows` deduplication.
