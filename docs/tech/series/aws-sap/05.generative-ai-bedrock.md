The elevation of Generative AI into **Domain 1 (Architecture Design)** and **Domain 2 (Security & Governance)** is the single most defining signature of the **AWS Certified Solutions Architect - Professional (SAP-C03)** exam. In enterprise architecture, the hard parts of generative AI are **data boundary defense, private network topology, retrieval-augmented generation (RAG), and zero-trust model governance**, much more than prompt wording.

When enterprise boards approve generative AI initiatives, the architectural contract is uncompromising: proprietary corporate data must never leak to third-party model providers, training data must never be used to retrain base models, PII and toxic content must be intercepted at the API boundary, and inference latency must remain predictable under enterprise SLA constraints.

---

## Before you start

Companies want to use large language models on their own documents, but they cannot paste confidential data into a public chatbot. This chapter covers how AWS lets you call hosted models from inside your own network, ground the answers in your data, and stop the model from saying or doing things it should not.

The core technique is retrieval-augmented generation (RAG). Say you ask a model, "What is our refund window?" The model has never seen your policy. A RAG system first searches your documents, finds the paragraph that mentions 30 days, and pastes it into the prompt alongside your question. The model answers from that text.

Read [chapter 4](/tech/series/aws-sap/04.cloud-native-compute-karpenter/) if you want the compute background, and [chapter 3](/tech/series/aws-sap/03.global-networking-lattice/) for private networking, which the PrivateLink section depends on.

Terms used in this chapter:

- **Foundation model**: a large pretrained model, such as a text-generating LLM, that you use through an API.
- **Bedrock**: the AWS service that hosts foundation models behind one API.
- **RAG**: fetching relevant documents at question time and giving them to the model along with the question.
- **Embedding / vector store**: an embedding is a list of numbers representing the meaning of text; a vector store finds the stored texts whose numbers are closest to the question's.
- **PrivateLink**: a way to reach an AWS service over private addresses without crossing the public internet.
- **Guardrails**: configurable filters that block unwanted topics, leaked personal data or unsafe output.
- **Provisioned throughput**: paying for reserved model capacity instead of per request.

## 1. Enterprise Foundation Model Access: On-Demand vs Provisioned Throughput

Amazon Bedrock provides serverless access to industry-leading foundation models (Anthropic Claude, Meta Llama, Mistral, Amazon Titan) through a single unified API. For professional architects, the primary decision lies in capacity planning and throughput guarantees:

| Dimension | On-Demand Pricing | Provisioned Throughput |
| :--- | :--- | :--- |
| **Billing Model** | Pay-as-you-go per 1,000 input/output tokens | Committed Model Units (MU) with 1-month or 6-month commitment |
| **Throughput & Latency** | Shared multi-tenant capacity; subject to service quotas and regional burst throttling | **Guaranteed TPS (Transactions Per Second)**; zero noisy-neighbor throttles |
| **Custom Model Support** | Base models only | **Mandatory** for custom fine-tuned models or continual pre-training models |
| **When to Choose (Exam Vector)** | Sporadic workloads, internal developer tools, unpredictable volume with tolerance for 429 throttling | **Mission-critical customer-facing workloads**, strict SLA latency guarantees, or running fine-tuned models |

## 2. Production RAG Architecture: Knowledge Bases & Vector Stores

Large language models have fixed knowledge cutoffs and lack visibility into internal enterprise documents (confluence wikis, ERP databases, PDFs). **Retrieval-Augmented Generation (RAG)** injects authoritative, real-time enterprise context into the model's prompt before generation.

### The Ingestion Pipeline Architecture

1. **Document Storage**: Raw source documents (PDF, DOCX, CSV, Markdown) reside in Amazon S3.
2. **Chunking Strategies**:
   - *Fixed-size Chunking*: Chunks text into fixed token counts (e.g., 512 tokens with 20% overlap).
   - *Hierarchical Chunking*: Generates parent-child chunk relationships; searches narrow child chunks for semantic precision but passes wider parent chunks to the LLM for context coherence.
   - *Semantic Chunking*: Breaks chunks dynamically at semantic boundaries (paragraphs, topic shifts).
3. **Vector Embeddings**: Amazon Titan Text Embeddings V2 converts text chunks into 1,024-dimensional continuous vectors.
4. **Vector Store Selection**:

| Vector Store Option | Operational Model | When to Choose (SAP-C03 Vector) |
| :--- | :--- | :--- |
| **Amazon OpenSearch Serverless (Vector Engine)** | Fully managed, serverless, automated scaling (OCU billing) | Primary enterprise choice for dedicated, high-throughput vector search without managing clusters. |
| **Amazon Aurora PostgreSQL (`pgvector`)** | Relational database with vector extension | Best when enterprise relational business data and vector embeddings must be queried together in a single ACID transaction. |
| **Amazon Neptune Analytics** | Graph database with vector search | Best when knowledge graphs, relationship topologies, and vector similarity must be traversed simultaneously. |

### Amazon Bedrock Knowledge Bases

Rather than writing custom Lambda functions to coordinate S3 polling, embedding generation, OpenSearch indexing, and prompt augmentation, **Amazon Bedrock Knowledge Bases** provides a fully managed RAG pipeline. It handles automated synchronization from S3 into your selected vector store and executes semantic retrieval via the `RetrieveAndGenerate` API.

## 3. Perimeter Security: PrivateLink & Data Confidentiality Invariants

In financial, healthcare, and enterprise environments, AI workloads cannot route traffic over the public internet.

### Network Ingress & Egress Isolation

- **Interface VPC Endpoints (AWS PrivateLink)**:
  Deploy interface endpoints for `com.amazonaws.region.bedrock-runtime` and `com.amazonaws.region.bedrock` inside your private application subnets.
- **DNS Resolution**: Private Route 53 hosted zones resolve Bedrock API calls directly to private ENI IP addresses (`10.x.x.x`).
- **No Internet Gateway Required**: Application EC2 instances, ECS tasks, and EKS pods in isolated subnets communicate with foundation models purely over the AWS hypervisor backbone.

### The Zero Data-Retention Guarantee

A critical exam fact: **AWS does not use your customer prompts, completions, or embeddings to train base foundation models**, nor are prompts shared with third-party model providers (e.g., Anthropic). Data is encrypted in transit with TLS (1.2 or later) and at rest, optionally under your own AWS KMS customer managed keys (CMK).

### Declarative VPC Endpoint Policy for Amazon Bedrock

To prevent principals inside your VPC from invoking unauthorized foundation models or using the VPC endpoint from external accounts, attach a strict **VPC Endpoint Policy** to the `com.amazonaws.<region>.bedrock-runtime` interface endpoint:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "RestrictBedrockToApprovedModelsAndOrg",
      "Effect": "Allow",
      "Principal": "*",
      "Action": [
        "bedrock:InvokeModel",
        "bedrock:InvokeModelWithResponseStream"
      ],
      "Resource": [
        "arn:aws:bedrock:us-east-1::foundation-model/<approved-model-id>",
        "arn:aws:bedrock:us-east-1:111122223333:guardrail/*"
      ],
      "Condition": {
        "StringEquals": {
          "aws:PrincipalOrgID": "o-enterprise123"
        }
      }
    }
  ]
}
```

## 4. Responsible AI Guardrails: Amazon Bedrock Guardrails

Traditional software systems use input validation regexes. Generative AI systems face novel threat vectors: **prompt injection attacks, jailbreaks, toxic speech, and unintentional PII leakage**.

**Amazon Bedrock Guardrails** provides an automated, policy-driven security boundary applied across foundation models and RAG queries:

```text
User / App Prompt ──► [ Amazon Bedrock Guardrails ] ──► Foundation Model
                           ├── 1. Prompt Attack Filter (Jailbreak / Injection Detection)
                           ├── 2. Denied Topics (Explicit business boundaries, e.g., "investment advice")
                           ├── 3. Content Filters (Hate, Insults, Sexual, Violence)
                           ├── 4. Sensitive Information Filters (PII Redaction: SSN, Credit Cards)
                           └── 5. Contextual Grounding Check (Halts hallucinations not supported by RAG)
```

### Architectural Key Features

1. **PII Masking & Anonymization**: Automatically replaces sensitive customer data (Social Security numbers, email addresses, phone numbers) with an identifier tag such as `{EMAIL}` (or blocks the request) before the prompt reaches the foundation model.
2. **Contextual Grounding**: Evaluates whether the generated response is factually grounded in the reference documents retrieved by the RAG knowledge base, blocking ungrounded model hallucinations.
3. **Cross-Model Reusability**: A single guardrail policy can be bound to multiple different foundation models, knowledge bases, and agent runtimes.

### Invoking Bedrock Knowledge Base RAG with Guardrails (`RetrieveAndGenerate`)

In production architectures, a single `retrieve_and_generate` API call orchestrates vector embedding lookup, contextual grounding verification, and PII redaction under a pinned Guardrail version:

```python
import boto3

bedrock_agent_runtime = boto3.client("bedrock-agent-runtime", region_name="us-east-1")

response = bedrock_agent_runtime.retrieve_and_generate(
    input={"text": "Summarize the Q3 margin covenant for client ACME Corp."},
    retrieveAndGenerateConfiguration={
        "type": "KNOWLEDGE_BASE",
        "knowledgeBaseConfiguration": {
            "knowledgeBaseId": "KB98765432",
            "modelArn": "arn:aws:bedrock:us-east-1::foundation-model/<approved-model-id>",
            "generationConfiguration": {
                "guardrailConfiguration": {
                    "guardrailId": "gr-enterprise-fin-01",
                    "guardrailVersion": "2",
                }
            },
            "retrievalConfiguration": {
                "vectorSearchConfiguration": {
                    "numberOfResults": 5,
                    "overrideSearchType": "HYBRID",  # Combines semantic vector + BM25 keyword search
                }
            },
        },
    },
)
```

## 5. Autonomous Tool Invocation: Bedrock Agents and AgentCore

When an application requires an LLM to take actions (e.g., check inventory, create an insurance claim, issue a database query), **Amazon Bedrock Agents** coordinates autonomous multi-step reasoning. (**Amazon Bedrock AgentCore** is the separate, more general platform for running agents built with any framework: managed runtime, gateway for tools, identity and memory services. The example below uses Bedrock Agents.)

- **Action Groups**: Define what tools the agent can invoke using **OpenAPI schemas** stored in Amazon S3.
- **Execution via AWS Lambda**: When the foundation model determines it needs external data, it constructs a structured JSON payload conforming to the OpenAPI schema and triggers the targeted Lambda function.
- **Zero-Trust Agent Authorization**: The Lambda function must assume an execution role adhering to least-privilege principles, validating inputs before mutating downstream transactional databases.

## 7. Exam Scenarios & Deciding Vectors

| Scenario Cue | Naive / Distractor Option | Architectural Winner (SAP-C03 Vector) | Why |
| :--- | :--- | :--- | :--- |
| *"Enterprise requires generative AI querying internal sensitive HR PDFs over private IP addresses with automated PII masking."* | Build custom Python scripts on EC2 to parse PDFs, query public OpenAI endpoints, and use regex for PII scrubbing. | **Deploy Bedrock Knowledge Bases** with OpenSearch Serverless and attach a **Bedrock Guardrail** with PII masking via **PrivateLink VPC endpoints**. | Managed enterprise RAG with zero internet exposure, native PII redaction, and strict data confidentiality guarantees. |
| *"Customer-facing AI assistant experiences frequent 429 Too Many Requests errors during peak hours and requires guaranteed sub-second response times."* | Request an On-Demand quota increase in Service Quotas. | **Purchase Provisioned Throughput (Model Units)** for the selected Bedrock foundation model. | Provisioned Throughput guarantees dedicated capacity and predictable TPS without being affected by multi-tenant noisy neighbors. |
| *"Financial advisory app must prevent the model from answering questions about cryptocurrency trading and detect prompt injection attempts."* | Write extensive negative system prompts in the prompt engineering template. | **Configure an Amazon Bedrock Guardrail** with Denied Topics for cryptocurrency and enable Prompt Attack Detection. | System prompts can be bypassed via adversarial jailbreaking; Guardrails enforce a deterministic API-level security boundary. |
