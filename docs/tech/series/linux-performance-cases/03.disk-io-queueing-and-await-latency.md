## Linux Performance Cases 03: Disk I/O, Block Queueing & Await Latency

Storage performance is governed by a fundamental physical invariant: **disk operations are orders of magnitude slower than CPU operations**. While an L1 CPU cache access takes 1 nanosecond and RAM takes 60 nanoseconds, a fast PCIe NVMe SSD takes 20,000 to 50,000 nanoseconds, and a spinning hard disk takes 10,000,000 nanoseconds.

Because of this vast latency chasm, the Linux kernel employs aggressive buffering, asynchronous writeback flusher threads, request merging algorithms, and multi-queue block scheduling (`blk-mq`) to shield user-space applications from direct disk latency.

Understanding when this shielding collapses—and how to diagnose block queue saturation using `iostat`—is essential for database and storage systems engineering.

---

### 1. The Linux Storage I/O Stack

Every file read or write traverses multiple kernel layers before touching physical storage silicon:

<Archify src="./diagrams/linux-storage-io-stack.workflow.json" />

1. **Virtual File System (VFS)**: Translates standard POSIX system calls (`read()`, `write()`, `pwritev()`) to file system-specific inode and extent operations (`ext4_file_write_iter`).
2. **Page Cache Layer**:
   - **Buffered I/O (Default)**: Writes return immediately once bytes are copied into memory page frames and marked `dirty`. Read requests check memory first, avoiding physical I/O on cache hits.
   - **Direct I/O (`O_DIRECT`)**: Bypasses the Page Cache completely. Memory buffers are transferred directly between user space and the storage controller via DMA (Direct Memory Access), preferred by database engines like MySQL InnoDB and RocksDB to avoid double-buffering.
3. **Block Layer & `blk-mq`**: Multi-queue block layer queues incoming `bio` structs, merges adjacent disk sector requests, and schedules them for dispatch.
4. **Device Controller (NVMe / SCSI)**: Executes commands against physical flash chips via hardware submission and completion rings.

---

### 2. Page Cache Dirty Writeback Dynamics

When applications write to buffered files, data accumulates in the Page Cache as **dirty pages**. The kernel regulates writeback via kernel flusher threads (`kworker`):

| Kernel Tunable (`/proc/sys/vm/`) | Default Value | Operational Behavior |
|---|---|---|
| `dirty_background_ratio` | 10% | When dirty pages exceed this percentage of RAM, `kworker` flusher threads wake up asynchronously to write pages to disk in the background. |
| `dirty_ratio` | 20% | **Hard Throttle Limit**: If dirty pages reach this threshold, the writing process is blocked synchronously! User-space threads stall until dirty pages drop. |
| `dirty_expire_centisecs` | 3000 (30s) | Pages that have remained dirty for more than 30 seconds are flushed regardless of total ratio. |

**The Writeback Stall Trap**:
On a server with 256 GB of RAM, a `dirty_ratio` of 20% allows up to **51.2 GB of unwritten data** to sit in memory. If a heavy batch job generates 50 GB of writes rapidly, the kernel suddenly hits the hard ceiling, freezing the application while flushing gigabytes across a saturated disk bus.

*Tuning for Low Latency*: Reduce `dirty_background_ratio = 3` and `dirty_ratio = 6` (or set absolute byte limits via `dirty_bytes` and `dirty_background_bytes`).

### 3. Decoding `iostat -xz 1`: Beyond `%util`

The standard tool for diagnosing disk saturation is `iostat -xz 1`:

```text
Device    r/s     w/s     rkB/s     wkB/s  rrqm/s  wrqm/s  %rrqm  %wrqm   r_await   w_await   aqu-sz    rareq-sz  wareq-sz   %util
nvme0n1  120.0  2500.0   4800.0  125000.0     0.0   450.0    0.0   15.3      0.15      0.85     2.10       40.0      50.0   98.5
sda        5.0   180.0    200.0    7200.0     0.0    20.0    0.0   10.0     45.20    180.50    15.40       40.0      40.0  100.0
```

#### 1. Why `%util` Is Misleading on Modern NVMe SSDs

- On historical spinning hard drives (with a single read/write head), `%util = 100%` meant the disk arm was permanently moving and completely saturated.
- On modern NVMe SSDs, the drive supports **64,000 independent hardware queues with queue depths of 64,000 commands each**. A single thread issuing sequential synchronous 4 KB writes can register `%util = 100%` because the device was never completely idle, even though the SSD was utilizing less than 1% of its parallel flash bus capacity!

#### 2. The True Metric of Saturation: `await` & `aqu-sz`

- **`await` (Average Wait Time in ms)**: The total time from when a request was queued in the block layer until the storage hardware completed it:
  $$\text{await} = \text{Queue Wait Time} + \text{Device Service Time}$$
- **`r_await` vs `w_await`**: Always evaluate read and write latencies separately. A system can have `w_await = 0.5 ms` (buffered writeback) while reads suffer `r_await = 80 ms` because storage read queues are starved by background flush bursts.
- **`aqu-sz` (Average Queue Size)**: Number of requests waiting in the driver queue. If `aqu-sz > 1` on a single spindle disk, requests are queueing. On enterprise NVMe SSDs, a queue size between 32 and 128 reflects healthy parallelism; an `aqu-sz > 500` indicates deep saturation.

### 4. Verification Lab: Block Queue Merging & Await Latency Simulator

The following self-contained Python lab simulates a Linux block device layer:

1. Emulates the **Page Cache dirty page threshold** triggering background flush vs synchronous write throttling.
2. Implements a **Block Request Queue (`blk-mq`)** with sector merging of adjacent sequential writes.
3. Computes exact **`iostat` metrics**: `r/s`, `w/s`, `await`, `aqu-sz`, and `%util`.
4. Generates a **`biolatency` log-2 histogram** showing storage latency distributions.

```python
"""
Linux Performance Cases Lab 03: Disk I/O, Block Queueing & Await Latency
Simulates Page Cache writeback thresholds, block request merging, and iostat metrics.
"""

from typing import List, Dict, Optional
import math

class BlockRequest:
    def __init__(self, req_id: int, is_write: bool, sector: int, size_kb: int, arrival_time_ms: float):
        self.req_id = req_id
        self.is_write = is_write
        self.sector = sector
        self.size_kb = size_kb
        self.arrival_time_ms = arrival_time_ms
        self.service_time_ms = 0.0
        self.completion_time_ms = 0.0

    @property
    def total_latency_ms(self) -> float:
        return self.completion_time_ms - self.arrival_time_ms

class BlockDeviceSimulator:
    def __init__(self, device_name: str, base_service_latency_ms: float = 1.0):
        self.device_name = device_name
        self.base_latency = base_service_latency_ms
        self.queue: List[BlockRequest] = []
        self.completed_requests: List[BlockRequest] = []
        self.current_time_ms = 0.0
        self.device_busy_until_ms = 0.0
        self.total_busy_time_ms = 0.0
        self.merged_requests = 0

    def submit_request(self, is_write: bool, sector: int, size_kb: int, timestamp_ms: float) -> Optional[BlockRequest]:
        self.current_time_ms = timestamp_ms

        # Block Layer Request Merging: check if request is adjacent to tail of queue
        if self.queue and self.queue[-1].is_write == is_write:
            last = self.queue[-1]
            last_end_sector = last.sector + int(last.size_kb * 2)  # 512 bytes per sector
            if last_end_sector == sector:
                # Merge into previous request!
                last.size_kb += size_kb
                self.merged_requests += 1
                return last

        req = BlockRequest(len(self.completed_requests) + len(self.queue) + 1, is_write, sector, size_kb, timestamp_ms)
        self.queue.append(req)
        return req

    def process_queue(self):
        """Simulates device servicing queue according to hardware concurrency."""
        while self.queue:
            req = self.queue.pop(0)
            # Service time scales with request size
            service_duration = self.base_latency + (req.size_kb / 1024.0) * 0.5
            start_service = max(req.arrival_time_ms, self.device_busy_until_ms)
            req.service_time_ms = service_duration
            req.completion_time_ms = start_service + service_duration

            busy_delta = req.completion_time_ms - start_service
            self.total_busy_time_ms += busy_delta
            self.device_busy_until_ms = req.completion_time_ms
            self.completed_requests.append(req)

    def calculate_iostat_metrics(self, duration_sec: float) -> Dict[str, float]:
        self.process_queue()
        total_reqs = len(self.completed_requests)
        if total_reqs == 0:
            return {"r_await": 0.0, "w_await": 0.0, "await": 0.0, "util": 0.0, "aqu_sz": 0.0}

        read_reqs = [r for r in self.completed_requests if not r.is_write]
        write_reqs = [r for r in self.completed_requests if r.is_write]

        r_await = sum(r.total_latency_ms for r in read_reqs) / len(read_reqs) if read_reqs else 0.0
        w_await = sum(r.total_latency_ms for r in write_reqs) / len(write_reqs) if write_reqs else 0.0
        total_await = sum(r.total_latency_ms for r in self.completed_requests) / total_reqs

        total_time_ms = duration_sec * 1000.0
        util_pct = min(100.0, (self.total_busy_time_ms / total_time_ms) * 100.0)
        # Average queue size (Little's Law: L = lambda * W)
        throughput_req_per_ms = total_reqs / total_time_ms
        aqu_sz = throughput_req_per_ms * total_await

        return {
            "r_await": round(r_await, 2),
            "w_await": round(w_await, 2),
            "await": round(total_await, 2),
            "util": round(util_pct, 2),
            "aqu_sz": round(aqu_sz, 2)
        }

    def generate_biolatency_histogram(self) -> Dict[str, int]:
        """Generates a log-2 latency histogram matching eBPF biolatency."""
        hist: Dict[str, int] = {}
        for req in self.completed_requests:
            lat = max(0.1, req.total_latency_ms)
            bucket_idx = int(math.log2(lat))
            range_label = f"{2**bucket_idx} -> {2**(bucket_idx + 1) - 1} ms"
            hist[range_label] = hist.get(range_label, 0) + 1
        return hist

def run_lab():
    sim = BlockDeviceSimulator(device_name="nvme0n1", base_service_latency_ms=0.5)

    # -------------------------------------------------------------
    # Test 1: Sequential Write Request Merging
    # 3 sequential 4KB writes at sectors 1000, 1008, 1016 (adjacent sectors)
    # -------------------------------------------------------------
    r1 = sim.submit_request(is_write=True, sector=1000, size_kb=4, timestamp_ms=0.0)
    r2 = sim.submit_request(is_write=True, sector=1008, size_kb=4, timestamp_ms=0.1)
    r3 = sim.submit_request(is_write=True, sector=1016, size_kb=4, timestamp_ms=0.2)

    # All 3 writes should merge into a single 12KB block request!
    assert len(sim.queue) == 1
    assert sim.queue[0].size_kb == 12
    assert sim.merged_requests == 2

    # -------------------------------------------------------------
    # Test 2: Random Reads & Interleaved Writes
    # -------------------------------------------------------------
    # Submit random reads (non-adjacent)
    sim.submit_request(is_write=False, sector=50000, size_kb=4, timestamp_ms=0.5)
    sim.submit_request(is_write=False, sector=90000, size_kb=4, timestamp_ms=1.0)
    assert len(sim.queue) == 3

    # Process batch across a 1-second monitoring window (1000 ms)
    metrics = sim.calculate_iostat_metrics(duration_sec=1.0)

    assert metrics["await"] > 0.0
    assert metrics["r_await"] > 0.0
    assert metrics["w_await"] > 0.0
    assert metrics["util"] > 0.0

    # -------------------------------------------------------------
    # Test 3: High-Queue Saturation Simulation
    # Piling 50 requests in rapid succession
    # -------------------------------------------------------------
    for i in range(50):
        sim.submit_request(is_write=False, sector=100000 + i * 100, size_kb=8, timestamp_ms=2.0 + i * 0.1)

    heavy_metrics = sim.calculate_iostat_metrics(duration_sec=2.0)
    # Under heavy queueing, await and aqu_sz escalate significantly
    assert heavy_metrics["await"] > metrics["await"]
    assert heavy_metrics["aqu_sz"] > metrics["aqu_sz"]
    assert heavy_metrics["await"] > 5.0

    histogram = sim.generate_biolatency_histogram()
    assert len(histogram) > 0

    print(f"Device: {sim.device_name} (Merged Requests: {sim.merged_requests})")
    print(f"iostat Metrics: await={heavy_metrics['await']}ms (r_await={heavy_metrics['r_await']}ms, w_await={heavy_metrics['w_await']}ms), %util={heavy_metrics['util']}%, aqu-sz={heavy_metrics['aqu_sz']}")
    print(f"biolatency log-2 histogram buckets: {histogram}")
    print("Linux Performance Cases Lab 03 passed.")

if __name__ == "__main__":
    run_lab()
```
