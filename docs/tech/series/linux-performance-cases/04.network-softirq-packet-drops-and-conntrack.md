## Linux Performance Cases 04: Network Softirq, Packet Drops & Conntrack

In high-throughput microservices, distributed databases, and high-frequency trading gateways, network packet loss is the primary driver of catastrophic tail latencies. When a single TCP packet is dropped, the connection does not simply wait for a resend—it triggers **TCP Fast Retransmit**, drops congestion windows (`cwnd`), and if timers expire, incurs an exponential backoff penalty of 200 ms to several seconds.

Yet when packet loss occurs inside a server, `ping` may report 0% loss, physical network cables are intact, and switches show zero port errors. The drops are happening silently **inside the Linux kernel network stack**.

---

### 1. The Linux Ingress Packet Journey

To diagnose packet drops, you must trace the exact physical and software boundaries a packet traverses from the wire to user-space memory:

<Archify src="./diagrams/linux-network-ingress-egress.workflow.json" />

#### Step 1: NIC PHY & DMA Ring Buffer

When electrical or optical signals arrive at the Network Interface Card (NIC), the physical controller parses Ethernet frames and writes packet bytes directly into pre-allocated host RAM using DMA (**Direct Memory Access**). The descriptors for these buffers reside in the **NIC RX Ring Buffer**.

- *Drop Symptom*: If packets arrive faster than the CPU can harvest the ring buffer, the ring overflows.
- *Diagnostic*: `ethtool -S eth0 | grep -E "rx_dropped|rx_over_errors|rx_missed_errors"`.

#### Step 2: Hard IRQ & NAPI Scheduling

Once a burst of packets arrives in the ring, the NIC raises a hardware interrupt (Hard IRQ). The kernel interrupt handler does minimal work: it disables further interrupts from that NIC queue and invokes `napi_schedule()` to initiate software polling.

#### Step 3: `NET_RX` Softirq & `netdev_budget`

The bottom-half softirq (`NET_RX`) wakes up to process packets in batches. To prevent network traffic from starving all other CPU tasks, the kernel enforces a processing budget:

- `/proc/sys/net/core/netdev_budget` (default: 300 packets per poll).
- `/proc/sys/net/core/netdev_budget_usecs` (default: 2000 $\mu$s).
If the budget expires while packets remain in the ring, `ksoftirqd` is awakened to continue processing on the next scheduler tick.

#### Step 4: `sk_buff` Allocation & Protocol Processing

The driver converts raw DMA ring buffers into kernel **`sk_buff` (Socket Buffer)** structs. The packet passes through:

1. **Generic Receive Offload (GRO)**: Recombines small TCP segments into larger packets to save CPU overhead.
2. **Netfilter / iptables**: Evaluates firewall rules and updates the **Connection Tracking (`nf_conntrack`)** state table.
3. **TCP Engine**: Verifies checksums, updates sequence and acknowledgment numbers, and manages TCP window flow control.

#### Step 5: Socket Receive Buffer (`sk_rcvbuf`)

Finally, the packet payload is appended to the target socket's receive queue. When an application calls `epoll_wait()`, the kernel wakes the listening thread to read bytes via `recv()` or `read()`.

### 2. The Four Stages of Packet Drops

Packet loss inside Linux occurs at four distinct tiers:

```text
[ Wire ]
   │
   ▼
[ 1. NIC Hardware Ring Buffer ] ──► Drop: ethtool -S (rx_dropped / rx_missed)
   │
   ▼
[ 2. Softnet Backlog Queue ]    ──► Drop: /proc/net/softnet_stat (column 2)
   │
   ▼
[ 3. Netfilter Conntrack Table] ──► Drop: dmesg ("nf_conntrack: table full")
   │
   ▼
[ 4. Socket Receive Buffer ]    ──► Drop: netstat -s / ss -it (RcvbufErrors)
   │
   ▼
[ Application recv() ]
```

#### Diagnostic Mapping for Drops

| Layer | Drop Reason | Metric Command | Kernel Remediation |
|---|---|---|---|
| **Ring Buffer** | CPU unable to process DMA descriptors | `ethtool -S <eth>` | Increase ring size: `ethtool -G <eth> rx 4096` |
| **Softnet Backlog** | Ingress queue overwhelmed before NAPI | `/proc/net/softnet_stat` | Tune: `sysctl -w net.core.netdev_max_backlog=10000` |
| **Netfilter (Conntrack)**| Maximum tracked connection states exceeded | `dmesg \| grep nf_conntrack` | Tune: `sysctl -w net.netfilter.nf_conntrack_max=1048576` |
| **Socket Buffer** | Application event loop blocked or slow | `netstat -s \| grep "buffer errors"` | Tune: `sysctl -w net.ipv4.tcp_rmem="4096 87380 16777216"` |

### 3. Netfilter `nf_conntrack` Table Saturation

The Linux kernel uses the `nf_conntrack` module to track the bidirectional state of all network sessions (required for stateful firewalls and NAT port forwarding in Docker/Kubernetes).

Every active TCP, UDP, or ICMP flow consumes one entry in an internal hash table. If the number of concurrent connections exceeds `nf_conntrack_max`:

```text
kernel: nf_conntrack: table full, dropping packet
```

**The Danger of Silent Drops**:
When `nf_conntrack` fills up, **the kernel immediately drops incoming SYN packets without sending a TCP RST**. Clients experience complete connection timeouts.

#### Calculating Proper Conntrack Sizing

```bash
# Check current vs maximum tracking entries
cat /proc/sys/net/netfilter/nf_conntrack_count
cat /proc/sys/net/netfilter/nf_conntrack_max

# Size hash buckets appropriately (Buckets = Max / 4)
echo 262144 > /sys/module/nf_conntrack/parameters/hashsize
sysctl -w net.netfilter.nf_conntrack_max=1048576
```

Each conntrack entry consumes ~320 bytes of non-swappable kernel slab memory (`nf_conntrack_entry`). Sizing the table to 1,000,000 connections consumes approximately 320 MB of kernel RAM—a modest footprint for modern production servers.

### 4. Verification Lab: Network Ingress, Drop Tiers & Conntrack Simulator

The following self-contained Python lab simulates the complete Linux network ingress pipeline:

1. Emulates the **NIC RX Ring Buffer** with capacity limits.
2. Models the **NAPI softirq batch harvesting** under budget constraints.
3. Implements **Netfilter `nf_conntrack` state tracking**, triggering packet drops upon table saturation.
4. Simulates **Socket Receive Buffer overflow** when user applications fail to drain sockets rapidly.

```python
"""
Linux Performance Cases Lab 04: Network Ingress, Packet Drops & Conntrack
Simulates NIC ring buffer, softnet budget, conntrack overflow, and socket buffer drops.
"""

from typing import List, Dict, Set, Optional

class Packet:
    def __init__(self, pkt_id: int, src_ip: str, src_port: int, dst_ip: str, dst_port: int, size_bytes: int):
        self.pkt_id = pkt_id
        self.flow_key = f"{src_ip}:{src_port}->{dst_ip}:{dst_port}"
        self.size_bytes = size_bytes

class LinuxNetworkIngress:
    def __init__(self, ring_capacity: int = 100, conntrack_max: int = 50, socket_buf_bytes: int = 4096):
        self.ring_capacity = ring_capacity
        self.conntrack_max = conntrack_max
        self.socket_buf_bytes = socket_buf_bytes

        # Buffers
        self.rx_ring_buffer: List[Packet] = []
        self.conntrack_table: Set[str] = set()
        self.socket_queue: List[Packet] = []
        self.socket_current_bytes = 0

        # Drop counters
        self.ring_dropped = 0
        self.conntrack_dropped = 0
        self.socket_buffer_dropped = 0
        self.delivered_packets = 0

    def receive_from_wire(self, pkt: Packet) -> bool:
        # Tier 1: Hardware NIC Ring Buffer Check
        if len(self.rx_ring_buffer) >= self.ring_capacity:
            self.ring_dropped += 1
            return False  # Overrun drop at NIC level

        self.rx_ring_buffer.append(pkt)
        return True

    def poll_softirq_batch(self, budget: int = 30):
        # Tier 2: NAPI Harvest within netdev_budget
        batch = []
        while self.rx_ring_buffer and len(batch) < budget:
            batch.append(self.rx_ring_buffer.pop(0))

        # Process harvested batch through protocol stack
        for pkt in batch:
            # Tier 3: Netfilter Connection Tracking
            if pkt.flow_key not in self.conntrack_table:
                if len(self.conntrack_table) >= self.conntrack_max:
                    self.conntrack_dropped += 1
                    continue  # Dropped because conntrack table full!
                self.conntrack_table.add(pkt.flow_key)

            # Tier 4: Socket Receive Buffer
            if self.socket_current_bytes + pkt.size_bytes > self.socket_buf_bytes:
                self.socket_buffer_dropped += 1
                continue  # Dropped because user app is not reading fast enough

            self.socket_queue.append(pkt)
            self.socket_current_bytes += pkt.size_bytes
            self.delivered_packets += 1

    def drain_socket_queue(self, max_packets: int = 10):
        """Simulates user application calling recv() to drain socket."""
        drained = 0
        while self.socket_queue and drained < max_packets:
            pkt = self.socket_queue.pop(0)
            self.socket_current_bytes -= pkt.size_bytes
            drained += 1

def run_lab():
    ingress = LinuxNetworkIngress(ring_capacity=10, conntrack_max=5, socket_buf_bytes=1000)

    # -------------------------------------------------------------
    # Test 1: NIC Ring Buffer Overrun
    # Flooding 15 packets when ring capacity is 10
    # -------------------------------------------------------------
    for i in range(15):
        pkt = Packet(i, "192.168.1.10", 1000 + i, "10.0.0.1", 80, size_bytes=100)
        ingress.receive_from_wire(pkt)

    assert len(ingress.rx_ring_buffer) == 10
    assert ingress.ring_dropped == 5  # 5 packets dropped at NIC ring

    # -------------------------------------------------------------
    # Test 2: NAPI Poll & Conntrack Table Exhaustion
    # Conntrack table max is 5 unique flows; 10 distinct flows are polled
    # -------------------------------------------------------------
    ingress.poll_softirq_batch(budget=10)

    # First 5 flows accepted into conntrack; remaining 5 dropped!
    assert len(ingress.conntrack_table) == 5
    assert ingress.conntrack_dropped == 5

    # -------------------------------------------------------------
    # Test 3: Socket Receive Buffer Saturation
    # Send 10 packets on an existing tracked flow (bypasses conntrack check)
    # Socket buffer limit is 1000 bytes (each packet is 200 bytes)
    # -------------------------------------------------------------
    # Add packets to wire
    for i in range(8):
        pkt = Packet(100 + i, "192.168.1.10", 1000, "10.0.0.1", 80, size_bytes=200)
        ingress.receive_from_wire(pkt)

    ingress.poll_softirq_batch(budget=10)

    # Socket capacity is 1000 bytes. With 500 bytes already present from Test 2,
    # exactly 2 more packets of 200B fit (reaching 900 bytes).
    # The remaining 6 packets are dropped due to socket buffer overflow!
    assert ingress.socket_buffer_dropped == 6
    assert ingress.socket_current_bytes == 900

    # User application reads 3 packets (3 * 100B = 300B), reducing buffer to 600 bytes
    ingress.drain_socket_queue(max_packets=3)
    assert ingress.socket_current_bytes == 600

    print(f"Delivered Packets: {ingress.delivered_packets}")
    print(f"Drop Breakdown: Ring={ingress.ring_dropped}, Conntrack={ingress.conntrack_dropped}, SocketBuf={ingress.socket_buffer_dropped}")
    print("Linux Performance Cases Lab 04 passed.")

if __name__ == "__main__":
    run_lab()
```
