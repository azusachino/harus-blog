## Nginx Master-Worker Architecture, Shared Memory Slabs & Gateway Routing

As the ingress gateway and edge reverse-proxy for the global internet, **Nginx** handles very large numbers of concurrent HTTP/HTTPS connections with a small memory footprint per connection. Rather than spinning up a new thread or process per connection (like traditional Apache MPM prefork), Nginx is built on an asynchronous, event-driven, non-blocking architecture.

This final chapter of the *Middleware Internals* series breaks down how Nginx coordinates worker processes, shares state without IPC serialization overhead, balances incoming TCP handshakes at the Linux kernel level, and routes dynamic traffic across backend upstreams.

---

### 1. The Master-Worker Process Architecture

Nginx divides operational responsibilities into a single privileged **Master** process and multiple unprivileged **Worker** processes:

```text
                      [ Master Process (PID 1000, root) ]
                         - Parses & validates nginx.conf
                         - Binds listening sockets (:80, :443)
                         - Listens for POSIX signals (HUP, QUIT, USR2)
                         - Spawns & monitors worker lifecycle
                                   |
         +-------------------------+-------------------------+
         |                         |                         |
         v                         v                         v
[ Worker 0 (PID 1001) ]   [ Worker 1 (PID 1002) ]   [ Worker 2 (PID 1003) ]
  - (optional) core 0 pin   - (optional) core 1 pin   - (optional) core 2 pin
  - epoll event loop        - epoll event loop        - epoll event loop
  - Non-blocking I/O        - Non-blocking I/O        - Non-blocking I/O
```

#### The Master Process

The master process runs as `root` (to bind privileged ports $< 1024$) but **never processes client traffic**. Its duties are administrative:

- Reading, compiling, and validating `nginx.conf`.
- Creating and binding listening sockets.
- Handling operational POSIX signals:
  - `SIGHUP` (`nginx -s reload`): Compiles new configuration, initializes new shared memory zones, forks new worker processes with updated settings, and signals old workers to drain gracefully (`SIGQUIT`).
  - `SIGQUIT`: Graceful shutdown—workers finish active HTTP transactions and close keepalive connections.
  - `SIGUSR2`: Live binary upgrade (`on-the-fly` zero-downtime Nginx executable replacement). The master re-executes the new binary and passes it the open socket descriptors; once you are satisfied the new one is healthy, you signal the old master to quit (`SIGQUIT`).

#### Worker Processes

Worker processes drop privileges to a non-root user (`nginx` or `www-data`). Each worker:

- Runs an independent, single-threaded event loop driven by `epoll_wait(2)` (Linux) or `kqueue(2)` (FreeBSD/macOS).
- Can be pinned to a CPU core via `worker_cpu_affinity` (off by default) to improve L1/L2 cache locality.
- Takes connection structures from a pre-allocated array sized by `worker_connections`, so accepting a connection does not malloc the connection object itself (per-request memory pools still allocate).

### 2. Thundering Herd & Socket Load Balancing

When multiple worker processes listen on the same shared TCP listening socket, an incoming SYN packet historically produced the **Thundering Herd** problem: the kernel woke up *all* sleeping worker processes, but only one successfully called `accept4(2)`, while the remaining workers returned `EAGAIN` and fell back asleep.

#### Evolution of Nginx Accept Balancing

```text
1. accept_mutex (Userspace Lock)
   Worker acquires shared spinlock in shm -> adds listen fd to epoll -> accepts -> releases lock.
   Drawback: High contention and serialized connection intake at 100k+ req/sec.

2. EPOLLEXCLUSIVE (Linux 4.5+)
   Kernel flag waking exactly one waiting worker in epoll_wait.

3. SO_REUSEPORT (Linux 3.9+, opt-in via `listen ... reuseport`)
   Each worker creates its own independent listen socket bound to the same IP:port.
   Kernel hashes incoming 4-tuples and distributes SYNs directly into worker queues.
```

With `listen 443 ssl reuseport;`:

- Every worker process owns an isolated file descriptor for the port.
- The Linux kernel's networking stack inspects the incoming SYN packet's 4-tuple `(src_ip, src_port, dst_ip, dst_port)` and hashes it directly into one of the worker listening queues.
- Lock contention between workers is completely eliminated.

### 3. Shared Memory & The Slab Allocator

Because workers are separate operating system processes rather than threads, they cannot share user heap memory directly. However, features like rate limiting (`limit_req`), concurrent connection tracking (`limit_conn`), SSL session caches, and upstream health status require unified global visibility.

Nginx solves this by allocating dedicated **POSIX Shared Memory Zones** (`mmap(MAP_SHARED | MAP_ANON)`) during master initialization.

#### The Slab Allocator Architecture

Inside each shared memory zone, calling standard `malloc(3)` is impossible because standard glibc heap structures are process-private and cause pointer corruption. Instead, Nginx embeds its own **Slab Allocator**, protected by a shared mutex:

```text
[ Shared Memory Region (e.g. 10MB Zone) ]
  |
  +-- ngx_slab_pool_t (Header & free page tracking)
  |
  +-- Array of ngx_slab_page_t (Page descriptors: 4KB per page)
  |
  +-- Data Pages:
        Page 0: [ 128B Slot | 128B Slot | 128B Slot | ... ] (Bitmap allocated)
        Page 1: [  64B Slot |  64B Slot |  64B Slot | ... ] (Bitmap allocated)
        Page 2..4: Large contiguous object (Span of 3 full 4KB pages)
```

1. **Slot Sizes**: Fixed power-of-two slot sizes: $8, 16, 32, 64, 128, 256, 512, 1024, 2048$ bytes.
2. **Page Allocation**: Memory is divided into 4KB pages. If an object is smaller than half a page ($\le 2048$ bytes), the page is marked as a *small/exact slab*.
3. **Bitmap Management**: Within a slab page, an in-page 32-bit or 64-bit unsigned integer serves as a allocation bitmap. Setting a bit to `1` marks a slot as allocated; clearing it returns the slot to the pool in $\mathcal{O}(1)$ time with zero external fragmentation.
4. **Large Objects**: Objects $> 2048$ bytes span contiguous 4KB pages tracked directly by the page array.

### 4. Upstream Gateway Routing & Consistent Hashing

When acting as a reverse proxy, Nginx forwards requests to upstream clusters defined in `upstream` blocks. Selecting the destination server depends on the configured routing policy:

#### Routing Algorithms

1. **Weighted Round-Robin (Default)**:
   Maintains `current_weight` and `effective_weight` per peer. In each selection cycle, Nginx increments each peer's `current_weight` by its configured `weight`, picks the peer with the maximum `current_weight`, and decrements its weight by the sum of all weights. This ensures perfectly smooth distribution without burst clustering.
2. **Least Connections (`least_conn`)**:
   Selects the upstream peer with the lowest number of active requests, weighted by server capacity. The connection counters are per worker unless the upstream block declares a shared-memory `zone`.
3. **Consistent Hashing (`hash $request_uri consistent`)**:
   Used heavily in caching proxies and stateful API routing. Nginx builds a **Ketama Ring**:
   - Each backend server is mapped to 160 virtual nodes (points on a $2^{32}-1$ integer circle) based on its hostname hash.
   - Incoming request keys (e.g. URI or user ID) are hashed onto the ring, and the first server clockwise from that point is selected.
   - If a backend node fails, only $1/N$ of keys are re-routed to adjacent servers, preserving cache hit ratios.

#### Upstream Keepalive Pooling

By default, Nginx opens a new TCP connection to the upstream server for every client request and closes it after receiving the response (`Connection: close`). Under high throughput, this exhausts ephemeral ports and leaves a pile of `TIME_WAIT` sockets on the proxy host.

Configuring `keepalive 64;` inside the upstream block (together with `proxy_http_version 1.1;` and `proxy_set_header Connection "";` in the proxy location) enables an internal LIFO connection cache. When an upstream request finishes, the socket remains open in an idle pool, allowing subsequent client requests to reuse the established TCP connection with zero handshake latency.

### 5. Verification Lab: Implementing a Slab Allocator & Consistent Hash Gateway

The following Python lab implements and verifies the two core building blocks of high-throughput gateway infrastructure:

1. **A Binary Slab Memory Allocator**: Pre-allocates a simulated page pool, assigns fixed-size slot slabs (32B, 64B, 128B) using bitwise allocation masks, and handles deallocations without heap fragmentation.
2. **Ketama Consistent Hash Ring**: Builds a 32-bit virtual node ring, routes keys to upstream servers, and verifies that adding or removing a node redistributes at most $\approx 1/N$ of keys.
3. **Weighted Round-Robin Engine**: Verifies smooth interleaved server selection matching Nginx's upstream scheduling.

```python
#!/usr/bin/env python3
"""
Lab: Nginx Slab Memory Allocator, Ketama Consistent Hash & Upstream Routing
Verifies page-bitmap slot allocation and minimal-disruption gateway balancing.
"""

import hashlib
import bisect
from typing import List, Dict, Optional, Tuple

# =====================================================================
# 1. Nginx-Style Slab Memory Allocator Simulation
# =====================================================================

PAGE_SIZE = 4096
SLOT_SIZES = [32, 64, 128, 256, 512, 1024, 2048]

class SlabPage:
    def __init__(self, page_id: int, slot_size: int):
        self.page_id = page_id
        self.slot_size = slot_size
        self.total_slots = PAGE_SIZE // slot_size
        # Bitmap: 1 = free, 0 = allocated
        self.bitmap = (1 << self.total_slots) - 1
        self.allocated_count = 0

    def alloc(self) -> Optional[int]:
        """Finds first free slot using bitwise operations."""
        if self.bitmap == 0:
            return None  # Page is full

        # Find position of lowest set bit
        lowest_set_bit = self.bitmap & -self.bitmap
        slot_idx = lowest_set_bit.bit_length() - 1

        # Clear the bit (mark as allocated)
        self.bitmap &= ~lowest_set_bit
        self.allocated_count += 1
        return slot_idx

    def free(self, slot_idx: int):
        """Marks slot as free."""
        bit = 1 << slot_idx
        assert (self.bitmap & bit) == 0, f"Double free on slot {slot_idx}!"
        self.bitmap |= bit
        self.allocated_count -= 1

class SlabPool:
    """Simulates Nginx shared-memory pre-allocated slab zone."""
    def __init__(self, num_pages: int = 16):
        self.num_pages = num_pages
        self.pages: Dict[int, SlabPage] = {}
        self.free_page_ids = list(range(num_pages))
        self.slot_to_page: Dict[int, List[int]] = {s: [] for s in SLOT_SIZES}

    def alloc(self, size: int) -> Tuple[int, int]:
        """Allocates (page_id, slot_idx) for the requested byte size."""
        # Find smallest slot size >= size
        slot_size = next((s for s in SLOT_SIZES if s >= size), None)
        if slot_size is None:
            raise ValueError(f"Size {size} exceeds max slab slot size (2048)")

        # Search existing pages for this slot size
        for pid in self.slot_to_page[slot_size]:
            page = self.pages[pid]
            slot_idx = page.alloc()
            if slot_idx is not None:
                return (pid, slot_idx)

        # No free slots in existing pages; allocate new page
        if not self.free_page_ids:
            raise MemoryError("Out of shared memory pages in slab zone!")

        new_pid = self.free_page_ids.pop(0)
        page = SlabPage(new_pid, slot_size)
        slot_idx = page.alloc()
        self.pages[new_pid] = page
        self.slot_to_page[slot_size].append(new_pid)
        return (new_pid, slot_idx)

    def free(self, page_id: int, slot_idx: int):
        page = self.pages.get(page_id)
        if not page:
            raise ValueError(f"Invalid page {page_id}")
        page.free(slot_idx)

        # If page becomes completely empty, return to free pool
        if page.allocated_count == 0:
            self.slot_to_page[page.slot_size].remove(page_id)
            del self.pages[page_id]
            self.free_page_ids.append(page_id)

# =====================================================================
# 2. Ketama Consistent Hashing Ring
# =====================================================================

class ConsistentHashRing:
    def __init__(self, replicas: int = 160):
        self.replicas = replicas
        self.ring: List[int] = []
        self.ring_map: Dict[int, str] = {}

    def _hash(self, key: str) -> int:
        """32-bit unsigned MD5 hash prefix."""
        digest = hashlib.md5(key.encode("utf-8")).digest()
        return int.from_bytes(digest[:4], byteorder="big")

    def add_node(self, node: str):
        for i in range(self.replicas):
            vnode_key = f"{node}#vnode{i}"
            h = self._hash(vnode_key)
            self.ring_map[h] = node
            bisect.insort(self.ring, h)

    def remove_node(self, node: str):
        for i in range(self.replicas):
            vnode_key = f"{node}#vnode{i}"
            h = self._hash(vnode_key)
            self.ring_map.pop(h, None)
            idx = bisect.bisect_left(self.ring, h)
            if idx < len(self.ring) and self.ring[idx] == h:
                self.ring.pop(idx)

    def get_node(self, key: str) -> Optional[str]:
        if not self.ring:
            return None
        h = self._hash(key)
        idx = bisect.bisect_right(self.ring, h)
        if idx == len(self.ring):
            idx = 0
        return self.ring_map[self.ring[idx]]

# =====================================================================
# 3. Smooth Weighted Round-Robin Scheduler
# =====================================================================

class UpstreamServer:
    def __init__(self, name: str, weight: int):
        self.name = name
        self.weight = weight
        self.current_weight = 0

class SmoothWeightedRoundRobin:
    """Nginx's smooth weighted round-robin upstream selection algorithm."""
    def __init__(self, servers: List[UpstreamServer]):
        self.servers = servers
        self.total_weight = sum(s.weight for s in servers)

    def select(self) -> str:
        if not self.servers:
            return ""

        best = None
        for s in self.servers:
            s.current_weight += s.weight
            if best is None or s.current_weight > best.current_weight:
                best = s

        best.current_weight -= self.total_weight
        return best.name

# =====================================================================
# Verification Tests
# =====================================================================

def test_slab_allocator():
    pool = SlabPool(num_pages=4)

    # Allocate 10 objects of size 40B (should map to 64B slot)
    allocations = []
    for _ in range(10):
        loc = pool.alloc(40)
        allocations.append(loc)

    # All should be in the same page (4096 / 64 = 64 slots)
    first_page_id = allocations[0][0]
    for pid, s_idx in allocations:
        assert pid == first_page_id, f"Expected page {first_page_id}, got {pid}"

    # Free half of them
    for i in range(5):
        pool.free(*allocations[i])

    # Allocate 5 again; should reuse the freed slots in the same page without taking a new page
    for _ in range(5):
        pid, s_idx = pool.alloc(40)
        assert pid == first_page_id

    # Clean up the 5 allocations that were never freed
    for loc in allocations[5:]:
        pool.free(*loc)

def test_consistent_hashing():
    ring = ConsistentHashRing(replicas=160)
    servers = ["backend-a:8080", "backend-b:8080", "backend-c:8080"]
    for s in servers:
        ring.add_node(s)

    # Route 1000 keys
    keys = [f"/api/v1/users/{i}" for i in range(1000)]
    initial_mapping = {k: ring.get_node(k) for k in keys}

    # Verify keys are distributed across all 3 backends
    counts = {}
    for node in initial_mapping.values():
        counts[node] = counts.get(node, 0) + 1

    assert len(counts) == 3, f"Expected 3 backends, got {counts}"
    for s in servers:
        assert 200 <= counts[s] <= 450, f"Unbalanced distribution: {counts}"

    # Remove 1 server: backend-c:8080
    ring.remove_node("backend-c:8080")
    remapped_count = 0
    for k in keys:
        new_node = ring.get_node(k)
        if initial_mapping[k] == "backend-c:8080":
            # Must be moved to A or B
            assert new_node in ["backend-a:8080", "backend-b:8080"]
        else:
            # Nodes that mapped to A or B should ideally STAY on A or B
            if new_node != initial_mapping[k]:
                remapped_count += 1

    # Remapped keys for untouched servers should be strictly 0 in a standard consistent hash ring
    assert remapped_count == 0, f"Keys unexpectedly moved between surviving nodes: {remapped_count}"

def test_smooth_weighted_round_robin():
    servers = [
        UpstreamServer("server-a", 5),
        UpstreamServer("server-b", 1),
        UpstreamServer("server-c", 1),
    ]
    swrr = SmoothWeightedRoundRobin(servers)

    results = [swrr.select() for _ in range(7)]
    # Nginx smooth pattern for {a:5, b:1, c:1}: a, a, b, a, c, a, a (no consecutive bursts of 5 a's)
    expected = ["server-a", "server-a", "server-b", "server-a", "server-c", "server-a", "server-a"]
    assert results == expected, f"Unexpected sequence: {results}"

if __name__ == "__main__":
    test_slab_allocator()
    test_consistent_hashing()
    test_smooth_weighted_round_robin()
    print("All Nginx slab allocator, consistent hashing, and SWRR tests PASSED!")
```

### 6. Summary & Complete Series Synthesis

Across the six chapters of this series, we have investigated how modern high-throughput middleware components push the boundaries of operating system performance:

| Middleware Component | Primary Bottleneck Solved | Core Architectural Mechanism |
| :--- | :--- | :--- |
| **Redis Compact Memory** | 64-bit pointer & heap overhead | SDS `embstr`, `listpack` backlen varints, dual-table incremental rehashing |
| **Redis Cluster & Sync** | CoW memory explosion during backup | Multi-Part AOF, `psync2` circular repl-backlog, CRC16 16k hash slots |
| **Kafka Zero-Copy** | OS context switches & page cache copies | `sendfile(2)` DMA network transfer, 8-byte sparse offset index |
| **RocketMQ CommitLog** | Head thrashing across thousands of queues | Unified 1GB sequential `CommitLog`, 20B `ConsumeQueue`, 2PC half-messages |
| **etcd MVCC & Watch** | State polling & lock contention | In-memory `treeIndex`, BoltDB copy-on-write B+Tree, `synced`/`unsynced` watch streams |
| **Nginx Gateway** | Thundering herd & IPC overhead | `SO_REUSEPORT` kernel load balancing, shared memory slab allocators, Ketama consistent hash |

Each of these components wins by matching its data structures to what the kernel and the hardware do cheaply: sequential I/O, page-cache reads, cache-line-sized records and few system calls.
