In Chapter 01, we saw that every heap allocation is tied to a stack owner, and references (`&T`, `&mut T`) borrow access without taking ownership. That immediately raises two design questions for high-performance libraries like `harus-aeron-rs`:

1. **How does the compiler prove that a zero-copy flyweight view (`Header<'a>`) never outlives the underlying memory-mapped term buffer?**
2. **When designing a polymorphic interface (`IdleStrategy`, `FragmentHandler`), when should we use generics (`<T: Trait>`) vs. trait objects (`&dyn Trait` / `Box<dyn Trait>`)?**

In **Chapter 02**, we dissect **Lifetimes (`'a`, `'static`)**, **Static Dispatch via Monomorphization**, **Dynamic Dispatch via 16-Byte Fat Pointers and `vtable` Layouts**, and **Object Safety**.

## Before you start

Two questions come up as soon as you write real Rust. The first: you have a function that returns a reference, so how does the compiler know the thing it points to is still alive when the caller uses it? A function that returns `&String` pointing at its own local variable would hand back a pointer to freed memory, and Rust refuses to compile it. Lifetime annotations are how you describe those relationships. The second: you want a function that works on "anything with a `read` method". You can have the compiler generate a copy per type, which is fast, or call through a table at run time, which is flexible. This chapter explains both choices and what each costs in bytes.

Read [chapter 01](/tech/series/rust-aeron/01.ownership-and-memory-layout/) first for ownership and borrowing.

Terms used in this chapter:

- **lifetime**: the span of code during which a reference is valid; written `'a`, and checked at compile time only.
- **borrow checker**: the compiler pass that rejects references that could outlive their data.
- **generic**: a function or type written over a placeholder type `T`, such as `fn f<T: Trait>(x: T)`.
- **trait**: a set of methods a type can implement, similar to an interface.
- **monomorphization**: the compiler generating a separate copy of a generic function for each concrete type used.
- **static dispatch**: the method to call is chosen at compile time, so it can be inlined.
- **dynamic dispatch**: the method is found at run time through a table of function pointers.
- **trait object (`dyn Trait`)**: a value used through a trait without its concrete type; it is passed as a pointer to the data plus a pointer to the vtable.
- **object safety**: the rules a trait must meet before it can be used as `dyn Trait`.

## 1. Lifetimes Are Descriptive Regions, Not Runtime Timers

A common misconception among newcomers is that adding a lifetime annotation `'a` makes a value live longer at runtime. **Lifetimes have zero runtime representation and generate zero machine instructions.** They are purely compile-time constraints telling the borrow checker how the lifetimes of output references relate to input references.

### Why Returning a Reference to a Local Stack Variable Fails

```rust
// COMPILE ERROR: `buf` is dropped when `bad_slice()` returns!
// fn bad_slice() -> &[u8] {
//     let buf = [1u8, 2, 3, 4];
//     &buf[..]
// }
```

Because the stack frame of `bad_slice()` is popped on `RET`, returning `&buf[..]` would create a dangling pointer in C/C++. Rust's borrow checker tracks the **liveness region** of every borrow (under **Non-Lexical Lifetimes, NLL**, a borrow ends at its *last usage point*, not necessarily the closing curly brace `}`) and verifies that the referent outlives every reference derived from it.

### Zero-Copy Flyweights with Lifetimes (`Header<'a>` in `harus-aeron-rs`)

In `harus-aeron-rs/crates/client/src/logbuffer.rs`, when `TermReader` polls a 16 MB shared-memory term buffer, copying each frame's 32-byte header into a heap-allocated struct would waste CPU cycles. Instead, `Header<'a>` borrows directly from the `AtomicBuffer` (simplified here; the real struct carries a few more fields):

```rust
pub struct Header<'a> {
    initial_term_id: i32,
    position_bits_to_shift: u32,
    buffer: &'a [u8],   // Zero-copy slice directly into the mmap'd Term Buffer!
    offset: usize,
}
```

Here `'a` guarantees at compile time that a `Header<'a>` view can never be stored or used after the underlying `AtomicBuffer` slice `'a` is unmapped or dropped—giving us **C-style zero-copy pointer arithmetic with compile-time memory safety**.

### What `'static` Actually Means (`T: 'static` vs. `&'static T`)

Two expressions look similar in Rust signatures but mean different things:

1. **`&'static T` (A Reference with `'static` Lifetime):** The referent data lives for the entire remaining execution of the process—such as string literals baked into the ELF `.rodata` segment (`let s: &'static str = "aeron:udp?endpoint=localhost:40123";`) or intentionally leaked heap allocations (`Box::leak`).
2. **`T: 'static` (A Type Bounded by `'static`, e.g., `std::thread::spawn`):**
   Why does `std::thread::spawn<F>(f: F)` require `F: Send + 'static`?
   - Because a newly spawned OS thread might outlive the parent function's stack frame!
   - **`T: 'static` does NOT mean `T` must be a global constant!** It means `T` contains **no non-`'static` borrowed references (`&'a U`)**. An owned `String`, `Vec<u8>`, or `Arc<AtomicBuffer>` constructed dynamically on the heap 1 millisecond ago satisfies `T: 'static` because it owns its data outright and will clean itself up whenever the spawned thread finishes.
   - And what if you *do* want worker threads to borrow a local stack array `&mut [u8]` without `Arc` or heap allocation? Use **`std::thread::scope(|s| { s.spawn(|| ...); })`**, which statically guarantees all spawned scoped threads `join()` before `scope()` returns!

## 2. Static Dispatch (`<T: Trait>`) vs. Dynamic Dispatch (`&dyn Trait`)

<Archify src="./diagrams/rust-fat-pointer-vtable.workflow.json" />

When you define a trait in Rust—such as Agrona's `IdleStrategy` (`crates/agrona/src/idle_strategy.rs`):

```rust
pub trait IdleStrategy {
    fn idle(&mut self, work_count: i32);
    fn reset(&mut self);
}
```

you can invoke implementations in two fundamentally different ways:

### Path A: Static Dispatch via Monomorphization (`impl Trait` / `<I: IdleStrategy>`)

```rust
pub fn duty_cycle<I: IdleStrategy>(idle_strategy: &mut I, work_count: i32) {
    idle_strategy.idle(work_count);
}
```

When you call `duty_cycle(&mut BusySpinIdleStrategy, 0)` and `duty_cycle(&mut YieldingIdleStrategy, 0)`, the compiler (**Monomorphization**) stamps out two specialized machine-code functions:

- `duty_cycle_BusySpinIdleStrategy`: The call `idle_strategy.idle(0)` is statically known to be `std::hint::spin_loop()` (`PAUSE` instruction on x86_64) and is **100% inlined into the caller's loop with zero pointer indirection and zero function-call overhead!**
- *Trade-off:* Code size (instruction cache footprint) grows for each distinct concrete type `I`, and a `Vec<I>` can only hold a single concrete type `I`, not a heterogeneous mix of strategies.

### Path B: Dynamic Dispatch via Trait Object Fat Pointers (`&dyn IdleStrategy` / `Box<dyn IdleStrategy>`)

What if an agent's idle strategy is chosen dynamically from a runtime config file (`"busy_spin"`, `"yielding"`, `"backoff"`), or you need a heterogeneous collection `Vec<Box<dyn Formatter>>`?

In C++ or Java, every object with virtual methods carries a hidden 8-byte `vptr` inside the object header on the heap. In Rust, **structs never carry hidden vtable pointers!** Even if `BusySpinIdleStrategy` implements 10 traits, `size_of::<BusySpinIdleStrategy>()` is **0 bytes** (a Zero-Sized Type, `ZST`).

Where does the `vtable` pointer live when you coerce `&BusySpinIdleStrategy` into `&dyn IdleStrategy`?
**Inside the reference itself—turning an 8-byte thin pointer into a 16-byte Fat Pointer!**

```text
Stack Fat Pointer: &dyn Formatter (16 bytes = 2 x usize)
┌───────────────────────────┬───────────────────────────┐
│ data_ptr (8 bytes)        │ vtable_ptr (8 bytes)      │
└─────────────┬─────────────┴─────────────┬─────────────┘
              │                           │
              ▼                           ▼
Concrete Struct (Heap/Stack)    Compiler-Generated .rodata vtable:
┌───────────────────────────┐   ┌──────────────────────────────────────────┐
│ HtmlFormatter { ... }     │   │ 0: drop_in_place: fn(*mut HtmlFormatter) │
└───────────────────────────┘   │ 1: size         : usize (bytes)          │
                                │ 2: align        : usize (bytes)          │
                                │ 3: format       : fn(*const (), &mut ..) │
                                └──────────────────────────────────────────┘
```

Look at why Rust's **Fat Pointer (`[data_ptr, vtable_ptr]`)** design is so powerful for systems programming:

1. **Pay Only When You Use `dyn`:** Concrete types pay zero `vptr` memory overhead when used directly or through generics.
2. **Retroactive Trait Implementation:** You can implement your own trait `MySerializer` for a standard-library type like `u64` or `Vec<u8>` and pass `&42u64 as &dyn MySerializer`, because the `vtable_ptr` lives in the fat pointer, not inside `u64`!
3. **Slices (`&[T]`, `&str`) Use the Exact Same 16-Byte Fat Pointer Trick:**
   - For `&[T]` and `&str`, Word 0 is `data_ptr: *const T` and Word 1 is `len: usize` (element/byte count).
   - For `&dyn Trait` and `Box<dyn Trait>`, Word 0 is `data_ptr: *mut ()` and Word 1 is `vtable_ptr: *const VTable`.

## 3. Object Safety — Why Some Traits Cannot Become `dyn Trait`

Have you ever written `Box<dyn Clone>` or `&dyn PartialEq` and hit compiler error `E0038: the trait cannot be made into an object`?

Once a concrete type is erased behind a 16-byte fat pointer `&dyn Trait`, the compiler only knows two things at compile time: the fat pointer is 16 bytes wide, and the `.rodata` vtable has a fixed number of function pointer slots. Therefore, a trait is **Object-Safe (`dyn`-compatible)** only if its callable methods obey the rules below (plus a few more, such as no `Sized` supertrait and no associated consts):

1. **No `Self` by Value in Return or Parameter Positions (Unless Sized-Excluded):**
   - Look at `Clone::clone(&self) -> Self`. If you call `x.clone()` on `x: &dyn Clone`, how many bytes should the caller allocate on its stack frame to hold the returned `Self`? `Self` could be a 1-byte `u8` or a 1,024-byte struct—the caller's stack layout must be fixed at compile time!
2. **No Generic Type Parameters on Methods (`fn process<T>(&self, item: T)`):**
   - A generic method `fn process<T>` represents an *infinite family* of monomorphized functions. A runtime `.rodata` `vtable` has a finite, fixed number of function-pointer slots and cannot contain a slot for every possible type `T` a downstream crate might pass!
3. **Has a Receiver (`&self`, `&mut self`, `Box<Self>`, `Arc<Self>`):**
   - Associated functions without a `self` receiver (like `Default::default() -> Self`) have no fat pointer from which to look up a `vtable_ptr`!
   - *Escape Hatch:* You can keep a trait `dyn`-compatible by adding **`where Self: Sized`** to any non-object-safe helper method (just like `std::io::Write::by_ref(&mut self) -> &mut Self where Self: Sized`), which excludes that specific method from the `vtable` while keeping it available on concrete types!

## 4. Verification Lab — Inspecting Raw Fat Pointers, `.rodata` VTables & Scoped Threads

Run this verification script to compile and execute a Rust probe that decomposes a 16-byte `&dyn IdleStrategy` fat pointer into its raw `(data_ptr, vtable_ptr)` words, reads the `size` and `align` headers directly out of the compiler-generated `.rodata` vtable, and verifies zero-allocation scoped thread borrows:

```python
#!/usr/bin/env python3
"""Compile & run a rustc probe inspecting 16-byte &dyn Trait fat pointers and vtable headers."""
import shutil
import subprocess
import tempfile
from pathlib import Path

RUST_SOURCE = r"""
use std::mem::{size_of, transmute};
use std::thread;

pub trait IdleStrategy {
    fn step(&mut self, work_count: i32) -> u64;
}

#[repr(C, align(16))]
struct BackoffState {
    spins: u64,
    yields: u64,
    parks: u64,
}

impl IdleStrategy for BackoffState {
    fn step(&mut self, work_count: i32) -> u64 {
        if work_count == 0 {
            self.spins += 1;
        }
        self.spins + self.yields + self.parks
    }
}

// Current rustc vtable header layout: [drop_in_place, size, align, method_0, ...].
// This is an implementation detail, not a stable guarantee: the probe may break on a future rustc.
#[repr(C)]
struct RawVTableHeader {
    drop_in_place: usize,
    size: usize,
    align: usize,
    step_fn: usize,
}

fn main() {
    let mut state = BackoffState { spins: 10, yields: 2, parks: 1 };
    let state_addr = &state as *const BackoffState as usize;

    // 1. Coerce concrete struct reference into a 16-byte &dyn IdleStrategy fat pointer
    let dyn_ref: &mut dyn IdleStrategy = &mut state;
    assert_eq!(size_of::<&dyn IdleStrategy>(), 16);
    assert_eq!(size_of::<&BackoffState>(), 8);

    let (data_ptr, vtable_ptr): (usize, *const RawVTableHeader) = unsafe {
        transmute::<&dyn IdleStrategy, (usize, *const RawVTableHeader)>(dyn_ref)
    };
    let vtable = unsafe { &*vtable_ptr };

    println!("Thin pointer (&BackoffState)     : {} bytes (addr=0x{:x})", size_of::<&BackoffState>(), state_addr);
    println!("Fat pointer  (&dyn IdleStrategy) : {} bytes (data_ptr=0x{:x}, vtable_ptr={:p})",
        size_of::<&dyn IdleStrategy>(), data_ptr, vtable_ptr);
    println!("Decoded .rodata VTable Header    : size={}B, align={}B, step_fn=0x{:x}",
        vtable.size, vtable.align, vtable.step_fn);

    assert_eq!(data_ptr, state_addr);
    assert_eq!(vtable.size, size_of::<BackoffState>());
    assert_eq!(vtable.align, align_of::<BackoffState>());
    assert_eq!(dyn_ref.step(0), 14);

    // 2. Verify std::thread::scope borrows non-'static stack data across OS threads safely
    let mut term_counters = [0u64; 4];
    thread::scope(|s| {
        for (idx, slot) in term_counters.iter_mut().enumerate() {
            s.spawn(move || {
                *slot = (idx as u64 + 1) * 1024;
            });
        }
    });
    println!("Scoped thread stack borrow result: {:?}", term_counters);
    assert_eq!(term_counters, [1024, 2048, 3072, 4096]);
}
"""

if __name__ == "__main__":
    rustc = shutil.which("rustc")
    assert rustc is not None
    with tempfile.TemporaryDirectory() as tmp:
        src = Path(tmp) / "vtable_probe.rs"
        bin_path = Path(tmp) / "vtable_probe"
        src.write_text(RUST_SOURCE, encoding="utf-8")
        subprocess.run([rustc, "--edition=2021", "-O", str(src), "-o", str(bin_path)], check=True)
        out = subprocess.run([str(bin_path)], capture_output=True, text=True, check=True)
        print(out.stdout.strip())
```
