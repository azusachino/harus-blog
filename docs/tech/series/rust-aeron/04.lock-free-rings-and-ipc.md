In `harus-aeron-rs/crates/agrona`, there is not a single `Mutex`, `RwLock`, or OS `Condvar`. Yet multiple client threads and the Aeron Media Driver exchange millions of commands, heartbeats, and telemetry counters per second across memory-mapped files (`mmap`) with sub-microsecond latency.

As the Agrona tutorial in `harus-aeron-rs` puts it:
> *"Every 'clever' concurrency trick in Agrona is really a byte layout wearing a trench coat. Once you can draw the buffer layout on a whiteboard, the algorithm is usually just: read this field, do the obvious thing, write that field back."*

In **Chapter 04**, we examine **MESI CPU Cache Coherency**, **False Sharing**, and the exact byte layouts of Agrona's **`OneToOneRingBuffer` (SPSC)**, **`ManyToOneRingBuffer` (MPSC)**, **`BroadcastTransmitter`/`Receiver`**, and **`CountersManager`**.

## 1. MESI Cache Coherency & Why Agrona Pads Counters to 128 Bytes

A modern CPU never reads or writes a single 8-byte `i64` in isolation from main RAM. Instead, L1/L2/L3 caches transfer memory in **64-byte Cache Lines** governed by the **MESI (Modified, Exclusive, Shared, Invalid)** hardware cache-coherency protocol:

- When Core 0 wants to modify an 8-byte counter inside Cache Line $X$, its L1 cache controller must broadcast a **Read-For-Ownership (RFO) / Invalidate** message across the CPU interconnect, marking Cache Line $X$ as **Invalid (`I`)** in every other core's L1/L2 cache.
- If Core 1 is simultaneously trying to modify—or even repeatedly Acquire-load—a *different* 8-byte variable that happens to sit in the **same 64-byte cache line**, Core 0 and Core 1 play "cache-line ping-pong" across the L3/socket interconnect (~40–80 ns per bounce instead of ~1 ns in L1 cache). This is **False Sharing**.

### Why 128 Bytes Instead of 64 Bytes (`COUNTER_PADDING = CACHE_LINE_LENGTH * 2`)?

Look at `harus-aeron-rs/crates/agrona/src/ring_buffer/mod.rs`:

```rust
pub const CACHE_LINE_LENGTH: usize = 64;
pub const COUNTER_PADDING: usize = CACHE_LINE_LENGTH * 2; // 128 bytes!
```

If a hardware cache line is 64 bytes, why does Agrona pad every ring-buffer trailer counter and every `CountersManager` value slot to **128 bytes (two cache lines)**?

- Because modern Intel/AMD x86_64 and ARM64 CPUs feature a **Spatial Hardware Prefetcher (Adjacent Cache-Line Prefetch)**: when a core fetches Cache Line $2k$, the prefetcher automatically pulls in the paired adjacent Cache Line $2k+1$ (`128-byte aligned pair`)!
- Padding hot atomic counters by **128 bytes** ensures that neither the target cache line nor its adjacent prefetched buddy line ever collides with another core's atomic counter.

## 2. The 768-Byte Ring Buffer Trailer Protocol (`spsc.rs` & `mpsc.rs`)

<Archify src="./diagrams/agrona-ring-buffer-ipc.workflow.json" />

An Agrona ring buffer (`OneToOneRingBuffer` or `ManyToOneRingBuffer`) wraps a contiguous `AtomicBuffer` whose length is a power-of-two **Data Capacity** ($2^k$, so wrapping index arithmetic uses a single-cycle bitwise mask `index & (capacity - 1)` instead of slow integer division `%`) followed by a **768-byte Trailer (`TRAILER_LENGTH = COUNTER_PADDING * 6`)**:

```text
┌───────────────────────────────────────────────┬───────────────────────────────────┐
│ Data Region (Power-of-2 bytes, e.g. 65,536 B) │ Trailer (768 bytes = 6 x 128 B)   │
└───────────────────────────────────────────────┴───────────────────────────────────┘
```

Here is the exact offset table of the 768-byte trailer in `harus-aeron-rs/crates/agrona/src/ring_buffer/mod.rs`:

| Trailer Offset | Constant Name | Owner / Writer | Role |
| :---: | :--- | :--- | :--- |
| `+128` | `TAIL_POSITION_OFFSET` | **Producer(s)** | Monotonic 64-bit byte position where the next producer frame will be claimed. |
| `+256` | `HEAD_CACHE_POSITION_OFFSET` | **Producer(s)** | **Producer's local cached copy** of the consumer's head position! |
| `+384` | `HEAD_POSITION_OFFSET` | **Consumer** | Monotonic 64-bit byte position up to which the consumer has finished reading. |
| `+512` | `CORRELATION_COUNTER_OFFSET` | **Either** | Atomic sequence generator (`next_correlation_id()`) for client RPC commands. |
| `+640` | `CONSUMER_HEARTBEAT_OFFSET` | **Consumer** | Millisecond timestamp updated by the consumer (`MediaDriver`) to prove liveness. |

### The Secret Weapon: `HEAD_CACHE_POSITION_OFFSET` (+256)

Why are there **two** head counters in the trailer—`HEAD_POSITION_OFFSET` (`+384`, written by Consumer) and `HEAD_CACHE_POSITION_OFFSET` (`+256`, written by Producer)?

Think about what would happen if the Producer read `HEAD_POSITION_OFFSET` (`+384`) on *every* `write()` to check if the ring buffer has enough free space (`capacity - (tail - head) >= required_bytes`):

- Every time the Consumer finishes reading a batch and updates `HEAD_POSITION_OFFSET` (`+384`), it invalidates that cache line in the Producer's L1 cache!
- On the very next `write()`, the Producer would suffer an L1/L2 cache miss waiting to fetch `+384` from the Consumer's core—**even when the 64 KB ring buffer is 99% empty!**

Agrona eliminates 99% of those cross-core cache misses with `HEAD_CACHE_POSITION_OFFSET` (`+256`):

1. On `write()`, the Producer reads its **own** `HEAD_CACHE_POSITION_OFFSET` (`+256`), which sits warm in the Producer core's L1 cache (`Modified`/`Exclusive` state) because the Consumer *never* touches `+256`!
2. As long as `tail + aligned_record_len <= head_cache + capacity`, the Producer knows immediately—with **zero cross-core cache traffic**—that there is room in the buffer!
3. **Only when the cached head looks full** does the Producer perform a volatile Acquire load of the real `HEAD_POSITION_OFFSET` (`+384`), update `HEAD_CACHE_POSITION_OFFSET` (`+256`), and re-check capacity!

### Frame Header & Two-Phase Commit Inside the Ring (`MPSC` vs. `SPSC`)

Each variable-length record in the Data Region is prefixed by an 8-byte header (`HEADER_LENGTH = 8`, aligned to 8 bytes):

- Offset `+0`: `frame_length: i32` (signed 32-bit total record length, or negative while in-flight in MPSC)
- Offset `+4`: `msg_type_id: i32` (positive message type ID, or `PADDING_MSG_TYPE_ID = -1` when wrapping around the end of the ring)

In **`ManyToOneRingBuffer` (MPSC)**, multiple client threads claim space concurrently by running a Compare-And-Swap (`CAS`) loop on `TAIL_POSITION_OFFSET` (`+128`). Wait: what if Producer Thread A wins the CAS for bytes `[0..64)` and Producer Thread B immediately wins the CAS for bytes `[64..128)`, and **Thread B finishes copying its payload before Thread A**?
If the Consumer blindly read up to `TAIL_POSITION_OFFSET`, it would read Thread A's half-written bytes!
Here is how MPSC solves it without locks:

1. Immediately after winning the CAS at offset `claim_offset`, Producer A writes **`-record_length` (negative!)** into `frame_length` at `claim_offset`, copies the message payload, and finally executes an **`Ordering::Release` store of `+record_length` (positive!)** at `claim_offset`.
2. The single Consumer scans forward from `head`:
   - If `frame_length <= 0` (either `0` unwritten or `< 0` still being copied by a producer), **the Consumer stops scanning immediately** and returns `read_count`.
   - If `frame_length > 0` and `msg_type_id == PADDING_MSG_TYPE_ID (-1)`, the Consumer skips the wrap-around padding to index `0`.
   - If `frame_length > 0` and `msg_type_id > 0`, the Consumer invokes the handler, zeroes the consumed byte span so future wrap-arounds see clean `0` headers, and Release-stores the new `HEAD_POSITION_OFFSET` (`+384`).

## 3. `BroadcastTransmitter` & Optimistic Lapping Detection (`broadcast.rs`)

A Ring Buffer is a **work queue** (consuming a message removes it and exerts backpressure when full). What if the `MediaDriver` needs to broadcast control responses (`ON_PUBLICATION_READY`, `ON_AVAILABLE_IMAGE`) to 10 independent client threads where a slow client must never block the driver?

`BroadcastTransmitter` and `BroadcastReceiver` (`crates/agrona/src/broadcast.rs`) use **SeqLock-style Optimistic Validation**:

1. Before writing a message at `tail`, the Transmitter stores `tail + record_length` into **`TAIL_INTENT_COUNTER_OFFSET`** (Release store), copies the record into the circular buffer, and then updates **`TAIL_COUNTER_OFFSET`**.
2. A `BroadcastReceiver` reads the record at its local `cursor` and **validates after reading (`validate()`)** that `cursor + capacity > tail_intent`.
   - If the Transmitter lapped the ring buffer and overwrote `cursor` while the Receiver was mid-read, `validate()` returns `false` (`AgronaError::Lapped`), telling the Receiver to discard the torn read and jump ahead to the latest record!

## 4. `CountersManager` — Shared-Memory Observability (`counters.rs`)

In Aeron, you never query an HTTP endpoint or database to check stream backpressure, bytes sent, or receiver positions. Instead, `CountersManager` (`crates/agrona/src/counters.rs`) manages two parallel, index-aligned arrays in a single memory-mapped file (`cnc.dat` — Command-and-Control file):

1. **Metadata Buffer (`METADATA_LENGTH = 512 bytes` per slot):**
   - Offset `0`: `record_state: i32` (`RECORD_UNUSED = 0`, `RECORD_ALLOCATED = 1`, `RECORD_RECLAIMED = -1`)
   - Offset `4`: `type_id: i32`
   - Offset `8`: `free_for_reuse_deadline_ms: i64`
   - Offset `16..128`: 112-byte binary key (e.g., `(session_id, stream_id, channel)`)
   - Offset `128..512`: 4-byte length + 380-byte human-readable UTF-8 label (e.g., `"pub-pos: session=1 stream=1001"`).
2. **Values Buffer (`COUNTER_LENGTH = 128 bytes` per slot):**
   - Offset `0`: The live 64-bit atomic counter value (`AtomicI64`), padded to 128 bytes so incrementing Counter $N$ at 20 million ops/sec never causes false sharing with Counter $N+1$!

Because `cnc.dat` is a flat memory-mapped file with fixed 512B/128B strides, external CLI tools (`aeron-stat`) can `mmap` the file read-only and display live nanosecond-accurate stream positions with **zero RPC overhead and zero impact on the running Media Driver**!

## 5. Verification Lab — Lock-Free SPSC Ring Buffer with `HEAD_CACHE` Verification

Run this verification script to compile and run a Rust implementation of Agrona's 768-byte trailer `OneToOneRingBuffer`, counting how many times the Producer satisfies capacity checks purely from its local `HEAD_CACHE_POSITION_OFFSET` (`+256`) vs. reloading the Consumer's `HEAD_POSITION_OFFSET` (`+384`):

```python
#!/usr/bin/env python3
"""Compile & run a Rust probe of Agrona's 768B-trailer RingBuffer & HEAD_CACHE hit rate."""
import shutil
import subprocess
import tempfile
from pathlib import Path

RUST_SOURCE = r"""
use std::sync::atomic::{AtomicI32, AtomicI64, Ordering};

const COUNTER_PADDING: usize = 128;
const TAIL_OFFSET: usize = COUNTER_PADDING * 1;       // +128
const HEAD_CACHE_OFFSET: usize = COUNTER_PADDING * 2; // +256
const HEAD_OFFSET: usize = COUNTER_PADDING * 3;       // +384
const TRAILER_LENGTH: usize = COUNTER_PADDING * 6;    // 768
const HEADER_LENGTH: usize = 8;
const PADDING_MSG_TYPE_ID: i32 = -1;

fn align8(val: usize) -> usize {
    (val + 7) & !7
}

struct MiniAgronaRing {
    buf: Vec<u8>,
    capacity: usize,
    mask: usize,
    pub fast_head_cache_hits: u64,
    pub slow_head_reloads: u64,
}

impl MiniAgronaRing {
    fn new(capacity: usize) -> Self {
        assert!(capacity.is_power_of_two());
        Self {
            buf: vec![0u8; capacity + TRAILER_LENGTH],
            capacity,
            mask: capacity - 1,
            fast_head_cache_hits: 0,
            slow_head_reloads: 0,
        }
    }

    fn atomic_i64(&self, offset: usize) -> &AtomicI64 {
        unsafe { &*(self.buf.as_ptr().add(offset) as *const AtomicI64) }
    }

    fn atomic_i32(&self, offset: usize) -> &AtomicI32 {
        unsafe { &*(self.buf.as_ptr().add(offset) as *const AtomicI32) }
    }

    fn write(&mut self, msg_type_id: i32, payload: &[u8]) -> bool {
        let record_len = payload.len() + HEADER_LENGTH;
        let aligned_len = align8(record_len);
        let tail = self.atomic_i64(self.capacity + TAIL_OFFSET).load(Ordering::Relaxed);
        let mut head_cache = self.atomic_i64(self.capacity + HEAD_CACHE_OFFSET).load(Ordering::Relaxed);

        let to_end = self.capacity - ((tail as usize) & self.mask);
        let required = if aligned_len > to_end { aligned_len + to_end } else { aligned_len };

        if tail + (required as i64) > head_cache + (self.capacity as i64) {
            // Fast path missed: reload true Consumer HEAD_POSITION (+384) via Acquire!
            self.slow_head_reloads += 1;
            let head = self.atomic_i64(self.capacity + HEAD_OFFSET).load(Ordering::Acquire);
            if tail + (required as i64) > head + (self.capacity as i64) {
                return false; // Ring buffer genuinely full!
            }
            head_cache = head;
            self.atomic_i64(self.capacity + HEAD_CACHE_OFFSET).store(head_cache, Ordering::Relaxed);
        } else {
            self.fast_head_cache_hits += 1;
        }

        let mut write_idx = (tail as usize) & self.mask;
        if aligned_len > to_end {
            // Write wrap-around PADDING frame at the tail end of the buffer
            self.atomic_i32(write_idx + 4).store(PADDING_MSG_TYPE_ID, Ordering::Relaxed);
            self.atomic_i32(write_idx).store(to_end as i32, Ordering::Release);
            write_idx = 0;
        }

        // Write msg_type_id + payload first, Release-store positive frame_length last!
        self.atomic_i32(write_idx + 4).store(msg_type_id, Ordering::Relaxed);
        unsafe {
            std::ptr::copy_nonoverlapping(
                payload.as_ptr(),
                self.buf.as_mut_ptr().add(write_idx + HEADER_LENGTH),
                payload.len(),
            );
        }
        self.atomic_i32(write_idx).store(record_len as i32, Ordering::Release);
        self.atomic_i64(self.capacity + TAIL_OFFSET).store(tail + required as i64, Ordering::Release);
        true
    }

    fn read<F: FnMut(i32, &[u8])>(&mut self, mut handler: F) -> usize {
        let head = self.atomic_i64(self.capacity + HEAD_OFFSET).load(Ordering::Relaxed);
        let mut bytes_read = 0usize;
        let mut msg_count = 0usize;

        while bytes_read < self.capacity {
            let idx = ((head as usize) + bytes_read) & self.mask;
            let frame_len = self.atomic_i32(idx).load(Ordering::Acquire);
            if frame_len <= 0 {
                break;
            }
            let aligned = align8(frame_len as usize);
            let msg_type = self.atomic_i32(idx + 4).load(Ordering::Relaxed);
            if msg_type != PADDING_MSG_TYPE_ID {
                let payload_len = (frame_len as usize) - HEADER_LENGTH;
                handler(msg_type, &self.buf[idx + HEADER_LENGTH .. idx + HEADER_LENGTH + payload_len]);
                msg_count += 1;
            }
            // Zero cleared span so future wrap-arounds see 0 length
            self.buf[idx .. idx + aligned].fill(0);
            bytes_read += aligned;
        }

        if bytes_read > 0 {
            self.atomic_i64(self.capacity + HEAD_OFFSET).store(head + bytes_read as i64, Ordering::Release);
        }
        msg_count
    }
}

fn main() {
    let mut ring = MiniAgronaRing::new(4096); // 4 KB data buffer + 768 B trailer
    let mut total_received = 0usize;

    // Simulate 100 batches of 40 messages (24B each -> 32B aligned -> 1,280B per batch)
    for batch in 0..100 {
        for i in 0..40 {
            let msg = format!("cmd:{:04}:{:04}", batch, i);
            assert!(ring.write(1, msg.as_bytes()));
        }
        total_received += ring.read(|msg_type, data| {
            assert_eq!(msg_type, 1);
            assert_eq!(data.len(), 13);
        });
    }

    let total_writes = ring.fast_head_cache_hits + ring.slow_head_reloads;
    let hit_rate = (ring.fast_head_cache_hits as f64 / total_writes as f64) * 100.0;
    println!("Total messages transferred : {}", total_received);
    println!("HEAD_CACHE (+256) hits     : {}/{} ({:.2}% avoided reading consumer cache line!)",
        ring.fast_head_cache_hits, total_writes, hit_rate);
    println!("True HEAD (+384) reloads   : {}", ring.slow_head_reloads);
    assert_eq!(total_received, 4000);
    assert!(hit_rate > 96.0);
}
"""

if __name__ == "__main__":
    rustc = shutil.which("rustc")
    assert rustc is not None
    with tempfile.TemporaryDirectory() as tmp:
        src = Path(tmp) / "ring_probe.rs"
        bin_path = Path(tmp) / "ring_probe"
        src.write_text(RUST_SOURCE, encoding="utf-8")
        subprocess.run([rustc, "--edition=2021", "-O", str(src), "-o", str(bin_path)], check=True)
        out = subprocess.run([str(bin_path)], capture_output=True, text=True, check=True)
        print(out.stdout.strip())
```
